# 为什么 `change` 中的 `x` 不需要重新定义？

## 一、核心原因：形参在参数列表里已经声明了

代码：

```java
public static void change(int x) {
    x = 100;
    System.out.println("方法内 x = " + x);
}
```

其中：

```java
int x
```

写在方法参数列表中，这本身就是一次**变量声明**。

也就是说，`change` 方法声明了一个 `int` 类型的形参，名字叫 `x`。方法体中的：

```java
x = 100;
```

只是对已经声明过的变量 `x` 进行**赋值**，不是重新定义变量。

---

## 二、形参本质上就是方法体作用域内的局部变量

形参可以理解为一种特殊的局部变量：

- 它在方法参数列表中声明；
- 它的作用域是整个方法体；
- 它的初始值由方法调用时传入的实参决定。

所以方法体内可以直接使用 `x`，不需要再写：

```java
int x;
```

---

## 三、对比局部变量

局部变量必须先声明再使用：

```java
public static void change(int x) {
    int y;       // 局部变量，需要先声明
    y = 100;     // 再赋值

    x = 100;     // x 是形参，已经在参数列表声明过了
}
```

对比表：

| 对比项      | 局部变量     | 形式参数        |
|----------|----------|-------------|
| 声明位置     | 方法体内     | 方法参数列表      |
| 初始值来源    | 方法体内手动赋值 | 调用方法时由实参传入  |
| 作用域      | 所在代码块    | 整个方法体       |
| 是否需要额外声明 | 需要       | 不需要，参数列表已声明 |

---

## 四、不能重复声明形参

因为 `x` 已经在参数列表中声明过了，所以方法体内不能再声明一个同名的 `x`：

```java
public static void change(int x) {
    int x = 100; // 编译错误：x 已经定义过了
}
```

错误原因：`x` 已经在方法参数列表中声明，方法体内不能重复声明同名变量。

---

## 五、调用 `change(a)` 时发生了什么

示例：

```java
public static void main(String[] args) {
    int a = 10;
    change(a);
}

public static void change(int x) {
    x = 100;
}
```

调用 `change(a)` 时，可以理解为：

```java
int x = a; // 形参 x 被初始化为实参 a 的值的副本
x = 100;   // 方法体内修改的是副本 x
```

执行过程：

```text
a = 10
x = 10   // 传入的是 a 的副本
x = 100  // 修改副本
a 仍然是 10
```

因此输出结果是：

```text
方法内 x = 100
方法外 a = 10
```

---

## 六、一句话总结

`int x` 写在方法参数列表里就是变量声明，方法体中的 `x = 100` 只是对已声明形参的赋值。形参本质上就是方法体作用域内的局部变量，它的初始值由调用方传入，所以不需要在方法体中重新定义。
