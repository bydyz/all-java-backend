# Java 集合框架体系详解

## 一、整体架构

Java 集合框架的核心接口分为两大分支：

```
Iterable
 └── Collection
      ├── List          有序、可重复、有索引
      ├── Set           无序（或按规则排序）、不可重复
      └── Queue         队列，FIFO / 优先级
           └── Deque    双端队列

Map                       键值对，key 唯一
 ├── HashMap
 ├── LinkedHashMap
 ├── TreeMap
 ├── Hashtable
 └── ConcurrentHashMap
```

**注意：Map 不继承 Collection**，它是独立的顶层接口。

核心实现类一览：

| 接口 | 实现类 | 底层结构 | 线程安全 |
|---|---|---|---|
| List | ArrayList | 动态数组 | 否 |
| List | LinkedList | 双向链表 | 否 |
| List | Vector | 动态数组 | 是（synchronized） |
| List | CopyOnWriteArrayList | 数组（写时复制） | 是 |
| Set | HashSet | HashMap | 否 |
| Set | LinkedHashSet | LinkedHashMap | 否 |
| Set | TreeSet | TreeMap（红黑树） | 否 |
| Queue | PriorityQueue | 二叉堆（数组） | 否 |
| Queue | ArrayDeque | 循环数组 | 否 |
| Map | HashMap | 数组+链表+红黑树 | 否 |
| Map | LinkedHashMap | HashMap+双向链表 | 否 |
| Map | TreeMap | 红黑树 | 否 |
| Map | ConcurrentHashMap | 数组+链表+红黑树（CAS+synchronized） | 是 |

## 二、Iterable 与 Collection

`Collection` 继承 `Iterable`，所以所有集合都能用 for-each 遍历（本质是拿到 Iterator）。

```java
Collection<String> c = new ArrayList<>(List.of("a", "b"));
for (String s : c) {        // 编译后等价于 iterator()
    System.out.println(s);
}
```

`Collection` 定义了 `add / remove / contains / size / isEmpty / clear / toArray / iterator` 等通用方法。

**fail-fast 机制**：`ArrayList`、`HashMap` 等的迭代器内部维护 `modCount`，遍历中若集合被结构性修改（add/remove），`next()` 会抛 `ConcurrentModificationException`。

```java
List<String> list = new ArrayList<>(List.of("a", "b", "c"));
for (String s : list) {
    if (s.equals("b")) list.remove(s); // 抛 ConcurrentModificationException
}

// 正确做法：用迭代器自身的 remove
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if (it.next().equals("b")) it.remove();
}

// 或使用 removeIf
list.removeIf(s -> s.equals("b"));
```

## 三、List

### 3.1 ArrayList

底层是 `Object[] elementArray`，**查询 O(1)，中间插入/删除 O(n)**。

- 默认初始容量 10（首次 add 时才分配，`DEFAULTCAPACITY_EMPTY_ELEMENTDATA`）
- 扩容规则：`newCapacity = oldCapacity + (oldCapacity >> 1)`，即 **1.5 倍**
- 允许 null，非线程安全

```java
List<Integer> list = new ArrayList<>();
for (int i = 0; i < 100; i++) list.add(i);
System.out.println(list.get(50));   // O(1)

// 已知大小时预分配容量，避免多次扩容复制
List<Integer> big = new ArrayList<>(10000);

list.add(1, 999);                   // 中间插入，后续元素整体后移 O(n)
list.remove(0);                     // 删除头部同理 O(n)
```

> 坑：`Arrays.asList(...)` 返回的是 `java.util.Arrays$ArrayList`，**定长**，add/remove 会抛 `UnsupportedOperationException`。

### 3.2 LinkedList

底层是双向链表 `Node<E>{prev, item, next}`，**头尾插入删除 O(1)，随机访问 O(n)**，同时实现了 `Deque`。

```java
LinkedList<String> ll = new LinkedList<>();
ll.addFirst("b");
ll.addFirst("a");
ll.addLast("c");
System.out.println(ll);          // [a, b, c]
System.out.println(ll.get(1));   // b，链表遍历，O(n)
System.out.println(ll.pollFirst()); // a，当作队列使用
```

### 3.3 Vector 与 CopyOnWriteArrayList

- `Vector`：方法全加 `synchronized`，扩容 2 倍，性能差，基本被淘汰。
- `CopyOnWriteArrayList`：**写时复制**，写操作加锁并复制整个数组，读操作无锁。适合**读多写极少**（如监听器列表）。

```java
List<String> cow = new CopyOnWriteArrayList<>();
cow.add("a");
for (String s : cow) {          // 遍历的是快照，遍历中 add 不会抛异常
    cow.add("x");
}
```

## 四、Set

Set 通常由对应的 Map 实现，value 存一个固定的 `PRESENT` 占位对象。

### 4.1 HashSet

基于 `HashMap`，元素作为 key 存入。

```java
Set<String> set = new HashSet<>();
set.add("apple");
set.add("apple");                // 重复，返回 false
System.out.println(set.size());  // 1
```

要点：
- 依赖 `hashCode()` 和 `equals()`，**自定义对象必须正确重写两者**，否则重复元素判不出来。
- 不保证顺序，允许一个 null。

```java
class User {
    String id;
    User(String id) { this.id = id; }
    @Override public boolean equals(Object o) {
        return o instanceof User u && u.id.equals(this.id);
    }
    @Override public int hashCode() { return id.hashCode(); }
}
```

### 4.2 LinkedHashSet

继承 `HashSet`，内部用 `LinkedHashMap`，通过双向链表维护**插入顺序**。

```java
Set<String> s = new LinkedHashSet<>();
s.add("c"); s.add("a"); s.add("b");
System.out.println(s);   // [c, a, b]  保持插入顺序
```

### 4.3 TreeSet

基于 `TreeMap`（红黑树），**有序**，元素必须实现 `Comparable` 或传入 `Comparator`。不允许 null（自然排序时）。

```java
TreeSet<Integer> ts = new TreeSet<>(List.of(5, 1, 3, 1, 9));
System.out.println(ts);          // [1, 3, 5, 9] 自动排序去重
System.out.println(ts.first());  // 1
System.out.println(ts.higher(3));// 5

// 自定义排序
TreeSet<String> byLen = new TreeSet<>(Comparator.comparingInt(String::length)
                                                .thenComparing(Comparator.naturalOrder()));
byLen.addAll(List.of("bbb", "a", "cc"));
System.out.println(byLen);       // [a, cc, bbb]
```

## 五、Queue / Deque

### 5.1 PriorityQueue

二叉堆实现，`peek/poll` 取最小（默认自然序），**add/offer/poll 均为 O(log n)**，`peek` O(1)。

```java
PriorityQueue<Integer> pq = new PriorityQueue<>();
pq.offer(5); pq.offer(1); pq.offer(3);
while (!pq.isEmpty()) System.out.print(pq.poll() + " "); // 1 3 5

// 大顶堆
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Comparator.reverseOrder());

// 对象按字段排序
PriorityQueue<Task> tasks = new PriorityQueue<>(Comparator.comparingInt(t -> t.priority));
```

注意：`PriorityQueue` 遍历不保证有序，只有 `poll` 才按序输出。

### 5.2 ArrayDeque

循环数组实现的双端队列，**比 LinkedList 更快**，官方推荐用来代替 `Stack` 和 `LinkedList` 做栈/队列。**不允许 null**。

```java
Deque<Integer> stack = new ArrayDeque<>();
stack.push(1); stack.push(2); stack.push(3);
System.out.println(stack.pop());   // 3

Deque<Integer> queue = new ArrayDeque<>();
queue.offer(1); queue.offer(2);
System.out.println(queue.poll());  // 1
```

### 5.3 阻塞队列（java.util.concurrent）

`BlockingQueue` 系列用于生产者-消费者：

| 类 | 结构 |
|---|---|
| ArrayBlockingQueue | 有界数组 |
| LinkedBlockingQueue | 链表（可选有界） |
| SynchronousQueue | 不存储元素，直接交接 |
| PriorityBlockingQueue | 无界优先级堆 |
| DelayQueue | 延迟元素 |

```java
BlockingQueue<String> q = new LinkedBlockingQueue<>(10);

Thread producer = new Thread(() -> {
    try { q.put("data"); } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
});
Thread consumer = new Thread(() -> {
    try { System.out.println(q.take()); } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
});
producer.start(); consumer.start();
```

## 六、Map

### 6.1 HashMap（重点）

**JDK 8 结构：数组 + 链表 + 红黑树**。

关键参数与机制：
- 默认容量 16，负载因子 0.75，阈值 `capacity * loadFactor`
- 容量永远是 **2 的幂**（`tableSizeFor`），这样 `(n-1) & hash` 等价于取模但更快
- hash 扰动：`(h = key.hashCode()) ^ (h >>> 16)`，让高位参与运算，减少冲突
- 链表长度 ≥ **8** 且数组容量 ≥ **64** 时树化；树节点数 ≤ **6** 时退化为链表
- 扩容：容量翻倍，元素重新分配（JDK8 用高低位拆分，无需重算 hash）

```java
Map<String, Integer> map = new HashMap<>();
map.put("a", 1);
map.put("b", 2);
map.put("a", 100);                       // 覆盖，返回旧值 1
System.out.println(map.getOrDefault("c", 0)); // 0

// 常用原子式操作
map.computeIfAbsent("c", k -> 3);        // 不存在才计算
map.merge("a", 10, Integer::sum);        // a -> 110
map.computeIfPresent("b", (k, v) -> v * 10); // b -> 20
```

遍历方式：

```java
map.forEach((k, v) -> System.out.println(k + "=" + v));

// 只遍历 entry，性能优于 keySet + get
for (Map.Entry<String, Integer> e : map.entrySet()) {
    System.out.println(e.getKey() + "=" + e.getValue());
}
```

**坑点**：
1. 自定义对象作 key 必须重写 `hashCode/equals`。
2. 并发下 `HashMap` 扩容可能死循环（JDK7 头插法）或数据丢失（JDK8），并发场景用 `ConcurrentHashMap`。
3. 不要在遍历中 `put` 新 key（结构性修改），需用 `Iterator.remove` 或 `removeIf`。

### 6.2 LinkedHashMap

在 HashMap 的 Node 上增加 `before/after` 双向链表，维护顺序。`accessOrder = false` 时保插入序，`true` 时保访问序（**LRU 缓存**基础）。

```java
// LRU 缓存：容量满时移除最久未访问的元素
class LRUCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;
    LRUCache(int capacity) {
        super(capacity, 0.75f, true);   // accessOrder = true
        this.capacity = capacity;
    }
    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > capacity;
    }
}

LRUCache<String, Integer> cache = new LRUCache<>(2);
cache.put("a", 1); cache.put("b", 2);
cache.get("a");            // 访问 a，a 变成最近使用
cache.put("c", 3);         // 淘汰最久未用的 b
System.out.println(cache); // {a=1, c=3}
```

### 6.3 TreeMap

红黑树实现，key 有序，支持范围查询。key 必须 `Comparable` 或提供 `Comparator`。

```java
TreeMap<Integer, String> tm = new TreeMap<>();
tm.put(3, "c"); tm.put(1, "a"); tm.put(2, "b");

System.out.println(tm.firstKey());            // 1
System.out.println(tm.headMap(2));            // {1=a}  不含 2
System.out.println(tm.tailMap(2, true));      // {2=b, 3=c}
System.out.println(tm.subMap(1, true, 3, false)); // {1=a, 2=b}
System.out.println(tm.floorEntry(5));         // 3=c  向下取最近的
```

### 6.4 Hashtable

早期线程安全 Map，方法全 `synchronized`，**不允许 null key/value**，性能差，已被 `ConcurrentHashMap` 取代。

### 6.5 ConcurrentHashMap

JDK 8 的实现：**CAS + synchronized 锁单个桶的头节点**，锁粒度细，读操作无锁（`volatile` 保证可见性）。

```java
ConcurrentHashMap<String, Integer> chm = new ConcurrentHashMap<>();
chm.put("a", 1);
chm.putIfAbsent("a", 2);                 // 已存在，不覆盖
chm.computeIfAbsent("b", k -> 0);
chm.merge("b", 1, Integer::sum);         // 原子累加

// 原子计数推荐用 merge 或 compute，而不是 get + put
chm.merge("counter", 1, Integer::sum);
```

注意：
- **不允许 null key/value**（因为并发下无法用 null 区分"不存在"和"值为 null"）
- `size()` 在并发下是弱一致的估计值
- 迭代器是**弱一致**的，不抛 `ConcurrentModificationException`

## 七、工具类 Collections / Arrays

```java
List<Integer> list = new ArrayList<>(List.of(3, 1, 2));
Collections.sort(list);                    // 升序
Collections.reverse(list);
Collections.shuffle(list);
Collections.unmodifiableList(list);        // 只读视图
Collections.synchronizedList(list);        // 包装为同步

Map<String, Integer> immutable = Map.of("a", 1, "b", 2); // 不可变，最多 10 对
List<Integer> immutableList = List.of(1, 2, 3);          // 不可变，不可含 null
```

## 八、选型建议

| 场景 | 推荐 |
|---|---|
| 一般列表、随机访问多 | `ArrayList` |
| 频繁头尾增删、当作队列/栈 | `ArrayDeque` |
| 去重、无序 | `HashSet` |
| 去重且保插入序 | `LinkedHashSet` |
| 去重且排序 / 范围查询 | `TreeSet` |
| 一般键值查询 | `HashMap` |
| 需要插入序 / LRU | `LinkedHashMap` |
| 需要 key 排序 / 范围查询 | `TreeMap` |
| 高并发读写 Map | `ConcurrentHashMap` |
| 读多写极少的并发 List | `CopyOnWriteArrayList` |
| 优先级调度 | `PriorityQueue` |
| 生产者-消费者 | `ArrayBlockingQueue` / `LinkedBlockingQueue` |

## 九、常见面试要点速记

1. **ArrayList vs LinkedList**：数组 vs 链表；随机访问 O(1) vs O(n)；中间增删 ArrayList 需移动元素 O(n)，LinkedList 定位 O(n) 后增删 O(1)。实践中 ArrayList 几乎总是更快（缓存友好）。
2. **HashMap 为什么容量是 2 的幂**：`(n-1) & hash` 定位桶，位运算比取模快，且 n 为 2 的幂时分布均匀。
3. **为什么负载因子 0.75**：空间与冲突概率的折中（泊松分布下链表长度 8 的概率极低）。
4. **为什么树化阈值 8、退化 6**：避免在 7/8 边界频繁转换。
5. **HashMap 线程不安全的表现**：并发 put 可能丢失数据、size 不准、扩容时结构错乱。JDK7 还会形成环形链表导致死循环。
6. **fail-fast vs fail-safe**：`ArrayList/HashMap` 迭代器 fail-fast；`ConcurrentHashMap`、`CopyOnWriteArrayList` 的迭代器基于快照/弱一致，fail-safe。
7. **Set 如何保证不重复**：底层是 Map，用元素作 key，value 是固定的 `PRESENT` 对象，依赖 `hashCode + equals`。
