# Java 密封类（Sealed Classes）全览

密封类是 **Java 17 正式引入**（JEP 409，Java 15/16 为预览特性）的语言特性。核心思想：**由父类型显式声明"谁可以继承/实现我"**，从而让继承体系封闭可控。核心关键字：`sealed`（声明密封）、`permits`（列出允许的子类型）、`non-sealed`（子类重新开放继承）。

下面分类列举常见用法，并附代码。

---

## 1. 基础：密封类 + final 子类

最典型的形态——父类密封，所有子类都是 `final`。

```java
public sealed class Shape permits Circle, Rectangle {
}

final class Circle extends Shape {
    private final double radius;
    Circle(double r) { this.radius = r; }
    double radius() { return radius; }
}

final class Rectangle extends Shape {
    private final double w, h;
    Rectangle(double w, double h) { this.w = w; this.h = h; }
    double w() { return w; }
    double h() { return h; }
}
```

要点：

- `permits` 中列出的类**必须**直接继承 `Shape`；
- 未列出的类（如 `class Oval extends Shape`）会**编译报错**；
- 子类必须是 `final` / `sealed` / `non-sealed` 三者之一。

---

## 2. 密封接口

接口同样可以密封。

```java
public sealed interface Vehicle permits Car, Truck, Bike {
    int wheels();
}

final class Car implements Vehicle {
    public int wheels() { return 4; }
}
final class Truck implements Vehicle {
    public int wheels() { return 6; }
}
final class Bike implements Vehicle {
    public int wheels() { return 2; }
}
```

---

## 3. 抽象密封类

`sealed` 与 `abstract` 可组合，适合"有实现也要限制子类"的场景。

```java
public abstract sealed class Animal permits Dog, Cat, Bird {
    abstract String sound();
}

final class Dog extends Animal {
    String sound() { return "Woof"; }
}
final class Cat extends Animal {
    String sound() { return "Meow"; }
}
final class Bird extends Animal {
    String sound() { return "Tweet"; }
}
```

---

## 4. 三种子类修饰：final / sealed / non-sealed

子类必须显式选择其一，构成"密封链"的三种断点。

```java
public sealed class Shape permits Circle, Polygon, FreeForm { }

// (a) final：终结，不能再被继承
final class Circle extends Shape { }

// (b) sealed：继续密封，延续限制
sealed class Polygon extends Shape permits Triangle, Quad { }

final class Triangle extends Polygon { }
final class Quad extends Polygon { }

// (c) non-sealed：解除密封，重新开放继承
non-sealed class FreeForm extends Shape { }

// 因为 FreeForm 是 non-sealed，任何类都可以继承它
class Blob extends FreeForm { }
class Splat extends FreeForm { }
```

> `non-sealed` 是 Java 中唯一以连字符命名的关键字。

---

## 5. 省略 permits（同一编译单元）

当所有子类型都与密封类在**同一个编译单元（同一个 .java 文件）**中时，可以省略 `permits`，编译器自动推断。

```java
public sealed class Expr {
    // 编译器自动推断 permits Num, Add, Mul
}

final class Num extends Expr { final double value; Num(double v) { value = v; } }
final class Add extends Expr { final Expr l, r; Add(Expr l, Expr r) { this.l = l; this.r = r; } }
final class Mul extends Expr { final Expr l, r; Mul(Expr l, Expr r) { this.l = l; this.r = r; } }
```

更常见的写法是把子类型写成**嵌套类**：

```java
public sealed class Result<T> {
    public static final class Ok<T> extends Result<T> {
        public final T value;
        public Ok(T v) { value = v; }
    }
    public static final class Err<T> extends Result<T> {
        public final String message;
        public Err(String m) { message = m; }
    }
}
```

---

## 6. record 作为密封子类型

`record` 天生是 `final`，可直接作为密封类型的子类型，非常适合"代数数据类型"建模。

```java
public sealed interface Expr permits Num, Add, Mul { }

record Num(double value) implements Expr { }
record Add(Expr left, Expr right) implements Expr { }
record Mul(Expr left, Expr right) implements Expr { }
```

---

## 7. enum 作为密封子类型

`enum` 隐式 `final`，可作为密封接口的实现，但注意 enum 不能 `extends` 类（只能实现接口）。

```java
public sealed interface Op permits Op.Add, Op.Sub {
    record Add() implements Op { }
    record Sub() implements Op { }
}
```

---

## 8. 与 switch 模式匹配结合（Java 21）

密封类最大的价值之一：编译器能判断 `switch` 是否**穷尽**，无需 `default`。

```java
static double area(Shape s) {
    return switch (s) {
        case Circle c       -> Math.PI * c.radius() * c.radius();
        case Rectangle r    -> r.w() * r.h();
        // 无需 default：编译器已知全部子类型
    };
}
```

对代数数据类型写求值器：

```java
static double eval(Expr e) {
    return switch (e) {
        case Num n  -> n.value();
        case Add a  -> eval(a.left()) + eval(a.right());
        case Mul m  -> eval(m.left()) * eval(m.right());
    };
}
```

若删除某个 case，编译会报 **"the switch expression does not cover all possible input values"**——这是密封类带来的"穷尽性检查"。

---

## 9. 反射支持

`Class` 增加了两个 API：

```java
Shape.class.isSealed();                     // true
Arrays.stream(Shape.class.getPermittedSubclasses())
      .forEach(System.out::println);         // Circle, Rectangle, ...
```

---

## 10. 约束与注意事项（速查）

| 约束 | 说明 |
|---|---|
| `permits` 列表非空 | 子类型必须真实存在且直接继承 |
| 位置约束 | 命名模块：同模块；无名模块：同包 |
| 子类修饰 | 必须 `final` / `sealed` / `non-sealed` |
| 禁止组合 | 不能同时 `final` + `sealed`；不能 `sealed` + `non-sealed` |
| 不能用于 | 匿名类、局部类、Lambda |
| 可组合 | `sealed` 可与 `abstract`、`static`（嵌套）、`public` 等组合 |
| 跨包使用 | 子类必须在同一模块/包，因此无法跨包"续密封" |

---

## 小结

| 形态 | 代码骨架 |
|---|---|
| 密封类 | `sealed class A permits B, C { }` |
| 密封接口 | `sealed interface I permits X, Y { }` |
| 抽象密封类 | `abstract sealed class A permits B { }` |
| 续密封 | `sealed class B extends A permits D { }` |
| 解除密封 | `non-sealed class C extends A { }` |
| 终结 | `final class D extends B { }` |
| 记录型子类 | `record R(...) implements I { }` |
| 省略 permits | 子类型在同一编译单元/嵌套时 |

密封类让"面向对象继承 + 函数式模式匹配"结合得更好，是设计**封闭领域模型**（如 AST、Result、状态机）的利器。
