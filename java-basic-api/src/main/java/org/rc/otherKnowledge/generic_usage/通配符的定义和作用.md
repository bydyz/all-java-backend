# Java 通配符（Wildcard）详解

## 一、什么是通配符

通配符是 Java 泛型中的一种**类型参数占位符**，用问号 `?` 表示"未知类型"。它只能出现在**使用泛型类型的位置**（变量声明、方法参数、返回值等），不能用于定义泛型类或泛型方法本身的类型参数。

```java
List<?> list;                 // 合法：使用处
class Box<?> { }              // 非法：定义处不能用通配符
<T> void foo(List<?> l) { }   // 合法：T 是类型参数，? 是通配符
```

Java 泛型默认是**不型变（invariant）**的：`List<Integer>` 不是 `List<Number>` 的子类型，甚至不是 `List<Object>` 的子类型。通配符的存在正是为了在保证类型安全的前提下，让泛型类型之间具备某种"协变/逆变"能力，从而提高 API 的灵活性。

---

## 二、三种通配符形式

### 1. 无界通配符 `<?>`

表示"某种未知类型"，等价于 `<? extends Object>`。方法内部**只能读取为 `Object`**，**不能写入**（除 `null` 外），因为编译器不知道具体类型。

```java
public static void printAll(List<?> list) {
    for (Object o : list) {
        System.out.println(o);   // 只能当 Object 用
    }
    // list.add("x");           // 编译错误：不知道元素真实类型
    list.add(null);              // 唯一允许的写入
}
```

调用时 `List<Integer>`、`List<String>` 都可以传入：

```java
printAll(Arrays.asList(1, 2, 3));
printAll(Arrays.asList("a", "b"));
```

### 2. 上界通配符 `<? extends T>`

表示"T 或 T 的某个子类型"，用于**读取场景（Producer）**。

```java
public static double sum(List<? extends Number> list) {
    double s = 0;
    for (Number n : list) {      // 可以安全读出 Number
        s += n.doubleValue();
    }
    // list.add(1);              // 编译错误：可能是 List<Double>
    return s;
}
```

调用：

```java
sum(Arrays.asList(1, 2, 3));          // List<Integer>  OK
sum(Arrays.asList(1.5, 2.5));         // List<Double>   OK
sum(Arrays.asList(1L, 2L));           // List<Long>     OK
```

**关键点**：`List<Integer>` 不是 `List<Number>` 的子类型，但它是 `List<? extends Number>` 的子类型。这就是上界通配符带来的协变效果。

### 3. 下界通配符 `<? super T>`

表示"T 或 T 的某个父类型"，用于**写入场景（Consumer）**。

```java
public static void addIntegers(List<? super Integer> list) {
    list.add(1);                 // 可以安全写入 Integer（及其子类）
    list.add(2);
    Object o = list.get(0);      // 读出来只能当 Object
}
```

调用：

```java
List<Number> nums = new ArrayList<>();
addIntegers(nums);               // OK
List<Object> objs = new ArrayList<>();
addIntegers(objs);               // OK
List<Integer> ints = new ArrayList<>();
addIntegers(ints);               // OK

// List<Double> doubles = ...;
// addIntegers(doubles);         // 编译错误：Double 不是 Integer 的父类型
```

## 三、核心作用：PECS 原则

Java 官方推荐使用 **PECS（Producer Extends, Consumer Super）** 原则来指导通配符的选用：

- **生产者（只读）** → 用 `? extends T`
- **消费者（只写）** → 用 `? super T`
- **既读又写** → 不要用通配符，用具体类型参数 `<T>`

JDK 中的经典例子是 `Collections.copy`：

```java
public static <T> void copy(List<? super T> dest, List<? extends T> src) {
    for (int i = 0; i < src.size(); i++) {
        dest.set(i, src.get(i));
    }
}
```

- `src` 是数据来源（生产者）→ `? extends T`
- `dest` 是数据去向（消费者）→ `? super T`

这样设计的直接好处是，可以做到下面这种调用：

```java
List<Object> dest = new ArrayList<>(Arrays.asList(new Object(), new Object()));
List<Integer> src = Arrays.asList(1, 2);
Collections.copy(dest, src);   // 如果签名写成 copy(List<T>, List<T>) 就无法通过编译
```

如果 `copy` 的方法签名写成 `<T> void copy(List<T> dest, List<T> src)`，那么由于泛型不型变，`List<Object>` 和 `List<Integer>` 无法匹配同一个 `T`，调用会失败。通配符让这个方法对更多类型组合可用。

## 四、通配符捕获（Capture Conversion）

有时方法内部需要对 `<?>` 做写操作，此时可以通过一个辅助泛型方法"捕获"通配符。经典例子是 `swap`：

```java
// 直接写会失败：? 无法确定类型
public static void swapBad(List<?> list, int i, int j) {
    // Object tmp = list.get(i);
    // list.set(i, list.get(j));   // 编译错误
}

// 用辅助方法捕获通配符
public static void swap(List<?> list, int i, int j) {
    swapHelper(list, i, j);
}

private static <E> void swapHelper(List<E> list, int i, int j) {
    E tmp = list.get(i);
    list.set(i, list.get(j));
    list.set(j, tmp);
}
```

调用 `swap` 时，编译器为 `?` 捕获出一个具体的（未知但唯一的）类型，称为 **capture of ?**，并把它作为 `E` 传给 `swapHelper`，从而在辅助方法内部可以安全读写。

## 五、通配符与类型参数 `T` 的区别

```java
// 使用通配符：方法内不知道具体类型
public static void foo(List<?> list) { }

// 使用类型参数：方法内可以引用该类型
public static <T> void bar(List<T> list, T item) {
    list.add(item);   // 因为 T 已知，可以写入
}
```

| 场景 | 选择 |
|---|---|
| 方法内不需要引用具体类型，只做读取/遍历 | `List<?>` |
| 方法内需要引用类型名，或做读写操作 | `<T> ... List<T>` |
| 需要接受更宽的子类型集合（协变） | `List<? extends T>` |
| 需要向集合写入元素（逆变） | `List<? super T>` |

在方法签名里，`List<?>` 与 `<T> void foo(List<T>)` 在语义上常常等价，但后者会引入一个无用的类型参数，可读性上通常推荐 `List<?>`。

## 六、使用限制与注意事项

1. **不能用于泛型类/方法定义**：`class Box<?> {}`、`<T extends ?>` 都是非法的，通配符只出现在使用处。

2. **不能实例化**：`new ArrayList<?>()`、`new ArrayList<? extends Number>()` 非法，因为运行时无法确定具体类型。

3. **不能作为数组元素类型创建**：`new List<?>[10]` 非法。

4. **读写受限**：
  - `List<? extends Number>` 只能读为 `Number`，不能写（除 `null`）。
  - `List<? super Integer>` 只能写 `Integer`（及其子类），读出来只能是 `Object`。
  - `List<?>` 只能读为 `Object`，不能写。

5. **与类型擦除有关**：通配符在运行时不产生任何类型信息，`List<Integer>`、`List<String>`、`List<?>` 在运行时都是 `List`，通配符只是**编译期的类型约束工具**，用于在编译期保证读写安全。

6. **不要滥用通配符**：返回类型上通常不用 `?`（会迫使调用方处理未知类型），标准做法是返回具体类型参数 `<T>`；通配符主要用于**方法参数**。

---

## 七、小结

| 通配符 | 语义 | 可读 | 可写 | 用途 |
|---|---|---|---|---|
| `<?>` | 未知类型 | 读为 `Object` | 仅 `null` | 只想遍历/打印，不关心具体类型 |
| `<? extends T>` | T 或其子类 | 读为 `T` | 不可写 | 数据源 / 生产者 |
| `<? super T>` | T 或其父类 | 读为 `Object` | 写 `T` 及子类 | 数据汇 / 消费者 |

一句话概括：**通配符解决的是"泛型不变性带来的 API 不够灵活"的问题，它通过编译期约束把"能读什么、能写什么"明确区分开来；选型时遵循 PECS 原则，既能获得最大灵活性，又能保持类型安全。**
