# Java 注解详解

## 一、Java 注解是什么？

**注解（Annotation）** 是 Java 5 引入的一种 **元数据机制**
。它可以用于修饰包、类、构造器、方法、成员变量、参数、局部变量，用来给这些元素“贴标签”或“附加说明信息”。还可以添加一些参数值，这些信息被保存在Annotation的
“name=value” 对中。

注解可以在类编译、运行时进行加载，体现不同的功能。

> 注解也可以看做是一种注释，通过使用 Annotation，程序员可以在不改变原有逻辑的情况下，在源文件中嵌入一些补充信息。但是，注解，不同于单行注释和多行注释。
    * 对于单行注释和多行注释是给程序员看的。
    * 而注解是可以被编译器或其他程序读取的。程序还可以根据注解的不同，做出相应的处理。

注解是一种趋势，一定程度上可以说：框架 = 注解 + 反射 + 设计模式。


一句话理解：
> **注解本身不直接改变程序逻辑，它只是给代码附加元数据；真正让注解产生作用的是编译器、注解处理器、反射、框架或字节码工具。**

例如：

```java
@Override
public String toString() {
    return "User";
}
```

`@Override` 告诉编译器：这个方法是重写父类/接口的方法。编译器会检查是否真的重写成功，写错了就报错。

注意：**注解不是注释**。

| 对比     | 注释                    | 注解                   |
|--------|-----------------------|----------------------|
| 形式     | `//`、`/* */`、`/** */` | `@Xxx`               |
| 是否参与编译 | 普通注释不参与               | 参与编译，可被编译器/工具读取      |
| 是否影响程序 | 一般不影响                 | 可被框架/反射/处理器使用，间接影响程序 |
| 用途     | 给人看                   | 给编译器、工具、框架、运行时看      |

## 二、注解长什么样？

注解本质上是一种特殊接口。比如自定义：

```java
import java.lang.annotation.*;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface LogExecutionTime {
    String value() default "";
}
```

使用：

```java
public class OrderService {
    @LogExecutionTime("创建订单")
    public void createOrder() {
        // ...
    }
}
```

`@interface` 表示定义注解。注解里的方法看起来像方法，其实是 **注解属性/元素**：

```java
String value() default "";
int timeout() default 3000;
```

使用时：

```java
@LogExecutionTime(value = "创建订单", timeout = 5000)
```

如果只有 `value` 一个属性，可以简写：

```java
@LogExecutionTime("创建订单")
```

## 三、注解的核心元注解

“元注解”就是 **用来修饰注解的注解**。常见有：

### 1. `@Retention`：注解保留到哪个阶段

```java
@Retention(RetentionPolicy.RUNTIME)
```

三种策略：

| 策略        | 含义                     | 典型用途                                       |
|-----------|------------------------|--------------------------------------------|
| `SOURCE`  | 只在源码中保留，编译后丢弃          | `@Override`、`@SuppressWarnings`、Lombok 类注解 |
| `CLASS`   | 保留到 class 文件，但运行时反射不可见 | 编译期处理、字节码工具                                |
| `RUNTIME` | 保留到运行期，可通过反射读取         | Spring、MyBatis、JUnit 等框架大量使用               |

默认是 `CLASS`。如果你希望运行时通过反射读取，必须写 `RUNTIME`。

### 2. `@Target`：注解能贴在哪里

```java
@Target({ElementType.METHOD, ElementType.TYPE})
```

常见 `ElementType`：

| 值                 | 可标注位置      |
|-------------------|------------|
| `TYPE`            | 类、接口、枚举、注解 |
| `FIELD`           | 字段         |
| `METHOD`          | 方法         |
| `PARAMETER`       | 方法参数       |
| `CONSTRUCTOR`     | 构造器        |
| `LOCAL_VARIABLE`  | 局部变量       |
| `ANNOTATION_TYPE` | 注解类型       |
| `PACKAGE`         | 包          |
| `TYPE_PARAMETER`  | 泛型类型参数     |
| `TYPE_USE`        | 类型使用处      |
| `MODULE`          | 模块         |

不写 `@Target` 时，默认大多数位置都可以用，但实际开发建议明确限制。

### 3. `@Documented`：是否进入 Javadoc

```java
@Documented
public @interface ApiNote {}
```

加了之后，使用该注解的地方会出现在生成的 API 文档中。

### 4. `@Inherited`：子类是否继承父类注解

```java
@Inherited
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
public @interface InheritedAnnotation {}
```

只对 **类注解** 有效，并且是“子类 Class 对象通过 `getAnnotation` 能查到父类注解”，不是注解本身被复制。

### 5. `@Repeatable`：同一位置可重复使用

```java
@Repeatable(Schedules.class)
@interface Schedule {
    String cron();
}

@interface Schedules {
    Schedule[] value();
}
```

使用：

```java
@Schedule(cron = "0 0 1 * * ?")
@Schedule(cron = "0 0 2 * * ?")
public void job() {}
```

### 6. `@FunctionalInterface` 等其实是普通内置注解

它不是元注解，但常用于编译检查。

## 四、Java 常见内置注解

### 1. `@Override`

表示重写父类或接口方法：

```java
@Override
public String toString() {
    return "demo";
}
```

作用：**编译期检查**，避免方法名、参数写错。

### 2. `@Deprecated`

表示已过时，不建议使用：

```java
@Deprecated
public void oldMethod() {}
```

编译器会给出警告，IDE 会划删除线。

### 3. `@SuppressWarnings`

抑制编译器警告：

```java
@SuppressWarnings("unchecked")
List<String> list = (List<String>) obj;
```

常见值：`unchecked`、`deprecation`、`rawtypes`、`all`。

### 4. `@SafeVarargs`

用于泛型可变参数方法，抑制堆污染警告：

```java
@SafeVarargs
public static <T> List<T> of(T... args) {
    return Arrays.asList(args);
}
```

### 5. `@FunctionalInterface`

检查接口是否是函数式接口，即只有一个抽象方法：

```java
@FunctionalInterface
public interface MyFunction {
    int apply(int a, int b);
}
```

## 五、注解到底有什么作用？

注解的作用可以分成几类：

### 1. 编译期检查

代表：`@Override`、`@FunctionalInterface`、`@Deprecated`、`@SuppressWarnings`。

作用：让编译器帮你发现错误或警告。

```java
@Override
public String tostring() { // 编译报错：并没有重写
    return "";
}
```

---

### 2. 生成文档

代表：`@Documented`、Javadoc 标签配合注解。

用于生成 API 文档或接口说明。

---

### 3. 编译期生成代码 / 修改代码

代表：Lombok、MapStruct、Dagger、Room、APT。

例如 Lombok：

```java
@Data
public class User {
    private String name;
    private int age;
}
```

Lombok 在编译期通过注解处理器生成 getter/setter/toString 等方法。源码里没有，但 class 文件里有。

这类注解通常是 `SOURCE` 或 `CLASS` 保留策略。

---

### 4. 运行时配置：框架最常用

代表：Spring、Spring Boot、MyBatis、JUnit、Jackson。

例如 Spring：

```java
@RestController
@RequestMapping("/users")
public class UserController {

    @GetMapping("/{id}")
    public User get(@PathVariable Long id) {
        return new User();
    }
}
```

这些注解本身不执行逻辑，是 Spring 启动时扫描类、读取注解、创建 Bean、注册路由。

MyBatis：

```java
@Select("select * from user where id = #{id}")
User findById(Long id);
```

MyBatis 解析注解中的 SQL，生成代理对象执行。

JUnit：

```java
@Test
void testCreate() {
}
```

JUnit 扫描 `@Test` 方法并调用。

---

### 5. 运行时校验

例如 Bean Validation：

```java
public class User {
    @NotBlank
    private String name;

    @Min(18)
    private int age;
}
```

框架通过反射读取注解，对对象字段进行校验。

---

### 6. AOP 横切逻辑

例如自定义日志注解、权限注解、限流注解：

```java
@LogExecutionTime
public void createOrder() {}
```

AOP 拦截方法，读取注解，决定是否记录耗时、校验权限、限流等。

---

### 7. 序列化 / 反序列化

Jackson：

```java
public class User {
    @JsonProperty("user_name")
    private String userName;

    @JsonIgnore
    private String password;
}
```

Jackson 根据注解决定字段名、忽略字段等。

---

### 8. 测试与依赖注入

```java
@Autowired
private UserService userService;

@Inject
private OrderService orderService;
```

容器读取注解完成依赖注入。

---

## 六、注解真正是怎么生效的？

注解有三种主要生效方式：

### 方式 1：编译器内置处理

```java
@Override
@SuppressWarnings("unchecked")
```

编译器直接识别。

### 方式 2：编译期注解处理器 APT

注解处理器在编译阶段扫描注解，生成 Java 代码、资源文件或报错。

典型：

- Lombok
- MapStruct
- Dagger
- Android Room
- AutoService

流程大致：

```text
源码 + 注解 -> 注解处理器 -> 生成新源码 -> 再编译
```

### 方式 3：运行时反射读取

注解必须 `@Retention(RetentionPolicy.RUNTIME)`。

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface LogExecutionTime {
    String value() default "";
}
```

运行时读取：

```java
Method method = OrderService.class.getMethod("createOrder");
if (method.isAnnotationPresent(LogExecutionTime.class)) {
    LogExecutionTime ann = method.getAnnotation(LogExecutionTime.class);
    System.out.println(ann.value());
}
```

框架大量使用这种方式：Spring、MyBatis、JUnit、Jackson 等都会扫描注解。

## 七、自定义注解完整示例

### 1. 定义注解

```java
import java.lang.annotation.*;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@Documented
public @interface LogExecutionTime {
    String value() default "";
}
```

### 2. 使用注解

```java
public class OrderService {

    @LogExecutionTime("创建订单")
    public void createOrder() throws InterruptedException {
        Thread.sleep(100);
        System.out.println("订单创建完成");
    }
}
```

### 3. 反射读取并执行逻辑

```java
import java.lang.reflect.Method;

public class AnnotationDemo {
    public static void main(String[] args) throws Exception {
        OrderService service = new OrderService();
        Method method = OrderService.class.getMethod("createOrder");

        long start = System.currentTimeMillis();

        if (method.isAnnotationPresent(LogExecutionTime.class)) {
            LogExecutionTime ann = method.getAnnotation(LogExecutionTime.class);
            System.out.println("开始执行：" + ann.value());
        }

        method.invoke(service);

        long cost = System.currentTimeMillis() - start;
        System.out.println("耗时：" + cost + "ms");
    }
}
```

注意：这里真正起作用的是 `method.invoke` 和反射判断，不是注解自己。

## 八、注解的定义限制

注解属性类型有限，只能是：

- 基本类型：`int`、`boolean`、`double` 等
- `String`
- `Class`
- 枚举
- 注解类型
- 以上类型的数组

不能是：

```java
Object obj();          // 不允许
List<String> list();   // 不允许
```

注解属性可以有默认值：

```java
String value() default "default";
```

但 **默认值不能是 `null`**：

```java
String value() default null; // 编译错误
```

如果确实想表达“没有值”，常用：

```java
String value() default "";
```

或者用特殊枚举/常量表示。

## 九、注解和反射的性能注意点

运行时注解依赖反射。反射本身比直接调用慢，但现代 JVM 和框架通常有缓存，不需要过度妖魔化。

注意：

1. 运行时读取注解需要 `RUNTIME`。
2. 频繁反射扫描可缓存 `Method`、注解信息或 Bean 元数据。
3. 框架启动时扫描大量类可能影响启动速度。
4. 注解不能替代清晰设计，不要为了“看起来高级”滥用。

## 十、注解常见误区

### 误区 1：加了注解就会自动生效？

不是。注解只是元数据，必须有处理器。

```java
@LogExecutionTime
public void createOrder() {}
```

如果没有 AOP、反射或编译期处理器读取它，它就是一段“标记”，不会记录日志。

### 误区 2：注解可以继承？

注解类型不能像类一样被继承。只有 `@Inherited` 对类注解有特殊语义。

### 误区 3：注解可以写方法体？

普通注解元素不能有方法体。注解里只能声明属性。

### 误区 4：所有注解运行时都能拿到？

只有 `@Retention(RetentionPolicy.RUNTIME)` 的注解能通过反射拿到。

### 误区 5：注解能直接改变业务逻辑？

不能直接。它通过编译器、APT、反射、AOP、字节码增强等间接影响程序。

---

## 十一、总结

Java 注解可以理解为：

> **贴在代码上的元数据标签，供编译器、工具、框架或运行时读取，从而实现检查、生成代码、配置、校验、AOP、序列化、测试等能力。**

核心记忆点：

1. 注解用 `@interface` 定义。
2. 注解属性类型有限，可有默认值，默认值不能为 `null`。
3. 常用元注解：`@Retention`、`@Target`、`@Documented`、`@Inherited`、`@Repeatable`。
4. `@Retention` 决定注解保留到源码、class 还是运行期。
5. 运行时反射读取必须用 `RUNTIME`。
6. 注解本身不执行逻辑，真正生效靠编译器、APT、反射、框架或字节码工具。
7. 典型用途：编译检查、代码生成、文档、框架配置、依赖注入、路由、ORM、校验、AOP、测试、序列化。

一句话再概括：

> **注解是“标签”，反射/框架/编译器是“读标签并做事的人”。**
