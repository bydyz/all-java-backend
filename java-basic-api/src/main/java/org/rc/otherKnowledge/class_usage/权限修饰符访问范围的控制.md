# Java 权限修饰符详解：修饰不同内容时的访问范围控制

Java 的权限修饰符在修饰不同内容时，访问范围并不完全一致。核心在于先区分**顶层类**与**类成员**，再理解 `protected`
在跨包继承时的特殊限制。

---

## 顶层类：只有两种选择

对于直接定义在包下的顶层类，可用的权限修饰符只有 **`public`** 和 **缺省（package-private）**。

- **`public` 类**：对所有包的所有类可见。
- **缺省类**：仅对**同一个包内**的类可见。

`private` 和 `protected` **都不能修饰顶层类**。`protected` 只能用于内部类。

---

## 类成员（变量、方法、构造方法、内部类）：四种权限

修饰成员时，四种修饰符都可用，但访问范围有明确层次。以 Oracle 官方表格为基准：

| 修饰符             | 当前类 | 同一包内 | 不同包的子类    | 全局  |
|:----------------|:----|:-----|:----------|:----|
| **`public`**    | 可见  | 可见   | 可见        | 可见  |
| **`protected`** | 可见  | 可见   | **有条件可见** | 不可见 |
| **缺省**          | 可见  | 可见   | 不可见       | 不可见 |
| **`private`**   | 可见  | 不可见  | 不可见       | 不可见 |

**`private`** 的限制最严格，仅当前类内部可访问。`private` 构造方法会禁止外部直接 `new` 该类的实例，常用于单例模式或工具类。

**缺省** 是包级私有，同包任意类可访问，包外完全不可见。

**`public`** 没有限制，任何位置都可访问。

**`protected`** 是唯一需要特别展开的修饰符，也是实际开发中最容易出错的环节。

---

## `protected` 的关键：跨包子类中的“有条件访问”

在同一包内，`protected` 的效果与缺省修饰符基本相同：包内任意类都可以访问。真正的复杂性出现在**不同包的子类**中。

跨包时，`protected` 成员**可以被继承**，但子类代码中对它的访问受到一条精确限制：

> 子类只能通过**自身类型**（或其子类型）的引用来访问继承来的 `protected` 成员；**不能通过父类类型的引用**去访问。

例如：

```java
package p1;
public class Parent {
    protected void doWork() { }
}

package p2;
public class Child extends Parent {
    void test() {
        this.doWork();        // ✅ 通过自身（Child）引用访问，允许
        new Child().doWork(); // ✅ 通过 Child 引用访问，允许

        Parent p = new Parent();
        p.doWork();           // ❌ 编译错误：不能通过父类引用访问
    }
}
```

换句话说，`protected` 在跨包时授予的是子类“**在自己的代码中操作自身继承状态**”的能力，而不是“操作任意父类实例”的能力。很多初学者误以为“继承后就能访问父类实例的
protected 方法”，实际上并非如此。

此外，如果 `protected` 成员同时被 `static` 修饰，上述“通过子类引用访问”的限制在部分场景下会有所放宽，但跨包的基本访问入口仍然限定在子类作用域内。

---

## 修饰不同内容时的特殊规则

**构造方法**：构造方法可以被 `public`、`protected`、缺省、`private` 修饰，作用与修饰普通成员一致。`private`
构造方法阻止外部实例化；`protected` 构造方法允许同包类和跨包子类在构造过程中调用 `super(...)`。

**接口成员**：接口中的成员有**隐式修饰符**，权限控制与普通类成员不同。

- 接口中的变量隐式为 **`public static final`**。
- 接口中的普通方法隐式为 **`public abstract`**；Java 8 之后允许 `default`、`static` 方法，Java 9 之后允许 `private` 方法。
- **不能**在接口成员上使用 `protected` 或包级缺省权限。

**内部类**：作为成员时，内部类可以被四种修饰符修饰，包括 `private` 和 `protected`。`private`
内部类仅外部类内部可访问；`protected` 内部类对同包和跨包子类开放。

---

## 选择原则

权限修饰符的核心用途是**封装**与**约束误用**。实践中一个常用的判断顺序是：

1. **优先使用能实现功能的最严格级别**。成员默认从 `private` 起步，确有外部访问需求再逐步放宽。
2. **`public` 成员应保持最小化**。`public` 字段除常量外一般不建议使用，因为它会把外部代码绑定到具体实现上，降低后续修改的灵活性。
3. **`protected` 用于“有意为继承而设计”的成员**。如果一个成员不打算被子类使用，就不应设为 `protected`；如果设为 `protected`
   ，就应视为对子类的一种约定。
