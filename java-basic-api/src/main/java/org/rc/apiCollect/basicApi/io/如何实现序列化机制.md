Java 序列化机制的核心，是将实现了 `Serializable` 或 `Externalizable` 接口的对象状态，转换为字节流，以便持久化或网络传输，并能从字节流中重建对象。其实现层次由浅入深，涵盖了标记接口、字段控制、自定义读写、版本兼容以及安全防护等多个方面。

### 🔑 核心基石：`Serializable` 标记接口

Java 序列化的起点是 `java.io.Serializable` 接口。它是一个**标记接口**，内部没有任何方法，仅用于向 JVM 表明该类的实例允许被序列化。

```java
public interface Serializable {
    // 标记接口，无任何方法
}
```

只有实现了此接口（或其子接口 `Externalizable`）的类，其对象才能被序列化；否则会抛出 `NotSerializableException`。序列化与反序列化的操作，分别由 `ObjectOutputStream` 和 `ObjectInputStream` 完成。

### 📦 基础实现：默认序列化与反序列化

下面是一个最基础的完整示例，演示如何将一个对象的状态保存到文件，再读取回来。

```java
import java.io.*;

class Person implements Serializable {
    private String name;
    private int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    public String toString() {
        return "Person{name='" + name + "', age=" + age + "}";
    }
}

public class BasicSerializationDemo {
    public static void main(String[] args) {
        Person person = new Person("John Doe", 30);

        // 序列化：将对象写入文件
        try (ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("person.ser"))) {
            oos.writeObject(person);
            System.out.println("序列化完成: " + person);
        } catch (IOException e) {
            e.printStackTrace();
        }

        // 反序列化：从文件中读取对象
        try (ObjectInputStream ois = new ObjectInputStream(new FileInputStream("person.ser"))) {
            Person deserialized = (Person) ois.readObject();
            System.out.println("反序列化结果: " + deserialized);
        } catch (IOException | ClassNotFoundException e) {
            e.printStackTrace();
        }
    }
}
```

默认序列化会保存对象的**类元数据**（类名、`serialVersionUID` 等）以及所有**非 `static`、非 `transient` 的字段值**。上述代码中，`person.ser` 文件里就包含了 `Person` 类的信息以及 `name`、`age` 的值。

### 🎛️ 字段级控制：`transient` 与静态字段

默认机制下，所有非静态字段都会被序列化，但这有时并不合适。`transient` 关键字和 `static` 修饰符提供了字段级别的排除控制。

- **`transient` 字段**：被它修饰的字段**不参与序列化**。反序列化后，该字段会被赋予其类型的默认值（对象为 `null`，`int` 为 `0` 等）。
- **`static` 字段**：静态字段属于类级别，不属于对象状态，因此**永远不会被序列化**。

下面的例子将密码字段标记为 `transient`，以阻止敏感信息被写入字节流：

```java
class Account implements Serializable {
    private String username;
    private transient String password; // 不会被序列化
    private double balance;

    public Account(String username, String password, double balance) {
        this.username = username;
        this.password = password;
        this.balance = balance;
    }

    @Override
    public String toString() {
        return "Account{username='" + username + "', password='"
               + (password == null ? "null" : "****") + "', balance=" + balance + "}";
    }
}
// 序列化并反序列化后，password 字段将恢复为 null。
```

### 🛠️ 自定义序列化：两种进阶方式

当默认规则无法满足需求（如字段加密、脱敏、兼容旧格式）时，可以通过以下两种方式接管序列化过程。

#### 方式一：`writeObject` / `readObject`（推荐）

在实现了 `Serializable` 的类中，声明私有的 `writeObject` 和 `readObject` 方法，即可在默认行为的基础上插入自定义逻辑。调用 `defaultWriteObject()` 和 `defaultReadObject()` 可以分别执行默认的字段序列化与反序列化。

```java
class SecureUser implements Serializable {
    private String name;
    private transient String password; // 先排除默认序列化

    private void writeObject(ObjectOutputStream out) throws IOException {
        out.defaultWriteObject();          // 序列化 name 等非 transient 字段
        out.writeObject(encrypt(password)); // 手动写入加密后的 password
    }

    private void readObject(ObjectInputStream in) throws IOException, ClassNotFoundException {
        in.defaultReadObject();             // 反序列化 name 等字段
        password = decrypt((String) in.readObject()); // 手动读取并解密
    }
    // encrypt / decrypt 方法略
}
```

这种方式适合需要对**个别字段**进行加密、脱敏或格式转换的场景。

#### 方式二：`Externalizable` 接口（完全接管）

`Externalizable` 接口继承自 `Serializable`，要求实现 `writeExternal` 和 `readExternal` 方法，**完全由开发者决定**序列化哪些字段、以什么顺序和格式写入。

```java
class CompactUser implements Externalizable {
    private String name;
    private int age;

    @Override
    public void writeExternal(ObjectOutput out) throws IOException {
        out.writeUTF(name);
        out.writeInt(age);
    }

    @Override
    public void readExternal(ObjectInput in) throws IOException, ClassNotFoundException {
        name = in.readUTF();
        age = in.readInt();
    }
    // 必须提供 public 无参构造器
    public CompactUser() {}
}
```

使用 `Externalizable` 时必须注意两点：**类必须提供 `public` 无参构造器**（反序列化时由 `ObjectInputStream` 调用），并且读写字段的**顺序和类型必须严格一致**，否则会导致数据错乱或异常。它通常用于对序列化体积或性能有极致要求的场景。

### 🔢 版本兼容：`serialVersionUID` 的作用

序列化机制使用一个名为 `serialVersionUID` 的长整型“指纹”来校验版本兼容性。序列化时，该 ID 被写入流；反序列化时，JVM 会比对流中的 ID 与本地类的 ID。**如果两者不一致，就会抛出 `InvalidClassException`**。

如果**没有显式声明** `serialVersionUID`，编译器会根据类的结构（字段、方法等）自动生成一个。这意味着，**对类结构的任何微小改动都可能导致自动生成的 ID 变化**，从而使旧的序列化数据无法被新版本的类反序列化。

因此，**最佳实践是显式声明一个固定的 `serialVersionUID`**：

```java
public class StableClass implements Serializable {
    private static final long serialVersionUID = 1L; // 显式指定版本号
    // ...
}
```

只要保持 `serialVersionUID` 一致，即使类中**新增或删除字段**，反序列化通常也能成功进行（新增字段取默认值，被删除字段的值被忽略），这为类的演进提供了灵活性。

### 🔄 对象图与循环引用

Java 序列化机制能够自动处理**对象图**，包括对同一对象的多次引用以及**循环引用**（如 A 引用 B，B 又引用 A）。它通过内部维护一个“已写入对象”的映射表，确保每个对象只被写入一次；再次遇到同一对象时，仅写入一个引用句柄，从而正确保留对象间的拓扑关系，避免无限递归。

### 🛡️ 安全实践与替代方案

Java 原生反序列化存在固有的安全风险：反序列化过程本质上会执行被反序列化类的代码（如 `readObject` 方法），攻击者可以构造恶意的字节流，利用“Gadget 类”触发任意代码执行或拒绝服务。

主要防护措施包括：

1. **不要反序列化不可信数据**：这是最根本的原则。
2. **使用序列化过滤器**：通过 `ObjectInputFilter` 或系统属性配置白名单/黑名单，在反序列化**之前**对流入的类进行筛选，拒绝未知或危险的类型。
3. **在 `readObject` 中校验**：在自定义的 `readObject` 方法中，对恢复的字段值进行有效性检查。
4. **敏感字段用 `transient` 排除**：避免密码、密钥等被写入序列化流。
5. **考虑跨平台替代方案**：在需要跨语言、跨系统交换数据的场景，**JSON（Jackson/Gson）或 Protocol Buffers** 等格式通常更安全、更可控，应优先于 Java 原生序列化。

### 💎 总结

Java 序列化的实现层次可以概括为：**`Serializable` 标记接口**开启能力，**`ObjectOutputStream`/`ObjectInputStream`** 执行默认的字段级序列化；**`transient`** 实现字段排除，**`writeObject`/`readObject`** 或 **`Externalizable`** 支持自定义控制；**`serialVersionUID`** 管理跨版本兼容性；而**序列化过滤器**和**避免反序列化不可信数据**则是安全使用的底线。
