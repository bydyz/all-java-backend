# Java 中如何查看某个类的类加载器对象

查看某个类的类加载器，核心方法是 **`Class.getClassLoader()`**。但在实际使用中，需要区分几个容易混淆的入口，并特别注意 **`null` 返回值**在不同场景下的含义可能不同。

---

## 核心方法：`Class.getClassLoader()`

每个已加载的 `Class` 对象内部都持有一个指向**定义它的类加载器**的引用，通过 `getClassLoader()` 即可取出。

```java
public class GetLoaderDemo {
    public static void main(String[] args) {
        // 方式一：通过类字面量
        ClassLoader loader1 = GetLoaderDemo.class.getClassLoader();

        // 方式二：通过实例对象
        GetLoaderDemo obj = new GetLoaderDemo();
        ClassLoader loader2 = obj.getClass().getClassLoader();

        // 方式三：通过 Class.forName
        // ClassLoader loader3 = Class.forName("com.example.GetLoaderDemo").getClassLoader();

        System.out.println("类加载器: " + loader1);
    }
}
```

输出通常类似：

```text
类加载器: sun.misc.Launcher$AppClassLoader@18b4aac2
```

这说明 `GetLoaderDemo` 是由**应用程序类加载器（AppClassLoader）** 加载的，因为它位于 classpath 上。

---

## 关键理解：`getClassLoader()` 返回 `null` 的两种情况

`Class.getClassLoader()` 返回 `null` 时，**不一定**都表示“由 Bootstrap ClassLoader 加载”，需要分场景判断。

### 情况一：返回 `null`，表示由 Bootstrap ClassLoader 加载

`String`、`int.class`、`void.class` 等由 JVM 启动类加载器（Bootstrap ClassLoader，C++ 实现，在 Java 层没有对应的对象）加载的类，调用 `getClassLoader()` 会得到 `null`。

```java
System.out.println(String.class.getClassLoader());   // null
System.out.println(int.class.getClassLoader());      // null
System.out.println(void.class.getClassLoader());     // null
```

这里的 `null` 是 **“Bootstrap ClassLoader 的 Java 层表示”**，意味着这些类来自 JDK 核心库（如 `rt.jar` / `java.base`）。

### 情况二：数组类的 `null`，含义可能不同

数组类由 JVM 在运行时按需自动创建，**不是由类加载器显式加载的**。数组类的 `getClassLoader()` 返回的是**其元素类型的类加载器**。

```java
String[] strArr = new String[1];
System.out.println(strArr.getClass().getClassLoader());  // null（元素 String 由 Bootstrap 加载）

int[] intArr = new int[1];
System.out.println(intArr.getClass().getClassLoader());  // null（基本类型，数组类本身“没有”类加载器）

GetLoaderDemo[] demoArr = new GetLoaderDemo[1];
System.out.println(demoArr.getClass().getClassLoader()); // AppClassLoader（元素由 AppClassLoader 加载）
```

- `String[]` 的 `null`，继承自元素 `String` 的 Bootstrap 加载器；
- `int[]` 的 `null`，是因为**基本类型数组没有类加载器**，这是另一种语义上的“无加载器”，不能等同于 Bootstrap。

## 其他常用入口

### 1. 获取系统类加载器：`ClassLoader.getSystemClassLoader()`

这是获取 AppClassLoader 的直接方式，它加载 classpath 上的应用类。

```java
ClassLoader appLoader = ClassLoader.getSystemClassLoader();
System.out.println(appLoader);                    // AppClassLoader
System.out.println(appLoader.getParent());        // ExtClassLoader（Java 8）
System.out.println(appLoader.getParent().getParent()); // null（ExtClassLoader 的 parent 为 null，代表 Bootstrap）
```

在 Java 9+ 模块化环境下，扩展类加载器被**平台类加载器（PlatformClassLoader）** 取代，但 `getParent()` 的层级逻辑仍然成立。

### 2. 线程上下文类加载器：`Thread.currentThread().getContextClassLoader()`

这个入口返回的是**当前线程绑定的上下文类加载器**，它与 `Class.getClassLoader()` 可能不同。

- `Class.getClassLoader()`：返回**加载该 Class 的那个加载器**，是固定的、与类定义绑定的。
- `Thread.currentThread().getContextClassLoader()`：返回**线程被创建时设置或通过 `setContextClassLoader` 设置的加载器**，是一个可变的“当前线程认为应该用哪个加载器”的约定。

在 Java EE 容器、Tomcat、Spring 等环境中，两者可能不一致，上下文类加载器常用于解决“父加载器无法看到子加载器所加载的类”的问题。

```java
ClassLoader tccl = Thread.currentThread().getContextClassLoader();
System.out.println("线程上下文类加载器: " + tccl);
```

## 动态代理类的类加载器

JDK 动态代理生成的 `$Proxy0` 等类，其类加载器由创建代理时**显式传入**的 `ClassLoader` 决定。

```java
import java.lang.reflect.Proxy;

interface Greeting {
    void sayHello();
}

public class ProxyLoaderDemo {
    public static void main(String[] args) {
        ClassLoader cl = ClassLoader.getSystemClassLoader(); // 指定 AppClassLoader

        Class<?> proxyClass = Proxy.getProxyClass(cl, Greeting.class);
        System.out.println("代理类的类加载器: " + proxyClass.getClassLoader());
        // 输出：sun.misc.Launcher$AppClassLoader@...

        Object proxy = Proxy.newProxyInstance(
                cl,
                new Class[]{Greeting.class},
                (p, m, a) -> null
        );
        System.out.println("代理实例的类加载器: " + proxy.getClass().getClassLoader());
    }
}
```

如果传入的 `cl` 不是系统类加载器，而是自定义加载器，代理类就会归属于那个自定义加载器。这在字节码增强、框架代理等场景中是判断“代理类是否与目标类属于同一加载器体系”的依据。

## 自定义类加载器的查看

自定义 `ClassLoader` 加载的类，其 `getClassLoader()` 返回的就是该自定义加载器实例本身。可以通过“加载后反查”来验证来源。

```java
class MyLoader extends ClassLoader {
    public MyLoader(ClassLoader parent) { super(parent); }
}

public class CustomLoaderCheck {
    public static void main(String[] args) throws Exception {
        ClassLoader appLoader = ClassLoader.getSystemClassLoader();
        MyLoader myLoader = new MyLoader(appLoader);

        // 此处仅为示意：实际加载需要提供 findClass/defineClass 逻辑
        // Class<?> clazz = myLoader.loadClass("com.example.SomeClass");

        System.out.println("自定义加载器的父加载器: " + myLoader.getParent());
        // 通常输出 AppClassLoader

        // 如果 clazz 确实由 myLoader 定义：
        // System.out.println(clazz.getClassLoader() == myLoader); // true
    }
}
```

自定义类加载器默认的 `parent` 是 AppClassLoader（除非显式指定为其他加载器或 `null`），但**父加载器 ≠ 实际定义该类的加载器**。一个类最终由哪个加载器定义，取决于双亲委派过程中**谁最先成功加载了它**。如果父加载器已经能加载，子加载器就不会自己定义；只有在父加载器无法加载时，才由子加载器通过 `findClass` 完成定义。

## 综合示例：一次查看多种类的加载器

```java
public class LoaderOverview {
    static class Inner {}

    public static void main(String[] args) {
        System.out.println("== 由 Bootstrap 加载 ==");
        System.out.println("String        : " + String.class.getClassLoader());          // null
        System.out.println("int           : " + int.class.getClassLoader());             // null

        System.out.println("\n== 由 AppClassLoader 加载 ==");
        System.out.println("本类           : " + LoaderOverview.class.getClassLoader());   // AppClassLoader
        System.out.println("内部类         : " + Inner.class.getClassLoader());            // AppClassLoader

        System.out.println("\n== 数组类 ==");
        System.out.println("String[]      : " + new String[0].getClass().getClassLoader());  // null
        System.out.println("int[]         : " + new int[0].getClass().getClassLoader());     // null
        System.out.println("本类[]         : " + new LoaderOverview[0].getClass().getClassLoader()); // AppClassLoader

        System.out.println("\n== 线程上下文类加载器 ==");
        System.out.println(Thread.currentThread().getContextClassLoader()); // AppClassLoader（通常）
    }
}
```

## 小结

查看某个类的类加载器，**首选 `Class.getClassLoader()`**。需要记住的三个要点是：

1. **`null` 不等于“没有加载器”**：对普通类而言，`null` 通常代表 Bootstrap ClassLoader；对基本类型数组而言，`null` 表示数组类本身没有加载器。
2. **数组类的加载器“继承”自元素类型**：元素由谁加载，数组类就显示谁；元素是基本类型，则显示 `null`。
3. **如果需要获取“当前线程认为应该用哪个加载器”**，使用 `Thread.currentThread().getContextClassLoader()`，它与类固定的 `getClassLoader()` 是两回事。
