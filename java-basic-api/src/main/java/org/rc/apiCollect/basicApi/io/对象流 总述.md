Java 对象流是 I/O 体系中专门用来**处理对象**的一类高级流。它的核心使命是解决一个根本问题：如何把内存中活生生的 Java 对象，变成可以保存到硬盘、或者在网络上传输的字节序列，并且之后还能从这些字节序列中把对象原样“复活”。

### 🎯 对象流是啥，有啥用？

普通的字节流和字符流只能处理基本类型（如 `int`, `char`）或文本数据。对象流则在此基础上，直接支持**对象（Object）**的读写。

它的核心作用就是实现 **序列化（Serialization）**与 **反序列化（Deserialization）**：
*   **序列化**：将内存中的 Java 对象转换为平台无关的二进制字节流。这使得对象可以被**持久化保存**到磁盘，或**通过网络传输**到另一台机器。
*   **反序列化**：将之前保存或接收到的二进制字节流，重新恢复为内存中的 Java 对象，并保留其当时的状态。

值得一提的是，对象流也兼容基本数据类型的读写，因为它的底层实现继承了 `DataInput` 和 `DataOutput` 接口，所以你可以在对象流中混合写入基本类型和对象。

### 📂 有哪些分类？

对象流主要分为两个方向，分别对应序列化和反序列化：

1.  **输出流：`ObjectOutputStream`**
  *   **角色**：执行**序列化**。
  *   **核心方法**：`writeObject(Object obj)`。它负责将指定的对象转换并写入底层输出流。
  *   **深层逻辑**：当你写入一个对象时，如果该对象内部引用了其他对象，`writeObject` 会**自动遍历整个对象引用图**，把所有关联的对象一并序列化，确保反序列化时能完整地重建整个对象网络。

2.  **输入流：`ObjectInputStream`**
  *   **角色**：执行**反序列化**。
  *   **核心方法**：`readObject()`。它从输入流中读取字节，并重构出一个对象。使用时通常需要将其强制转换为预期的类型。

除了这两个流类，还有两个关键的接口定义了对象“能否”被序列化：
*   **`Serializable`**：一个**标记接口**，不含任何方法。一个类只要实现了它，就代表其对象**允许**被序列化。这是最常用的方式。
*   **`Externalizable`**：继承自 `Serializable`，但它要求你**手动实现** `writeExternal` 和 `readExternal` 方法，以便完全自定义序列化的细节，控制粒度更细。

### 💻 代码详解：从序列化到反序列化

下面通过一个完整的例子，展示对象流的典型用法及关键注意事项。

#### 1. 定义一个可序列化的类
一个类要能被对象流处理，**必须**实现 `Serializable` 接口。

```java
import java.io.Serializable;

// 1. 必须实现 Serializable 接口
public class Student implements Serializable {
    // 2. 强烈建议显式声明 serialVersionUID
    private static final long serialVersionUID = 1L;

    private String name;
    private int age;
    // 3. address 被 transient 修饰，不会被序列化
    private transient String address;

    public Student(String name, int age, String address) {
        this.name = name;
        this.age = age;
        this.address = address;
    }

    @Override
    public String toString() {
        return "Student{name='" + name + "', age=" + age + ", address='" + address + "'}";
    }
}
```
**代码中的三个关键点：**
*   **`implements Serializable`**：这是前提。如果尝试序列化一个未实现此接口的对象，会立即抛出 **`NotSerializableException`** 异常。
*   **`serialVersionUID`**：这是一个版本号。反序列化时，JVM 会比对流中的版本号与本地类的版本号。如果版本不一致（例如，序列化后你修改了类的结构），就会抛出 `InvalidClassException`。显式指定它可以确保在类发生合理演进时，旧的序列化数据依然能被兼容读取。
*   **`transient`**：用于标记**不希望被序列化**的字段（如敏感信息 `password`，或不可序列化的引用）。被 `transient` 修饰的字段在反序列化后将恢复为其类型的默认值（对象为 `null`，基本类型为 `0`/`false`）。`static` 字段同样不会被序列化，因为它属于类而非对象。

#### 2. 序列化（写出对象）
使用 `ObjectOutputStream` 将对象保存到文件。

```java
import java.io.FileOutputStream;
import java.io.ObjectOutputStream;

public class SerializeDemo {
    public static void main(String[] args) throws Exception {
        Student student = new Student("张三", 21, "北京");

        // 将对象序列化到 student.dat 文件
        try (ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("student.dat"))) {
            oos.writeObject(student);
        }
        System.out.println("序列化完成，对象状态已保存。");
    }
}
```

#### 3. 反序列化（读回对象）
使用 `ObjectInputStream` 从文件中恢复对象。

```java
import java.io.FileInputStream;
import java.io.ObjectInputStream;

public class DeserializeDemo {
    public static void main(String[] args) throws Exception {
        try (ObjectInputStream ois = new ObjectInputStream(new FileInputStream("student.dat"))) {
            // readObject() 返回 Object，需要强制类型转换
            Student restored = (Student) ois.readObject();
            System.out.println("反序列化结果: " + restored);
        }
    }
}
```
**预期输出**会清晰地展示 `transient` 的效果：
```
反序列化结果: Student{name='张三', age=21, address='null'}
```
可以看到，`name` 和 `age` 被成功恢复，而 `transient` 字段 `address` 的值变回了 `null`。

### 💎 总结与提醒

对象流通过 `ObjectOutputStream` 和 `ObjectInputStream` 这对组合，在 `Serializable` 接口的契约下，实现了 Java 对象在“内存”与“字节世界”之间的双向转换。使用时请务必记住：**类需实现 `Serializable`**、**敏感或无关字段用 `transient` 排除**、**显式声明 `serialVersionUID` 以避免版本兼容问题**。此外，`readObject()` 可能抛出 `ClassNotFoundException`（如果 JVM 找不到对应的类文件），需要进行处理。
