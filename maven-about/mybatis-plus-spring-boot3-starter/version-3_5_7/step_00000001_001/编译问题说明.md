# step_00000001_001 编译失败问题说明

## 一、现象

在未修复前，执行以下命令会导致编译失败：

```bash
mvn clean compile test-compile
```

报错信息：

```
[ERROR] Failed to execute goal org.apache.maven.plugins:maven-compiler-plugin:3.11.0:compile ...
[ERROR] 不允许在使用 --release 时从系统模块 jdk.compiler 导出程序包:
[ERROR] 不允许在使用 --release 时从系统模块 jdk.compiler 导出程序包:
...（重复 7 次）
```

或在 JDK 8 环境下：

```
[ERROR] Fatal error compiling: 无效的标记: --release
```

测试类 `BaseMapperTest` 和 `IServiceTest` 因为整个工程无法通过编译，无法被正确编译。

---

## 二、根本原因（两层问题叠加）

### 问题 1：`<compilerArgs>` 中的 `--add-exports` 与 Spring Boot 的 `--release` 冲突

#### 冲突详解

Spring Boot 3.x 的 parent POM 会根据 `<java.version>` 配置自动在编译参数中加入 `--release <版本>`：

```xml
<!-- pom.xml 第 16 行 -->
<java.version>17</java.version>
```

这会让 Maven 编译时实际调用：

```bash
javac --release 17 ...
```

而 pom.xml 中又手动配置了 7 个 `--add-exports` 参数：

```xml
<compilerArgs>
    <arg>--add-exports=jdk.compiler/com.sun.tools.javac.api=ALL-UNNAMED</arg>
    <arg>--add-exports=jdk.compiler/com.sun.tools.javac.file=ALL-UNNAMED</arg>
    <arg>--add-exports=jdk.compiler/com.sun.tools.javac.main=ALL-UNNAMED</arg>
    <arg>--add-exports=jdk.compiler/com.sun.tools.javac.model=ALL-UNNAMED</arg>
    <arg>--add-exports=jdk.compiler/com.sun.tools.javac.processing=ALL-UNNAMED</arg>
    <arg>--add-exports=jdk.compiler/com.sun.tools.javac.tree=ALL-UNNAMED</arg>
    <arg>--add-exports=jdk.compiler/com.sun.tools.javac.util=ALL-UNNAMED</arg>
</compilerArgs>
```

#### JDK 规范说明

根据 JEP 261（模块系统）和 `javac` 官方文档：

> **使用 `--release` 时，`javac` 会隐式设置该版本平台允许访问的 API 范围（通过 `--system`）。此时不允许再使用 `--add-exports` 等模块访问控制参数，因为 `--release` 的语义已经锁定了目标平台的可见模块，额外的 `--add-exports` 会造成冲突。**

简单来说：`--release` 是一个"一键锁定"目标 JDK API 的参数，一旦用了它，就不能再单独调整模块导出了。

#### 那 Lombok 还能工作吗？

能。Lombok 的注解处理器（annotation processor）运行在 **编译期**，它通过 `annotationProcessorPaths` 配置，走的是 `javax.annotation.processing` 标准 SPI 机制。

`--add-exports=jdk.compiler/...` 这类参数是早期（JDK 9-16）为了让旧版 Lombok 能反射访问 `javac` 内部类的一种 **兼容性 hack**。从 **Lombok 1.18.22+** 开始，Lombok 已经适配了 JDK 模块系统，不再需要这些 hack。

本工程使用 Lombok `1.18.30`，完全可以去掉 `--add-exports`。

### 问题 2：系统默认 JDK 版本过低

| 组件 | 要求版本 | 系统实际版本 |
|------|----------|-------------|
| Spring Boot 3.2.5 | JDK 17+ | JDK 1.8.0_401 |
| mybatis-plus-spring-boot3-starter 3.5.7 | JDK 17+ | JDK 1.8.0_401 |

即使修好了 pom.xml 配置冲突，在 JDK 8 下依然会因为 `--release` 参数不被识别而报错：

```
无效的标记: --release
```

系统上实际存在 JDK 17，路径为 `D:\JDK\17.0.10`。

## 三、解决方案

### 修改 `pom.xml` — 删除冲突配置

**修改位置**：`maven-compiler-plugin` 的 `<configuration>` 部分

**修改前（有问题）**：

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <version>3.11.0</version>
    <configuration>
        <source>17</source>
        <target>17</target>
        <annotationProcessorPaths>
            <path>
                <groupId>org.projectlombok</groupId>
                <artifactId>lombok</artifactId>
                <version>1.18.30</version>
            </path>
        </annotationProcessorPaths>
        <!-- 以下 7 行 --add-exports 与 --release 冲突，需要删除 -->
        <compilerArgs>
            <arg>--add-exports=jdk.compiler/com.sun.tools.javac.api=ALL-UNNAMED</arg>
            <arg>--add-exports=jdk.compiler/com.sun.tools.javac.file=ALL-UNNAMED</arg>
            <arg>--add-exports=jdk.compiler/com.sun.tools.javac.main=ALL-UNNAMED</arg>
            <arg>--add-exports=jdk.compiler/com.sun.tools.javac.model=ALL-UNNAMED</arg>
            <arg>--add-exports=jdk.compiler/com.sun.tools.javac.processing=ALL-UNNAMED</arg>
            <arg>--add-exports=jdk.compiler/com.sun.tools.javac.tree=ALL-UNNAMED</arg>
            <arg>--add-exports=jdk.compiler/com.sun.tools.javac.util=ALL-UNNAMED</arg>
        </compilerArgs>
    </configuration>
</plugin>
```

**修改后（已修复）**：

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <version>3.11.0</version>
    <configuration>
        <annotationProcessorPaths>
            <path>
                <groupId>org.projectlombok</groupId>
                <artifactId>lombok</artifactId>
                <version>1.18.30</version>
            </path>
        </annotationProcessorPaths>
    </configuration>
</plugin>
```

**删除了什么？为什么？**

| 删除内容 | 原因 |
|---------|------|
| `<source>17</source>` | Spring Boot parent POM 已通过 `<java.version>17</java.version>` 统一管理，重复配置 |
| `<target>17</target>` | 同上，与 `--release 17` 功能重复 |
| 整个 `<compilerArgs>` 块 | 7 个 `--add-exports` 与 Spring Boot 自动注入的 `--release` 参数冲突 |

### 使用 JDK 17 编译

Maven 编译时必须使用 JDK 17+，临时切换方式：

```powershell
$env:JAVA_HOME = "D:\JDK\17.0.10"
$env:Path = "$env:JAVA_HOME\bin;" + $env:Path
mvn clean compile test-compile
```

如果希望永久生效，需要在 IDE（IntelliJ IDEA / Eclipse）中将 Project SDK 设置为 JDK 17。

## 五、知识扩展

### `--release` vs `-source/-target` 的区别

| 选项 | 作用 | 推荐场景 |
|------|------|---------|
| `-source N` | 指定源码语法兼容到 JDK N | 不推荐单独使用 |
| `-target N` | 指定生成字节码兼容到 JDK N | 不推荐单独使用 |
| `--release N` | 同时锁定源码语法 + 字节码版本 + API 可见范围 | **官方推荐** |

`--release` 比 `-source/-target` 更严格，它会确保编译时调用的 API 也是目标版本中实际存在的。例如用 `--release 8` 编译时，即使 classpath 中有 JDK 17 的类库，编译器也会拒绝使用 `var` 或 `List.of()` 等 Java 9+ 的 API。

### Lombok 与 JDK 模块系统的关系演进

| 时间 | 里程碑 |
|------|--------|
| JDK 9 (2017) | 引入模块系统，默认隐藏 `jdk.compiler` 内部包 |
| Lombok 1.16+ | 需要手动加 `--add-exports` 才能访问 javac 内部类 |
| Lombok 1.18.22 (2021) | 适配 JDK 模块系统，不再需要 `--add-exports` hack |
| Lombok 1.18.30 (2023) | 完全支持 JDK 21，推荐版本 |

### Spring Boot parent POM 的编译器配置

Spring Boot parent POM 会自动配置：

```
maven-compiler-plugin → 根据 java.version 自动加上 --release
maven-surefire-plugin → 自动使用 JUnit 5
```

因此在 Spring Boot 项目中，开发者 **几乎不需要显式配置 maven-compiler-plugin** 的 source/target/release 等参数，只需确保 `<java.version>` 属性正确即可。
