# Java 构造器声明的完整结构

你给出的语法模板 `[修饰符] 构造器名(参数列表){}` 抓住了构造器声明的**核心框架**，但它并不完整。根据 Java
语言规范（JLS），一个构造器的完整声明结构，除了你列出的部分，还可能包含**类型参数（泛型）** 和 **`throws` 异常声明子句**；同时，*
*构造器体 `{}`** 内部也有严格的规则。

## 📝 构造器声明的完整语法结构

构造器声明的完整语法可以表示为：

```text
[构造器修饰符] [类型参数] 构造器名 ( 参数列表 ) [throws 异常列表] { 构造器体 }
```

下面逐一说明每个部分的具体内容。

---

## 1. 构造器修饰符 (Constructor Modifiers)

你模板中的 `[修饰符]` 主要指**访问修饰符**，但构造器修饰符的范围更广，限制也更多。

* **访问修饰符**：可以是 `public`、`protected`、`private`，或者**包私有**（不写任何访问修饰符）。它们决定了哪些代码可以调用这个构造器来创建对象。
* **注解 (Annotations)**
  ：构造器可以被注解修饰。注解本身不是“修饰符”，但出现在修饰符的位置上。一个注解要用于构造器，其定义必须包含 `@Target(ElementType.CONSTRUCTOR)`。
* **禁止使用的修饰符**：构造器**不能**被 `abstract`、`static`、`final`、`native`、`strictfp` 或 `synchronized`
  修饰。这是因为构造器不被继承，且总是伴随对象实例调用，这些修饰符对它没有意义或不被允许。

**代码示例**：

```java
public class MyClass {
    // public 访问修饰符
    public MyClass() { }

    // private 访问修饰符（常用于单例模式）
    private MyClass(int data) { }

    // 包私有（无访问修饰符）
    MyClass(String name) { }

    // 带注解的构造器（假设 @Deprecated 可用于构造器）
    @Deprecated
    protected MyClass(boolean flag) { }
}
```

---

## 2. 类型参数 (Type Parameters) — 泛型构造器

这是你模板中**遗漏**的部分。构造器本身可以是泛型的，即它可以声明自己的类型参数，使其能够以泛型的方式初始化对象，独立于类本身的泛型参数。

**代码示例**：

```java
public class Box<T> {
    private T content;

    // 这是一个泛型构造器，声明了自己的类型参数 U
    // U 必须是 T 的子类型
    public <U extends T> Box(U content) {
        this.content = content;
    }
}

// 使用示例
Box<Number> numberBox = new <Integer>Box<>(100); // 显式指定类型参数 U 为 Integer
```

---

## 3. 构造器名 (Constructor Declarator's Name)

构造器名**必须**与所在类的**简单名称**完全一致，包括大小写。如果名称不匹配，编译器会报错。这是构造器与方法最显著的区别之一。

**代码示例**：

```java
public class Person {
    // 构造器名必须是 Person
    public Person() { }
}

// 下面这个类如果试图将构造器命名为 "MyClass" 就会出错
// public class Student {
//     public MyClass() { } // 编译错误：构造器名必须与类名 Student 一致
// }
```

---

## 4. 参数列表 (Parameter List)

这部分你的模板是正确的。构造器的参数列表在语法和语义上与方法的参数列表**完全相同**。它支持：

* **普通参数**：`类型 参数名`
* **`final` 参数**：表示在构造器体内不能修改该参数的值。
* **可变参数 (Varargs)**：使用 `...` 声明，使得构造器可以接受可变数量的参数。这样的构造器被称为**可变参数构造器 (variable
  arity constructor)**。

**代码示例**：

```java
public class Configuration {
    // 无参构造器
    public Configuration() { }

    // 带普通参数的构造器
    public Configuration(String host, int port) { }

    // 带 final 参数的构造器
    public Configuration(final String protocol) {
        // protocol = "new"; // 编译错误：final 参数不能被重新赋值
    }

    // 可变参数构造器
    public Configuration(String... keys) {
        // 可以传入任意数量的 String 参数
    }
}
```

---

## 5. `throws` 异常声明子句 (Throws Clause)

这也是你模板中**遗漏**的部分。构造器可以在其声明中通过 `throws` 关键字声明它可能抛出的受检异常（Checked
Exceptions）。如果构造器抛出了受检异常，调用者必须处理它。`throws` 子句的结构和行为与方法是**完全相同**的。

**代码示例**：

```java
import java.io.IOException;

public class FileLoader {
    // 构造器声明可能抛出 IOException
    public FileLoader(String filePath) throws IOException {
        if (filePath == null) {
            throw new IOException("File path cannot be null");
        }
        // 模拟加载文件可能抛出的异常
    }
}

// 调用者必须处理或继续声明抛出该异常
class Client {
    void createLoader() {
        try {
            // 调用可能抛出异常的构造器
            FileLoader loader = new FileLoader("/path/to/file");
        } catch (IOException e) {
            // 必须捕获或处理
            e.printStackTrace();
        }
    }
}
```

## 6. 构造器体 (Constructor Body)

`{}` 内部不仅仅是普通语句的集合，它有**严格的起始规则**。构造器体的语法结构为 `{ [显式构造器调用] [语句块] }`。

* **显式构造器调用 (Explicit Constructor Invocation)**：构造器体的**第一条语句**（如果存在）必须是以下三种形式之一：

1. **`this(...)`**：调用**同一个类**中的另一个构造器。用于构造器重载时的代码复用。
2. **`super(...)`**：调用**直接父类**的构造器。用于确保父类先于子类初始化。
3. **`this.字段 = ...`**：如果第一条语句不是 `this(...)` 或 `super(...)`，编译器会**隐式**插入一个无参的 `super()`
   调用。如果父类没有无参构造器，则会导致编译错误。

* **语句块**：在显式（或隐式）的 `super()`/`this()` 调用之后，可以编写任何合法的 Java 语句来进行对象初始化。

**代码示例 (使用 `this` 和 `super`)**：

```java
class Parent {
    String name;
    Parent(String name) {
        this.name = name;
    }
}

class Child extends Parent {
    int age;

    // 构造器1：使用 super(...) 调用父类构造器
    public Child(String name) {
        super(name); // 第一条语句必须是 super 调用
        // 之后可以写其他初始化代码
    }

    // 构造器2：使用 this(...) 调用本类的另一个构造器（重载）
    public Child(String name, int age) {
        this(name); // 调用本类的 Child(String name) 构造器
        this.age = age; // 之后再进行自己的初始化
    }
}
```

# 格式说明

* 构造器名必须与它所在的类名必须相同。
* 它没有返回值，所以不需要返回值类型，也不需要 void。
* 构造器的修饰符只能是权限修饰符，不能被其他任何修饰。比如，不能被 static、final、synchronized、abstract、native 修饰，不能有
  return 语句返回值

---

# 使用说明

* 当我们没有显式的声明类中的构造器时，系统会默认提供一个无参的构造器并且该构造器的修饰符默认与类的修饰符相同
* 当我们显式的定义类的构造器以后，系统就不再提供默认的无参的构造器了。
* 在类中，至少会存在一个构造器。
* 构造器是可以重载的。
