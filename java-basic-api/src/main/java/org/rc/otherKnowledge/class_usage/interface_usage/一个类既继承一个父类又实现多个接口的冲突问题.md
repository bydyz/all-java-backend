# Java 中同时继承父类并实现多个接口时的冲突处理

当一个类同时继承父类并实现多个接口时，冲突主要发生在**方法签名相同**的默认方法（`default` method）之间，或**同名的字段（常量）
** 上。Java 的解决机制并非“多继承”，而是遵循一套明确的优先级规则和强制覆盖原则。

## 核心规则：类优先与子类型优先

Java 语言规范为解决此类冲突定义了两个基础规则：

1. **类优先（Class wins）**：如果父类中**已经存在**一个具体方法或抽象方法声明，那么它会优先于所有接口中的默认方法。实现类无需为此做任何事，编译器会自动选择父类的方法。
2. **子类型优先（Subtype wins）**：如果一个接口继承了另一个接口，且两者都提供了同签名的默认方法，那么**更具体**的子接口中的默认方法优先。

## 场景一：父类方法与接口默认方法冲突

这是最容易被自动处理的情况。由于“类优先”原则，只要父类（无论是具体类还是抽象类）中存在同名方法，接口的默认方法就会被忽略，调用时会执行父类的方法。

```java
class Parent {
    public void greet() { System.out.println("Parent"); }
}
interface Greeting {
    default void greet() { System.out.println("Interface"); }
}
class Child extends Parent implements Greeting { }

// new Child().greet(); 输出 "Parent"，无需在 Child 中重写
```

即使父类中的方法是 `abstract`，它的声明依然会屏蔽接口的默认实现，此时子类必须提供具体实现，但依然**不需要**
用 `接口名.super` 来消歧。

## 场景二：多个接口的默认方法相互冲突

如果实现类所实现的多个**独立**接口（彼此没有继承关系）中存在同签名的默认方法，编译器无法裁决，会产生**编译错误**。此时，实现类
**必须显式重写**该方法来解决冲突。

重写时，你有两种选择：

### 选择一：提供全新实现

```java
interface A { default void run() { System.out.println("A"); } }
interface B { default void run() { System.out.println("B"); } }

class C implements A, B {
    @Override
    public void run() {
        System.out.println("C"); // 自己的实现
    }
}
```

### 选择二：委托给指定接口的默认实现

使用 `接口名.super.方法名()` 语法，可以显式调用某个父接口的默认实现。

```java
class C implements A, B {
    @Override
    public void run() {
        A.super.run(); // 明确选择接口 A 的默认实现
        // 也可以再调用 B.super.run();
    }
}
```

## 场景三：字段（常量）的冲突

接口中的字段隐式为 `public static final`。如果一个类从父类和接口，或从多个接口继承了**同名字段**，直接使用简单名称访问会导致
**编译错误**（歧义）。

解决方式是使用**限定名**（类名或接口名）来明确指定来源。

```java
interface ConstantsA { String NAME = "A"; }
interface ConstantsB { String NAME = "B"; }

class FieldConflict implements ConstantsA, ConstantsB {
    void print() {
        // System.out.println(NAME); // 编译错误：引用的 NAME 不明确
        System.out.println(ConstantsA.NAME); // 输出 A
        System.out.println(ConstantsB.NAME); // 输出 B
    }
}
```

如果父类中也定义了同名字段，用 `super.字段名` 或 `父类名.字段名` 来访问父类字段。

## 总结与补充

处理这类冲突时，遵循的核心逻辑是：

1. **类优先**：父类中的方法（无论具体或抽象）优先于接口默认方法。
2. **子类型优先**：在接口继承链中，子接口的默认方法优先。
3. **无法裁决时强制覆盖**：多个独立接口的默认方法冲突时，实现类**必须**重写，并可用 `接口名.super` 选择性地调用特定接口的实现。
4. **字段需限定**：同名字段产生歧义时，使用 `接口名.字段名` 或 `super.字段名` 来消除歧义。

从设计角度看，接口的默认方法本意是用于**渐进式演进**（在不破坏现有实现类的前提下新增方法）。因此，在你自己设计接口时，应尽量避免定义可能产生歧义的、同签名的默认方法，从源头上减少冲突的发生。
