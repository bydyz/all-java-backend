Java 中严格意义上的“数据流”，特指 **`DataInputStream` 与 `DataOutputStream`**。它们并非用于处理原始的字节或字符，而是解决一个更具体的问题：**如何以与机器无关的二进制格式，读写 Java 的基本数据类型和字符串**。

---

### 数据流是什么，解决什么问题

普通的 `InputStream`/`OutputStream` 以字节为单位读写，`Reader`/`Writer` 以字符为单位读写。但当你需要保存或传输一个 `int`、`double`、`boolean` 时，直接用字节流会面临两个麻烦：一是你需要手动处理这些类型与字节之间的转换；二是转换方式可能依赖平台，导致一份数据在不同机器上无法正确还原。

数据流正是为了消除这些麻烦而存在的。`DataInputStream` 和 `DataOutputStream` 提供了一组 `readInt()` / `writeInt()`、`readDouble()` / `writeDouble()`、`readUTF()` / `writeUTF()` 等方法，直接以**基本数据类型为单位**进行二进制 I/O。写入时，它们按固定字节数（如 `int` 写 4 字节）和固定字节序（大端序）输出；读取时按同样的规则还原，从而保证数据在不同平台间可以一致地读写。

一个典型的用途是**保存结构化记录**。例如一条商品记录包含价格（`double`）、数量（`int`）和描述（`String`），用数据流可以依次写入，再依次读回，读取顺序与写入顺序严格对应即可。

### 在流的分类体系中的位置

Java 的 I/O 流通常从两个角度分类，数据流在其中占据明确的位置。

**按数据单位**分为字节流和字符流。数据流属于**字节流**家族，它们是 `InputStream` / `OutputStream` 的子类，底层仍然是字节的传输，只是在字节之上附加了基本类型的解释能力。

**按功能角色**分为**节点流**和**处理流**。这是理解数据流的关键：

| 分类 | 含义 | 典型代表 |
|---|---|---|
| **节点流** | 直接连接数据源（文件、网络、内存），负责“把数据搬进来/送出去” | `FileInputStream`、`FileOutputStream`、`ByteArrayInputStream` |
| **处理流** | 包装在其他流之上，对流过它的数据进行加工或提供额外功能 | `BufferedInputStream`、`DataInputStream`、`ObjectInputStream` |

`DataInputStream` 和 `DataOutputStream` 是典型的**处理流**，它们不能独立指向一个文件，必须包装一个已存在的字节流来工作。它们本身不直接与磁盘或网络打交道，而是在字节流之上增加了“按基本类型读写”这一层加工能力。

因此，在实际使用中，它们几乎总是以**包装链**的形式出现：节点流负责连接数据源，缓冲流负责提高效率，数据流负责类型化的读写。

### 代码示例：写入并读回一条结构化记录

下面的示例演示了用 `DataOutputStream` 写入一组基本类型和字符串，再用 `DataInputStream` 按相同顺序读回。代码体现了处理流包装节点流的典型结构。

```java
import java.io.*;

public class DataStreamDemo {
    public static void main(String[] args) {
        String file = "record.dat";

        // ---------- 写入 ----------
        try (DataOutputStream out = new DataOutputStream(
                new BufferedOutputStream(new FileOutputStream(file)))) {

            out.writeDouble(19.99);          // 价格
            out.writeInt(12);               // 数量
            out.writeUTF("Java T-Shirt");   // 描述（以 UTF-8 变体写入）

            out.writeDouble(9.99);
            out.writeInt(8);
            out.writeUTF("Java Mug");

        } catch (IOException e) {
            e.printStackTrace();
        }

        // ---------- 读取 ----------
        try (DataInputStream in = new DataInputStream(
                new BufferedInputStream(new FileInputStream(file)))) {

            // 注意：读取顺序必须与写入顺序完全一致
            double price1 = in.readDouble();
            int unit1 = in.readInt();
            String desc1 = in.readUTF();

            double price2 = in.readDouble();
            int unit2 = in.readInt();
            String desc2 = in.readUTF();

            System.out.println(unit1 + " × " + desc1 + " @ " + price1);
            System.out.println(unit2 + " × " + desc2 + " @ " + price2);

        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

运行后输出：
```text
12 × Java T-Shirt @ 19.99
8 × Java Mug @ 9.99
```

这段代码中，`FileOutputStream` / `FileInputStream` 是节点流，直接操作文件；`BufferedOutputStream` / `BufferedInputStream` 是处理流，增加缓冲以减少实际的磁盘读写次数；`DataOutputStream` / `DataInputStream` 是数据流，在缓冲之上完成“`double` → 8 字节”“`int` → 4 字节”“`String` → UTF-8 字节序列”的转换。整条链的分工是清晰的。

### 一个需要留意的行为细节

`DataInputStream` 的 `readInt()`、`readDouble()` 等方法在读到文件末尾时，**不会返回一个特殊值**来表示“结束了”。原因在于，任何可以返回的值（例如 `-1`）都可能恰好是一条合法记录中的数据，用它充当结束标记会产生歧义。因此，这些方法在流意外结束时抛出 **`EOFException`**。这意味着用数据流读取未知数量的记录时，通常需要用 `try-catch` 捕获 `EOFException` 来判断读取结束，或者你自己在写入时额外保存一个记录条数，读取时按已知条数循环。
