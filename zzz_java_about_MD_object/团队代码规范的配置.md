# Java 团队代码规范：业界最佳配置文件方案

"业界最好的配置文件"并不是一个单一文件，而是一套**分层协同的体系**。单一文件要么管不到 Java
特有的格式细节（如 `.editorconfig`），要么无法约束所有人的 IDE（如纯 IDEA XML）。

业界共识的分层方案是：**`.editorconfig` 作为跨 IDE 的基础层，IDEA 的 `Project.xml` 作为深度定制层，而 Spotless + Google
Java Format 作为 CI 强制执行的权威层**。下面直接给出可直接落地的配置。

---

## 第一层：.editorconfig（跨 IDE 基础层）

放在项目根目录，IDEA、VS Code 等主流编辑器**原生自动识别**，无需插件。它定义字符集、换行符、缩进等跨语言的"底线规则"。

```ini
# .editorconfig
# 跨IDE基础格式约定 —— 第一道防线
root = true

[*]
charset = utf-8
end_of_line = lf
indent_style = space
indent_size = 4
insert_final_newline = true
trim_trailing_whitespace = true
max_line_length = 120

[*.{yml,yaml,json,xml,html,css,md}]
indent_size = 2

[*.java]
# Java 特有的基础约定
indent_size = 4
ij_continuation_indent_size = 8
ij_java_align_consecutive_assignments = false
ij_java_align_consecutive_variable_declarations = false
ij_java_align_group_field_declarations = false
ij_java_align_multiline_parameters = true
ij_java_block_brace_style = end_of_line
ij_java_blank_lines_after_package = 1
ij_java_blank_lines_after_imports = 1
ij_java_blank_lines_around_class = 1
ij_java_blank_lines_around_method = 1
ij_java_class_count_to_use_import_on_demand = 999
ij_java_layout_static_imports_separately = true

# 关闭行注释顶格，使其跟随代码缩进
ij_java_line_comment_at_first_column = false
# 如果块注释（/* */）也顶格，一并关闭
ij_java_block_comment_at_first_column = false

# 建议同时开启：在注释符号 // 后自动补一个空格
ij_java_line_comment_add_space = true
```

**要点说明**：

- `end_of_line = lf`：强制 LF，避免 Windows/Linux 开发者因换行符不同产生无意义 diff。
- `ij_java_class_count_to_use_import_on_demand = 999`：禁止 `import xxx.*` 星号导入（星号导入会让依赖来源不清晰）。
- `ij_java_layout_static_imports_separately = true`：静态导入与普通导入分组，符合主流规范。
- `ij_*` 系列是 IDEA 能识别的私有属性，放在 `.editorconfig` 里可以让 IDEA 在不导入 XML 的情况下也尽量贴近团队风格。

## 第二层：IDEA 项目级 Project.xml（深度定制层）

`.editorconfig` 管不到 Java 的**空行策略、换行位置、对齐规则**等深层格式。这些需要 IDEA 的 `Project.xml` 来兜底。

**放置位置**：`项目根目录/.idea/codeStyles/Project.xml`。提交到 Git 后，团队成员克隆项目时 IDEA **自动读取**，零操作成本。

```xml
<!-- .idea/codeStyles/Project.xml -->
<component name="ProjectCodeStyleConfiguration">
  <code_scheme name="Project" version="173">
    <JavaCodeStyleSettings>
      <option name="CLASS_COUNT_TO_USE_IMPORT_ON_DEMAND" value="999"/>
      <option name="NAMES_COUNT_TO_USE_IMPORT_ON_DEMAND" value="999"/>
      <option name="PACKAGES_TO_USE_IMPORT_ON_DEMAND">
        <value/>
      </option>
      <option name="IMPORT_LAYOUT_TABLE">
        <value>
          <package name="" withSubpackages="true" static="true"/>
          <emptyLine/>
          <package name="java" withSubpackages="true" static="false"/>
          <package name="javax" withSubpackages="true" static="false"/>
          <emptyLine/>
          <package name="" withSubpackages="true" static="false"/>
        </value>
      </option>
    </JavaCodeStyleSettings>
    <codeStyleSettings language="JAVA">
      <option name="RIGHT_MARGIN" value="120"/>
      <option name="KEEP_BLANK_LINES_IN_CODE" value="1"/>
      <option name="BLANK_LINES_AFTER_PACKAGE" value="1"/>
      <option name="BLANK_LINES_AFTER_IMPORTS" value="1"/>
      <option name="BLANK_LINES_AROUND_CLASS" value="1"/>
      <option name="BLANK_LINES_AROUND_METHOD" value="1"/>
      <option name="BLANK_LINES_AROUND_FIELD" value="0"/>
      <option name="BLANK_LINES_BEFORE_METHOD_BODY" value="0"/>
      <option name="BRACE_STYLE" value="1"/>
      <option name="ELSE_ON_NEW_LINE" value="false"/>
      <option name="CATCH_ON_NEW_LINE" value="false"/>
      <option name="FINALLY_ON_NEW_LINE" value="false"/>
      <option name="WHILE_ON_NEW_LINE" value="false"/>
      <option name="ALIGN_MULTILINE_PARAMETERS" value="true"/>
      <option name="ALIGN_MULTILINE_PARAMETERS_IN_CALLS" value="false"/>
      <option name="ALIGN_MULTILINE_EXTENDS_LIST" value="true"/>
      <option name="ALIGN_MULTILINE_THROWS_LIST" value="true"/>
      <option name="ALIGN_MULTILINE_TERNARY_OPERATION" value="false"/>

      <option name="LINE_COMMENT_ADD_SPACE" value="true"/>
    </codeStyleSettings>
  </code_scheme>
</component>
```

**配套的 `codeStyleConfig.xml`**（同一目录下，确保 IDEA 使用项目级方案而非默认方案）：

```xml
<!-- .idea/codeStyles/codeStyleConfig.xml -->
<component name="ProjectCodeStyleConfiguration">
  <state>
    <option name="USE_PER_PROJECT_SETTINGS" value="true"/>
  </state>
</component>
```

## 第三层：Spotless + Google Java Format（CI 强制执行层）

前面两层是"建议"，这一层是"**必须**"。Spotless 在构建时格式化或校验代码，不通过则构建失败，彻底杜绝风格漂移。

### Maven 配置（`pom.xml`）

```xml

<plugin>
  <groupId>com.diffplug.spotless</groupId>
  <artifactId>spotless-maven-plugin</artifactId>
  <version>2.44.2</version>
  <configuration>
    <java>
      <googleJavaFormat>
        <version>1.25.2</version>
        <style>GOOGLE</style>
      </googleJavaFormat>
      <removeUnusedImports/>
      <trimTrailingWhitespace/>
      <endWithNewline/>
      <toggleOffOn/>
    </java>
  </configuration>
  <executions>
    <execution>
      <goals>
        <goal>check</goal>
      </goals>
      <phase>compile</phase>
    </execution>
  </executions>
</plugin>
```

- `googleJavaFormat`：使用 Google 官方格式引擎，**格式唯一、不可协商**，这是团队避免风格争论的关键。
- `check` 绑定到 `compile` 阶段：**任何格式不合格的代码，`mvn compile` 直接失败**，无法进入后续构建。
- 开发者在本地可运行 `mvn spotless:apply` 一键修复。

### Gradle 配置（`build.gradle`）

```groovy
plugins {
  id 'com.diffplug.spotless' version '6.25.0'
}

spotless {
  java {
    target 'src/**/*.java'
    googleJavaFormat('1.25.2').aosp().reorderImports(true)
    removeUnusedImports()
    trimTrailingWhitespace()
    endWithNewline()
    toggleOffOn()
  }
}

// 可选：让 check 在 build 时自动执行
check.dependsOn spotlessCheck
```

`googleJavaFormat().aosp()` 使用 **4 空格缩进**的 AOSP 变体，比标准 Google 风格的 2 空格更容易被多数团队接受。如果团队接受
2 空格，去掉 `.aosp()` 即可。

## 如何让三层协同工作

| 层级      | 文件                                     | 作用                    | 执行时机                                |
|:--------|:---------------------------------------|:----------------------|:------------------------------------|
| **基础层** | `.editorconfig`                        | 统一字符集、换行、基础缩进         | 打字/保存时，IDE 自动应用                     |
| **定制层** | `.idea/codeStyles/Project.xml`         | Java 深层格式（空行、换行、导入顺序） | IDEA 打开项目时自动加载                      |
| **权威层** | `pom.xml` / `build.gradle` 中的 Spotless | **强制**格式化，不通过即失败      | `mvn compile` / `gradle build` / CI |

**关键原则**：

- `.editorconfig` 和 `Project.xml` 让开发者在**日常编码中自然贴近规范**；
- Spotless 在**构建/CI 时兜底**，确保无论本地 IDE 怎么设置，进入仓库的代码一定是统一的。
- 三者缺一不可——只有前两层，有人用其他 IDE 或改本地设置就会破防；只有 Spotless，每次都要手动跑 `spotlessApply`，体验割裂。

## 附：Google Java Format IDEA 插件（提升本地体验）

如果希望 IDEA 内的 `Ctrl + Alt + L` 也直接使用 Google 格式，可安装官方插件：

1. `Settings` → `Plugins` → 搜索 **Google Java Format** → 安装并重启。
2. `Settings` → `Other Settings` → `Google Java Format Settings` → 勾选 **Enable google-java-format**。
3. 选择 **AOSP** 风格（4 空格）或 **Google** 风格（2 空格），与 Spotless 配置保持一致。

---

## 总结

> **`.editorconfig` 管底线，`Project.xml` 管深度，Spotless + Google Java Format 管强制。** 这三份配置一起入库，就是当前 Java
> 生态里经过大量头部项目验证的"业界最好"方案。
