转换流是 Java I/O 体系中两个**处理流**的合称：`InputStreamReader` 和 `OutputStreamWriter`。它们本身属于字符流体系（分别继承自 `Reader` 和 `Writer`），但需要“套接”在一个字节流之上工作。理解转换流的关键在于：**字节流负责“搬运”原始字节，转换流负责在字节与字符之间按照指定的字符集进行“翻译”**。

---

### 核心作用：充当字节流与字符流之间的“桥梁”

转换流最主要的作用是在**字节流**和**字符流**之间进行转换，并在这个过程中**指定或控制字符编码**。

#### 为什么需要转换流？

`FileReader` 和 `FileWriter` 虽然也是字符流，但它们**只能使用平台默认的字符集**，无法在代码中指定编码。当文件的实际编码与平台默认编码不一致时，就会产生乱码。

例如，一个在 Windows 上用 GBK 编码保存的文本文件，如果在默认 UTF-8 的环境下直接用 `FileReader` 读取，中文字符就会变成乱码。转换流允许你在**创建流对象时显式指定字符集**，从而保证解码（读取）或编码（写出）时使用的规则与文件的实际编码一致。

从设计模式的角度看，转换流采用了**适配器模式**：它把一个字节流“适配”成一个字符流接口，使原本只能操作字节的代码能够以字符为单位进行读写。

---

### 分类与代码详解

转换流只有两个具体类，方向相反：

| 类 | 方向 | 父类 | 核心行为 |
|---|---|---|---|
| **`InputStreamReader`** | 字节输入流 → 字符输入流 | `Reader` | **解码**：读取字节，按指定字符集将其解释为字符 |
| **`OutputStreamWriter`** | 字符输出流 → 字节输出流 | `Writer` | **编码**：接收字符，按指定字符集将其转换为字节后写出 |

两者的构造方法都提供了**默认字符集**和**指定字符集**两种形式：

```java
// InputStreamReader
new InputStreamReader(InputStream in);                 // 使用平台默认字符集
new InputStreamReader(InputStream in, String charset); // 指定字符集

// OutputStreamWriter
new OutputStreamWriter(OutputStream out);                 // 使用平台默认字符集
new OutputStreamWriter(OutputStream out, String charset); // 指定字符集
```

#### 1. `InputStreamReader`：用正确编码读取文本

假设 `data.txt` 是 GBK 编码，直接按默认 UTF-8 读取会产生乱码；指定 `"GBK"` 后即可正确解码：

```java
try (InputStreamReader isr = new InputStreamReader(
        new FileInputStream("data.txt"), "GBK")) {
    int ch;
    while ((ch = isr.read()) != -1) {
        System.out.print((char) ch);
    }
}
```

关键点在于构造时传入的 `"GBK"`：它告诉 `InputStreamReader` 底层字节应该按照 GBK 规则来“翻译”，而不是默认的 UTF-8。

---

#### 2. `OutputStreamWriter`：按指定编码写出文本

将字符以 GBK 编码写入文件，同样需要显式指定：

```java
try (OutputStreamWriter osw = new OutputStreamWriter(
        new FileOutputStream("out.txt"), "GBK")) {
    osw.write("你好，世界");
}
```

这里 `osw.write("你好，世界")` 接收到的是字符，`OutputStreamWriter` 会按照 `"GBK"` 将它们编码为字节，再交给底层的 `FileOutputStream` 写入磁盘。

---

#### 3. 典型场景：文件编码转换

转换流最常见的用途之一，是把一个编码的文件读取出来，再用另一种编码写出，完成编码转换。下面的例子把一个 UTF-8 文件以 GBK 编码复制：

```java
try (InputStreamReader isr = new InputStreamReader(
        new FileInputStream("source_utf8.txt"), StandardCharsets.UTF_8);
     OutputStreamWriter osw = new OutputStreamWriter(
        new FileOutputStream("target_gbk.txt"), "GBK")) {

    char[] buffer = new char[1024];
    int len;
    while ((len = isr.read(buffer)) != -1) {
        osw.write(buffer, 0, len);
    }
}
```

**输入侧的 `InputStreamReader` 指定 `UTF_8`**：正确解码源文件；**输出侧的 `OutputStreamWriter` 指定 `"GBK"`**：将读到的字符重新编码为 GBK 字节写出。读和写的字符集各司其职，编码转换得以精确完成。

---

#### 4. 标准输入/输出的包装

`System.in` 和 `System.out` 本质上都是字节流。如果需要按字符或按行操作，可以用转换流进行包装：

```java
BufferedReader br = new BufferedReader(
        new InputStreamReader(System.in));
BufferedWriter bw = new BufferedWriter(
        new OutputStreamWriter(System.out));

String line;
while ((line = br.readLine()) != null && !"exit".equals(line)) {
    bw.write(line);
    bw.newLine();
    bw.flush();
}
```

`InputStreamReader` 将 `System.in` 的字节输入转换为字符输入，再交给 `BufferedReader` 以获得按行读取的能力；`OutputStreamWriter` 则把字符输出转换为 `System.out` 可以处理的字节输出。

---

### 总结

转换流本身不直接连接文件或网络，而是**包裹在一个字节流外面**，在字节与字符之间进行带编码控制的转换。它的核心价值可以用一句话概括：**字节流负责传输，转换流负责按你指定的字符集进行解码或编码**。凡是需要在读写文本时明确控制字符集、避免乱码的场合，`InputStreamReader` 和 `OutputStreamWriter` 就是最直接的工具。
