以下是Java接口相关的高频面试题整理，按考察维度分为**基础对比、版本演进、函数式接口、特殊接口、设计模式与多态**五个板块，每题均附代码说明。

## 一、接口 vs 抽象类

这是接口方向出现频率最高的问题，回答时需要从**设计目的**和**语法约束**两个层面展开。

### Q1：接口和抽象类的本质区别是什么？

设计目的不同：抽象类描述“**is-a**”关系，用于**代码复用**和**模板方法**——多个相关类共享状态和行为时使用；接口描述“**can-do**
”关系，定义一组**行为契约**，不关心实现者是谁。

语法层面的关键差异：

| 维度      | 接口                                                   | 抽象类                          |
|---------|------------------------------------------------------|------------------------------|
| 关键字     | `interface` / `implements`                           | `abstract class` / `extends` |
| 构造方法    | **不能有**                                              | **可以有**（供子类 `super()` 调用）    |
| 成员变量    | 默认 `public static final`                             | 访问修饰符不限，可普通成员变量              |
| 方法      | 抽象方法 + `default`/`static`（JDK 8+）+ `private`（JDK 9+） | 抽象方法 + 普通方法，自由组合             |
| 继承/实现数量 | 一个类可**实现多个**接口                                       | 一个类只能**继承一个**抽象类             |
| 接口本身    | 接口可以**多继承**接口                                        | 类只能单继承                       |

```java
abstract class Animal {                     // 抽象类：is-a，可持有状态
    protected String name;
    public Animal(String name) { this.name = name; }
    public abstract void makeSound();
    public void eat() { System.out.println(name + " 在进食"); }
}

interface Flyable {                          // 接口：can-do，只定义契约
    int MAX_HEIGHT = 10000;                  // 隐式 public static final
    void fly();
    default void land() { System.out.println("着陆"); }
}

// 一个类只能继承一个抽象类，但可以实现多个接口
class Bird extends Animal implements Flyable {
    public Bird(String name) { super(name); }   // 抽象类的构造方法在此被调用
    @Override public void makeSound() { System.out.println("啾啾"); }
    @Override public void fly() { System.out.println(name + " 在飞行"); }
}
```

### Q2：接口为什么不能有构造方法，抽象类为什么可以有？

接口是**纯契约**，不承载任何实例状态，因此不需要构造方法；它的所有字段都是 `static final`
常量，也不存在“初始化实例字段”的需求。抽象类虽然不能被 `new`，但它可以拥有**实例成员变量**，子类构造时必须通过 `super(...)`
完成父类部分的初始化，所以必须有构造方法。

## 二、JDK 8+ 接口的演进

### Q3：JDK 8 为什么引入默认方法（default method）？

核心动机是**接口的二进制兼容性**。以 `Collection` 接口为例，JDK 8 需要新增 `stream()`、`forEach()`、`removeIf()`
等方法；如果仍以抽象方法加入，所有已有的 `Collection` 实现类都会编译失败。默认方法允许在不破坏现有实现的前提下扩展接口。

```java
interface CollectionLike<T> {
    default void forEachLike(Consumer<T> action) { /* 默认实现，实现类可不重写 */ }
}
```

**代价**：接口与抽象类的边界变得模糊——接口开始携带实现，设计时需要更谨慎地判断“这个行为是否真的应该放在接口里”。

### Q4：多个接口有同名同参的 default 方法，实现类会怎样？

这里有一个**优先级链**，面试中常被追问：

1. **类中的具体方法优先级最高**：如果实现类或它的父类已经提供了方法实现，接口的 default 方法被忽略。
2. **子接口优先于父接口**：`B extends A`，二者都有 `hello()` 的 default 实现，`B` 的胜出。
3. **没有规则三**：如果两条都不适用（例如实现了两个互不继承的接口，都有同名 default 方法），**实现类必须重写该方法**，否则编译报错。

```java
interface A { default void hello() { System.out.println("A"); } }
interface B { default void hello() { System.out.println("B"); } }

class C implements A, B {
    // 不重写则编译错误；必须显式覆盖，并可选择调用某一个接口的版本
    @Override public void hello() {
        A.super.hello();   // 显式选择 A 的默认实现
    }
}
```

### Q5：接口中的 static 方法能被子接口或实现类继承吗？

**不能**。接口的 `static` 方法属于接口本身，不被继承，也不能通过实现类的实例调用，只能通过 `接口名.方法名()`
调用。这与类中的静态方法可以被子类继承的行为不同，是面试中的易错点。

## 三、函数式接口（Functional Interface）

### Q6：什么是函数式接口？“一个抽象方法”如何精确计数？

函数式接口是**有且仅有一个抽象方法**的接口，是 Lambda 表达式和方法引用的**唯一合法目标类型**。计数时有三类方法**不计入**
“一个”：

- 从 `Object` 继承的方法（`equals`、`hashCode`、`toString`）；
- `default` 方法（可以有任意多个）；
- `static` 方法（可以有任意多个）。

`@FunctionalInterface` 是**编译期检查注解**，不是必需的，但加了之后如果误增第二个抽象方法，编译器会立刻报错，强烈建议使用。

```java
@FunctionalInterface
interface StringProcessor {
    String process(String input);          // 唯一的抽象方法

    default boolean isEmpty(String s) {    // default 方法不破坏函数式特性
        return s == null || s.trim().isEmpty();
    }
    static StringProcessor identity() {    // static 方法也不影响
        return s -> s;
    }
}

// Lambda 实现
StringProcessor upper = s -> s.toUpperCase();
```

### Q7：`java.util.function` 中必须掌握的四个内置函数式接口是什么？

| 接口              | 抽象方法     | 签名            | 典型场景             |
|-----------------|----------|---------------|------------------|
| `Predicate<T>`  | `test`   | `T → boolean` | `filter` 条件筛选    |
| `Function<T,R>` | `apply`  | `T → R`       | `map` 数据转换       |
| `Consumer<T>`   | `accept` | `T → void`    | `forEach` 消费元素   |
| `Supplier<T>`   | `get`    | `() → T`      | 惰性创建、`orElseGet` |

这四个接口是 Stream API 和 Lambda 编程的基础，面试中经常要求现场用其中一个配合 Stream 写出一段数据处理逻辑。

## 四、特殊接口类型

### Q8：什么是标记接口（Marker Interface）？举两个例子。

标记接口是**内部没有任何方法声明**的空接口，作用是向 JVM 或编译器传递元信息，触发特定行为。

- **`Serializable`**：实现该接口的类允许被序列化；未实现时执行序列化会抛出 `NotSerializableException`。
- **`Cloneable`**：实现该接口的类才能合法调用 `Object.clone()`；否则抛出 `CloneNotSupportedException`。注意 `Cloneable`
  本身也不声明 `clone()` 方法，`clone()` 定义在 `Object` 中。

标记接口 vs 注解：注解是更现代、更灵活的元数据载体，但标记接口在**类型系统层面**仍有意义——你可以将 `Serializable`
作为方法参数类型来约束“只接受可序列化对象”，而注解无法直接充当类型。

### Q9（进阶）：JDK 9 给接口增加了什么？private 方法有什么用？

JDK 9 允许接口中定义 `private` 方法和 `private static` 方法，目的是**在接口内部复用代码而不暴露给实现类**
。典型场景：多个 `default` 方法或 `static` 方法共享一段辅助逻辑，这段逻辑不应该成为接口公开 API 的一部分。

```java
interface Logger {
    default void logInfo(String msg) { log("INFO", msg); }
    default void logError(String msg) { log("ERROR", msg); }

    private void log(String level, String msg) {   // 仅接口内部可用
        System.out.println("[" + level + "] " + msg);
    }
}
```

## 五、接口在设计模式与多态中的角色

### Q10：接口如何支撑策略模式（Strategy Pattern）？

策略模式的核心是将**可变行为抽象为接口**，让不同的算法实现可以互相替换，而调用方只依赖接口。这是接口最经典的设计模式应用，面试中常要求手写。

```java
interface PaymentStrategy {                    // 策略接口
    void pay(int amount);
}

class AlipayStrategy implements PaymentStrategy {
    public void pay(int amount) { System.out.println("支付宝支付 " + amount); }
}
class WechatStrategy implements PaymentStrategy {
    public void pay(int amount) { System.out.println("微信支付 " + amount); }
}

class OrderService {
    private PaymentStrategy strategy;
    public void setStrategy(PaymentStrategy strategy) { this.strategy = strategy; }
    public void checkout(int amount) { strategy.pay(amount); }
}
```

调用方 `OrderService` 只依赖 `PaymentStrategy` 接口，新增支付方式时**不需要修改已有代码**，符合开闭原则。

### Q11：接口多态与“向上转型”在面试题中的典型考法

接口多态的本质是：**父接口引用指向实现类对象，运行时动态绑定到实际实现**。面试中常见的陷阱题是考查“引用类型决定可调用方法，实际类型决定执行逻辑”：

```java
interface USB { void work(); }
class Mouse implements USB {
    public void work() { System.out.println("鼠标工作"); }
    public void click() { System.out.println("点击"); }
}

USB usb = new Mouse();   // 向上转型：接口引用指向实现类实例
usb.work();               // OK：接口中声明了 work()
// usb.click();           // 编译错误：USB 接口中没有 click()
((Mouse) usb).click();    // 向下转型后才能调用子类特有方法
```

`usb` 的**编译时类型是 `USB`**，所以只能调用接口中声明的方法；`work()` 执行的是 `Mouse` 的实现，体现运行时多态。
