# Java 异常体系详解

## 一、整体体系结构

Java 中所有可抛出（throwable）对象都继承自 `java.lang.Throwable`，其下分为两大分支：**Error** 和 **Exception**。

```
                        java.lang.Throwable
                        (implements Serializable)
                                 │
              ┌──────────────────┴──────────────────┐
           Error                                Exception
      （程序无法处理）                      （程序可以处理）
              │                                   │
   ┌──────────┼──────────┐          ┌─────────────┴─────────────┐
OutOfMemoryError  StackOverflowError  ...   RuntimeException        受检异常(Checked)
NoClassDefFoundError  ...                   （非受检/Unchecked）         │
                                            │                ┌────────┼─────────┐
                            ┌───────────────┼───────┐     IOException  SQLException
                    NullPointerException  ClassCastException  ...   ├─ FileNotFoundException
                    ArrayIndexOutOfBoundsException  ...      ClassNotFoundException
                    IllegalArgumentException                InterruptedException
                    ├─ NumberFormatException                CloneNotSupportedException
                    ArithmeticException                     ...
                    UnsupportedOperationException
```

核心要点：
- **Throwable** 是根类，只有它的实例才能被 `throw` / `catch`。
- **Error**：JVM 级别的严重问题（内存耗尽、栈溢出、类定义错误等），程序**不应尝试捕获和恢复**。
- **Exception**：程序可以处理的异常，又分 **受检异常（Checked）** 和 **非受检异常（Unchecked, 即 RuntimeException 及其子类）**。

---

## 二、Throwable 的核心 API

| 方法 | 说明 |
|---|---|
| `getMessage()` | 异常描述信息 |
| `getCause()` | 引发当前异常的原因（异常链） |
| `getStackTrace()` | 堆栈跟踪元素数组 |
| `printStackTrace()` | 打印到标准错误流 |
| `addSuppressed(Throwable)` | 添加被抑制的异常（try-with-resources 使用） |
| `getSuppressed()` | 获取被抑制的异常数组 |

## 三、Error：不该捕获的错误

`Error` 表示 JVM 自身或运行环境出现的严重故障，程序通常无法恢复。

```java
public class ErrorDemo {
    public static void main(String[] args) {
        // StackOverflowError：无限递归导致栈溢出
        try {
            recurse();
        } catch (StackOverflowError e) {
            System.out.println("栈溢出（仅演示，实际不应捕获 Error）");
        }

        // OutOfMemoryError：不断创建大对象
        // List<long[]> list = new ArrayList<>();
        // while (true) list.add(new long[1024 * 1024]);
    }

    static void recurse() { recurse(); }
}
```

**结论：** `Error` 一般不要捕获；`catch (Throwable)` 这种写法在业务代码中应极力避免，它会吞掉 `OutOfMemoryError` 之类的问题。

## 四、Exception 的两大分类

### 4.1 受检异常（Checked Exception）

编译器强制要求处理：要么用 `try-catch` 捕获，要么用 `throws` 声明抛出，否则**编译不通过**。

典型代表：`IOException`、`SQLException`、`ClassNotFoundException`、`InterruptedException`。

```java
import java.io.*;

public class CheckedDemo {

    // 方式一：throws 声明，交给调用者处理
    public static String readFirstLine(String path) throws IOException {
        try (BufferedReader br = new BufferedReader(new FileReader(path))) {
            return br.readLine();
        }
    }

    public static void main(String[] args) {
        // 方式二：调用方必须 try-catch
        try {
            String line = readFirstLine("data.txt");
            System.out.println(line);
        } catch (FileNotFoundException e) {      // 子类在前
            System.err.println("文件不存在: " + e.getMessage());
        } catch (IOException e) {               // 父类在后
            System.err.println("IO 错误: " + e.getMessage());
        }
    }
}
```

> 注意：`catch` 块的顺序必须**从子类到父类**，否则父类分支会拦截子类，编译器直接报错（"already caught"）。

### 4.2 非受检异常（Unchecked / RuntimeException）

编译器不检查，通常表示**编程错误**（空指针、数组越界、类型转换错误等）。这类异常应当通过**修正代码逻辑**来避免，而不是靠 `try-catch` 兜底。

```java
public class UncheckedDemo {
    public static void main(String[] args) {
        // 1. NullPointerException
        String s = null;
        // System.out.println(s.length());   // NPE

        // 2. ArrayIndexOutOfBoundsException
        int[] arr = {1, 2, 3};
        // System.out.println(arr[3]);       // 越界

        // 3. ArithmeticException
        // System.out.println(10 / 0);

        // 4. ClassCastException
        Object obj = "hello";
        // Integer i = (Integer) obj;

        // 5. NumberFormatException（IllegalArgumentException 子类）
        // int n = Integer.parseInt("abc");

        // 6. UnsupportedOperationException
        // List.of("a").add("b");
    }
}
```

**受检 vs 非受检的对比：**

| 特性 | 受检异常 | 非受检异常 |
|---|---|---|
| 基类 | `Exception`（不含 RuntimeException 分支） | `RuntimeException` |
| 编译期检查 | 必须捕获或声明 | 不检查 |
| 语义 | 外部可恢复的意外情况（IO、网络、DB） | 编程错误（逻辑缺陷） |
| 常见处理 | `try-catch` / `throws` | 修正代码，必要时在边界处兜底 |

## 五、异常处理语法详解

### 5.1 try-catch-finally

```java
public static int divide(int a, int b) {
    try {
        return a / b;
    } catch (ArithmeticException e) {
        System.err.println("除数不能为 0: " + e.getMessage());
        return 0;
    } finally {
        System.out.println("finally 一定会执行（除 System.exit / JVM 崩溃外）");
    }
}
```

**`finally` 的经典陷阱：**

```java
// 陷阱 1：finally 中 return 会吞掉异常
static int bad() {
    try {
        throw new RuntimeException("boom");
    } finally {
        return 1;   // 异常被丢弃，方法正常返回 1
    }
}

// 陷阱 2：finally 中修改返回值对基本类型无效
static int bad2() {
    int x = 1;
    try {
        return x;      // 返回的是 1 的副本
    } finally {
        x = 100;       // 修改无效
    }
}
```

> 规范建议：**不要**在 `finally` 中 `return`、`break`、`continue`，也不要抛异常。

### 5.2 多重 catch（Java 7+）

```java
try {
    riskyOperation();
} catch (IOException | SQLException | ClassNotFoundException e) {
    // 多异常合并，此时 e 隐式为 final，不能重新赋值
    log(e);
}
```

### 5.3 try-with-resources（Java 7+，推荐）

凡是实现了 `AutoCloseable` 的资源（流、连接、锁等），都可以自动关闭，且**关闭顺序与声明顺序相反**。

```java
public static String readAll(String path) throws IOException {
    try (BufferedReader br = new BufferedReader(new FileReader(path));
         StringWriter sw = new StringWriter()) {   // 后声明先关闭
        String line;
        while ((line = br.readLine()) != null) {
            sw.write(line);
        }
        return sw.toString();
    }   // 自动调用 sw.close() 再 br.close()
}
```

**Suppressed 异常的机制**：如果 `try` 块和 `close()` 同时抛异常，主异常会携带 close 抛出的异常（作为 suppressed），不会丢失。

```java
class MyResource implements AutoCloseable {
    private final String name;
    MyResource(String name) { this.name = name; }

    @Override
    public void close() {
        throw new RuntimeException("close 失败: " + name);
    }
}

public class SuppressedDemo {
    public static void main(String[] args) {
        try (MyResource r = new MyResource("R1")) {
            throw new IllegalStateException("业务异常");
        } catch (Exception e) {
            System.out.println("主异常: " + e.getMessage());
            for (Throwable s : e.getSuppressed()) {
                System.out.println("被抑制: " + s.getMessage());
            }
        }
    }
}
// 输出：
// 主异常: 业务异常
// 被抑制: close 失败: R1
```

## 六、自定义异常

### 6.1 受检自定义异常

```java
public class InsufficientBalanceException extends Exception {
    private final double balance;
    private final double amount;

    public InsufficientBalanceException(double balance, double amount) {
        super(String.format("余额不足：余额 %.2f，需支付 %.2f", balance, amount));
        this.balance = balance;
        this.amount = amount;
    }

    public double getBalance() { return balance; }
    public double getAmount()  { return amount; }
}
```

```java
public class Account {
    private double balance;

    public void withdraw(double amount) throws InsufficientBalanceException {
        if (amount > balance) {
            throw new InsufficientBalanceException(balance, amount);
        }
        balance -= amount;
    }
}
```

### 6.2 非受检自定义异常（业务异常最常见写法）

```java
public class BusinessException extends RuntimeException {
    private final int code;

    public BusinessException(int code, String message) {
        super(message);
        this.code = code;
    }

    // 保留 cause，用于异常链
    public BusinessException(int code, String message, Throwable cause) {
        super(message, cause);
        this.code = code;
    }

    public int getCode() { return code; }
}
```

**自定义异常的原则：**
1. 名字要能自解释（`OrderNotFoundException` 而不是 `MyException`）。
2. 至少提供 `(String message)`、`(String message, Throwable cause)` 两个构造器。
3. 继承 `RuntimeException` 还是 `Exception` 取决于语义：**调用方必须处理才能继续的 → 受检；编程错误或不可恢复的业务规则 → 非受检**。

## 七、异常链（Exception Chaining）

底层异常不应该被简单丢弃，而应包装成上层业务异常并保留 `cause`，这样堆栈里能看到完整调用链路。

```java
public class UserService {

    public User loadUser(long id) {
        try {
            return userDao.findById(id);         // 可能抛 SQLException
        } catch (SQLException e) {
            // 保留原始异常，形成异常链
            throw new BusinessException(5001, "加载用户失败, id=" + id, e);
        }
    }
}
```

打印时：

```java
try {
    service.loadUser(1L);
} catch (BusinessException e) {
    e.printStackTrace();
    // Caused by: java.sql.SQLException: connection refused
}
```

> 常见错误做法：`catch (SQLException e) { throw new BusinessException(5001, "失败"); }` —— 丢失了 cause，排查问题时会很难受。正确写法是传 `e` 作为构造参数。

## 八、常见异常速查表

| 异常 | 类型 | 触发原因 |
|---|---|---|
| `NullPointerException` | 非受检 | 对 `null` 调用方法/访问字段 |
| `ArrayIndexOutOfBoundsException` | 非受检 | 数组下标越界 |
| `StringIndexOutOfBoundsException` | 非受检 | 字符串索引越界 |
| `ClassCastException` | 非受检 | 强制类型转换失败 |
| `NumberFormatException` | 非受检 | 字符串解析数字失败 |
| `ArithmeticException` | 非受检 | 整数除以 0 |
| `IllegalArgumentException` | 非受检 | 方法参数非法 |
| `IllegalStateException` | 非受检 | 对象状态不允许该操作 |
| `UnsupportedOperationException` | 非受检 | 不可变集合调用 `add` 等 |
| `ConcurrentModificationException` | 非受检 | 迭代中修改集合 |
| `IOException` / `FileNotFoundException` | 受检 | IO 失败 |
| `SQLException` | 受检 | 数据库访问失败 |
| `ClassNotFoundException` | 受检 | 类加载失败 |
| `InterruptedException` | 受检 | 线程被中断 |
| `OutOfMemoryError` | Error | 内存不足 |
| `StackOverflowError` | Error | 栈深度超限 |

## 九、最佳实践总结

1. **不要吞异常**：`catch (Exception e) {}` 是最糟糕的写法，至少 log 或重新抛出。
2. **不要用异常控制流程**：正常分支不应依赖异常实现（性能差、语义差）。
3. **尽早抛出，尽早失败（Fail Fast）**：参数校验用 `Objects.requireNonNull`、`IllegalArgumentException`。
4. **保持异常链**：包装时务必传入 `cause`。
5. **捕获具体异常而非 `Exception`**，避免捕获 `Throwable`/`Error`。
6. **`finally` 中只做资源清理**，不 `return`、不抛异常。
7. **优先使用 try-with-resources**，避免手写 `finally { try { close(); } catch ... }`。
8. **业务异常收敛到统一出口**：Spring 中通过 `@ExceptionHandler` / `@ControllerAdvice` 全局处理，减少散落的 try-catch。
9. **异常信息要包含关键上下文**：如 `"用户 123 下单失败, orderId=456"`，而不是笼统的 `"失败"`。
10. **`printStackTrace()` 只用于调试**，生产代码用日志框架（SLF4J）并带上异常对象：`log.error("加载失败", e)`。
