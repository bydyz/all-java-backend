`DataInputStream` 是 Java I/O 体系中用于**读取二进制原始数据类型**的核心装饰器类。它的设计目标与 `DataOutputStream` 严格对称：后者写入的基本类型数据，前者能够以**与机器无关**的方式准确还原。这种机器无关性，以及它所依赖的**大端序**字节排列约定，构成了跨平台二进制协议的基础。

---

## 功能定位

`DataInputStream` 继承自 `FilterInputStream`，实现了 `DataInput` 接口。它本身不直接持有数据源，而是“包装”另一个底层输入流（如 `FileInputStream`、`Socket.getInputStream()`），将底层流提供的原始字节按照 Java 基本类型的宽度和编码规则重新解释。

它的核心功能可以概括为：

- **将字节流解释为 Java 基本类型**：`int`、`long`、`short`、`byte`、`float`、`double`、`char`、`boolean`；
- **读取字符串**：`readUTF()` 按照 **Modified UTF-8** 格式解码字符串；
- **精确填充字节数组**：`readFully()` 保证读满指定长度，或抛出 `EOFException`；
- **跳过字节**：`skipBytes()` 向前跳过指定数量。

由于它依赖底层流的状态，**`DataInputStream` 本身不是线程安全的**，多线程访问时需要外部同步或为每个线程使用独立实例。

---

## 构造器

`DataInputStream` 只有一个公开构造器：

```java
public DataInputStream(InputStream in)
```

参数 `in` 是底层输入流。构造器本身只做一件事：将 `in` 保存为被装饰的流。所有读取操作最终都委托给这个底层流。

典型用法是与缓冲流组合，以减少系统调用：

```java
DataInputStream dis = new DataInputStream(
    new BufferedInputStream(
        new FileInputStream("data.bin")
    )
);
```

---

## 核心 API 详解

### 读取基本类型

`DataInputStream` 为每种基本类型提供了对应的读取方法。它们共同遵循两条规则：

1. **字节宽度固定**：如 `readInt()` 始终读取 4 字节，`readLong()` 读取 8 字节；
2. **字节序为大端序**：高位字节在前，低位字节在后。

| 方法 | 读取字节数 | 返回类型 |
|---|---|---|
| `readBoolean()` | 1 | `boolean` |
| `readByte()` | 1 | `byte` |
| `readUnsignedByte()` | 1 | `int`（0–255） |
| `readShort()` | 2 | `short` |
| `readUnsignedShort()` | 2 | `int`（0–65535） |
| `readChar()` | 2 | `char` |
| `readInt()` | 4 | `int` |
| `readLong()` | 8 | `long` |
| `readFloat()` | 4 | `float` |
| `readDouble()` | 8 | `double` |

```java
try (DataInputStream dis = new DataInputStream(
        new FileInputStream("primitives.dat"))) {
    boolean flag = dis.readBoolean();
    byte b      = dis.readByte();
    char c      = dis.readChar();
    int i       = dis.readInt();
    long l      = dis.readLong();
    float f     = dis.readFloat();
    double d    = dis.readDouble();
    int ub      = dis.readUnsignedByte();   // 无符号扩展为 int
    int us      = dis.readUnsignedShort();  // 无符号扩展为 int
}
```

> **无符号方法的意义**：当底层二进制格式使用无符号 `byte` 或 `short` 时（如某些网络协议头字段），`readUnsignedByte()` 返回 `int`，值域为 0–255，避免了 `byte` 符号扩展带来的负数问题。

---

### `readFully()`：精确填充

普通的 `InputStream.read(byte[])` 可能只读取部分字节就返回。`readFully()` 的语义不同：**它会阻塞，直到读满指定数量，或在未读满前遇到流末尾而抛出 `EOFException`**。

```java
byte[] header = new byte[16];
dis.readFully(header);              // 读满 16 字节，否则 EOFException

byte[] body = new byte[1024];
dis.readFully(body, 128, 512);      // 从 body[128] 开始填充 512 字节
```

这个特性使它成为读取**固定长度协议头**或**长度已知的负载**的首选方法。典型的“长度前缀”模式如下：

```java
int length = dis.readInt();          // 先读 4 字节长度
byte[] payload = new byte[length];
dis.readFully(payload);              // 再精确读满负载
```

> **注意**：`readFully()` 在流数据不足时会**一直阻塞**，直到数据到齐或流关闭抛出异常。在交互式网络场景中使用时需要确认对端一定会发送足量数据。

---

### `skipBytes(int n)`：跳过字节

`skipBytes(int n)` 尝试向前跳过 `n` 个字节，返回**实际跳过的字节数**。如果提前到达流末尾，实际跳过数可能小于 `n`，但不会抛出 `EOFException`（这一点与 `readFully` 不同）。

```java
int skipped = dis.skipBytes(50);
System.out.println("实际跳过: " + skipped);  // 接近末尾时可能 < 50
```

---

### `readUTF()`：读取字符串

`readUTF()` 读取的是由 `DataOutputStream.writeUTF()` 写入的字符串，编码格式为 **Modified UTF-8**。它的结构是：

1. 先读 **2 字节无符号 short**，表示后续字节数据的长度 `utflen`；
2. 再调用 `readFully()` 一次性读入 `utflen` 字节；
3. 按 Modified UTF-8 规则解码为 `String`。

```java
String str1 = dis.readUTF();
String str2 = dis.readUTF();
```

Modified UTF-8 与标准 UTF-8 的关键差异在于：**空字符 `\u0000` 被编码为 2 字节（`C0 80`），而不是标准 UTF-8 的 1 字节（`00`）** 。因此，`readUTF()` 不能用于读取普通 UTF-8 文本文件；读取普通文本应使用 `InputStreamReader` 配合 `BufferedReader`。

---

### 关于 `readLine()`：已废弃

`DataInputStream.readLine()` 在 JDK 1.1 中已被标记为 `@Deprecated`，原因是它**不能正确地在字节和字符之间进行转换**。读取文本行的需求应改用 `BufferedReader.readLine()`。

---

## 关键原理与使用注意事项

### 大端序

Java 的 `DataInputStream` / `DataOutputStream` 对所有多字节基本类型统一采用**大端序**。这意味着 `readInt()` 读到的 4 个字节中，第一个字节被放置到结果的最高有效字节位置。如果与 C/C++ 程序或某些使用小端序的硬件交互，需要注意字节序的转换。

### `EOFException` 的含义

当试图读取完整的基本类型（如 4 字节的 `int`）但流中剩余字节不足时，`DataInputStream` 抛出 `EOFException`。例如，流中只剩 3 字节时调用 `readInt()`，会抛出 `EOFException`；而普通的 `read()` 在流末尾只会返回 `-1`，不会抛出异常。在循环读取的场景中，捕获 `EOFException` 通常被用作“数据已读完”的信号。

### 必须与 `DataOutputStream` 的写入顺序严格对应

`DataInputStream` 本身不携带字段边界信息。如果写入时依次写入了 `int`、`String`、`double`，读取时就必须以**完全相同的顺序**调用 `readInt()`、`readUTF()`、`readDouble()`。任何顺序错位都会导致后续解析全部错乱。

### 推荐配合缓冲流使用

`DataInputStream` 的读取方法往往一次只向底层流请求少量字节（如 `readInt()` 请求 4 字节）。如果底层是未经缓冲的 `FileInputStream` 或网络流，频繁的小量系统调用会显著影响性能。推荐用 `BufferedInputStream` 包装底层流后再交给 `DataInputStream`。

## 完整示例：与 `DataOutputStream` 配对使用

下面的示例演示了写入与读取的严格对称性，以及 `readFully` 处理变长字节数组的标准模式。

```java
import java.io.*;

public class DataStreamDemo {

    public static void main(String[] args) throws IOException {
        File file = new File("demo.bin");

        // ---- 写入端 ----
        try (DataOutputStream dos = new DataOutputStream(
                new BufferedOutputStream(new FileOutputStream(file)))) {
            dos.writeInt(2026);                    // 4 字节
            dos.writeUTF("DataInputStream Demo");  // 长度前缀 + Modified UTF-8
            byte[] payload = {0x01, 0x02, 0x03};
            dos.writeInt(payload.length);           // 先写长度
            dos.write(payload);                     // 再写数据
        }

        // ---- 读取端 ----
        try (DataInputStream dis = new DataInputStream(
                new BufferedInputStream(new FileInputStream(file)))) {
            int year = dis.readInt();
            String title = dis.readUTF();
            int len = dis.readInt();
            byte[] data = new byte[len];
            dis.readFully(data);                    // 精确读满

            System.out.println("year = " + year);
            System.out.println("title = " + title);
            System.out.println("data length = " + data.length);
        }
    }
}
```

这个模式的核心是：**写入端先写长度，读取端先读长度再 `readFully`**，从而在不依赖分隔符的情况下安全地传输任意长度的字节数组。
