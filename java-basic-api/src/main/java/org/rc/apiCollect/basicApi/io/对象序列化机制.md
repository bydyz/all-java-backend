# Java 对象序列化机制详解

## 一、概念

**序列化（Serialization）**：把 JVM 堆中的对象状态转换为字节流，以便持久化到文件、数据库或通过网络传输。
**反序列化（Deserialization）**：把字节流还原为内存中的对象。

Java 原生序列化由 `java.io.Serializable` 标记接口、`ObjectOutputStream` / `ObjectInputStream` 共同实现。

---

## 二、最基础的用法

```java
public class Person implements Serializable {
    private static final long serialVersionUID = 1L;   // 强烈建议显式声明

    private String name;
    private int age;
    private transient String password;                 // 不参与序列化

    public Person(String name, int age, String password) {
        this.name = name;
        this.age = age;
        this.password = password;
    }
    // getter/setter 省略
}

public class Demo {
    public static void main(String[] args) throws Exception {
        Person p = new Person("张三", 20, "secret");

        // 序列化
        try (ObjectOutputStream oos =
                     new ObjectOutputStream(new FileOutputStream("person.ser"))) {
            oos.writeObject(p);
        }

        // 反序列化
        try (ObjectInputStream ois =
                     new ObjectInputStream(new FileInputStream("person.ser"))) {
            Person p2 = (Person) ois.readObject();
            System.out.println(p2.getName() + ", " + p2.getAge() + ", " + p2.getPassword());
            // 输出: 张三, 20, null
        }
    }
}
```

注意：`password` 被 `transient` 修饰，反序列化后为 `null`（引用类型）或 `0/false`（基本类型）。

## 三、核心机制

### 1. Serializable 是标记接口

它没有任何方法，仅用于**在运行时告知序列化框架"这个类可以被序列化"**。若类未实现该接口却试图序列化，会抛出 `NotSerializableException`。

### 2. 反序列化**不会调用构造器**

对于实现了 `Serializable` 的类，反序列化时对象由 `ObjectStreamClass` 借助 `ReflectionFactory`/`Unsafe` 直接分配，**构造函数、`static` 初始化块都不会被执行**（下面"父类构造器"是例外）。

```java
public class Foo implements Serializable {
    public Foo() { System.out.println("构造器被调用"); }
}
// 反序列化 Foo 时不会打印任何内容
```

这也是为什么"构造函数里做校验"的类在反序列化时能绕过校验——安全问题的一大来源。

### 3. serialVersionUID 与版本兼容

反序列化时 JVM 会比较流中记录的 `serialVersionUID` 和本地类的 `serialVersionUID`，不一致会抛 `InvalidClassException`。

- **不显式声明**：编译器会根据类名、修饰符、接口、字段、方法、构造器签名计算一个 64 位哈希。类结构稍微一改（哪怕是加一个方法），值就变，旧数据就反序列化失败。
- **显式声明**：只要字段增减是兼容的（例如新增字段），仍能读旧流；新字段取默认值。

```java
// 版本 1
public class User implements Serializable {
    private static final long serialVersionUID = 1L;
    private String name;
}

// 版本 2：新增字段，serialVersionUID 不变 → 能读旧流，age 为 0
public class User implements Serializable {
    private static final long serialVersionUID = 1L;
    private String name;
    private int age;
}
```

### 4. 序列化是**深度遍历**的（对象图）

序列化会沿引用递归处理所有字段；同一个对象在流中**只出现一次**，后续出现用"引用"（`TC_REFERENCE`）表示，因此：

- 循环引用不会死循环；
- 对象图结构（共享引用）会被完整保留。

```java
class Node implements Serializable {
    String name;
    Node next;
}

Node a = new Node(); a.name = "A";
Node b = new Node(); b.name = "B";
a.next = b; b.next = a;      // 环形引用
// 序列化 a 完全没问题；反序列化后 a.next.next == a 仍然成立
```

### 5. 静态字段不参与序列化

序列化的是**实例状态**。`static` 字段属于类，不属于对象，因此不会被写入流中；`transient` 字段也被跳过。

```java
class Counter implements Serializable {
    static int count = 100;   // 不序列化
    transient int cache = 5;  // 不序列化
    int value = 1;            // 序列化
}
```

注意：`static final long serialVersionUID` 本身也是 static，但它会被特殊处理写入类描述中。

### 6. 序列化流格式（简要）

`ObjectOutputStream` 写出的字节流以固定魔术头开始：

```
AC ED 00 05
```

- `AC ED`：`STREAM_MAGIC`，标识 Java 序列化流
- `00 05`：`STREAM_VERSION`（协议版本 5）

之后是 `TC_OBJECT(0x73)`、`TC_CLASSDESC(0x72)`、`TC_STRING`、`TC_REFERENCE` 等标记，以及字段名、类型、值。可以通过 `hexdump person.ser` 观察。

## 四、继承关系的处理

### 1. 父类可序列化 → 正常

```java
class Parent implements Serializable { int a = 1; }
class Child extends Parent { int b = 2; }
// 二者字段都会被序列化
```

### 2. 父类**不可**序列化 → 父类字段丢失，且反序列化会调用父类**无参构造器**

```java
class Parent {                       // 没有 implements Serializable
    protected int a = 1;
    public Parent() {
        System.out.println("Parent() 被调用");
    }
}

class Child extends Parent implements Serializable {
    private static final long serialVersionUID = 1L;
    int b = 2;
}
```

- 序列化 `Child` 时**只写 `b`**，`a` 不会被写入；
- 反序列化时**会调用 `Parent` 的无参构造器**（这是"反序列化不调用构造器"的唯一例外）；
- 如果 `Parent` 没有无参构造器 → `InvalidClassException: no valid constructor`。

**实践建议**：可序列化的类，其所有祖先类要么也实现 `Serializable`，要么提供一个可访问的无参构造器。

## 五、自定义序列化行为

### 1. `writeObject` / `readObject`（推荐方式）

在类中声明**私有**的 `writeObject` / `readObject` 方法，`ObjectOutputStream` 会通过反射调用它们：

```java
public class Account implements Serializable {
    private static final long serialVersionUID = 1L;

    private String user;
    private transient String password;

    public Account(String user, String password) {
        this.user = user;
        this.password = password;
    }

    private void writeObject(ObjectOutputStream out) throws IOException {
        out.defaultWriteObject();                 // 先按默认机制写非 transient 字段
        out.writeObject(encrypt(password));       // 再写加密后的密码
    }

    private void readObject(ObjectInputStream in)
            throws IOException, ClassNotFoundException {
        in.defaultReadObject();                   // 读默认字段
        this.password = decrypt((String) in.readObject());
    }

    private String encrypt(String s) { return "ENC(" + s + ")"; }
    private String decrypt(String s) { return s.substring(4, s.length() - 1); }
}
```

关键点：
- 方法签名必须严格为 `private void writeObject(ObjectOutputStream)` / `private void readObject(ObjectInputStream)`；
- 不要调用 `out.defaultWriteObject()` 就表示**放弃默认机制**，字段需要自己逐个写出；
- 这是 JDK 集合类的标准做法：`ArrayList` 把 `elementData` 声明为 `transient`，自己按实际 `size` 写出，避免序列化未使用的空闲槽位。

```java
// ArrayList 内部（简化）
private transient Object[] elementData;
private void writeObject(ObjectOutputStream s) throws IOException {
    s.defaultWriteObject();
    s.writeInt(size);
    for (int i = 0; i < size; i++) s.writeObject(elementData[i]);
}
```

### 2. `writeReplace` / `readResolve`

- `writeReplace`：在真正序列化前把对象**替换**为另一个对象；
- `readResolve`：反序列化返回前把对象**替换**为另一个对象。

#### 单例被破坏的经典问题

```java
public class Singleton implements Serializable {
    public static final Singleton INSTANCE = new Singleton();
    private Singleton() {}
}

// 反序列化会得到一个新对象，破坏单例
Singleton s = (Singleton) ois.readObject();
System.out.println(s == Singleton.INSTANCE);   // false
```

修复方式：

```java
public class Singleton implements Serializable {
    private static final long serialVersionUID = 1L;
    public static final Singleton INSTANCE = new Singleton();
    private Singleton() {}

    private Object readResolve() {          // 反射调用
        return INSTANCE;
    }
}
```

#### 枚举天然防破坏

```java
public enum Color { RED, GREEN }
```

JVM 保证枚举的反序列化返回原实例，且 `readObject` 等方法无法通过反射绕过——这就是《Effective Java》推荐"用枚举实现单例"的原因。

### 3. Externalizable：完全自行控制

```java
public class Point implements Externalizable {
    private int x, y;

    public Point() {}                        // 必须 public 无参构造器

    public Point(int x, int y) { this.x = x; this.y = y; }

    @Override
    public void writeExternal(ObjectOutput out) throws IOException {
        out.writeInt(x);
        out.writeInt(y);
    }

    @Override
    public void readExternal(ObjectInput in) throws IOException {
        this.x = in.readInt();
        this.y = in.readInt();
    }
}
```

| 对比 | Serializable | Externalizable |
|------|--------------|----------------|
| 是否需要方法 | 不需要（标记接口） | 必须实现 `writeExternal`/`readExternal` |
| 字段处理 | 默认自动 | 完全由你决定 |
| 无参构造器 | 非必需 | **必须 public 无参构造器** |
| 反序列化时构造器 | 不调用 | **会调用** public 无参构造器 |
| 效率 | 一般 | 略好（只写你关心的字段） |

### 4. `serialPersistentFields`

可以显式指定"参与序列化的字段集合"，与 `writeObject` 一起用可以做到**字段名与流中的名称解耦**：

```java
private static final ObjectStreamField[] serialPersistentFields = {
    new ObjectStreamField("username", String.class)
};
```

### 5. 序列化代理模式（Effective Java 推荐）

用一个嵌套的 `static` 类作为"代理"，由 `writeReplace` 生成、`readResolve` 还原，隔离不可信数据：

```java
public final class Period implements Serializable {
    private static final long serialVersionUID = 1L;
    private final Date start, end;

    public Period(Date start, Date end) {
        if (start.after(end)) throw new IllegalArgumentException();
        this.start = start; this.end = end;
    }

    private Object writeReplace() {
        return new SerializationProxy(this);
    }

    private void readObject(ObjectInputStream in) throws InvalidObjectException {
        throw new InvalidObjectException("请使用序列化代理");
    }

    private static class SerializationProxy implements Serializable {
        private static final long serialVersionUID = 1L;
        private final Date start, end;
        SerializationProxy(Period p) { this.start = p.start; this.end = p.end; }
        private Object readResolve() { return new Period(start, end); }  // 走正规构造器，恢复约束
    }
}
```

优点：反序列化必须经过构造器，天然恢复不变式；防止字段伪造。

## 六、常见坑与安全问题

### 1. 反序列化漏洞（最严重）

攻击者可以构造恶意字节流，触发目标类中 `readObject` 的副作用（如 `Runtime.exec`），形成 **gadget chain**。历史上大量的 RCE 漏洞（Commons Collections、Fastjson、WebLogic 等）都源于此。

**防御手段（Java 9+）：`ObjectInputFilter`（JEP 290）**

```java
ObjectInputStream ois = new ObjectInputStream(fis);
ois.setObjectInputFilter(info -> {
    Class<?> c = info.serialClass();
    if (c == null) return ObjectInputFilter.Status.UNDECIDED;
    return c.getName().startsWith("com.example.myapp.")
            ? ObjectInputFilter.Status.ALLOWED
            : ObjectInputFilter.Status.REJECTED;
});
```

也可以通过系统属性全局配置：

```bash
-Djdk.serialFilter=com.example.myapp.**;!*
```

Java 17（JEP 415）允许注册多个"上下文相关"过滤器；Java 21 起 `jdk.serialFilter` 的默认行为更严格。

### 2. 深拷贝 ≠ 序列化

有人用"序列化→反序列化"实现深拷贝，这能工作，但性能极差且必须保证所有字段可序列化。日常应优先用复制构造器、`clone` 或专门的映射工具。

### 3. transient + final 的陷阱

`transient final` 字段在反序列化后无法重新赋值（`final` 由反射的 `setAccessible` 在某些 JDK 版本上才能改），因此**不要**对需要恢复的字段同时使用 `transient final`。

### 4. 非静态内部类会拖家带口

非静态内部类隐含持有外部类 `this$0` 引用，序列化内部类时**外部类也会被序列化**（若外部类不可序列化则直接失败）。需要序列化时请用 `static` 嵌套类。

### 5. 性能与体积

原生序列化：
- 二进制体积大（含大量类描述元数据）；
- 速度慢（反射 + 深度遍历）；
- 语言绑定，不跨语言。

因此现代分布式系统多用 **JSON（Jackson/Gson）、Protobuf、Avro、Thrift、Kryo** 等。原生序列化主要用于：
- 本地对象缓存；
- 少量 RMI / 进程间通信；
- 需要保留对象图、多态、循环引用的场景。

### 6. `record` 的序列化（Java 16+）

`record` 有专门的序列化机制：序列化时只写组件的值，反序列化时**必须经过规范构造器**，因此天然满足不变式；`writeObject` / `readObject` 中若调用 `defaultWriteObject` 会被忽略。

```java
record Point(int x, int y) implements Serializable {}   // 只需这样
```

## 七、要点速查表

| 主题 | 结论 |
|------|------|
| 标记接口 | `Serializable`，无方法 |
| 反序列化是否调用构造器 | 默认**不调用**；首个不可序列化的父类会调用其无参构造器；`Externalizable` 会调用 public 无参构造器 |
| `static` 字段 | 不参与序列化 |
| `transient` 字段 | 不参与序列化，反序列化取默认值 |
| `serialVersionUID` | 强烈建议显式声明，否则类结构改变即不兼容 |
| 引用/环 | 自动处理（handle 机制），共享引用被保留 |
| 自定义读写 | 私有 `writeObject` / `readObject`（配合 `defaultWriteObject`） |
| 对象替换 | `writeReplace`（写前）/ `readResolve`（读后） |
| 完全自定义 | `Externalizable` |
| 单例保护 | `readResolve`，或直接用 `enum` |
| 安全 | `ObjectInputFilter` / `jdk.serialFilter`，或改用 JSON/Protobuf |
| 现代替代 | Protobuf、Jackson、Kryo、Avro 等 |

## 八、完整可运行示例（综合演示）

```java
import java.io.*;

public class SerializationDemo {

    static class User implements Serializable {
        private static final long serialVersionUID = 1L;

        private String name;
        private transient String password;
        private static int population = 0;   // 不序列化

        User(String name, String password) {
            this.name = name;
            this.password = password;
            population++;
        }

        private void writeObject(ObjectOutputStream out) throws IOException {
            out.defaultWriteObject();
            out.writeObject("ENC:" + password);
        }

        private void readObject(ObjectInputStream in)
                throws IOException, ClassNotFoundException {
            in.defaultReadObject();
            String enc = (String) in.readObject();
            this.password = enc.substring(4);
        }

        @Override
        public String toString() {
            return "User{name='" + name + "', password='" + password + "'}";
        }
    }

    public static void main(String[] args) throws Exception {
        File f = new File("user.ser");

        try (ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream(f))) {
            oos.writeObject(new User("张三", "secret"));
        }

        try (ObjectInputStream ois = new ObjectInputStream(new FileInputStream(f))) {
            System.out.println(ois.readObject());   // User{name='张三', password='secret'}
        }

        System.out.println("population = " + User.population);  // 静态字段未被恢复
    }
}
```

这个例子同时演示了：`Serializable`、`serialVersionUID`、`transient`、静态字段、`writeObject`/`readObject` 自定义编解码、`defaultWriteObject` 的用法。
