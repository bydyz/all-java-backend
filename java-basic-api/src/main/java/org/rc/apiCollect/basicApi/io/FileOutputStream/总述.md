`java.io.FileOutputStream` 是Java I/O体系中用于将**原始字节流**写入文件的基石类。它继承自 `OutputStream`，专注于处理像图像数据这样的二进制文件，而非字符数据（字符数据应使用 `FileWriter`）。

### 🎯 核心功能与定位

- **写入原始字节**：它的核心职责是将内存中的字节数据写入到文件的输出流中。当你需要写入图片、音频或任何非文本格式的二进制数据时，它就是正确的选择。
- **文件管理**：根据构造时的设置，它能够创建新文件、覆盖已有文件或在文件末尾追加内容。
- **非线程安全**：该类本身不保证线程安全，多线程并发写入同一个 `FileOutputStream` 实例时需要额外的同步措施。

---

### 🏗️ 构造器详解

`FileOutputStream` 提供了多种构造器，以适应不同的文件定位方式和写入模式。所有构造器在无法打开文件时都会抛出 `FileNotFoundException`。

| 构造器签名 | 描述 | 关键点 |
| :--- | :--- | :--- |
| `FileOutputStream(String name)` | 通过文件路径字符串创建流。 | **默认覆盖模式**。如果文件已存在，其内容将被清空。如果文件不存在，则自动创建。父目录必须存在。 |
| `FileOutputStream(String name, boolean append)` | 通过文件路径字符串创建流，并可指定**追加模式**。 | `append = true` 时，数据写入文件末尾；`append = false` 时，效果同默认覆盖模式。 |
| `FileOutputStream(File file)` | 通过 `File` 对象创建流。 | 行为与 `FileOutputStream(String)` 相同。 |
| `FileOutputStream(File file, boolean append)` | 通过 `File` 对象创建流，并支持追加模式。 | 便于与 `java.io.File` 相关的文件操作API集成。 |
| `FileOutputStream(FileDescriptor fdObj)` | 通过已存在的**文件描述符**创建流。 | 用于包装一个底层已经打开的文件连接，常见于系统级或框架编程。 |

> **💡 补充说明**：当追加模式开启（`append=true`）时，写入操作始终从文件末尾开始，**无法中途指定偏移量进行覆盖**。如果你需要随机访问文件的不同位置，应该使用 `RandomAccessFile` 类。

### ⚙️ 核心API与使用方法

`FileOutputStream` 的核心方法主要来自其父类 `OutputStream`，并重写了关键的 `write` 方法。

#### 1. 数据写入：`write()` 方法族

这是 `FileOutputStream` 最核心的功能，提供了三种重载形式。

- **`void write(int b)`**：写入单个字节。参数 `int` 仅其**最低8位**会被写入，高24位被忽略。例如，写入 `97`，文件中会存入字符 `'a'`（ASCII码）。
  ```java
  try (FileOutputStream fos = new FileOutputStream("single-byte.txt")) {
      fos.write(65); // 写入 ASCII 'A'
      fos.write(66); // 写入 ASCII 'B'
  } catch (IOException e) {
      e.printStackTrace();
  }
  ```

- **`void write(byte[] b)`**：将整个字节数组写入文件。这是**效率最高**的批量写入方式，因为它减少了底层系统调用次数。
  ```java
  byte[] data = "Hello, FileOutputStream!".getBytes(StandardCharsets.UTF_8);
  try (FileOutputStream fos = new FileOutputStream("bulk-data.txt")) {
      fos.write(data); // 一次性写入整个数组
  } catch (IOException e) {
      e.printStackTrace();
  }
  ```

- **`void write(byte[] b, int off, int len)`**：写入字节数组的指定部分。`off` 是起始索引，`len` 是要写入的字节数。这在处理大数据块并只想写入其中一部分时非常有用。
  ```java
  byte[] source = {10, 20, 30, 40, 50, 60};
  try (FileOutputStream fos = new FileOutputStream("partial-data.txt")) {
      // 从索引 1 (值20) 开始，写入 3 个字节: 20, 30, 40
      fos.write(source, 1, 3);
  } catch (IOException e) {
      e.printStackTrace();
  }
  ```

#### 2. 资源管理：`close()`

`close()` 方法用于关闭流并释放其占用的系统资源（如文件句柄）。**这是一个必须执行的操作**。未关闭的流会导致资源泄漏，并可能使文件在操作系统层面被锁定，无法被其他程序访问。

**最佳实践是使用 `try-with-resources` 语句**，它能确保在代码块结束时自动调用 `close()`，即使在写入过程中发生异常。
```java
// 推荐：try-with-resources 自动关闭
try (FileOutputStream fos = new FileOutputStream("auto-close.txt")) {
    fos.write("data".getBytes());
} // 在这里，fos.close() 会被自动调用
```

#### 3. 刷新与持久化：`flush()`, `getFD().sync()`

- **`void flush()`**：清空输出流中可能存在的缓冲区，并强制将任何缓冲的字节写出。`FileOutputStream` 本身通常是无缓冲的，但当你将其包装在 `BufferedOutputStream` 中时，`flush()` 就变得至关重要，它能确保数据被传递到 `FileOutputStream` 进而写入操作系统。
- **`FileDescriptor getFD()` 与 `sync()`**：`getFD()` 返回与此流关联的 `FileDescriptor` 对象。其 `sync()` 方法（`fos.getFD().sync()`）会强制将**操作系统内核缓冲区**中的数据**同步到物理存储设备**上，这对于需要确保数据在系统崩溃时也不丢失的场景（如数据库事务日志）至关重要。一次完整的持久化流程通常是：`write()` → `flush()` → `getFD().sync()` → `close()`。

#### 4. 其他方法

- **`FileChannel getChannel()`**：返回与此文件输出流关联的 `FileChannel` 对象，可用于进行更高级的通道操作（如 `transferTo/From`, 内存映射等）。

---

### 💎 总结

`FileOutputStream` 是Java进行字节级文件写入的核心。掌握其要点在于：
1.  **明确构造器选择**：根据是否需要**追加**，以及使用**路径**还是**`File`对象**来选择合适的构造器。
2.  **正确使用`write`方法**：优先使用 `byte[]` 进行批量写入以获得最佳性能。
3.  **坚守资源释放原则**：始终使用 `try-with-resources` 来保证 `close()` 被调用，避免资源泄漏。
4.  **理解持久化层次**：在需要更高数据安全性时，了解 `flush()` 和 `getFD().sync()` 的作用与区别。
