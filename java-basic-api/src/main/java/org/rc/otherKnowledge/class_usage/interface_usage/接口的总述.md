# Java 接口（interface）全面详解

接口就是规范，定义的是一组规则，体现了现实世界中“如果你是/要...则必须能...”的思想。继承是一个"是不是"的 is-a
关系，而接口实现则是 "能不能"的

接口的本质是契约、标准、规范，就像我们的法律一样。制定好后大家都要遵守。

接口是 Java 中实现**抽象**与**多实现**的核心机制。Java 8 引入 `default`/`static` 方法，Java 9 引入 `private`
方法后，接口的成员类型和冲突规则都变得更丰富。下面按“语法 → 成员 → 使用规则 → 冲突”四部分展开，每部分都配可运行示例。

---

## 一、语法格式

```java
[访问修饰符] interface 接口名 [extends 父接口1, 父接口2, ...] {
    // 公共的静态常量
    // 公共的抽象方法
    // 公共的default 方法
    // 公共的static 方法
    // private 方法（Java 9+）
    // 嵌套类型
}
```

规则要点：

- 顶层接口的访问修饰符只能是 `public` 或包私有（缺省）。
- `abstract` 可写但冗余；不能写 `final`（接口就是用来被实现的）；`sealed`/`non-sealed` 是 Java 17 的新特性。
- 接口可以 `extends` **多个**接口，但不能 `extends` 类。
- 接口**没有构造器**，不能被 `new` 实例化。

```java
public interface Flyable extends Comparable<Flyable>, java.io.Serializable {
    // ...
}
```

## 二、成员说明

| 成员           | 隐式修饰符                 | 说明                      |
|--------------|-----------------------|-------------------------|
| 字段（常量）       | `public static final` | 必须显式初始化，不能是空白 final     |
| 抽象方法         | `public abstract`     | 无方法体                    |
| `default` 方法 | `public`              | Java 8+，有方法体，可被实现类继承/覆盖 |
| `static` 方法  | `public`              | Java 8+，属于接口本身，**不被继承** |
| `private` 方法 | `private`             | Java 9+，必须有方法体，仅接口内部可用  |
| 嵌套类型         | `public static`       | 类 / 接口 / 枚举 / 注解        |

* 公共的默认的方法：其中 public 可以省略，建议保留，但是 default 不能省略
* 公共的静态的方法：其中 public 可以省略，建议保留，但是 static 不能省略
* 接口中没有构造器，没有初始化块，因为接口中没有成员变量需要动态初始化。

### 2.1 综合示例

```java
public interface Animal {

    // 1. 常量：隐式 public static final
    int MAX_AGE = 100;
    String CATEGORY = "ANIMAL";

    // 2. 抽象方法：隐式 public abstract
    void eat(String food);
    String name();

    // 3. default 方法：Java 8，有方法体
    default void sleep() {
        log("sleep");                        // 调用 private 方法
        System.out.println(name() + " 正在睡觉");
    }

    // 4. static 方法：Java 8，只能通过 Animal.isAlive() 调用
    static boolean isAlive(int age) {
        return age < MAX_AGE;
    }

    // 5. private 方法：Java 9，只能在本接口内部使用
    private void log(String action) {
        System.out.println("[LOG] " + action);
    }
    private static void staticLog(String msg) {
        System.out.println("[LOG-STATIC] " + msg);
    }

    // 6. 嵌套类型：隐式 public static
    enum Species { DOG, CAT }
    interface Tag { String code(); }
}
```

### 2.2 几个容易忽略的约束

```java
interface Bad {
    // default String toString() { return "x"; } // ❌ 编译错误：不能为 Object 的 public 方法提供 default
    // default boolean equals(Object o) { return true; } // ❌ 同上
    // default int hashCode() { return 1; } // ❌ 同上

    String toString();   // ✅ 允许声明为抽象（实现类自动继承 Object.toString 即满足）

    // int x;             // ❌ 常量必须初始化
    // private default void m() {} // ❌ private 与 default 不能组合
}
```

## 三、使用规则

### 3.1 实现与多态

实现类实现接口，类似于子类继承父类，因此，接口类型的变量与实现类的对象之间，也可以构成多态引用。

```java
public class Dog implements Animal {
    @Override public void eat(String food) { System.out.println("狗吃 " + food); }
    @Override public String name() { return "Dog"; }
    // sleep() 不覆盖，直接继承 default 实现
    // log() 不可访问，因为它是 private
}

public class Test {
    public static void main(String[] args) {
        Animal a = new Dog();            // 接口引用指向实现类对象
        a.eat("骨头");
        a.sleep();                       // 输出 default 实现
        System.out.println(Animal.CATEGORY);     // 常量通过接口名访问
        System.out.println(Animal.isAlive(10));  // true
        // Dog.isAlive(10);              // ❌ 编译错误：static 方法不被继承
    }
}
```

### 3.2 必须实现所有抽象方法，否则声明为抽象类

接口不能创建对象，但是可以被类实现

* 如果接口的实现类是非抽象类，那么必须重写接口中所有抽象方法。当然如果实现类是抽象类，那么可以不重写。
* 默认方法可以选择保留，也可以重写。
* 重写时，default 单词就不要再写了，它只用于在接口中表示默认方法，到类中就没有默认方法的概念了
* 接口中的静态方法不能被继承也不能被重写

一个类是可以实现多个接口的，接口中，有多个抽象方法时，实现类必须重写所有抽象方法。如果抽象方法有重名的，只需要重写一次。

```java
class HalfDog implements Animal {          // 只实现了 eat
    @Override public void eat(String food) { }
    // 编译错误：HalfDog 不是抽象的，却未覆盖 name()
}
```

```java
abstract class AbstractDog implements Animal {   // ✅ 抽象类可以只实现一部分
    @Override public void eat(String food) { }
}
```

### 3.3 实现方法必须是 public

```java
class Cat implements Animal {
    // @Override void eat(String f) { }   // ❌ 编译错误：正在尝试分配更低的访问权限
    @Override public void eat(String f) { }
    @Override public String name() { return "Cat"; }
}
```

### 3.4 抽象类可以把 default 方法"重新抽象化"

```java
interface Greeting { default void hello() { System.out.println("Greeting"); } }

abstract class Base implements Greeting {
    @Override public abstract void hello();   // 允许：将 default 重新变为抽象
}

class Impl extends Base {
    @Override public void hello() { System.out.println("Impl"); }
}
```

### 3.5 接口不能 `new`，但可作函数式接口

```java
@FunctionalInterface
interface Calculator {
    int calc(int a, int b);            // 唯一的抽象方法
    default Calculator andThen(Calculator other) {
        return (a, b) -> other.calc(calc(a, b), b);
    }
}

Calculator add = (a, b) -> a + b;      // lambda
```

### 3.6 对于接口的静态方法，直接使用“接口名.”进行调用即可，也只能使用“接口名."进行调用，不能通过实现类的对象进行调用

## 四、冲突问题（核心难点）

接口多实现带来的冲突分为 8 类。下面逐一给出示例和解释。

### 4.1 多个接口有相同的 `default` 方法 → 编译错误，必须显式解决

```java
interface A { default void hello() { System.out.println("A.hello"); } }
interface B { default void hello() { System.out.println("B.hello"); } }

// class C implements A, B { }   // ❌ 编译错误：类 C 从 A 和 B 继承了不相关的 hello() 默认方法

class C implements A, B {
    @Override
    public void hello() {           // 必须重写，并可用 InterfaceName.super 选择调用 ， 或者全不调用
        A.super.hello();            // A 是 C 的直接超接口，合法
        B.super.hello();
    }
}
```

**规则**：当两个平级接口提供同签名 `default` 方法时，实现类必须覆盖；`X.super.m()` 中的 `X` 必须是该类的**直接**超接口。

### 4.2 子接口覆盖父接口的 `default` → 更具体的优先

```java
interface A { default void hello() { System.out.println("A"); } }
interface B extends A {
    @Override default void hello() { System.out.println("B"); }   // B 更具体
}
interface C extends A { }                 // C 继承 A 的实现

class D implements B, C { }
// new D().hello();  → 输出 "B"，因为 B 是 A 的子接口，更具体，C 未覆盖 A
```

**菱形继承特例**：若 B、C 都没有覆盖 A 的 default，实现类不会有冲突，因为它们继承的是同一个 A 的方法。

```java
interface B2 extends A { }
interface C2 extends A { }
class D2 implements B2, C2 { }
// new D2().hello(); → "A"，无冲突
```

### 4.3 `default` 与抽象方法混合 → 无冲突，`default` 满足抽象要求

```java
interface A { default void hello() { System.out.println("A.default"); } }
interface B { void hello(); }     // 抽象方法

class C implements A, B { }       // ✅ 编译通过
// new C().hello(); → "A.default"
```

**规则**：签名相同的一个 `default` 方法和一个抽象方法可以共存，`default` 实现自动满足抽象方法的要求。

### 4.4 父类具体方法优先于接口 `default` ； 无冲突，但 类优先

```java
class Base { public void hello() { System.out.println("Base"); } }
interface I { default void hello() { System.out.println("I"); } }

class Sub extends Base implements I {
  public static void main(String[] args) {
    new Sub().hello();



  }

  // 若不重写 hello 则最终打印 Base
  @Override
  public void hello() {
    // 打印 Sub Base
    System.out.println("Sub Base");

    // 调用 父类 的方法，打印 Base
    super.hello();

    // 调用 父接口 的方法，打印 I
    I.super.hello();

    调用接口的  非静态方法    接口名.super.非静态方法名()
    调用接口的  静态方法      接口名.静态方法名()
  }
}
```

### 4.5 父类**抽象**方法也优先，`default` 不会为它提供实现

```java
abstract class Base2 { public abstract void hello(); }
interface I2 { default void hello() { System.out.println("I2"); } }

// class Sub2 extends Base2 implements I2 { }   // ❌ 编译错误：Sub2 必须实现 hello()
// 类优先原则甚至对抽象父类方法生效，接口 default 不参与提供实现

class Sub3 extends Base2 implements I2 {
    @Override public void hello() { }           // ✅ 必须自己实现
}
```

### 4.6 常量同名冲突

```java
interface X { int VALUE = 1; }
interface Y { int VALUE = 2; }

class Z implements X, Y {
    void print() {
        // System.out.println(VALUE);   // ❌ 编译错误：对 VALUE 的引用不明确
        System.out.println(X.VALUE);    // 1
        System.out.println(Y.VALUE);    // 2
    }
}
```

**解决方式**：

1. 用 `X.VALUE`、`Y.VALUE` 限定；
2. 或在实现类中**自己声明同名字段**，遮蔽掉接口字段：

```java
class Z2 implements X, Y {
    int VALUE = 3;                      // 隐藏了 X.VALUE 和 Y.VALUE
    void print() { System.out.println(VALUE); }   // 3
}
```

### 4.7 返回类型不兼容冲突

```java
interface P { Object get(); }
interface Q { String get(); }           // String 是 Object 的子类型（协变）

class R implements P, Q {
    @Override public String get() { return "ok"; }   // ✅ String 可同时满足两者
}
```

```java
interface P2 { String get(); }
interface Q2 { Integer get(); }         // String 与 Integer 无公共子类型

// class R2 implements P2, Q2 { }        // ❌ 编译错误：无法用单一方法同时满足两者
```

**规则**：多个抽象方法签名相同时，返回类型必须存在公共子类型（通常是一个比其它都更具体的返回类型）。

### 4.8 `static` 方法不参与冲突，也不会被继承

```java
interface A3 { static void hello() { System.out.println("A3"); } }
interface B3 { static void hello() { System.out.println("B3"); } }

class C3 implements A3, B3 {
    void test() {
        A3.hello();     // ✅
        B3.hello();     // ✅
        // hello();     // ❌ 编译错误：static 方法不被继承，不能简单名调用
        // C3.hello();  // ❌ 编译错误：接口 static 方法只能通过接口名调用
    }
}
```

### 4.9 边界：接口 `default` 与父类 `static` 方法冲突

```java
class Base4 { public static void hello() { System.out.println("Base.static"); } }
interface I4 { default void hello() { System.out.println("I4.default"); } }

// class Sub4 extends Base4 implements I4 { }
// ❌ 编译错误：类 Sub4 同时继承了 static 方法和实例方法 hello()，签名冲突
```

### 4.10 `private` 方法不参与任何继承与冲突

```java
interface A5 {
    default void hello() { helper(); }
    private void helper() { System.out.println("A5.helper"); }
}
interface B5 {
    default void hello() { helper(); }
    private void helper() { System.out.println("B5.helper"); }
}

class C5 implements A5, B5 {
    @Override public void hello() {        // 仍然是 default-default 冲突，必须覆盖
        A5.super.hello();                  // 输出 A5.helper
        B5.super.hello();                  // 输出 B5.helper
    }
}
```

`private` 方法只影响接口内部实现复用，对外不可见，不参与冲突判定。

## 五、冲突解决优先级总结

方法解析时，按以下优先级从高到低：

1. **类中显式声明/覆盖的方法**（最高）
2. **父类中的具体方法**（类优先于接口，即使父类方法是抽象的，也不会被 `default` 填补）
3. **子接口覆盖的 `default` 方法**（更具体的接口优先）
4. **多个平级 `default` 方法**（冲突 → 必须显式覆盖并用 `X.super.m()` 选择）
5. **`static` / `private` 方法**（不参与继承和多态，各自通过接口名调用）

常用口诀：

> **类优先 > 子接口优先 > 平级冲突显式覆盖**
> **default 可以填补抽象，但无法击败类方法**
> **static/private 不继承，不参与冲突**

## 六、实践建议

1. **接口尽量定义“能力”，避免在多个接口里放同名 `default` 方法**，否则实现类被迫覆盖。
2. **`default` 方法适合做“向后兼容的扩展”**（例如 Java 8 给 `Collection` 增加 `stream()`），而不是承载核心业务。
3. **常量尽量少用**，多个接口都有同名常量时极易产生歧义。
4. **抽象类 + 接口组合**：接口定义契约，抽象类提供部分公共实现，可减少 `default` 冲突。
5. 用 `@FunctionalInterface` 标注单抽象方法接口，编译器会帮你检查。
