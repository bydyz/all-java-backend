# Java 元注解详解

**元注解（Meta-annotation）是“注解的注解”**，它的核心作用是**定义和约束其他注解的行为**
，例如指定一个注解能用在哪些地方（类、方法、字段）、能保留到什么时候（源码、字节码、运行时）、是否可被继承等。元注解是自定义注解的基础。

### 📜 元注解的来源

元注解并非一开始就全部存在，它们随着 Java 版本迭代而逐步完善：

* **Java 5 (JDK 1.5)**：随着注解特性的引入，定义了 **4 个基础元注解**：`@Target`、`@Retention`、`@Documented`
  和 `@Inherited`。
* **Java 8 (JDK 1.8)**：为了支持更灵活的注解用法，新增了 **2 个元注解**：`@Repeatable`（支持重复注解）和 `@Native`
  （标记本地代码可访问的字段）。

### 🎯 六大元注解详解与代码示例

#### @Target：指定注解的“用武之地”

`@Target` 用于明确一个注解可以应用在哪些 Java 元素上，其值来自 `ElementType` 枚举。

**常用 `ElementType` 取值：**

* `TYPE`：类、接口（包括注解类型）或枚举声明。
* `FIELD`：字段（成员变量），包括枚举常量。
* `METHOD`：方法。
* `PARAMETER`：方法参数。
* `CONSTRUCTOR`：构造方法。
* `LOCAL_VARIABLE`：局部变量。
* `ANNOTATION_TYPE`：注解类型（用于元注解）。
* `PACKAGE`：包。
* `TYPE_PARAMETER` (Java 8+)：类型参数（如 `<@MyAnnotation T>`）。
* `TYPE_USE` (Java 8+)：任何使用类型的地方。

**代码示例**：定义一个只能用于方法的注解。

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Target;

@Target(ElementType.METHOD) // 限定 @MyMethodAnnotation 只能用于方法
public @interface MyMethodAnnotation {
    String value() default "";
}

// 正确用法：注解在方法上
class MyClass {
    @MyMethodAnnotation("hello")
    public void doSomething() {}
}

// 错误用法：如果尝试用在类上，编译器会报错
// @MyMethodAnnotation // 编译错误: annotation type not applicable to this kind of declaration
// class AnotherClass {}
```

#### @Retention：定义注解的“生命周期”

`@Retention` 决定了注解被保留的时长，其值来自 `RetentionPolicy` 枚举，这是自定义注解时**必须考虑**的关键属性。

**三种保留策略：**

* `SOURCE`：**仅保留在源码级别**，编译时会被丢弃。例如 `@Override`，只在编译时用于检查，不进入 `.class` 文件。
* `CLASS`：**默认策略**，注解会保留在 `.class` 字节码文件中，但在 JVM 运行类时会被丢弃。
* `RUNTIME`：**最常用的策略**，注解不仅保留在字节码中，在 JVM 运行时依然存在，**可以通过反射机制读取**
  。绝大多数自定义注解（如框架中的 `@Autowired`、`@RequestMapping`）都使用此策略。

唯有 RUNTIME 阶段才能被反射读取到。

**代码示例**：一个可在运行时通过反射读取的注解。

```java
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;

@Retention(RetentionPolicy.RUNTIME) // 生命周期到运行时，可通过反射获取
public @interface RuntimeAnnotation {
    String value();
}
```

#### @Documented：决定是否纳入 Javadoc

`@Documented` 是一个标记注解。默认情况下，使用 `javadoc`
工具生成文档时，注解信息不会被包含进去。如果在一个注解的定义上添加了 `@Documented`，那么所有使用该注解的地方，其注解信息都会被
**提取到生成的 API 文档中**。

**代码示例**：

```java
import java.lang.annotation.Documented;

@Documented
public @interface DocumentedAnnotation {
    String author() default "unknown";
}

// 使用 @DocumentedAnnotation 标注的类，在 Javadoc 中会显示该注解信息
@DocumentedAnnotation(author = "Alice")
public class MyDocumentedClass {}
```

#### @Inherited：控制注解的“家族继承”

`@Inherited` 也是一个标记注解，但它只对 **`@Target(ElementType.TYPE)`**（即类级别）的注解生效。当一个类使用了被 `@Inherited`
标记的注解时，它的**子类会自动继承这个注解**（即使子类没有显式声明）。**注意**：它**不适用于接口继承**，也**不适用于方法上的注解继承
**。

**代码示例**：

```java
import java.lang.annotation.Inherited;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;

@Inherited // 使该注解可被子类继承
@Retention(RetentionPolicy.RUNTIME)
@interface InheritedAnnotation {}

@InheritedAnnotation
class Parent {}

class Child extends Parent {} // Child 类会自动继承 @InheritedAnnotation

// 测试
public class TestInherited {
    public static void main(String[] args) {
        // 在 Child 类上能成功获取到 @InheritedAnnotation，说明继承生效
        System.out.println(Child.class.getAnnotation(InheritedAnnotation.class) != null); // 输出 true
    }
}
```

#### @Repeatable (Java 8+)：允许注解“重复出现”

在 Java 8 之前，同一个注解在同一个位置只能使用一次。`@Repeatable` 元注解解决了这个问题，它允许**同一个注解在同一个元素上多次使用
**。使用时，`@Repeatable` 的参数是一个“容器注解”的 `Class` 对象，该容器注解内部需要有一个数组属性来存储可重复注解的多个实例。

**代码示例**：实现可重复的 `@Role` 注解。

```java
import java.lang.annotation.Repeatable;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;

// 1. 定义容器注解，其 value() 方法返回一个 Role 数组
@Retention(RetentionPolicy.RUNTIME)
@interface Roles {
    Role[] value();
}

// 2. 用 @Repeatable 标记 @Role 为可重复注解
@Repeatable(Roles.class)
@Retention(RetentionPolicy.RUNTIME)
@interface Role {
    String name();
}

// 3. 在同一个方法上重复使用 @Role
class RoleHolder {
    @Role(name = "admin")
    @Role(name = "user") // 重复使用
    public void doWork() {}
}
```

#### @Native (Java 8+)：标记本地代码可访问的字段

`@Native` 是一个较为特殊的元注解，它**只能用于修饰字段（成员变量）**。它的作用是提示代码生成工具（如 `javah`），被它标记的字段常量可能会被
**本地（Native）代码**（如 C/C++ 通过 JNI 调用的代码）所引用。在日常业务开发中**极少直接使用**，主要出现在 JDK 内部或与 JNI
交互的底层库中。

### 💎 综合示例：组合使用元注解

一个自定义注解通常会组合使用多个元注解来精确控制其行为。下面这个例子定义了一个 `@ApiEndpoint` 注解，它**只能用于方法**，*
*可在运行时通过反射读取**，并且其信息**会包含在 Javadoc 中**。

```java
import java.lang.annotation.*;

@Target(ElementType.METHOD)           // 限定只能用于方法
@Retention(RetentionPolicy.RUNTIME)   // 运行时保留，可通过反射读取
@Documented                           // 包含在生成的 Javadoc 中
public @interface ApiEndpoint {
    String path();
    String method() default "GET";
}

// 使用示例
class ApiService {
    @ApiEndpoint(path = "/users", method = "POST")
    public void createUser() { /* ... */ }
}

// 通过反射读取注解信息（模拟框架行为）
public class Demo {
    public static void main(String[] args) throws Exception {
        var method = ApiService.class.getMethod("createUser");
        var endpoint = method.getAnnotation(ApiEndpoint.class);
        System.out.println("Path: " + endpoint.path());     // 输出: Path: /users
        System.out.println("Method: " + endpoint.method()); // 输出: Method: POST
    }
}
```

### 📋 核心要点速查

| 元注解               | 核心作用             | 关键点                                         |
|:------------------|:-----------------|:--------------------------------------------|
| **`@Target`**     | 限定注解的使用位置        | 最常用 `TYPE`, `METHOD`, `FIELD`；不写则几乎可用于任何地方。 |
| **`@Retention`**  | 定义注解的生命周期        | 自定义注解**通常必须设为 `RUNTIME`**，否则反射无法读取。         |
| **`@Documented`** | 控制注解是否进入 Javadoc | 标记注解，无成员变量。                                 |
| **`@Inherited`**  | 允许类注解被继承         | **仅对类级别（`TYPE`）注解有效**，接口和方法不适用。             |
| **`@Repeatable`** | 允许同一注解重复使用       | **Java 8+**，需配合一个容器注解使用。                    |
| **`@Native`**     | 标记字段可能被本地代码引用    | **Java 8+**，日常开发几乎用不到。                      |

元注解是理解 Java 注解体系（尤其是各类框架如 Spring、MyBatis 的运作机制）的基石。掌握它们，你就能清晰地定义出符合业务需求的、行为精确可控的自定义注解。
