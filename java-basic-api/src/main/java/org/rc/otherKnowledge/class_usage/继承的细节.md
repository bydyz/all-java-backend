# Java 继承的细节详解

Java 继承的许多“意外”，根源在于混淆了 **“成为类型的一部分”** 与 **“在子类代码里可以直接使用”**
这两件事。下面按你关心的几个点展开，并补充一些容易被忽略的细节。

---

## 1. 子类会继承父类哪些内容

**成员变量**：子类会继承父类中**非 private** 的成员变量（public、protected、包访问权限视包关系而定）。private 字段在对象内存中
**仍然存在**，但子类代码不能直接命名访问。

**成员方法**：子类继承父类中**可访问的实例方法**。可重写的方法（非 final、非 static、非 private）构成多态的基础。

**嵌套类/成员类型**：父类的成员内部类、成员枚举等，在访问权限允许时，子类可以继承或引用。

**不继承的内容**：**构造方法绝对不被继承**。子类不能通过“继承”得到一个父类构造器；它只能通过 `super(...)`
调用父类构造器来完成父类部分的初始化。**private 成员**在效果上也不继承——子类代码无法直接访问它，但对象里依然有这部分数据。

---

## 2. 不能直接访问 vs. 可以直接访问

访问控制取决于修饰符**以及子类与父类是否同包**，不能一概而论“private 不行、public 就行”：

| 父类成员修饰符     | 子类**同包**   | 子类**不同包**    |
|-------------|------------|--------------|
| `public`    | 直接访问       | 直接访问         |
| `protected` | 直接访问       | 直接访问（通过继承关系） |
| 包访问权限（无修饰符） | 直接访问       | **不能直接访问**   |
| `private`   | **不能直接访问** | **不能直接访问**   |

关键细节是**包访问权限成员的跨包阻断**。Oracle 的经典示例：`points` 包中的 `Point` 有包访问权限的 `x`、`y`
，同包的 `Point3d extends Point` 可以直接用；但另一个包中的 `Point4d extends Point3d` **既不能直接访问 `x`、`y`
，也不能直接访问 `Point3d` 的包访问字段 `z`**，编译失败。

对于 `private`，子类**无法直接访问，但可以通过父类提供的 public/protected getter/setter 间接操作**；private 方法则无法通过继承覆盖或调用。

---

## 3. 多层继承

Java **不支持一个类同时 extends 多个父类**，但支持**多层继承**（A extends B，B extends C）。`C` 是 `A` 的间接父类，`A`
会间接获得 `C` 中可继承的成员。

多层继承下最需要关注的是**构造方法与初始化的执行链条**。创建最底层对象时，初始化**先向上追溯到 `Object`，再依次向下执行**：

```java
class University {
    University() { System.out.println("University"); }
}
class Department extends University {
    Department() { System.out.println("Department"); }
}
class Student extends Department {
    Student() { System.out.println("Student"); }
}
new Student();
// 输出：University → Department → Student
```

之所以必然如此，是因为子类构造方法的第一条语句**隐式或显式地是 `super(...)`**；如果父类没有无参构造器，子类**必须**
手动调用父类的某个有参构造器，否则编译失败。

还需要区分**类初始化**与**实例初始化**：类加载时，静态变量和静态块**先父后子**，且只执行一次；真正 `new`
对象时，才执行实例变量、实例块、构造方法，同样是**父类部分先于子类部分**完成。

---

## 4. 父类与子类的对应关系

从**单个对象看**，一个子类**有且只有一个直接父类**（单继承）；从**类层次看**，一个父类**可以有多个子类**，形成**一对多**
的树状结构。所以准确地说：**一个子类对应一个直接父类，一个父类可以对应多个子类**。

以 `Object` 为例：它是所有类的根，所有类都直接或间接继承 `Object`；没有写 `extends` 的类，**隐式继承 `Object`**。`Object`
本身没有父类。需要注意的是，Java 的“一对多”是**父类到子类的派生关系**，与“一个子类只能有一个直接父类”并不矛盾；单继承限制的是
**子类端的直接父类数量**。

接口可以弥补单继承在类型能力上的不足：一个类只能继承一个父类，但**可以实现多个接口**，这也是“单继承 + 多实现”这一设计的用意之一。

---

## 5. 有无 `extends` 的区别

```java
class A { }                 // 隐式 extends Object
class B extends A { }       // 显式继承 A
```

**没有 `extends` 时**：该类**仍然有父类**，即 `java.lang.Object`，只是没有写出。它会继承 `Object`
的 `toString()`、`equals(Object)`、`hashCode()` 等方法。

**写了 `extends` 时**：直接父类变成指定的类，`Object` 退居为**间接父类**。子类可以通过 `super`
访问直接父类的可访问成员，也可以重写从直接父类或间接父类继承来的方法。

需要注意：**`extends` 只能指定一个直接父类**。`class B extends A, C` 是语法错误。另外，`final` 类不能被 `extends`；`final`
方法不能被重写。

---

## 6. 其他重要细节

### 6.1 方法重写的规则：“两同两小一大”

重写发生在**实例方法**上，必须满足：

- **方法名、参数列表相同**（“两同”）；
- **返回类型相同或为父类返回类型的子类型**（协变返回，Java 5+）；
- **访问权限不能比父类更严格**（可以相同或更宽）；
- **抛出的受检异常不能比父类更宽**（可以更少或更窄）。

违反其中任何一条，都会编译失败或构成错误的重写。静态方法、`private` 方法、`final` 方法、构造方法**都不能被重写**。

### 6.2 静态成员：隐藏，不是重写

如果子类定义了与父类**签名相同的静态方法**，子类方法**隐藏**父类方法，而非重写。隐藏的方法调用在**编译期**
根据引用类型决定，不参与运行时多态；重写的实例方法则根据**实际对象类型**动态分派。

静态字段同理：子类中同名字段会隐藏父类字段，两者在对象/类空间中同时存在，通过 `父类名.字段` 或 `子类名.字段` 区分访问。

### 6.3 字段没有多态

父类引用指向子类对象时，**通过该引用访问字段，得到的是父类声明的字段**
，而不是子类中可能存在的同名字段。字段的访问在编译期根据引用类型决定。如果需要在子类中访问父类被隐藏的字段，可以使用 `super.字段`
（前提是父类字段对子类可访问）。

### 6.4 `super` 与 `this` 的配合

`super(...)` 和 `this(...)` **不能同时出现在同一个构造方法中**
，因为两者都要求是第一行语句。子类构造器如果调用本类另一个构造器（`this(...)`），那个被调用的构造器最终仍会通过 `super(...)`
完成父类初始化，因此父类构造器**仍然会执行，且只执行一次**。

### 6.5 继承的代价：强耦合

继承是**编译期绑定**的强耦合关系：父类的实现细节会暴露给子类，父类修改可能直接破坏子类逻辑。因此实践中有一条常见原则：*
*优先使用组合，只有在明确的“is-a”关系成立时才使用继承**。如果仅仅是为了复用代码，而两类之间并没有真正的类型从属关系，组合通常更灵活。

### 6.6 抽象类与接口在继承体系中的分工

抽象类适合在**一组密切相关的类**之间共享**部分实现**和**公共状态**，同时强制子类实现抽象方法；接口适合定义**跨继承树的能力契约
**，并弥补单继承无法提供多类型来源的限制。一个类可以**继承一个抽象类并实现多个接口**，但抽象类本身仍然遵循单继承规则。

---

**一句话总结**：Java
继承在“类型层面”让子类成为父类的子类型，但在“代码访问层面”受访问修饰符和包的严格切割；构造器不被继承但必然被调用；多层继承下初始化自顶向下；一个父类可以有多个子类，但一个子类只有一个直接父类；重写、隐藏、字段访问各有独立规则，不能混用。
