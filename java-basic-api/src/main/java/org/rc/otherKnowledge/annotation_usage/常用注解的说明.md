# Java 常用注解详解

Java 注解本质上是为代码附加的元数据，本身不直接影响程序逻辑，真正的“魔法”发生在**编译器检查**、**注解处理器**或**运行时反射
**读取这些元数据的时候。下面按来源梳理最常用的一批注解，厘清它们分别“从哪里来、干什么用、怎么用”。

---

## 🧩 Java 标准库注解（`java.lang`）

### 🔍 `@Override`

- **来源**：`java.lang.Override`
- **作用**：声明当前方法意图**重写**父类或接口中的方法。如果方法签名与父类不匹配，**编译器会直接报错**
  ，防止因拼写错误导致“看起来重写了，实际上新增了一个方法”。
- **使用方式**：只能标注在方法上，保留到源码级别（`SOURCE`）。

```java
class Animal {
    void makeSound() { System.out.println("animal sound"); }
}
class Dog extends Animal {
    @Override
    void makeSound() { System.out.println("bark"); } // 若写成 makeSund()，编译器立即报错
}
```

### ⏳ `@Deprecated`

- **来源**：`java.lang.Deprecated`
- **作用**：标记类、方法、字段等**已过时**，编译器在调用处发出警告。Java 9 起还可配合 `since` 和 `forRemoval` 属性表达更精确的弃用语义。
- **使用方式**：可以标注在类、方法、字段、构造器等多种程序元素上。

```java
class LegacyApi {
    @Deprecated(since = "9", forRemoval = true)
    public void oldMethod() { }
}
```

### ⚠️ `@SuppressWarnings`

- **来源**：`java.lang.SuppressWarnings`
- **作用**：**抑制**编译器产生的特定警告（如 `unchecked`、`unused`、`deprecation`）。适合在明确知道警告可忽略的局部范围内使用，不宜滥用。
- **使用方式**：可标注在类、方法、字段、参数等上，通过 `value` 指定要抑制的警告类型。

```java
@SuppressWarnings("unchecked")
List<String> raw = (List<String>) someRawList; // 抑制“未经检查的转换”警告
```

### ⚡ `@FunctionalInterface`

- **来源**：`java.lang.FunctionalInterface`
- **作用**：声明一个接口是**函数式接口**（只含一个抽象方法）。如果接口中意外出现第二个抽象方法，**编译器会报错**。它不是使用
  Lambda 的必要条件，而是一种**编译期契约校验**。
- **使用方式**：标注在接口定义上。

```java
@FunctionalInterface
interface Calculator {
    int apply(int a, int b);
}
// 配合 Lambda 使用
Calculator add = (a, b) -> a + b;
```

## 🏷️ 元注解与自定义注解

元注解是**用来定义注解的注解**，Java 在 `java.lang.annotation` 中提供了四个核心元注解。

| 元注解           | 作用                                                                        |
|---------------|---------------------------------------------------------------------------|
| `@Target`     | 限定注解可以标注在哪些位置（`TYPE`、`METHOD`、`FIELD`、`PARAMETER` 等）                      |
| `@Retention`  | 指定注解的生命周期：`SOURCE`（仅源码）、`CLASS`（默认，编译到 class 但不被运行时读取）、`RUNTIME`（可通过反射读取） |
| `@Documented` | 使注解出现在 Javadoc 中                                                          |
| `@Inherited`  | 使注解可被子类继承（仅对类级别注解有效）                                                      |

自定义注解的基本模式：**用 `@interface` 定义**，**用元注解约束行为**，**运行时通过反射读取**。

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
@interface Benchmark {
    String value() default "default";
}

class Service {
    @Benchmark("query")
    public void query() { }
}

// 反射读取
Method m = Service.class.getMethod("query");
if (m.isAnnotationPresent(Benchmark.class)) {
    Benchmark b = m.getAnnotation(Benchmark.class);
    System.out.println(b.value()); // "query"
}
```

## 🍃 Spring 生态注解

Spring 注解数量众多，按职责分组来理解最清晰。

### 🏗️ 组件声明（把类交给 IoC 容器）

`@Component`、`@Service`、`@Repository`、`@Controller` **本质相同**：它们的元注解都包含 `@Component`，区别在于**语义分层**
和极少数额外能力。

| 注解                | 典型用途         | 特殊之处                                             |
|-------------------|--------------|--------------------------------------------------|
| `@Component`      | 通用组件         | 基础注解                                             |
| `@Service`        | 业务层          | 语义标识                                             |
| `@Repository`     | 持久层（DAO）     | 将原生异常转换为 Spring `DataAccessException`            |
| `@Controller`     | Web 控制器      | 配合视图解析                                           |
| `@RestController` | REST API 控制器 | `@Controller` + `@ResponseBody`，方法返回值直接序列化为 JSON |

```java
@Service
public class UserService { }

@Repository
public class UserDao { }

@RestController
@RequestMapping("/users")
public class UserController { }
```

### 💉 依赖注入

**`@Autowired`**（Spring 提供）默认**按类型**注入；当同一类型存在多个 Bean 时，可配合 **`@Qualifier`** 按名称精确指定。

```java
@Service
public class OrderService {
    @Autowired
    @Qualifier("alipayPayment")
    private PaymentService paymentService;
}
```

**`@Resource`** 是 JSR-250 标准注解，默认**按名称**注入，名称找不到时回退到按类型。在 Spring 项目中，`@Autowired`
更常用，但 `@Resource` 在跨框架场景下可移植性更好。

### 🛣️ Web 请求映射（Spring MVC）

| 注解                               | 作用                    |
|----------------------------------|-----------------------|
| `@RequestMapping`                | 通用请求映射，可指定路径、HTTP 方法等 |
| `@GetMapping` / `@PostMapping` 等 | 语义化简写，更推荐             |
| `@PathVariable`                  | 提取 URI 模板变量           |
| `@RequestParam`                  | 提取查询参数                |
| `@RequestBody`                   | 将请求体（JSON）反序列化为对象     |

```java
@RestController
@RequestMapping("/users")
public class UserController {
    @GetMapping("/{id}")
    public User get(@PathVariable Long id) { ... }

    @PostMapping
    public void create(@RequestBody User user) { ... }

    @GetMapping
    public List<User> list(@RequestParam String name) { ... }
}
```

### 🔄 事务与切面

**`@Transactional`** 声明式事务，可标注在类或方法上，通过 `readOnly`、`propagation`、`isolation` 等属性控制事务行为。**注意**
：同类内部方法调用不会触发事务，因为代理被绕过。

```java
@Service
public class AccountService {
    @Transactional
    public void transfer(Long from, Long to, BigDecimal amount) { ... }

    @Transactional(readOnly = true)
    public BigDecimal getBalance(Long accountId) { ... }
}
```

## 🧪 测试框架注解（JUnit 5 + Mockito）

### 🧪 JUnit 5 生命周期与测试标记

| 注解                           | 作用                |
|------------------------------|-------------------|
| `@Test`                      | 标记测试方法            |
| `@BeforeEach` / `@AfterEach` | 每个测试方法执行前/后运行     |
| `@BeforeAll` / `@AfterAll`   | 所有测试执行前/后运行（静态方法） |
| `@Disabled`                  | 暂时禁用某个测试          |

```java
class CalculatorTest {
    @BeforeEach
    void setUp() { /* 初始化 */ }

    @Test
    void testAdd() {
        assertEquals(5, 2 + 3);
    }

    @Disabled("暂不运行")
    @Test
    void pendingTest() { }
}
```

### 🎭 Mockito 模拟注解

| 注解             | 作用                            |
|----------------|-------------------------------|
| `@Mock`        | 创建一个**模拟对象**，真实方法不会被执行        |
| `@InjectMocks` | 创建被测对象，并将 `@Mock` 自动注入其中      |
| `@Spy`         | 创建**间谍对象**，默认调用真实方法，但可对特定方法打桩 |

```java
@ExtendWith(MockitoExtension.class)
class UserServiceTest {
    @Mock
    private UserDao userDao;

    @InjectMocks
    private UserService userService;

    @Test
    void findUser() {
        when(userDao.findById(1L)).thenReturn(new User(1L, "Alice"));
        User user = userService.findUser(1L);
        assertEquals("Alice", user.getName());
    }
}
```

## 🪄 Lombok 注解（编译期代码生成）

Lombok 的原理是在**编译期通过 JSR 269 注解处理器修改抽象语法树（AST）**，将注解“展开”为常规 Java 代码，因此运行时并不需要
Lombok 的注解本身。

### 🛠️ `@Data`（最常用的组合注解）

标注在类上，等价于同时添加 `@Getter`、`@Setter`（非 `final`
字段）、`@ToString`、`@EqualsAndHashCode`、`@RequiredArgsConstructor`。

```java
@Data
public class User {
    private Long id;
    private String name;
    private final String tenant;
}
// 编译后自动获得 getId/setId、getName/setName、toString、equals、hashCode、
// 以及 required 构造器（tenant 为 final，参与构造）
```

### 🪵 `@Slf4j`

标注在类上，**编译期生成**一个名为 `log` 的 `static final` SLF4J `Logger` 字段。

```java
@Slf4j
@Service
public class PayService {
    public void pay() {
        log.info("支付开始"); // 无需手动声明 Logger
    }
}
// 编译后相当于插入了：
// private static final Logger log = LoggerFactory.getLogger(PayService.class);
```

### 🧱 构造器与 `@Builder`

| 注解                         | 作用                             |
|----------------------------|--------------------------------|
| `@NoArgsConstructor`       | 生成无参构造器                        |
| `@AllArgsConstructor`      | 生成全参构造器                        |
| `@RequiredArgsConstructor` | 为 `final` / `@NonNull` 字段生成构造器 |
| `@Builder`                 | 生成**建造者模式**的流式 API             |

> **注意**：同时使用 `@Data` 和 `@Builder` 时，通常需要显式加上 `@NoArgsConstructor` 和 `@AllArgsConstructor`
> ，否则 `@Builder` 生成的私有全参构造器会覆盖默认构造器，导致无法直接 `new` 对象。

```java
@Data
@Builder
@NoArgsConstructor
@AllArgsConstructor
public class Order {
    private Long id;
    private String product;
    private int quantity;
}

// 使用
Order order = Order.builder()
        .product("Book")
        .quantity(2)
        .build();
```

## 🔌 序列化与 API 文档注解（常用补充）

### 📋 Jackson（JSON 序列化）

| 注解                      | 作用                       |
|-------------------------|--------------------------|
| `@JsonProperty("name")` | 指定 JSON 字段名，与 Java 字段名解耦 |
| `@JsonIgnore`           | 序列化和反序列化时**忽略**该属性       |

```java
public class Person {
    @JsonProperty("full_name")
    private String fullName;

    @JsonIgnore
    private int age; // 不出现在 JSON 中
}
```

### 📖 Swagger / OpenAPI（接口文档）

| 注解                     | 作用                     |
|------------------------|------------------------|
| `@Api(tags = "...")`   | 标注在 Controller 类上，描述模块 |
| `@ApiOperation("...")` | 标注在方法上，描述接口用途          |
| `@ApiParam("...")`     | 标注在参数上，描述参数含义          |

```java
@RestController
@RequestMapping("/users")
@Api(tags = "用户管理")
public class UserController {
    @GetMapping("/{id}")
    @ApiOperation(value = "根据 ID 查询用户", notes = "id 必须为正整数")
    public User get(@PathVariable @ApiParam("用户 ID") Long id) { ... }
}
```

## 💎 总结

| 来源                | 注解                                                                   | 生效阶段                         | 核心机制                   |
|-------------------|----------------------------------------------------------------------|------------------------------|------------------------|
| Java 标准库          | `@Override`、`@Deprecated`、`@SuppressWarnings`、`@FunctionalInterface` | 编译期                          | 编译器检查 / 警告             |
| 元注解               | `@Target`、`@Retention` 等                                             | 定义阶段                         | 约束自定义注解的行为             |
| Spring            | `@Component`、`@Autowired`、`@RequestMapping`、`@Transactional` 等       | 运行期                          | IoC 容器扫描 + 反射 / AOP 代理 |
| 测试                | JUnit `@Test`、Mockito `@Mock`                                        | 运行期                          | 测试框架反射调用               |
| Lombok            | `@Data`、`@Slf4j`、`@Builder` 等                                        | **编译期**                      | 注解处理器修改 AST            |
| Jackson / Swagger | `@JsonProperty`、`@ApiOperation` 等                                    | 运行期（Jackson）/ 文档生成期（Swagger） | 反射读取元数据                |

理解注解时，抓住**“谁在什么时候读取它”**这个关键问题，就能把看似零散的注解串成体系：编译器检查的归编译器，Spring
容器在启动时扫描，JUnit 在运行时反射调用，Lombok 则在编译期直接改写代码结构。
