## 1. 核心结论

Java 泛型是**不变**的：`List<Integer>` 不是 `List<Number>` 的子类型。通配符用于在使用点提供更灵活的类型关系：

- `List<? extends T>`：**上界通配符**，适合“读”，是**生产者**。
  - 可以读出 `T` 或 `T` 的父类型。
  - 不能写入非 `null` 元素。
- `List<? super T>`：**下界通配符**，适合“写”，是**消费者**。
  - 可以写入 `T` 及其子类。
  - 只能安全读出 `Object`。
- `List<?>`：无界通配符。
  - 只能读出 `Object`。
  - 不能写入非 `null` 元素。

记忆口诀：**PECS**
> Producer Extends, Consumer Super
> 生产者用 `extends`，消费者用 `super`。

---

## 2. 读写规则表

| 变量类型 | 读元素可赋给 | 可写入元素 `add/set` | 典型用途 |
|---|---|---|---|
| `List<T>` | `T` | `T` 及其子类 | 正常读写 |
| `List<?>` | `Object` | 仅 `null` | 任意 List 的只读访问 |
| `List<? extends T>` | `T` 或其父类 | 仅 `null` | 生产者：从集合读数据 |
| `List<? super T>` | `Object` | `T` 及其子类，另可 `null` | 消费者：向集合写数据 |

注意：`add(null)` 能编译通过，是因为 `null` 可以赋给任何引用类型；实际开发中不要依赖这个例外。

## 3. 代码示例：读与写

```java
import java.util.*;

public class WildcardDemo {

    // 只读：生产者，使用 extends
    static double sum(List<? extends Number> nums) {
        double s = 0;
        for (Number n : nums) {   // 可以安全读成 Number
            s += n.doubleValue();
        }

        // nums.add(1);       // 编译错误
        // nums.add(1.0);     // 编译错误
        // nums.set(0, 1);    // 编译错误
        nums.add(null);       // 仅 null 可以，编译层面允许

        return s;
    }

    // 只写：消费者，使用 super
    static void fill(List<? super Integer> list, int n) {
        list.add(n);                  // 可以写 Integer
        list.add(Integer.valueOf(n)); // 可以写 Integer
        list.set(0, n);               // 可以 set Integer

        // list.add(1L);              // 编译错误：Long 不是 Integer 子类

        Object o = list.get(0);       // 只能安全读成 Object
        // Integer i = list.get(0);   // 编译错误
    }

    // 无界通配符：只能读成 Object
    static void inspect(List<?> list) {
        Object o = list.get(0);       // 可以读成 Object

        // list.add("abc");           // 编译错误
        list.add(null);               // 仅 null
        list.clear();                 // 结构操作可以
    }

    // PECS：src 生产 T，dest 消费 T
    static <T> void copy(List<? super T> dest, List<? extends T> src) {
        for (T t : src) {  // src 可读为 T
            dest.add(t);   // dest 可写 T
        }
    }

    public static void main(String[] args) {
        List<Integer> ints = new ArrayList<>(List.of(1, 2, 3));
        List<Double> doubles = new ArrayList<>(List.of(1.5, 2.5));
        List<Number> nums = new ArrayList<>();

        // 上界通配符：可以接收 List<Integer>、List<Double>、List<Number>
        List<? extends Number> producer = ints;
        Number n = producer.get(0);  // OK
        // producer.add(4);          // 编译错误

        // 下界通配符：可以接收 List<Integer>、List<Number>、List<Object>
        List<? super Integer> consumer = nums;
        consumer.add(4);             // OK
        Object o = consumer.get(0);  // OK
        // Integer x = consumer.get(0); // 编译错误

        copy(nums, ints);            // OK
        copy(nums, doubles);         // OK
    }
}
```

## 4. 为什么 `extends` 不能写？

看一个反例：

```java
List<Integer> ints = new ArrayList<>();
List<? extends Number> nums = ints;

// nums.add(3.14); // 如果编译器允许，会怎样？
```

`nums` 实际指向的是 `List<Integer>`。如果允许 `nums.add(3.14)`，那么 `ints` 中就会出现一个 `Double`，这会破坏 `List<Integer>` 的类型安全。所以编译器禁止：

```java
nums.add(3.14); // 编译错误
nums.add(1);    // 也编译错误，因为 nums 实际可能是 List<Double>
```

虽然 `1` 是 `Integer`，但编译器只知道 `nums` 是“某种 Number 子类型的 List”，不能确定到底是 `Integer`、`Double` 还是其他类型，因此不能写入。

读取是安全的：

```java
Number n = nums.get(0); // 无论实际是 Integer 还是 Double，至少是 Number
```

## 5. 为什么 `super` 不能读成 `Integer`？

```java
List<Number> nums = new ArrayList<>();
nums.add(3.14);

List<? super Integer> list = nums;

// Integer i = list.get(0); // 如果允许，会怎样？
```

`list` 实际指向 `List<Number>`，其中可能存的是 `Double`。如果允许把 `get(0)` 赋给 `Integer`，运行时就会发生类型转换问题。因此编译器只允许安全读成 `Object`：

```java
Object o = list.get(0); // OK
Integer i = list.get(0); // 编译错误
```

但写入 `Integer` 是安全的，因为 `list` 的实际元素类型一定是 `Integer` 的父类型，能够容纳 `Integer`：

```java
list.add(1); // OK
```

## 6. `List<?>` 与 `List<Object>` 的区别

很多人容易混淆：

```java
List<Object> objects = new ArrayList<>();
objects.add("abc");  // OK
objects.add(123);    // OK
Object o1 = objects.get(0);

List<?> any = new ArrayList<String>();
// any.add("abc");   // 编译错误
any.add(null);       // 仅 null
Object o2 = any.get(0);
```

区别是：

- `List<Object>`：明确元素类型是 `Object`，可以写入任意对象。
- `List<?>`：表示“某种未知类型的 List”，不能写入非 `null`，只能读成 `Object`。

## 7. 通配符捕获：`List<?>` 不能直接 swap

对 `List<?>` 直接读写元素通常不行：

```java
static void swap(List<?> list, int i, int j) {
    // list.set(i, list.get(j)); // 编译错误
}
```

原因是通配符会被“捕获”为一个未知类型 `CAP#1`，`get` 返回 `CAP#1`，`set` 需要 `CAP#1`，编译器不能直接证明这个表达式安全。常见做法是用泛型辅助方法捕获类型：

```java
static void swap(List<?> list, int i, int j) {
    swapHelper(list, i, j);
}

private static <T> void swapHelper(List<T> list, int i, int j) {
    T tmp = list.get(i);
    list.set(i, list.get(j));
    list.set(j, tmp);
}
```

调用 `swapHelper(list, i, j)` 时，`T` 被推断为通配符捕获到的具体类型，因此可以安全读写。

## 8. 方法签名设计建议

### 只读参数：用 `? extends T`

```java
static double sum(List<? extends Number> nums) {
    double s = 0;
    for (Number n : nums) {
        s += n.doubleValue();
    }
    return s;
}
```

调用更灵活：

```java
sum(List.of(1, 2, 3));       // List<Integer>
sum(List.of(1.5, 2.5));      // List<Double>
sum(List.of(1, 2.5, 3L));    // List<Number> 或 List<? extends Number>
```

### 只写参数：用 `? super T`

```java
static void fill(List<? super Integer> list) {
    list.add(1);
    list.add(2);
}
```

可以接收：

```java
fill(new ArrayList<Integer>());
fill(new ArrayList<Number>());
fill(new ArrayList<Object>());
```

### 既读又写：用泛型方法 `<T>`

如果方法内部既要读又要写，通常不要用通配符，而用泛型方法：

```java
static <T> void reverse(List<T> list) {
    for (int i = 0, j = list.size() - 1; i < j; i++, j--) {
        T tmp = list.get(i);
        list.set(i, list.get(j));
        list.set(j, tmp);
    }
}
```

因为 `List<T>` 中读出的就是 `T`，写入的也是 `T`，类型完全一致。

## 9. JDK 中的经典例子：`Collections.copy`

JDK 的 `Collections.copy` 签名体现了 PECS：

```java
public static <T> void copy(List<? super T> dest, List<? extends T> src)
```

含义是：

- `src` 是生产者：从里面读 `T`，所以用 `? extends T`。
- `dest` 是消费者：向里面写 `T`，所以用 `? super T`。

自己实现类似逻辑：

```java
static <T> void copy(List<? super T> dest, List<? extends T> src) {
    for (T t : src) {
        dest.add(t);
    }
}
```

---

## 10. 总结

- `List<? extends T>`：**可读不可写**，读成 `T`，写只能 `null`。适合生产者。
- `List<? super T>`：**可写不可安全读成 T**，写 `T` 及子类，读只能 `Object`。适合消费者。
- `List<?>`：读 `Object`，不能写非 `null`。
- 需要同时读写时，优先使用泛型方法 `<T> void foo(List<T> list)`。
- 记住 **PECS**：**Producer Extends, Consumer Super**。
