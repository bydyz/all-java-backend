# Java 创建和启动线程的方式

Java 里“创建并启动线程”有**核心 API 层**和**任务框架层**两类方式。前者直接 new 出 `Thread` 对象，后者把任务交给框架，由框架负责线程的创建、调度和复用。下面先把所有常见方式逐一列出并附代码，最后统一对比。

---

## 一、逐一列举

### 1. 继承 `Thread` 类，重写 `run()`

```java
class MyThread extends Thread {
    public MyThread(String name) { super(name); }
    @Override
    public void run() {
        System.out.println("running in " + Thread.currentThread().getName());
    }
}

new MyThread("t1").start();   // 必须调 start()，不能调 run()
```

> 注意：直接调 `run()` 只是普通方法调用，仍在当前线程执行，不会创建新线程。

### 2. 实现 `Runnable`，作为 `Thread` 构造参数（含 Lambda 写法）

```java
Runnable task = () -> System.out.println("running in " + Thread.currentThread().getName());
new Thread(task, "t2").start();

// 匿名内部类写法（本质同上）
new Thread(new Runnable() {
    @Override public void run() { System.out.println("anon"); }
}).start();
```

### 3. 实现 `Callable` + `FutureTask`

`FutureTask` 同时实现 `Runnable` 和 `Future`，可拿到返回值、捕获异常。

```java
Callable<Integer> callable = () -> {
    Thread.sleep(500);
    return 42;
};
FutureTask<Integer> ft = new FutureTask<>(callable);
new Thread(ft, "t3").start();

Integer result = ft.get();   // 阻塞直到完成，可抛 ExecutionException
```

### 4. 线程池 `ExecutorService`

最常用的生产写法。线程由池管理复用，任务通过 `execute`（无返回）或 `submit`（有返回）提交。

```java
ExecutorService pool = new ThreadPoolExecutor(
        4, 8, 60L, TimeUnit.SECONDS,
        new ArrayBlockingQueue<>(100),
        r -> new Thread(r, "biz-" + r.hashCode()),
        new ThreadPoolExecutor.CallerRunsPolicy());

pool.execute(() -> System.out.println("fire-and-forget"));
Future<Integer> f = pool.submit(() -> 42);
Integer v = f.get();

pool.shutdown();   // 生产环境通常由 Spring 等容器托管生命周期
```

> 不建议用 `Executors.newFixedThreadPool(...)` 等工厂方法：无界队列或无限线程数易导致 OOM，阿里规约也明确禁止。

### 5. `ScheduledExecutorService`（定时/延时任务）

```java
ScheduledExecutorService ses = Executors.newScheduledThreadPool(2);
ses.schedule(() -> System.out.println("delay 1s"), 1, TimeUnit.SECONDS);
ses.scheduleAtFixedRate(() -> System.out.println("tick"), 0, 2, TimeUnit.SECONDS);
```

内部也是线程池，属于方式 4 的变体。

### 6. `CompletableFuture`（异步编排）

```java
CompletableFuture.supplyAsync(() -> 42)                 // 默认 ForkJoinPool.commonPool
    .thenApply(x -> x * 2)
    .thenAccept(System.out::println);

// 指定线程池（推荐）
CompletableFuture.supplyAsync(() -> 42, pool)
    .thenApplyAsync(x -> x + 1, pool)
    .join();
```

### 7. `ForkJoinPool` + `RecursiveTask` / `RecursiveAction`（分治）

```java
class SumTask extends RecursiveTask<Long> {
    final int lo, hi;
    SumTask(int lo, int hi) { this.lo = lo; this.hi = hi; }
    @Override protected Long compute() {
        if (hi - lo <= 1000) {
            long s = 0;
            for (int i = lo; i < hi; i++) s += i;
            return s;
        }
        int mid = (lo + hi) >>> 1;
        SumTask l = new SumTask(lo, mid), r = new SumTask(mid, hi);
        l.fork(); r.fork();
        return l.join() + r.join();
    }
}
ForkJoinPool pool = new ForkJoinPool();
long sum = pool.invoke(new SumTask(0, 1_000_000));
```

### 8. 并行流 `parallelStream`（底层就是 ForkJoinPool）

```java
long sum = IntStream.range(0, 1_000_000).parallel().asLongStream().sum();
```

属于方式 7 的语法糖，**不可指定线程池**（共享 commonPool），不适合做阻塞型任务。

### 9. Java 21 虚拟线程：`Thread.ofVirtual()` / `Thread.startVirtualThread()`

```java
Thread t = Thread.ofVirtual().name("vt-1").start(() -> System.out.println("virtual"));
t.join();

// 或
Thread.startVirtualThread(() -> System.out.println("vt-2"));
```

### 10. Java 21 虚拟线程池：`Executors.newVirtualThreadPerTaskExecutor()`

```java
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 10_000; i++) {
        executor.submit(() -> { /* 阻塞 IO */ return null; });
    }
}   // 自动 close，等待所有任务结束
```

### 11. Java 21 `Thread.Builder`（统一构造平台线程/虚拟线程）

```java
Thread t = Thread.ofPlatform()
        .name("worker-", 0)      // 自动编号 worker-0, worker-1 ...
        .daemon(true)
        .unstarted(() -> System.out.println("builder"));
t.start();
```

### 12. 结构化并发 `StructuredTaskScope`（Java 21 预览，Java 25 正式）

```java
try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
    Supplier<Integer> a = scope.fork(() -> 1);
    Supplier<Integer> b = scope.fork(() -> 2);
    scope.join().throwIfFailed();
    System.out.println(a.get() + b.get());
}
```

### 13. `java.util.Timer`（定时任务老 API）

```java
Timer timer = new Timer("timer-thread", true);
timer.schedule(new TimerTask() {
    @Override public void run() { System.out.println("tick"); }
}, 1000, 2000);
```

内部会自己 new 一个 `TimerThread`，属于方式 1 的封装，单线程且异常会终止整个 Timer，**生产不推荐**，用方式 5 替代。

## 二、对比说明

### 对比表

| # | 方式 | 是否直接 new Thread | 有返回值 | 异常捕获 | 线程复用 | 复杂度 | 典型场景 |
|---|------|:---:|:---:|:---:|:---:|:---:|------|
| 1 | 继承 Thread | ✅ | ❌ | 需在 run 内 try-catch | ❌ | 低 | 教学、极简 demo |
| 2 | Runnable + Thread | ✅ | ❌ | 同上 | ❌ | 低 | 一次性任务 |
| 3 | Callable + FutureTask | ✅ | ✅ | `get()` 抛 `ExecutionException` | ❌ | 中 | 单次异步有结果 |
| 4 | ExecutorService | ❌（池内建） | ✅/❌ | `get()` 捕获 | ✅ | 中 | **生产首选** |
| 5 | ScheduledExecutor | ❌ | ✅/❌ | 同上 | ✅ | 中 | 定时/延时 |
| 6 | CompletableFuture | ❌ | ✅ | `exceptionally/handle` | 取决于执行器 | 中高 | 异步编排、组合 |
| 7 | ForkJoinPool | ❌ | ✅ | `get()` | ✅ | 高 | CPU 密集型分治 |
| 8 | parallelStream | ❌ | ✅ | 需外层捕获 | ✅（commonPool） | 低 | 集合并行计算 |
| 9 | 虚拟线程 | ✅ | ❌ | 同 Thread | ❌ | 低 | 海量阻塞 IO |
| 10 | 虚拟线程池 | ❌ | ✅ | `get()` | ✅（每个任务一个 VT） | 低 | 高并发 IO 服务 |
| 11 | Thread.Builder | ✅ | ❌ | 同 Thread | ❌ | 低 | 需要统一配置线程属性 |
| 12 | StructuredTaskScope | ❌ | ✅ | `throwIfFailed()` | ✅ | 中 | 请求内多任务并发聚合 |
| 13 | Timer | ❌ | ❌ | 会终止整个 Timer | ❌ | 低 | 遗留代码 |

### 关键差异解读

**① 继承 Thread vs 实现 Runnable**

`Thread` 只能单继承，且把“任务”和“线程”耦合在一起；`Runnable` 把任务独立出来，可复用、可实现多接口，是更好的设计。

```java
// 差：任务与线程耦合
class T extends Thread { public void run(){...} }
// 好：任务独立
Runnable r = () -> {...};
new Thread(r).start();
new Thread(r).start();   // 同一个任务可以复用
```

**② Runnable vs Callable**

`Runnable.run()` 返回 `void`、不能抛受检异常；`Callable.call()` 返回 `V`、可抛 `Exception`。需要结果就用 `Callable`。

**③ 直接 new Thread vs 线程池**

- 每次 `new Thread().start()` 都会触发一次系统调用创建内核线程，开销大（默认栈约 1MB），无法复用、无法限流、无序管理，**高并发下必然出问题**。
- 线程池复用线程、控制并发度、提供队列缓冲和拒绝策略，是生产标配。

```java
// 反面教材：一万个请求就创建一万个线程，可能直接 OOM
for (int i = 0; i < 10_000; i++) new Thread(() -> handle()).start();

// 正解
ExecutorService pool = Executors.newFixedThreadPool(200);  // 示例，生产用 ThreadPoolExecutor
for (int i = 0; i < 10_000; i++) pool.execute(() -> handle());
```

**④ 平台线程池 vs 虚拟线程（Java 21+）**

- 平台线程是 1:1 映射到 OS 线程，阻塞时占用内核线程，线程数受限于内存（几千级别）。
- 虚拟线程是 M:N 映射，阻塞（`Thread.sleep`、IO）时自动让出载体线程，可以创建**百万级**，特别适合高并发 IO（Web 服务、DB 调用）。
- 虚拟线程**不适合 CPU 密集型任务**（如计算、加密），那仍然用固定大小的平台线程池。
- 虚拟线程不要池化（“每个任务一个虚拟线程”就是正确用法），因为它本身就极轻量。

```java
// 传统：200 个平台线程处理高并发 IO，容易成瓶颈
ExecutorService old = Executors.newFixedThreadPool(200);
// 虚拟线程：每个请求一个虚拟线程，能扛几十万并发连接
try (var vt = Executors.newVirtualThreadPerTaskExecutor()) {
    for (var req : requests) vt.submit(() -> handle(req));
}
```

**⑤ CompletableFuture vs Future**

`Future.get()` 是阻塞式的；`CompletableFuture` 支持链式回调、组合（`thenCombine`、`allOf`）、异常处理（`exceptionally`、`handle`），更适合编排多个异步任务。默认用 `ForkJoinPool.commonPool`，**生产一定要传自定义线程池**，否则可能拖垮公共池或出现线程上下文类加载器、TraceId 丢失等问题。

**⑥ ForkJoinPool / parallelStream vs 普通线程池**

- FJP 采用工作窃取（work-stealing），适合可递归拆分的 CPU 密集任务，任务应尽量**无阻塞**。
- `parallelStream` 用 commonPool，无法指定线程池、无法控制并发度，且不适合阻塞 IO；只是语法糖，不适合作为服务端并发方案。

**⑦ 结构化并发**

`StructuredTaskScope` 让“父任务”与“子任务”的生命周期绑定：父任务退出时子任务全部取消；子任务失败可以全部取消（`ShutdownOnFailure`）或只要一个成功（`ShutdownOnSuccess`）。相比 `CompletableFuture.allOf`，**不会出现任务泄漏**，是 Java 21+ 推荐处理“请求内多路并发”的新方式。

```java
// CompletableFuture 老写法：任一失败需要手动 cancel 其他任务
var a = CompletableFuture.supplyAsync(this::callA, pool);
var b = CompletableFuture.supplyAsync(this::callB, pool);
CompletableFuture.allOf(a, b).join();   // b 失败时 a 仍在跑

// StructuredTaskScope：b 失败自动取消 a
try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
    var a = scope.fork(this::callA);
    var b = scope.fork(this::callB);
    scope.join().throwIfFailed();
    return new Result(a.get(), b.get());
}
```

## 三、选型建议

| 场景 | 推荐方式 |
|------|----------|
| 学习/演示、写个 demo | 方式 1 或 2 |
| 需要一次性异步结果（少量） | 方式 3 `FutureTask` |
| **生产环境的通用异步任务** | **方式 4 自定义 `ThreadPoolExecutor`** |
| 定时任务 | 方式 5 `ScheduledExecutorService` |
| 多任务组合、链式异步 | 方式 6 `CompletableFuture` + 自定义线程池 |
| CPU 密集、可拆分大任务 | 方式 7 `ForkJoinPool` |
| 集合元素独立并行计算 | 方式 8 `parallelStream` |
| **高并发阻塞 IO（JDK 21+）** | **方式 10 虚拟线程池** |
| 需要统一配置线程名/daemon/优先级 | 方式 11 `Thread.Builder` |
| 一个请求内多路并发且需要“全成功或全失败” | 方式 12 `StructuredTaskScope` |
| 老代码里的 `Timer` | 迁移到方式 5 |

**一句话总结**：生产代码几乎不应该出现 `new Thread(...).start()`；应把任务交给**线程池**（平台线程池做 CPU 密集，虚拟线程做 IO 密集），用 `CompletableFuture` / 结构化并发做异步编排，用 `Thread.Builder` 统一配置线程属性。
