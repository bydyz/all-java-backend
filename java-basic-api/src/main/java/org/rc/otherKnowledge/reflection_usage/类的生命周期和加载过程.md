# Java 中类的生命周期和加载过程详解

Java 类的生命周期远不止“加载”这一个动作，它是一套从**诞生到消亡**的完整规则。理解这套规则，是排查 `ClassNotFoundException`、`NoClassDefFoundError`、静态初始化顺序错误以及热部署内存泄漏等问题的根基。

一个类从被 JVM 加载到内存，到最终可能被卸载，完整生命周期分为 **7 个阶段**：

**加载 → 链接（验证 → 准备 → 解析） → 初始化 → 使用 → 卸载**

其中，**加载、验证、准备、初始化和卸载的起始顺序是确定的**，但解析阶段为了支持动态绑定，可以在初始化之后才进行。

下面逐阶段展开，并尽量结合代码说明。

---

## 加载（Loading）：找到字节流，创建 Class 对象

加载阶段的核心任务是：**通过类的全限定名获取其二进制字节流，并据此在方法区（或元空间）建立运行时数据结构，同时在堆中创建一个 `java.lang.Class` 对象作为访问入口**。

字节流的来源不限于本地 `.class` 文件，也可以是 JAR 包、网络、动态代理生成的字节码等。执行这一动作的代码就是 **类加载器（ClassLoader）**。

Java 的类加载器采用**双亲委派模型**：收到加载请求时，先委派给父加载器，父加载器无法完成时才由自己尝试加载。这保证了像 `java.lang.String` 这样的核心类始终由最顶层的启动类加载器加载，防止核心 API 被篡改。

一个验证当前类加载器层级的小示例：

```java
public class ClassLoaderDemo {
    public static void main(String[] args) {
        ClassLoader cl = ClassLoaderDemo.class.getClassLoader();
        System.out.println(cl);                    // AppClassLoader
        System.out.println(cl.getParent());        // ExtClassLoader（JDK 8）
        System.out.println(cl.getParent().getParent()); // null（Bootstrap 在 Java 中不可见）
    }
}
```

这段输出表明，用户类默认由 **应用类加载器** 加载，它的父加载器是扩展类加载器，再往上就是由 C++ 实现的启动类加载器（在 Java 层表现为 `null`）。

---

## 链接（Linking）：验证、准备、解析

链接阶段把加载进来的二进制数据合并到 JVM 运行时环境中，分三步。

### 验证（Verification）

确保字节流符合 JVM 规范，不会危害虚拟机安全。包括文件格式验证（魔数等）、元数据验证、字节码验证和符号引用验证。这是保障 JVM 自身安全的第一道防线。

### 准备（Preparation）

**为静态变量分配内存，并设置“零值”**（`0`、`0L`、`null`、`false` 等），而不是代码中写的初始值。**但 `final` 常量例外**，它在准备阶段就会被直接赋值为代码中指定的值。

```java
public class PreparationDemo {
    static int a = 10;          // 准备阶段：a = 0
    static final int B = 20;    // 准备阶段：B = 20（final 直接赋值）
    static String s = "hello";  // 准备阶段：s = null
}
```

`a` 要到 **初始化阶段** 才会变成 `10`，`s` 才会指向 `"hello"`。

### 解析（Resolution）

把常量池中的**符号引用**替换为**直接引用**（内存地址指针）。例如，把“`Car.run()`”这个字符串描述，替换为指向 `Car` 类 `run()` 方法在方法区中实际位置的指针。解析可以延迟到初始化之后进行，以支持多态等运行时绑定行为。

---

## 初始化（Initialization）：执行 `<clinit>()`

这是生命周期中**最需要关注“时机”**的阶段。JVM 会执行**类构造器 `<clinit>()`**，它由**静态变量的显式赋值语句**和**静态代码块**按源码顺序合并而成。

### 主动使用 vs 被动使用

JVM 严格规定：**只有首次发生“主动使用”时，才会触发类的初始化**。被动使用不会触发。

**主动使用的 6 种场景**：

1. `new` 实例化对象；
2. 读取或设置静态变量（`final` 常量除外）；
3. 调用静态方法；
4. 反射调用（如 `Class.forName`）；
5. 初始化子类时，父类先初始化；
6. 启动类（含 `main` 方法的类）先初始化。

**经典被动使用陷阱**：通过**子类**访问**父类的静态字段**，只触发父类初始化，子类不会初始化。

```java
class Parent {
    static { System.out.println("Parent 初始化"); }
    static int value = 1;
}

class Child extends Parent {
    static { System.out.println("Child 初始化"); }
}

public class PassiveUseDemo {
    public static void main(String[] args) {
        System.out.println(Child.value); // 只输出 "Parent 初始化"
    }
}
```

`Child.value` 实际定义在 `Parent` 中，属于对 `Parent` 的主动使用，`Child` 并未被初始化。

**反射的差异**：`Class.forName("X")` 默认会触发初始化；而 `X.class` 或 `Class.forName("X", false, loader)` **只获取 Class 对象，不触发初始化**。

### 线程安全与死锁风险

JVM 保证 `<clinit>()` **只执行一次**，多线程同时初始化时，只有一个线程执行，其余阻塞等待。但如果两个类的 `<clinit>()` **互相依赖**，又恰好在两个线程中同时初始化，可能造成**隐蔽的初始化死锁**——线程状态显示为 `RUNNABLE`，但实际在等待对方释放初始化锁。

---

## 使用（Using）

初始化完成后，类进入正常使用阶段：创建实例、调用方法、访问字段。使用期间，类的元数据常驻方法区/元空间。

---

## 卸载（Unloading）：条件严苛，通常与自定义加载器相关

**类可以被卸载，但条件极其严格**，必须**同时满足**以下三点：

1. 该类的**所有实例**都已被 GC 回收；
2. **加载该类的 ClassLoader** 已经被 GC 回收；
3. 该类的 **`java.lang.Class` 对象**没有任何地方引用（无法通过反射访问）。

由应用类加载器加载的普通类，其 ClassLoader 在应用运行期间一直存活，因此**几乎不会被卸载**。卸载主要发生在**自定义类加载器**的动态场景中（如热部署、插件化、OSGi）。

一个演示卸载思路的代码骨架：

```java
public class UnloadDemo {
    public static void main(String[] args) throws Exception {
        URLClassLoader loader = new URLClassLoader(
            new URL[]{ new File("/path/to/classes/").toURI().toURL() }
        );
        Class<?> clazz = loader.loadClass("com.example.SampleClass");
        Object obj = clazz.getDeclaredConstructor().newInstance();

        // 切断所有可达引用
        obj = null;
        clazz = null;
        loader = null;   // 加载该类的 ClassLoader 不再被引用

        System.gc();     // 触发 Full GC（不保证立即执行卸载）
    }
}
```

配合 JVM 参数 `-XX:+TraceClassUnloading` 可以观察卸载日志。注意，**`System.gc()` 只是建议**，是否真正卸载由 GC 决定。

## 一张表回顾

| 阶段 | 核心动作 | 关键注意点 |
|---|---|---|
| **加载** | 获取字节流，生成 `Class` 对象 | 双亲委派保证核心类安全 |
| **验证** | 检查字节码合法性 | 文件格式、元数据、字节码、符号引用 |
| **准备** | 静态变量分配内存，设零值 | `final` 常量直接赋真实值 |
| **解析** | 符号引用 → 直接引用 | 可延迟到初始化之后 |
| **初始化** | 执行 `<clinit>()` | **仅主动使用触发**；`<clinit>` 线程安全 |
| **使用** | 正常调用 | — |
| **卸载** | 方法区数据被清除 | 三条件同时满足；普通应用类几乎不卸载 |

理解这套生命周期，核心价值在于**预测“类在什么时刻会被初始化”**以及**判断“一个类是否可能被卸载”**。前者决定了静态代码块的执行时机和潜在的死锁风险，后者是判断热部署方案是否会引发元空间泄漏的关键依据。
