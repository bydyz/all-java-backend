Java 在 `java.lang` 包中预定义了三个最基础、最常用的注解：`@Override`、`@Deprecated` 和 `@SuppressWarnings`
。它们由编译器直接处理，用于增强代码的**可读性、安全性与可维护性**。

### 📝 `@Override`：声明重写意图

**来源**：位于 `java.lang` 包，自 Java 5 引入。

**作用**：明确告知编译器，被注解的方法意图**重写（Override）父类或接口中的方法**。它本身不产生任何代码逻辑，核心价值在于*
*编译期检查**。如果方法签名与父类方法不匹配（如方法名拼写错误、参数列表不一致），编译器会立即报错，从而避免因“看似重写、实则新增方法”而引发的隐蔽
Bug。
会被编译器程序读取。

**使用方式**：只能用于**方法**。尽管在重写方法时并非强制要求添加，但强烈建议始终使用，以获取编译器的保护。

**代码示例**：

```java
class Animal {
    public void makeSound() {
        System.out.println("Animal makes a sound");
    }
}

class Dog extends Animal {
    // 正确重写：编译器校验通过
    @Override
    public void makeSound() {
        System.out.println("Dog barks");
    }

    // 错误示例：方法名拼写错误（makeSund）
    // 若不加 @Override，编译器不会报错，tHis方法会被当作 Dog 类的新方法
    // 加上 @Override 后，编译器会立即提示错误：方法未重写或实现超类型方法
    // @Override
    // public void makeSund() { ... }
}
```

> **提示**：`@Override` 同样可用于接口方法的实现以及接口中重写 `Object` 类的方法（如 `toString`、`equals`）的场景。

### ⚠️ `@Deprecated`：标记过时 API

**来源**：位于 `java.lang` 包，自 Java 5 引入。

**作用**：标记某个程序元素（类、方法、字段等）已**过时（deprecated）**，**不建议继续使用**。当其他代码使用被 `@Deprecated`
标记的元素时，编译器会产生警告，提醒开发者该元素可能存在风险（如不安全）、已有更好的替代方案，或计划在未来版本中移除。
会被编译器程序读取。

**使用方式**：可应用于**属性、方法、构造、类、包、局部变量、参数**等多种声明。自 Java 9 起，`@Deprecated` 注解增加了两个可选属性，以提供更精确的语义：

- **`since`**：指明从哪个版本开始被弃用。
- **`forRemoval`**：若为 `true`，表示该 API 计划在未来版本中**移除**，编译器会生成更强的 “removal warning”。

**代码示例**：

```java
public class LegacyService {

    /**
     * @deprecated 此方法已过时，请改用 {@link #newPerformAction()}。
     */
    @Deprecated(since = "1.5", forRemoval = true)
    public void oldPerformAction() {
        System.out.println("Old action (dangerous)");
    }

    public void newPerformAction() {
        System.out.println("New safe action");
    }
}

class Client {
    void useService() {
        LegacyService service = new LegacyService();
        // 调用 oldPerformAction() 时，编译器会发出警告：
        // “oldPerformAction() 在 LegacyService 中已被弃用，并标记为待移除”
        service.oldPerformAction();
    }
}
```

> **注意**：注解 `@Deprecated`（首字母大写 D）是给**编译器**看的；而 Javadoc 注释中的 `@deprecated` 标签（首字母小写 d）是给*
*文档**看的，二者应配合使用，以完整传达弃用信息。

### 🔇 `@SuppressWarnings`：抑制特定编译警告

**来源**：位于 `java.lang` 包，自 Java 5 引入。

**作用**：指示编译器**抑制（suppress）** 指定类别的编译警告。它并不“修复”引发警告的代码，而是让开发者能在确信代码安全或警告无实际影响的情况下，
**主动关闭**特定的警告信息，使编译输出保持整洁，从而让真正重要的警告更容易被注意到。

**使用方式**：可应用于**几乎任何声明**（类、方法、变量等）。它接受一个**字符串数组**，用于指定要抑制的警告类别。Java
语言规范定义了一些标准类别，如 `"unchecked"`（未检查的泛型操作）、`"deprecation"`（使用已弃用 API）等。不同编译器（如
Eclipse、IntelliJ）还支持更多扩展类别（如 `"unused"`、`"rawtypes"`、`"all"`）。
会被编译器程序读取。

可以指定的警告类型有（了解）
– all，抑制所有警告
– unchecked，抑制与未检查的作业相关的警告
– unused，抑制与未用的程式码及停用的程式码相关的警告
– deprecation，抑制与淘汰的相关警告
– nls，抑制与非 nls 字串文字相关的警告
– null，抑制与空值分析相关的警告
– rawtypes，抑制与使用 raw 类型相关的警告
– static-access，抑制与静态存取不正确相关的警告
– static-method，抑制与可能宣告为 static 的方法相关的警告
– super，抑制与置换方法相关但不含 super 呼叫的警告

**最佳实践**：`@SuppressWarnings` 的作用范围应**尽可能小**。如果只在某个方法内需要抑制警告，就应将注解标注在该方法上，而非整个类上，以避免掩盖其他位置可能存在的同类问题。

**代码示例**：

```java
import java.util.ArrayList;
import java.util.List;

public class WarningExample {

    // 抑制“使用了已弃用 API”的警告（仅作用于该方法）
    @SuppressWarnings("deprecation")
    public void useLegacyApi() {
        new LegacyService().oldPerformAction(); // 此处的弃用警告被抑制
    }

    // 抑制“未检查”警告：将原始类型 List 赋值给泛型 List 引用
    @SuppressWarnings("unchecked")
    public void uncheckedAssignment() {
        List rawList = new ArrayList();
        rawList.add("item");
        // 此强制转换通常会产生“unchecked”警告，但此处被抑制
        List<String> stringList = (List<String>) rawList;
    }

    // 同时抑制多个类别的警告
    @SuppressWarnings({"unchecked", "deprecation"})
    public void mixedWarnings() {
        List rawList = new ArrayList();
        rawList.add("data");
        List<String> list = (List<String>) rawList; // 抑制 unchecked
        new LegacyService().oldPerformAction(); // 抑制 deprecation
    }
}
```

### 💎 总结

| 注解                      | 核心目的                | 关键特性                                           |
|:------------------------|:--------------------|:-----------------------------------------------|
| **`@Override`**         | 声明重写意图，**确保正确性**    | 编译期检查方法签名是否匹配父类/接口方法，防止拼写错误                    |
| **`@Deprecated`**       | 标记过时 API，**传递弃用信号** | 触发编译器警告，引导开发者使用替代方案；可配置 `since` 和 `forRemoval` |
| **`@SuppressWarnings`** | 抑制特定编译警告，**管理警告噪音** | 需精确指定警告类别，作用范围应最小化，避免掩盖真实问题                    |

这三个注解虽小，却分别从**正确性保障**（`@Override`）、**API 演进管理**（`@Deprecated`）和**警告治理**（`@SuppressWarnings`
）三个维度，构成了 Java 代码质量基础设施的重要组成部分。
