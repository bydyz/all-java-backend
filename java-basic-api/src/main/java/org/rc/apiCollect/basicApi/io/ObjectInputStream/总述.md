`ObjectInputStream` 是 Java 原生序列化机制的核心输入类，负责将 `ObjectOutputStream` 写出的字节流还原为对象图。它的功能远不止“读一个对象”，还涉及类加载、字段恢复、引用共享处理以及反序列化安全控制。

---

### 功能定位：不只是“读对象”

`ObjectInputStream` 反序列化的是**对象图**，而非孤立对象。当它读取一个对象时，会自动追踪该对象引用的其他对象，并按需从流中一并还原，从而保证原本的引用关系（包括循环引用）被正确重建。恢复字段时，它遵循特定的顺序：从最接近 `java.lang.Object` 的序列化类开始，逐步填充到最具体的子类；对于不可序列化的超类，则会调用其无参构造器。`transient` 和 `static` 字段会被直接跳过，不参与反序列化。

典型用途包括：与 `FileInputStream` 配合实现对象的持久化存储，通过 Socket 在网络主机之间传递对象，或在 RMI 中编组参数。

---

### 构造器：头部验证与阻塞语义

#### `public ObjectInputStream(InputStream in)`

这是日常使用的构造器。它并非简单地包装一个底层输入流——**在构造过程中，它会立即调用 `readStreamHeader()` 读取并验证序列化流的头部（魔数与版本号）**。如果头部不匹配，会抛出 `StreamCorruptedException`；如果读取头部时发生 I/O 错误，则抛出 `IOException`。

一个容易被忽视的行为是：**该构造器会阻塞，直到对应的 `ObjectOutputStream` 已经写入并刷新了头部**。因此，如果在同一线程中先创建 `ObjectInputStream` 再创建 `ObjectOutputStream`，就会死锁，因为双方都在等待对方先写头部。

```java
try (FileInputStream fis = new FileInputStream("data.ser");
     ObjectInputStream ois = new ObjectInputStream(fis)) {
    // 构造时已自动读取并验证流头部
    Person p = (Person) ois.readObject();
} catch (IOException | ClassNotFoundException e) {
    // StreamCorruptedException 是 IOException 的子类
    e.printStackTrace();
}
```

#### `protected ObjectInputStream()`

供**完全重新实现** `ObjectInputStream` 的子类使用，避免分配本实现所需的私有数据。如果安装了安全管理器，该构造器会检查 `SerializablePermission("enableSubclassImplementation")` 权限。

---

### 核心 API 的使用方法与代码示例

#### 1. `readObject()`：读取对象图的主入口

```java
public final Object readObject() throws OptionalDataException, ClassNotFoundException, IOException
```

`readObject` 是反序列化的核心方法。它读取流中的下一个对象，返回 `Object`，需要由调用方进行安全的强制类型转换。**字符串和数组在序列化体系中也被视为对象**，因此同样通过 `readObject()` 读取后再转型。

```java
try (ObjectInputStream ois = new ObjectInputStream(new FileInputStream("graph.ser"))) {
    String name = (String) ois.readObject();   // 字符串也是对象
    Person person = (Person) ois.readObject();
    Person sameRef = (Person) ois.readObject(); // 若流中共享引用，此处返回同一实例
}
```

**`OptionalDataException`** 值得注意：如果在读取对象时遇到了原始数据（而非对象），或者在读取原始数据时遇到了对象，就会抛出此异常。它表明流中的数据类型与方法期望不匹配。

#### 2. `readUnshared()`：拒绝后续引用共享

```java
public Object readUnshared() throws OptionalDataException, ClassNotFoundException, IOException
```

`readUnshared()` 与 `readObject()` 行为基本相同，但有一个关键限制：**它阻止后续的 `readObject` 和 `readUnshared` 调用返回本次调用所获实例的额外引用**。如果流中确实包含对该实例的后续引用，会抛出 `InvalidObjectException`。当你需要确保反序列化出的对象不被流中其他部分共享时，应使用此方法。

```java
Object obj = ois.readUnshared();
// 后续若流中再次出现对同一实例的引用，读取会失败
```

#### 3. 自定义 `readObject` 中的 `defaultReadObject()` 与 `readFields()`

当类需要干预自身的反序列化过程时，可以定义 `private void readObject(ObjectInputStream in)`。在这个方法内部，`defaultReadObject()` 用于按默认机制读取**当前类的非静态、非瞬态字段**：

```java
private void readObject(ObjectInputStream in) throws IOException, ClassNotFoundException {
    in.defaultReadObject();          // 先恢复当前类字段的默认状态
    if (someField == null) {         // 再进行校验或补充逻辑
        someField = "default";
    }
}
```

`defaultReadObject()` **只能从正在执行反序列化的那个类的 `readObject` 方法内部调用**，否则抛出 `NotActiveException`。

`readFields()` 则提供了更精细的字段访问方式。它返回一个 `GetField` 对象，允许按名称读取字段，并可判断某个字段是否因流中缺失而使用了默认值：

```java
private void readObject(ObjectInputStream in) throws IOException, ClassNotFoundException {
    ObjectInputStream.GetField fields = in.readFields();
    int version = fields.get("version", 1);      // 若流中无此字段，返回默认值 1
    String name = (String) fields.get("name", "unknown");
    boolean nameDefaulted = fields.defaulted("name"); // 可检测是否用了默认值
}
```

#### 4. 原始类型与字节级读取

`ObjectInputStream` 同时实现了 `ObjectInput` 接口，因此可以直接读取原始类型。当你用 `ObjectOutputStream` 依次写入原始类型和对象时，读取端必须用**对应的方法按相同顺序**读取：

```java
// 写入端：ois 为 ObjectOutputStream
// out.writeInt(42); out.writeUTF("hello"); out.writeObject(new Date());

// 读取端
int i = ois.readInt();
String s = ois.readUTF();
Date d = (Date) ois.readObject();
```

常用方法包括 `readInt()`、`readLong()`、`readUTF()`、`readFully(byte[])` 等。其中 `readFully` 会**读满指定长度或抛出 `EOFException`**，适合处理已知长度的字节块。

#### 5. 生命周期与状态方法

- `close()`：关闭底层输入流，释放资源。
- `available()`：返回在不阻塞的情况下可读取的字节数估计值，**不应用于判断对象是否读完**，因为对象边界与字节计数并不直接对应。

### 安全警告：反序列化不可信数据本身就是危险操作

Java 官方文档在 `ObjectInputStream` 的类说明顶部给出了明确警告：**对不可信数据进行反序列化本质上是危险的，应当避免**。攻击者可以构造恶意字节流，使反序列化过程实例化任意类，并在还原对象图时间接触发危险方法。

从 Java 9 开始，`ObjectInputStream` 集成了 `ObjectInputFilter` 机制，用于在反序列化过程中检查类名、数组长度、引用数量、嵌套深度和已消费字节数。每个流都可以设置一个过滤器：

```java
ObjectInputStream ois = new ObjectInputStream(inputStream);
ObjectInputFilter filter = ObjectInputFilter.Config.createFilter(
    "com.myapp.dto.*;java.base/*;!*"   // 仅允许应用DTO和java.base，其余全部拒绝
);
ois.setObjectInputFilter(filter);
```

也可以使用 Lambda 方式实现白名单逻辑：

```java
ois.setObjectInputFilter(info -> {
    if (info.serialClass() != null &&
        info.serialClass().getName().startsWith("com.myapp.dto.")) {
        return ObjectInputFilter.Status.ALLOWED;
    }
    return ObjectInputFilter.Status.REJECTED;
});
```

更安全的做法是在 JVM 级别设置全局过滤器，使所有 `ObjectInputStream` 默认受到约束：

```java
ObjectInputFilter.Config.setSerialFilter(
    ObjectInputFilter.Config.createFilter("com.myapp.dto.*;java.base/*;!*")
);
```

过滤器的检查范围不仅限于类名，还可以限制 `maxdepth`、`maxarray`、`maxrefs` 等资源指标，防止拒绝服务型载荷。

---

### 小结

`ObjectInputStream` 的构造器在实例化时就会验证流头部，并可能因等待头部而阻塞；`readObject()` 负责还原对象图，`readUnshared()` 用于切断引用共享；自定义 `readObject` 时，`defaultReadObject()` 和 `readFields()` 提供了从“全盘接受”到“逐字段控制”的不同粒度。而所有这些能力都建立在一个前提之上：**只应反序列化来自可信来源的数据**。在必须处理外部数据的场景中，设置 `ObjectInputFilter` 白名单不是可选项，而是必要防线。
