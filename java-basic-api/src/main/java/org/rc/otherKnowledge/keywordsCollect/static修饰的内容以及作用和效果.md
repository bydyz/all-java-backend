在 Java 中，`static` 表示“属于类本身”，而不是“属于某个对象实例”。被 `static` 修饰的内容在类加载/类初始化阶段处理，通常通过类名访问。

## 被修饰后的成员具备以下特点

* 随着类的加载而加载
* 优先于对象存在
* 修饰的成员，被所有对象所共享
* 访问权限允许时，可不创建对象，直接被类调用

## 静态变量的特点

* 静态变量的默认值规则和实例变量一样。
* 静态变量值是所有对象共享。
* 静态变量在本类中，可以在任意方法、代码块、构造器中直接使用。
* 如果权限修饰符允许，在其他类中可以通过“类名.静态变量”直接访问，也可以通过“对象.静态变量”的方式访问（但是更推荐使用类名.静态变量的方式）。
* 静态变量的 get/set 方法也静态的，当局部变量与静态变量重名时，使用“类名.静态变量”进行区分。

## 静态方法的特点

* 静态方法在本类的任意方法、代码块、构造器中都可以直接被调用。
* 只要权限修饰符允许，静态方法在其他类中可以通过“类名.静态方法“的方式调用。也可以通过”对象.静态方法“的方式调用（但是更推荐使用类名.静态方法的方式）。
* 在 static 方法内部只能访问类的 static 修饰的属性或方法，不能访问类的非 static 的结构。
* 静态方法可以被子类继承，但不能被子类重写。
* 静态方法的调用都只看编译时类型。
  * 静态方法属于类，不属于对象；
  * 静态方法不支持运行时多态；
  * 静态方法可以被继承，子类同名静态方法只是隐藏父类方法，不是重写，故不能使用@Override；
  * 编译器根据引用变量的声明类型决定调用哪个类的静态方法；
  * 运行时不会因为引用实际指向子类对象而改变静态方法的调用目标。
* 因为不需要实例就可以访问 static 方法，因此 static 方法内部不能有 this，也不能有super。如果有重名问题，使用“类名.”进行区别。

## 一、static 可以修饰哪些内容

### 1. static 成员变量（类变量）

```java
class User {
    static int count = 0; // 所有 User 实例共享
    String name;          // 实例变量，每个对象一份
}
```

作用和效果：

- 所有实例共享同一份静态变量。
- 可通过 `类名.变量` 访问，也可通过实例访问，但不推荐。
- 生命周期通常与类相同，不随对象创建/销毁。
- 适合做计数器、全局配置、常量等。
- 静态变量不是对象状态的一部分，不参与实例序列化。

注意：

- 共享可变静态变量存在线程安全问题，需要同步或使用并发容器/原子类。
- 静态集合长期持有对象可能导致内存泄漏。

### 2. static 方法（类方法）

```java
class MathUtil {
    static int add(int a, int b) {
        return a + b;
    }
}
```

作用和效果：

- 不依赖实例即可调用：`MathUtil.add(1, 2)`。
- 静态方法内不能使用 `this`、`super`。
- 不能直接访问实例变量和实例方法，只能直接访问静态成员；如需访问实例成员，必须先创建对象。
- 静态方法可以被继承，但不能被重写，只能被隐藏；调用时编译期绑定，不体现运行时多态。
- 常用于工具方法、工厂方法、单例获取方法等。
- `static` 方法不能是 `abstract`；接口中的 `static` 方法必须有方法体，且不被实现类继承。

### 3. static 代码块

```java
class Config {
    static {
        System.out.println("类初始化时执行一次");
    }
}
```

作用和效果：

- 在类初始化阶段执行，通常只执行一次。
- 多个静态代码块和静态变量显式初始化按源码顺序执行。
- 常用于初始化静态资源、加载配置、注册驱动等。
- 如果静态初始化抛出异常，会得到 `ExceptionInInitializerError`，类可能初始化失败。

### 4. static 内部类（静态嵌套类）

```java
class Outer {
    static class Inner {
    }
}
```

作用和效果：

- 静态内部类不持有外部类实例的隐式引用。
- 可以独立创建：`new Outer.Inner()`。
- 可直接访问外部类的静态成员；访问外部类实例成员需要外部类对象。
- 常用于 Builder、工具类嵌套结构，避免非静态内部类带来的外部实例引用。

### 5. static import（静态导入）

```java
import static java.lang.Math.PI;
import static java.lang.Math.max;

double x = PI;
int y = max(1, 2);
```

作用和效果：

- 简化静态成员调用。
- 可读性可能下降，通常不建议大面积使用。

### 6. 接口中的 static 方法（Java 8+）

```java
interface Utils {
    static void hello() {
        System.out.println("hello");
    }
}
```

作用和效果：

- 属于接口本身，通过接口名调用。
- 不被实现类继承，也不能通过实现类实例调用。

## 二、static 的核心作用和效果

1. **属于类而非实例**
   静态成员只有一份，被该类的所有实例共享。

2. **无需创建对象即可访问**
   通过 `类名.成员` 访问，适合工具方法、常量、全局状态。

3. **生命周期较长**
   静态变量通常随类加载产生，随类卸载消失，而不是随对象销毁。

4. **节省对象内存**
   对每个实例都相同的数据可设为静态，避免每个对象保存一份。

5. **类初始化时执行**
   静态变量显式初始化和静态代码块在类初始化阶段执行。

6. **静态方法编译期绑定**
   静态方法不参与运行时重写多态，只存在隐藏。

## 三、常见限制和注意点

- `static` 不能修饰顶层类，只能修饰嵌套类。
- `static` 不能修饰局部变量、方法参数、构造器。
- 静态方法不能使用 `this`、`super`，不能直接访问实例成员。
- 静态方法不能被重写，只能被隐藏。
- 静态变量共享，多线程修改时要注意线程安全。
- 通过实例访问静态成员虽然合法，但应使用类名访问。
- 不同类加载器加载同一个类，可能各自拥有不同的静态变量副本。
- 静态字段不参与对象序列化。

一句话总结：
> `static` 让成员从"对象级别"上升到"类级别"——**随类加载而生，被所有实例共享，可直接用类名调用**
> ；代价是失去对象状态、不能访问实例成员、并且要注意共享带来的线程安全问题。
