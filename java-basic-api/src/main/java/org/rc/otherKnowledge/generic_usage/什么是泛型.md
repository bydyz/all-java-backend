# Java 泛型详解

## 一、什么是泛型

泛型（Generics）是 Java 5 引入的一种**参数化类型**机制。它允许在定义类、接口、方法时使用**类型参数**，把具体的类型推迟到使用时才确定。

泛型的核心目标有三个：

1. **类型安全**：在编译期就能发现类型错误，而不是运行时抛出 `ClassCastException`。
2. **代码复用**：一套逻辑可以适配多种类型，无需为每种类型重复编写。
3. **消除强制类型转换**：取出元素时不需要手写 `(String)` 这类转换。

对比一下没有泛型时的写法：

```java
// 没有泛型：List 内部存的是 Object
List list = new ArrayList();
list.add("hello");
list.add(123);          // 编译通过，但埋下隐患

String s = (String) list.get(1); // 运行时抛 ClassCastException
```

使用泛型后：

```java
List<String> list = new ArrayList<>();
list.add("hello");
// list.add(123);        // 编译期直接报错
String s = list.get(0); // 无需强制转换
```

## 二、泛型类

在类名后声明类型参数，类内部就可以把它当作一个"占位类型"来使用。

```java
public class Box<T> {
    private T content;

    public void set(T content) {
        this.content = content;
    }

    public T get() {
        return content;
    }
}
```

使用时指定具体类型：

```java
Box<String> stringBox = new Box<>();
stringBox.set("hello");
String s = stringBox.get();   // 不需要强转

Box<Integer> intBox = new Box<>();
intBox.set(100);
int i = intBox.get();
```

类型参数可以有多个，约定俗成的命名：

| 符号 | 含义 |
|------|------|
| `T` | Type（通用类型） |
| `E` | Element（集合元素） |
| `K` / `V` | Key / Value（键值对） |
| `N` | Number（数字） |
| `?` | 通配符 |

多类型参数示例：

```java
public class Pair<K, V> {
    private final K key;
    private final V value;

    public Pair(K key, V value) {
        this.key = key;
        this.value = value;
    }
    public K getKey()   { return key; }
    public V getValue() { return value; }
}

Pair<String, Integer> p = new Pair<>("age", 18);
```

## 三、泛型接口

接口也可以声明类型参数，实现类有两种处理方式：

**方式一：实现时确定具体类型**

```java
public interface Converter<T> {
    T convert(String s);
}

public class StringToIntegerConverter implements Converter<Integer> {
    @Override
    public Integer convert(String s) {
        return Integer.parseInt(s);
    }
}
```

**方式二：实现类继续保留类型参数**

```java
public class GenericConverter<T> implements Converter<T> {
    @Override
    public T convert(String s) {
        return null; // 具体逻辑由子类决定
    }
}
```

## 四、泛型方法

泛型方法在**方法签名**中声明自己的类型参数（放在返回类型之前），与所在类是否是泛型类无关。

```java
public class Util {
    // <T> 是方法自己的类型参数
    public static <T> T getFirst(List<T> list) {
        return list.isEmpty() ? null : list.get(0);
    }

    // 多参数、带边界的泛型方法
    public static <T extends Comparable<T>> T max(T a, T b) {
        return a.compareTo(b) >= 0 ? a : b;
    }
}
```

调用时通常可以**类型推断**，无需显式指定：

```java
List<String> list = List.of("a", "b");
String first = Util.getFirst(list);          // 推断 T = String

int m = Util.max(3, 7);                      // 推断 T = Integer
String s = Util.<String>max("apple", "pear"); // 也可以显式指定
```

> 注意：`<T>` 必须写在返回值之前，否则编译器会把它当成普通类型名。例如 `public T foo()` 不是泛型方法，而是使用类上的 `T`。

## 五、类型参数的边界（Bounded Type Parameters）

用 `extends` 限定类型参数的上界（可以是类或接口，多个用 `&` 连接，类必须放最前）。

```java
// T 必须是 Number 或其子类
public static <T extends Number> double sum(List<T> list) {
    double total = 0;
    for (T t : list) {
        total += t.doubleValue();
    }
    return total;
}

sum(List.of(1, 2, 3));          // OK，Integer
sum(List.of(1.5, 2.5));         // OK，Double
// sum(List.of("a", "b"));      // 编译错误
```

多重边界：

```java
public static <T extends Comparable<T> & Serializable> T pick(T a, T b) {
    return a.compareTo(b) >= 0 ? a : b;
}
```

## 六、通配符与 PECS 原则

通配符 `?` 用于表示"未知类型"，主要出现在方法参数中。它有三种形式：

### 1. 无界通配符 `?`

```java
public static void printAll(List<?> list) {
    for (Object o : list) {
        System.out.println(o);
    }
}
```

`List<?>` 可以接收 `List<String>`、`List<Integer>` 等任意泛型 List，但**不能往里面添加元素**（除了 `null`），因为编译器不知道具体类型。

### 2. 上界通配符 `? extends T`

表示"T 或 T 的子类"。**适合读取**（生产者）。

```java
public static double sumAll(List<? extends Number> list) {
    double total = 0;
    for (Number n : list) {     // 可以安全地读成 Number
        total += n.doubleValue();
    }
    return total;
}

sumAll(List.of(1, 2, 3));        // List<Integer> ✓
sumAll(List.of(1.1, 2.2));       // List<Double>  ✓
```

但**不能写入**：`list.add(1)` 会编译失败，因为 `? extends Number` 可能是 `Integer`、`Double` 等，编译器无法保证安全。

### 3. 下界通配符 `? super T`

表示"T 或 T 的父类"。**适合写入**（消费者）。

```java
public static void addInts(List<? super Integer> list) {
    list.add(1);   // 可以安全写入 Integer
    list.add(2);
}

List<Number> nums = new ArrayList<>();
addInts(nums);     // List<Number> 是 List<? super Integer> 的子类型
```

但**读取时**只能读成 `Object`，因为具体类型不确定。

### PECS 原则

> **P**roducer **E**xtends, **C**onsumer **S**uper
>
> - 如果参数是**生产者**（只读取），用 `? extends T`
> - 如果参数是**消费者**（只写入），用 `? super T`

典型例子：`Collections.copy`

```java
public static <T> void copy(List<? super T> dest, List<? extends T> src)
//                    目标 dest 是消费者 → super
//                    源   src  是生产者 → extends
```

## 七、类型擦除（Type Erasure）

这是理解泛型行为的关键。**泛型是编译期特性，编译后类型参数会被擦除**：

- 无界类型参数 `T` → 擦除为 `Object`
- 有界类型参数 `T extends Number` → 擦除为 `Number`
- 泛型方法/类在字节码层面不再携带具体类型实参

```java
List<String> a = new ArrayList<>();
List<Integer> b = new ArrayList<>();

System.out.println(a.getClass() == b.getClass()); // true！都是 java.util.ArrayList
```

编译器会在必要处插入**桥接方法**和**强制类型转换**，保证运行时正确性。这也是为什么下面这些写法不被允许：

```java
T obj = new T();              // ❌ 编译错误：擦除后不知道 T 是什么
T[] arr = new T[10];          // ❌ 不能创建泛型数组
if (obj instanceof List<String>) { } // ❌ 运行时没有类型信息
List<String>[] arr = new List<String>[10]; // ❌
```

创建泛型数组的替代方案：

```java
@SuppressWarnings("unchecked")
T[] arr = (T[]) new Object[10]; // 需要显式强转并压制警告
```

## 八、泛型的常见限制与注意事项

### 1. 类型参数不能是基本类型

```java
List<int> list = new ArrayList<>();     // ❌
List<Integer> list = new ArrayList<>(); // ✅ 用包装类
```

### 2. 静态成员不能使用类的类型参数

```java
public class Box<T> {
    // private static T value; // ❌ 静态成员属于类，而 T 属于实例
    private static <U> U identity(U u) { return u; } // ✅ 泛型方法可以
}
```

### 3. 泛型不具备协变性

```java
List<String> strings = new ArrayList<>();
// List<Object> objs = strings;  // ❌ 编译错误

List<Object> objs = new ArrayList<>();
objs.add(123);   // 如果上一行成立，strings 里就混进了 Integer
```

但数组是协变的，这恰恰是泛型要避免的隐患：

```java
Object[] arr = new String[1];
arr[0] = 123;    // 运行时 ArrayStoreException
```

### 4. 不能用 `==` 或 `equals` 直接比较泛型类型

```java
// 以下都是编译错误
// if (a instanceof T) {}
// if (list instanceof List<String>) {}
```

### 5. 异常类不能是泛型的

```java
// class MyException<T> extends Exception {} // ❌ 编译错误
```

### 6. 泛型与继承的配合

`List<String>` 与 `List<Object>` 是**两个独立的类型**，没有父子关系。若想要"接受某类型的子类集合"，应使用通配符：

```java
void process(List<? extends Number> list) { }
process(new ArrayList<Integer>()); // ✅
process(new ArrayList<Double>());  // ✅
```

## 九、综合示例：一个类型安全的缓存

```java
public class Cache<K, V> {
    private final Map<K, V> store = new HashMap<>();

    public void put(K key, V value) {
        store.put(key, value);
    }

    public V get(K key) {
        return store.get(key);
    }

    // 泛型方法：把本缓存的值批量拷贝到目标集合（消费者）
    public void copyValuesTo(Collection<? super V> target) {
        target.addAll(store.values());
    }

    // 泛型方法：从源集合读取并批量写入（生产者）
    public void putAllFrom(Map<? extends K, ? extends V> source) {
        store.putAll(source);
    }
}
```

使用：

```java
Cache<String, Integer> cache = new Cache<>();
cache.put("a", 1);
cache.put("b", 2);

List<Number> sink = new ArrayList<>();
cache.copyValuesTo(sink);            // Integer 可写入 Number 集合
System.out.println(sink);            // [1, 2]

Map<String, Integer> more = Map.of("c", 3);
cache.putAllFrom(more);              // OK
```

## 十、总结

| 要点 | 说明 |
|------|------|
| 本质 | 参数化类型，编译期类型检查，运行时类型擦除 |
| 泛型类/接口 | 在类/接口名后声明 `<T>` |
| 泛型方法 | 在返回类型前声明 `<T>`，支持类型推断 |
| 边界 | `<T extends Number & Comparable<T>>` |
| 通配符 | `?`、`? extends T`、`? super T` |
| PECS | 生产者用 extends，消费者用 super |
| 限制 | 不能是基本类型、不能 new T()、静态成员不能用类类型参数、不支持 instanceof 具体泛型 |
| 价值 | 类型安全 + 代码复用 + 消除强转 |

掌握泛型的关键在于理解"**编译期参数化 + 运行时擦除**"这一核心机制，以及通配符的**读写方向**（PECS 原则）。理解这两点，绝大多数泛型使用与编译错误都能迎刃而解。
