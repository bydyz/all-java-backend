`java.io.Reader` 是 Java 字符输入流的**抽象根类**，它的核心职责是将外部数据源（文件、字符串、内存等）中的字符读取到程序内存中。与 `InputStream` 按字节操作不同，`Reader` 以 **16 位 Unicode 字符**为基本单位，并在内部或通过桥接类处理编码转换，因此它是处理文本数据的正确抽象。

---

## 功能定位：为什么需要 Reader

`InputStream` 直接操作字节，适合二进制数据；但当数据是文本时，一个字符可能由多个字节编码而成（如 UTF-8 下的中文通常占 3 字节）。逐字节读取文本不仅需要手动处理编码，还容易造成乱码。`Reader` 在字节层面之上增加了**字符编解码**的职责，让程序以字符为单位进行读取，从而隔离了编码细节。

`Reader` 本身是抽象的，不能直接 `new`。它定义的是所有字符输入流的**共性契约**，具体读取行为由子类实现，例如：

```
Reader
├── InputStreamReader (字节流 → 字符流的桥接)
│   └── FileReader (读取文件的便捷类)
├── BufferedReader (带缓冲、支持 readLine)
├── StringReader (从字符串读取)
├── CharArrayReader (从字符数组读取)
└── FilterReader (过滤流基类)
```


## 构造器：protected 与锁机制

`Reader` 的构造器是 `protected` 的，这意味着**不能在外部直接实例化 Reader**，它的构造器仅供子类通过 `super(...)` 调用。

```java
protected Reader()                    // 以 this 作为同步锁
protected Reader(Object lock)        // 指定同步锁对象
```

- **`protected Reader()`**：将当前 `Reader` 实例自身作为同步监视器，后续 `read`、`skip`、`close` 等操作默认在这个对象上同步。
- **`protected Reader(Object lock)`**：允许子类传入一个专门的对象作为锁。如果需要在更细粒度上控制并发，或避免以 `this` 作为锁带来的外部干扰，可以使用这个构造器。传入 `null` 会抛出 `NullPointerException`。

在自定义 `Reader` 子类时，通常的写法是：

```java
class MyReader extends Reader {
    public MyReader() {
        super(); // 以 this 为锁
    }

    // 必须实现 read(char[], int, int) 和 close()
    @Override
    public int read(char[] cbuf, int off, int len) throws IOException {
        // ...
        return -1;
    }

    @Override
    public void close() throws IOException {
        // ...
    }
}
```

`Reader` 的子类在实现同步时，应当使用继承来的 `lock` 字段，而不是直接 `synchronized(this)`，以便与构造器中指定的锁保持一致。


## 核心 API 详解

`Reader` 提供了以下几类方法。其中 `read(char[], int, int)` 和 `close()` 是**抽象方法**，所有具体子类必须实现；其余方法大多基于这两个抽象方法构建默认实现。

### 读取方法族

| 方法 | 说明 |
|---|---|
| `int read()` | 读取单个字符，返回 `0~65535` 的 int；末尾返回 `-1` |
| `int read(char[] cbuf)` | 将字符读入数组，返回实际读取的字符数；末尾返回 `-1` |
| `abstract int read(char[] cbuf, int off, int len)` | **抽象方法**，将字符读入数组的指定区间 |
| `int read(CharBuffer target)` | 将字符读入 `CharBuffer`，返回读取字符数 |

**逐个字符读取** 适合处理逻辑简单或字符量较小的场景。由于每次 `read()` 返回的是 int，需要显式转换为 `char` 才能作为字符使用：

```java
try (Reader reader = new StringReader("Hello, Reader")) {
    int ch;
    while ((ch = reader.read()) != -1) {
        System.out.print((char) ch); // H e l l o ,   R e a d e r
    }
}
```

**批量读取到 char 数组** 是实际开发中更常用的方式，可以显著减少方法调用次数。需要注意：一次读取返回的 `charsRead` 可能小于数组长度，构造字符串时应使用 `new String(buffer, 0, charsRead)`，而不是 `new String(buffer)`，否则可能把数组末尾的旧数据或空字符包含进来。

```java
try (Reader reader = new FileReader("data.txt")) {
    char[] buffer = new char[1024];
    int charsRead;
    while ((charsRead = reader.read(buffer)) != -1) {
        System.out.print(new String(buffer, 0, charsRead));
    }
}
```

### 跳过与就绪检查

| 方法 | 说明 |
|---|---|
| `long skip(long n)` | 跳过并丢弃 `n` 个字符，返回**实际跳过的数量** |
| `boolean ready()` | 下一次 `read()` 是否保证不会阻塞；返回 `false` **不一定**代表流已结束 |

`skip` 的实际跳过数量可能小于请求值（例如接近流末尾时）。`ready()` 常用于非阻塞 I/O 的预检查，但对于大多数文件和内存流，它通常总是返回 `true`，因此不应将 `ready()` 作为判断流结束的手段——判断结束仍应依赖 `read()` 是否返回 `-1`。

```java
try (Reader reader = new StringReader("ABCDEFGHIJKLMNOPQRSTUVWXYZ")) {
    long skipped = reader.skip(10);          // 实际跳过 10
    System.out.println("Next: " + (char) reader.read()); // K
    long skipped2 = reader.skip(100);        // 实际只会跳过剩余部分
    System.out.println("Skipped2: " + skipped2);
}
```

### mark / reset 与 markSupported

`Reader` 提供了**有条件支持**的回退读取能力：

| 方法 | 说明 |
|---|---|
| `boolean markSupported()` | 当前 Reader 是否支持 mark/reset |
| `void mark(int readAheadLimit)` | 标记当前位置；`readAheadLimit` 限制标记失效前可读取的字符数 |
| `void reset()` | 将读取位置回退到上一次 `mark` 处 |

`Reader` 的默认实现中，`markSupported()` 返回 `false`，`mark()` 和 `reset()` 在未重写时分别抛出 `IOException`。`StringReader` 和 `BufferedReader` 支持这些操作；`FileReader` 本身**不支持**。在使用 `mark/reset` 前，**必须先调用 `markSupported()` 检查**，否则可能运行时抛异常。

```java
try (Reader reader = new StringReader("Java Reader Mark")) {
    char[] part = new char[5];

    reader.read(part);
    System.out.println(new String(part)); // Java

    if (reader.markSupported()) {
        reader.mark(10);
        reader.read(part);
        System.out.println(new String(part)); // Reade

        reader.reset();
        reader.read(part);
        System.out.println(new String(part)); // Reade（重读相同内容）
    }
}
```

### close 与资源释放

`close()` 是 `Reader` 继承自 `Closeable` 的方法，用于释放文件句柄、网络连接等底层资源。**必须确保在读取完成后关闭**。最推荐的方式是使用 **try-with-resources**，它在代码块结束时自动调用 `close()`，即使发生异常也不会遗漏：

```java
try (Reader reader = new FileReader("data.txt")) {
    // 使用 reader
} // 自动 close()
```

如果手动管理，应在 `finally` 块中关闭，并注意关闭操作的异常处理。


## 常用子类与典型用法

### FileReader：读取文本文件

`FileReader` 是读取文件字符流最直接的便捷类，构造器接收 `File` 对象或文件路径字符串，使用系统默认字符编码和默认缓冲区大小。

```java
try (Reader reader = new FileReader("poem.txt")) {
    int ch;
    while ((ch = reader.read()) != -1) {
        System.out.print((char) ch);
    }
}
```

`FileReader` 的局限在于**无法指定字符编码**。如果文件不是系统默认编码（例如在 GBK 环境下读取 UTF-8 文件），应改用 `InputStreamReader` 显式指定 `Charset`。

---

### BufferedReader：按行读取的首选

`BufferedReader` 继承自 `Reader`，通过内部缓冲减少底层 I/O 次数，并提供了 `readLine()` 方法，这是按行读取文本的标准方式。

```java
try (BufferedReader br = new BufferedReader(new FileReader("log.txt"))) {
    String line;
    while ((line = br.readLine()) != null) {
        System.out.println(line);
    }
}
```

`readLine()` 返回不含换行符的行内容；到达末尾时返回 `null`。`BufferedReader` 也支持 `mark/reset`，且缓冲区使这些操作更高效。

---

### StringReader：将字符串作为 Reader 源

`StringReader` 把 `String` 适配为 `Reader`，适用于测试、解析内存中的文本，或需要以统一 `Reader` 接口处理字符串的场景。

```java
try (Reader reader = new StringReader("a=1\nb=2\nc=3");
     BufferedReader br = new BufferedReader(reader)) {
    String line;
    while ((line = br.readLine()) != null) {
        System.out.println(line);
    }
}
```

`StringReader` 不持有外部系统资源，`close()` 实际上不做任何资源释放操作，但为了保持接口一致性，仍建议调用或使用 try-with-resources。


## 使用 Reader 的关键注意事项

1. **Reader 是抽象类，面向接口编程**：方法参数和变量声明应尽量使用 `Reader` 类型，而不是具体子类，这样可以在 `FileReader`、`StringReader`、`BufferedReader` 之间灵活切换。

2. **编码是字符流的核心**：`FileReader` 使用系统默认编码；需要指定编码时，使用 `new InputStreamReader(new FileInputStream(path), StandardCharsets.UTF_8)`。这是字符流相较于字节流最重要的增值点，也是容易出现乱码的根源。

3. **`read(char[])` 的返回值必须使用**：不能假设一次读取就填满数组，也不能用 `new String(buffer)` 而不指定长度，否则会引入多余字符。

4. **mark/reset 不是普遍能力**：先 `markSupported()`，再 `mark()`。`FileReader` 不支持，`BufferedReader` 和 `StringReader` 支持。

5. **始终关闭流**：优先使用 try-with-resources。关闭顺序上，如果存在包装关系，关闭最外层即可，内层通常会被级联关闭。
