# Java 函数式接口（Functional Interface）详解

## 一、什么是函数式接口

**函数式接口 = 只包含一个抽象方法的接口**（SAM，Single Abstract Method）。

这是 Java 8 引入 Lambda 表达式的基础：Lambda 表达式本身没有类型，它必须**依附于一个目标类型（target type）**，而这个目标类型就是函数式接口。换句话说：

> 一个函数式接口，就是 Lambda 表达式 / 方法引用的“类型载体”。

```java
@FunctionalInterface
public interface Greeting {
    void sayHello(String name);   // 唯一的抽象方法
}

// Lambda 赋值给函数式接口类型
Greeting g = name -> System.out.println("Hello, " + name);
g.sayHello("Tom");   // Hello, Tom
```

这里 `Greeting` 定义了 Lambda 的“函数形状”：**接收一个 String，返回 void**。Lambda 只要形状匹配就能赋值。

## 二、`@FunctionalInterface` 注解

```java
@FunctionalInterface
public interface Greeting {
    void sayHello(String name);
}
```

要点：

| 说明 | 详情 |
|---|---|
| 是否必需 | **不必需**，只是编译器检查。只要接口满足“单个抽象方法”，就自动是函数式接口 |
| 作用 | 在编译期校验：若接口不满足条件（0 个或多个抽象方法），直接编译报错 |
| 推荐 | 只要打算让别人写 Lambda，就应该加上，防止后续维护时误加方法 |

```java
@FunctionalInterface
interface Bad {
    void a();
    void b();   // 编译错误：Multiple non-overriding abstract methods found
}
```

## 三、判定规则：哪些方法“不算”抽象方法

这是理解函数式接口最关键的部分。

### 1. `default` 方法和 `static` 方法不算

```java
@FunctionalInterface
public interface Calculator {
    int calculate(int a, int b);              // 抽象方法：算 1 个

    default Calculator andThen(Calculator next) {   // 默认方法：不算
        return (a, b) -> next.calculate(this.calculate(a, b), b);
    }

    static Calculator plus() {                      // 静态方法：不算
        return Integer::sum;
    }

    private int helper() { return 0; }              // 私有方法（Java 9+）：不算
}

Calculator sum = Calculator.plus();
Calculator twice = sum.andThen((x, y) -> x + y);
System.out.println(twice.calculate(1, 2));   // 6
```

### 2. 与 `Object` 的 public 方法**签名完全相同**的方法不算

```java
@FunctionalInterface
interface Foo {
    boolean equals(Object o);   // 不算，因为 Object 已有
    int hashCode();             // 不算
    String toString();          // 不算

    void doWork();              // 唯一的抽象方法 —— 所以 Foo 是函数式接口
}
```

⚠️ **注意签名必须完全一致**：`boolean equals(Foo other)` 就**算**抽象方法了（重载），此时会有两个抽象方法，编译报错。

### 3. 继承关系中的处理

```java
@FunctionalInterface
interface A { void foo(); }

@FunctionalInterface
interface B extends A { }                 // ✅ 仍只有 1 个抽象方法

@FunctionalInterface
interface C extends A {
    void foo();                           // ✅ 覆写父接口方法，不算新增
}

@FunctionalInterface
interface D extends A {
    void bar();                           // ❌ 编译错误：2 个抽象方法
}
```

## 四、Java 自带的四大函数式接口（`java.util.function`）

| 接口 | 函数形状 | 方法 | 用途 |
|---|---|---|---|
| `Function<T,R>` | T → R | `R apply(T t)` | 转换/映射 |
| `Consumer<T>` | T → void | `void accept(T t)` | 消费/副作用 |
| `Supplier<T>` | () → T | `T get()` | 提供/工厂 |
| `Predicate<T>` | T → boolean | `boolean test(T t)` | 判断/过滤 |

```java
import java.util.function.*;

// Function：String -> Integer
Function<String, Integer> len = String::length;
System.out.println(len.apply("hello"));          // 5

// Consumer：消费，无返回
Consumer<String> printer = System.out::println;
printer.accept("消费一条数据");

// Supplier：无输入，产出
Supplier<List<String>> newList = ArrayList::new;
List<String> list = newList.get();

// Predicate：判断
Predicate<String> isEmpty = String::isEmpty;
System.out.println(isEmpty.test(""));            // true
```

### 组合式方法（这是设计上最精妙的地方）

```java
// Function 的组合
Function<Integer, Integer> times2 = x -> x * 2;
Function<Integer, Integer> plus1  = x -> x + 1;
System.out.println(times2.andThen(plus1).apply(3));  // (3*2)+1 = 7
System.out.println(times2.compose(plus1).apply(3));  // (3+1)*2 = 8

// Predicate 的 and / or / negate
Predicate<String> notEmpty   = s -> !s.isEmpty();
Predicate<String> notTooLong = s -> s.length() <= 10;
Predicate<String> valid = notEmpty.and(notTooLong);
System.out.println(valid.test("java"));          // true
```

### 常用变体一览

```java
BiFunction<Integer, Integer, Integer> add = Integer::sum;     // (T,U) -> R
BiConsumer<String, Integer> put = (k, v) -> System.out.println(k + "=" + v);
BiPredicate<String, String> eq  = String::equals;
UnaryOperator<String> upper     = String::toUpperCase;        // T -> T
BinaryOperator<Integer> max     = Integer::max;               // (T,T) -> T

// 原始类型特化版，避免装箱开销
IntFunction<String>   f1 = i -> "n=" + i;
ToIntFunction<String> f2 = String::length;
IntPredicate          f3 = i -> i > 0;
IntBinaryOperator     f4 = (a, b) -> a + b;
BooleanSupplier       f5 = () -> true;
```

## 五、自定义函数式接口（三种实例化方式）

```java
@FunctionalInterface
interface Validator<T> {
    boolean validate(T value);

    // 可以有静态工具方法
    static <T> Validator<T> notNull() {
        return v -> v != null;
    }
}
```

```java
// 方式 1：Lambda
Validator<String> v1 = s -> s.startsWith("A");

// 方式 2：方法引用
Validator<String> v2 = String::isBlank;

// 方式 3：匿名内部类（Java 8 之前的写法，仍有效）
Validator<String> v3 = new Validator<String>() {
    @Override
    public boolean validate(String s) { return s.length() > 3; }
};
```

### 方法引用的四种形式

```java
Function<String, Integer> a = Integer::parseInt;        // 静态方法引用
Function<String, Integer> b = String::length;           // 实例方法引用（未绑定）
Consumer<String> c = System.out::println;               // 实例方法引用（已绑定对象）
Supplier<ArrayList<String>> d = ArrayList::new;         // 构造器引用
Function<String, String[]> e = String[]::new;           // 数组构造器引用
```

## 六、常见坑与注意事项

### 坑 1：Lambda 变量捕获必须是 effectively final

```java
int base = 10;                          // 之后未再赋值
Function<Integer, Integer> f = x -> x + base;   // ✅

int counter = 0;
// Function<Integer, Integer> g = x -> x + counter++;  // ❌ 编译错误
```

### 坑 2：重载导致 Lambda 歧义

当两个重载方法的参数都是函数式接口，且形状“兼容”时，编译器无法确定目标类型：

```java
static void call(Runnable r)      { System.out.println("Runnable"); }
static void call(Supplier<Integer> s) { System.out.println("Supplier"); }

call(() -> System.out.println("hi"));  // ✅ Runnable（void 兼容）
call(() -> 42);                        // ✅ Supplier（有返回值）
// call(() -> Integer.parseInt("1"));  // ❌ 歧义：既是语句表达式又是值表达式
```

解决方案是显式转型：`call((Supplier<Integer>) () -> Integer.parseInt("1"));`

经典现实例子：`ExecutorService.submit(Runnable)` 与 `submit(Callable<T>)`。

### 坑 3：受检异常无法直接抛出

`Function`、`Consumer` 等标准接口的方法签名**没有 `throws`**，所以 lambda 内部不能抛受检异常：

```java
@FunctionalInterface
interface ThrowingFunction<T, R> {
    R apply(T t) throws Exception;      // 允许受检异常

    // 提供一个桥接：转成标准 Function，异常包成 RuntimeException
    static <T, R> Function<T, R> wrap(ThrowingFunction<T, R> f) {
        return t -> {
            try { return f.apply(t); }
            catch (Exception e) { throw new RuntimeException(e); }
        };
    }
}

// 使用
Function<String, Integer> safe = ThrowingFunction.wrap(s -> Integer.parseInt(s));
```

### 坑 4：Lambda 中的 `this` 指向外部类

```java
public class Demo {
    void run() {
        Runnable anon = new Runnable() {
            @Override public void run() { System.out.println(this); }  // 匿名类实例
        };
        Runnable lambda = () -> System.out.println(this);              // 外部 Demo 实例！
    }
}
```

Lambda 是**无状态的、编译期生成的**，不产生新的类实例（不同于匿名内部类），也没有自己的 `this`。

### 坑 5：`Object o = () -> {};` 编译错误

Lambda 没有独立类型，**必须有明确的目标类型**：

```java
// Object o = () -> {};            // ❌ 编译错误
Object o = (Runnable) () -> {};    // ✅ 显式转型
Runnable r = () -> {};             // ✅
```

同理 `var f = (String s) -> s.length();` 也不行（Java 11 起仍然需要目标类型）。

### 坑 6：Java 8 之前就已存在的函数式接口

它们本身就是 SAM 接口，只是没叫这个名字：

```java
Runnable          r = () -> {};
Callable<String>  c = () -> "done";
Comparator<Integer> cmp = (a, b) -> a - b;
FileFilter        ff = f -> f.getName().endsWith(".java");
```

注意 `Callable` 的 `call()` 带 `throws Exception`，而 `Runnable` 不带——这也是判断接口“形状”时要看签名的原因。

## 七、总结速查

| 问题 | 答案 |
|---|---|
| 定义 | 有且仅有一个抽象方法的接口 |
| 注解 | `@FunctionalInterface`，可选，仅编译期检查 |
| 不算抽象方法 | `default`、`static`、`private` 方法，以及与 `Object` 的 public 方法签名完全相同的方法 |
| 用途 | 作为 Lambda / 方法引用的目标类型 |
| 4 个核心 | `Function` / `Consumer` / `Supplier` / `Predicate` |
| 能否有多个 default 方法 | 可以，任意多个 |
| 能否是泛型接口 | 可以（`Comparator<T>`、`Function<T,R>` 都是） |
| 何时编译报错 | 抽象方法数 ≠ 1、重载歧义、捕获非 final 变量、无目标类型 |
