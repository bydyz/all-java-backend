# Java 中 java.io.InputStream 详解

`java.io.InputStream` 是 Java I/O 体系中所有**字节输入流**的抽象基类。它本身不能被实例化，而是定义了“从数据源读取字节”的统一契约，具体的读取行为由子类（如 `FileInputStream`、`ByteArrayInputStream`、`BufferedInputStream` 等）实现。下面从其功能定位、构造器机制以及核心 API 的使用方法展开说明。

---

## 功能定位：字节输入流的统一抽象

InputStream 的核心职责是**从某个数据源（文件、内存字节数组、网络连接、键盘等）按字节读取数据到程序中**。它以 8 位字节为基本单位，因此天然适合处理二进制数据（图片、音频、序列化对象等）。

它的抽象性体现在 `read()` 方法是 `abstract` 的：基类只规定“读一个字节”这个动作，至于“从哪里读、怎么读”，完全交给具体子类决定。正因如此，你永远不会直接 `new InputStream()`，而是面向 `InputStream` 类型编程，运行时注入不同的子类实例。例如：

```java
// 面向 InputStream 抽象编程
InputStream input = new FileInputStream("data.bin");
// 或者
InputStream input = new ByteArrayInputStream(new byte[]{1, 2, 3});
```

这种设计的好处是：后续读取数据的代码（调用 `read`、`close` 等）对数据源透明。只要持有 `InputStream` 引用，就可以用同一套逻辑处理文件、内存或网络流。

---

## 构造器：受保护的无参构造器，供子类调用

`InputStream` 自身**只有一个隐式的 `protected` 无参构造器**，它不能被 `new`，但子类可以通过 `super()` 调用它。抽象类可以有构造器，其作用是让子类在初始化时能够完成基类层面的必要设置；对于 `InputStream` 而言，这个构造器主要是为了满足 Java 语言规范中“子类构造器必须先初始化父类”的要求。

实际使用中，你通过**子类的公共构造器**来获取 `InputStream` 实例。常见的子类构造器示例如下：

```java
// 1. 从文件读取——最常用的子类
InputStream fis = new FileInputStream("input.txt");           // 字符串路径
InputStream fis2 = new FileInputStream(new File("input.txt")); // File 对象

// 2. 从内存字节数组读取——适合测试或内存中数据
byte[] data = "Hello".getBytes(StandardCharsets.UTF_8);
InputStream bais = new ByteArrayInputStream(data);

// 3. 包装另一个 InputStream，增加缓冲能力（装饰器模式）
InputStream bis = new BufferedInputStream(new FileInputStream("large.bin"));
```

其中 `BufferedInputStream` 的构造器接收另一个 `InputStream`，这体现了 `InputStream` 体系中的**装饰器模式**：在不改变原始流类型的前提下，增强其读取性能。

## 核心 API 的使用方法

### 读取数据：`read()` 的三个重载

`read()` 是 InputStream 最核心的方法，共有三个版本，分别对应**逐字节读取、批量读取到数组、批量读取到数组指定区间**。

#### `int read()`：读取单个字节

```java
public abstract int read() throws IOException;
```

它返回读取到的字节值，范围是 **0 ~ 255**（无符号字节被提升为 `int`）。当到达流末尾时，返回 **-1**，这是判断读取结束的标准信号。注意：它返回的是 `int` 而非 `byte`，正是为了用 `-1` 表示“没有更多数据”。

逐字节读取文件的典型写法：

```java
try (InputStream in = new FileInputStream("input.txt")) {
    int b;
    while ((b = in.read()) != -1) {
        System.out.print((char) b);
    }
} // try-with-resources 自动调用 close()
```

这种写法逻辑最简单，但每次 `read()` 都是一次底层 I/O 调用，**性能较差**，仅适合小文件或简单场景。

#### `int read(byte[] b)`：批量读入字节数组

```java
public int read(byte[] b) throws IOException;
```

它尝试将数据读入数组 `b`，返回**实际读取的字节数**；如果没有可用字节，返回 `-1`。关键点：**它不保证一次读满整个数组**，返回的读取数量可能小于 `b.length`，因此必须通过循环反复调用，直到返回 `-1`。

```java
byte[] buffer = new byte[1024];
try (InputStream in = new FileInputStream("large.bin")) {
    int bytesRead;
    while ((bytesRead = in.read(buffer)) != -1) {
        // 处理 buffer[0] 到 buffer[bytesRead-1] 的数据
        process(buffer, bytesRead);
    }
}
```

这是实际项目中最常用的读取模式：**固定大小缓冲区 + 循环直到 `-1`**。缓冲区大小的选择会影响性能，常见取值为 1KB、4KB 或 8KB。

#### `int read(byte[] b, int off, int len)`：读入数组的指定区间

```java
public int read(byte[] b, int off, int len) throws IOException;
```

它与 `read(byte[])` 类似，但允许将数据写入数组的 `off` 位置开始、最多 `len` 个字节的区域。这在需要**复用数组的不同片段**时很有用，也是 `read(byte[])` 的底层等价形式（`read(b)` 等价于 `read(b, 0, b.length)`）。通常直接使用 `read(byte[])` 即可，除非有明确的偏移需求。

### 跳过与预判：`skip()` 与 `available()`

#### `long skip(long n)`：跳过并丢弃指定字节数

```java
public long skip(long n) throws IOException;
```

它尝试跳过 `n` 个字节，返回**实际跳过的字节数**（可能小于 `n`，比如流提前结束）。相比手动调用 `read()` 丢弃数据，`skip()` 通常更高效，因为具体子类可能直接移动文件指针或缓冲区索引，而不必真正读取每个字节。

```java
try (InputStream in = new FileInputStream("data.bin")) {
    long skipped = in.skip(100); // 跳过前 100 字节
    System.out.println("实际跳过了: " + skipped);
    int next = in.read(); // 从第 101 字节开始读取
}
```

#### `int available()`：估计可无阻塞读取的字节数

```java
public int available() throws IOException;
```

它返回的是**在不阻塞的情况下**可以从流中读取的估计字节数，而不是流的总长度。对于 `FileInputStream`，它通常接近剩余文件大小；但对于网络流等，`available()` 可能返回 0 或很小的值，**不能用来判断流是否结束**（判断结束只能用 `read()` 是否返回 `-1`）。

一个常见用法是**根据 `available()` 一次性分配刚好大小的数组**来读取文件（仅适用于文件等可预知长度的源）：

```java
try (InputStream in = new FileInputStream("input.txt")) {
    byte[] all = new byte[in.available()];
    in.read(all);
    System.out.println(new String(all));
}
```

但需要注意：如果数据源长度可能变化，或者 `available()` 的返回值不精确，这种写法存在风险。更稳健的方式仍是使用固定缓冲区循环读取。

### 标记与重置：`mark()`、`reset()`、`markSupported()`

这三个方法提供**回退重新读取**的能力，但并非所有流都支持。

```java
public synchronized void mark(int readlimit);
public synchronized void reset() throws IOException;
public boolean markSupported();
```

- **`mark(int readlimit)`**：在当前读取位置打一个“标记”，`readlimit` 表示标记之后最多还能读多少字节而标记仍然有效。
- **`reset()`**：将流的位置回退到上一次 `mark()` 的位置。
- **`markSupported()`**：判断当前流是否支持标记/重置。`InputStream` 基类的默认实现返回 `false`，`BufferedInputStream` 等子类通常返回 `true`。

```java
InputStream in = new BufferedInputStream(new FileInputStream("data.bin"));
if (in.markSupported()) {
    in.mark(1024);        // 标记当前位置，允许后续最多读 1024 字节后仍可重置
    byte[] header = new byte[16];
    in.read(header);      // 读取一部分
    // ... 判断格式后决定是否回退
    in.reset();           // 回到标记处，重新读取
}
```

如果流的 `markSupported()` 为 `false`，调用 `mark()` 不会报错但也不会生效，调用 `reset()` 会抛出 `IOException`。因此**使用前应先检查 `markSupported()`**。

---

### 关闭流：`close()` 与 try-with-resources

```java
public void close() throws IOException;
```

`close()` 释放流持有的系统资源（文件句柄、网络连接等）。`InputStream` 实现了 `Closeable` 接口，因此可以配合 **try-with-resources** 语句自动关闭，避免因异常导致资源泄漏。

```java
// 推荐写法：try-with-resources 自动关闭
try (InputStream in = new FileInputStream("input.txt")) {
    // 使用 in
} catch (IOException e) {
    e.printStackTrace();
}
// 退出 try 块时，in.close() 会被自动调用
```

如果不使用 try-with-resources，则必须在 `finally` 块中手动调用 `close()`，并注意 `close()` 本身也可能抛出 `IOException`。

## Java 9+ 新增的便捷方法

从 Java 9 开始，`InputStream` 增加了几个常用的默认方法，简化了常见操作：

- **`byte[] readAllBytes()`**：一次性读取流中所有剩余字节，返回字节数组。
- **`long transferTo(OutputStream out)`**：将当前输入流的全部字节传输到指定的输出流，返回传输的字节数。

```java
// readAllBytes 示例
try (InputStream in = new FileInputStream("input.txt")) {
    byte[] content = in.readAllBytes();
    System.out.println(new String(content, StandardCharsets.UTF_8));
}

// transferTo 示例：文件复制的一行式写法
try (InputStream in = new FileInputStream("src.bin");
     OutputStream out = new FileOutputStream("dest.bin")) {
    in.transferTo(out);
}
```

这两个方法内部已经处理了循环读取和缓冲区管理，适合**小文件**或**不想手动管理缓冲区**的场景。对于超大文件，`readAllBytes()` 会将全部内容载入内存，仍应使用固定缓冲区循环读取以控制内存占用。

---

## 小结

`InputStream` 的核心使用脉络可以概括为：**面向抽象类型编程，通过子类构造器获取实例，用 `read()` 系列方法读取字节，用 `skip()`/`available()` 辅助定位与预判，用 `mark()/reset()` 实现回退（需先确认支持），始终用 try-with-resources 确保 `close()` 被调用**。在日常代码中，最常出现的模式是 `while ((n = in.read(buffer)) != -1)` 的缓冲区循环；Java 9 之后，`readAllBytes()` 和 `transferTo()` 在小文件场景下提供了更简洁的替代方案。
