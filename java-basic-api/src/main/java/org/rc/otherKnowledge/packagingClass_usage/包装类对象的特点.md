# Java 包装类对象详解

下面按“对象性、不可变性、缓存、装箱拆箱、比较、空值、性能”等角度详解 Java 包装类对象，并尽量配代码说明。以下代码基于 Java
8+；`new Integer(...)` 在 Java 9+ 已弃用，仅用于演示“不走缓存”。


包装类缓存机制是Java中的一种优化技术，它可以提高程序的性能和节省内存空间。当通过自动装箱机制创建包装类对象时，Java会对一定范围内的包装类对象进行缓存，以便重复使用。具体来说，当需要使用某个包装类的对象时，如果该对象封装的值在缓存的范围内，就返回缓存的对象，否则创建新的对象并返回123.

Java中的八大包装类中，Integer、Byte、Short、Long、Character五大包装类都有缓存机制，且缓存的默认值范围都是-128~127。而Float、Double、Boolean三大包装类并没有缓存机制

---

## 1. 八种基本类型对应的包装类

| 基本类型      | 包装类         | 说明           |
|-----------|-------------|--------------|
| `byte`    | `Byte`      | 继承 `Number`  |
| `short`   | `Short`     | 继承 `Number`  |
| `int`     | `Integer`   | 继承 `Number`  |
| `long`    | `Long`      | 继承 `Number`  |
| `float`   | `Float`     | 继承 `Number`  |
| `double`  | `Double`    | 继承 `Number`  |
| `char`    | `Character` | 不继承 `Number` |
| `boolean` | `Boolean`   | 不继承 `Number` |

所有包装类都是 `final`，不能被继承；都实现 `Serializable`，数值包装类还实现 `Comparable`，可用于排序、作为泛型参数、放入集合。

```java
List<Integer> list = new ArrayList<>();
list.add(1); // 自动装箱

// List<int> list2 = new ArrayList<>(); // 编译错误，泛型不能是基本类型
```

---

## 2. 包装类对象是引用类型：可为 `null`、可调用方法、可放入集合

包装类对象本质是对象引用，因此可以赋值为 `null`，可以作为泛型类型参数，也可以调用对象方法。

```java
Integer a = null;      // 合法，表示“没有值”
Number n = 1;          // 自动装箱为 Integer，再向上转型为 Number
System.out.println(n.intValue()); // 1

System.out.println(Integer.TYPE == int.class);     // true
System.out.println(Integer.class == int.class);    // false
```

注意：`Integer` 是对象，`int` 是基本类型，二者在反射、泛型、默认值上不同。

---

## 3. 包装类对象不可变

包装类对象内部保存的值是 `final` 的，对象一旦创建，值不能修改。类似：

```java
public final class Integer extends Number implements Comparable<Integer> {
    private final int value;
    // ...
}
```

因此 `a++` 并不是修改原对象，而是“拆箱计算，再装箱，让引用指向新对象”。

```java
Integer a = 100;
Integer b = a;

a = a + 1; // 拆箱计算，再装箱，a 指向新对象
System.out.println(a); // 101
System.out.println(b); // 100，b 仍指向原对象
```

方法参数中也能体现：

```java
static void change(Integer x) {
    x = 200; // 只是让局部引用指向新对象
}

Integer v = 100;
change(v);
System.out.println(v); // 100
```

因为不可变，包装类对象本身是线程安全的，适合作为 `HashMap` 的 key；但“引用变量”本身仍可能被多线程修改，需要额外同步控制。

---

## 4. 包装类对象有缓存机制

这是 `==` 最容易踩坑的地方。常见缓存范围：

- `Integer`：默认 `-128 ~ 127`，上限可通过 JVM 参数调整；
- `Byte`：全部 `-128 ~ 127` 缓存；
- `Short`、`Long`：`-128 ~ 127`；
- `Character`：`0 ~ 127`；
- `Boolean`：只有 `TRUE`、`FALSE` 两个常量；
- `Float`、`Double`：通常不缓存。

自动装箱和 `valueOf` 会使用缓存，`new` 不会。

```java
Integer a = 127;
Integer b = 127;
Integer c = 128;
Integer d = 128;
Integer e = new Integer(127); // Java 9+ 已弃用，仅演示

System.out.println(a == b); // true，命中缓存
System.out.println(c == d); // false，超出默认缓存范围
System.out.println(c.equals(d)); // true，值相等
System.out.println(a == e); // false，new 不走缓存
```

其他例子：

```java
Long l1 = 127L, l2 = 127L;
Long l3 = 128L, l4 = 128L;
System.out.println(l1 == l2); // true
System.out.println(l3 == l4); // false

Double d1 = 1.0, d2 = 1.0;
System.out.println(d1 == d2); // false，Double 无缓存

Boolean b1 = true, b2 = true;
System.out.println(b1 == b2); // true，Boolean.TRUE

Character c1 = 'a', c2 = 'a';
Character c3 = '中', c4 = '中';
System.out.println(c1 == c2); // true，0~127 缓存
System.out.println(c3 == c4); // false，超出缓存范围
```

结论：**不要用 `==` 比较两个包装类对象的值**
，除非你明确知道缓存范围且业务允许依赖它。比较值应使用 `equals`、`Objects.equals` 或 `compareTo`。


// 此处是通过自动装箱机制创建包装类对象，故有缓存
Integer a = 1;
Integer b = 1;
System.out.println(a == b); // true

// 在缓存的范围内，对象都来自缓存，故地址一样，范围外的则不同
Integer i = 128;
Integer j = 128;
System.out.println(i == j); // false

// 用new 创建对象，没有缓存
Integer m = new Integer(1); // 新 new 的在堆中
Integer n = 1; // 这个用的是缓冲的常量对象，在方法区
System.out.println(m == n); // false

Integer x = new Integer(1); // 新 new 的在堆中
Integer y = new Integer(1); // 另一个新 new 的在堆中
System.out.println(x == y); // false

Double d1 = 1.0;
Double d2 = 1.0;
System.out.println(d1==d2);//false 比较地址，没有缓存对象，每一个都是新new 的

## 5. 自动装箱与自动拆箱

自动装箱：基本类型 → 包装类，编译后通常调用 `valueOf`。
自动拆箱：包装类 → 基本类型，编译后通常调用 `xxxValue()`。

```java
Integer a = 10;  // 等价于 Integer.valueOf(10)
int b = a;       // 等价于 a.intValue()
a++;             // 等价于 a = Integer.valueOf(a.intValue() + 1)

List<Integer> list = new ArrayList<>();
list.add(1);     // 装箱
int c = list.get(0); // 拆箱
```

自动拆箱最大的坑是 `null`：

```java
Integer n = null;

// int x = n;        // NullPointerException
// int y = n + 1;    // NullPointerException
// if (n == 1) {}    // NullPointerException，n 会拆箱

if (n == null) {
    System.out.println("安全");
}
```

条件表达式也可能触发拆箱：

```java
Integer v = null;
boolean flag = true;

// int r = flag ? v : 0; // 条件表达式类型为 int，v 会拆箱，NPE
```

`switch` 使用包装类型时，如果为 `null` 也会 NPE。

## 6. `equals`、`hashCode`、`compareTo`

包装类的 `equals` 通常是“同类型且值相等”：

```java
Integer i = 1;
Long l = 1L;

System.out.println(i.equals(l)); // false，类型不同
System.out.println(i.intValue() == l.longValue()); // true，拆箱后比较数值
System.out.println(Objects.equals(i, l)); // false
```

`hashCode` 与 `equals` 保持一致，因此包装类适合作为 `HashMap` 的 key：

```java
System.out.println(Integer.valueOf(100).hashCode()); // 100
```

比较大小：

```java
System.out.println(Integer.compare(1, 2)); // -1
System.out.println(Integer.valueOf(1).compareTo(2)); // -1
```

## 7. 包装类对象与基本类型的差异

| 维度     | 基本类型          | 包装类对象                         |
|--------|---------------|-------------------------------|
| 默认值    | `0`、`false` 等 | `null`                        |
| 存储     | 值本身           | 对象引用，对象通常在堆上                  |
| 泛型     | 不支持           | 支持                            |
| 方法     | 无             | 可调用 `intValue()`、`equals()` 等 |
| `null` | 不可以           | 可以                            |
| 比较     | `==` 比较值      | `==` 比较引用，混合时可能拆箱             |
| 性能     | 更轻量           | 有对象头、分配、GC 开销                 |

字段默认值示例：

```java
class Demo {
    Integer a;
    int b;
}

Demo demo = new Demo();
System.out.println(demo.a); // null
System.out.println(demo.b); // 0
```

混合比较示例：

```java
Integer x = 1000;
int y = 1000;
System.out.println(x == y); // true，x 拆箱后与 y 比较

Integer p = 1000;
Integer q = 1000;
System.out.println(p == q); // false，两个引用比较
System.out.println(p.equals(q)); // true，值比较

Integer z = null;
// System.out.println(z == 0); // NPE，z 拆箱
```

## 8. 常用方法：解析、转换、常量

```java
int a = Integer.parseInt("123");       // 返回基本类型 int
Integer b = Integer.valueOf("123");    // 返回包装对象 Integer
Integer c = Integer.valueOf(123);      // 可能使用缓存

System.out.println(Integer.toBinaryString(5)); // 101
System.out.println(Integer.MAX_VALUE);         // 2147483647
```

数值包装类都继承 `Number`，可以统一转换：

```java
Number n1 = 1;     // Integer
Number n2 = 2L;    // Long
Number n3 = 3.9;   // Double

System.out.println(n1.intValue()); // 1
System.out.println(n2.longValue()); // 2
System.out.println(n3.intValue()); // 3，截断，不是四舍五入
```

## 9. 性能注意：循环中避免频繁装箱拆箱

```java
Long sum = 0L;
for (int i = 0; i < 1_000_000; i++) {
    sum += i; // 每轮拆箱、加法、再装箱
}

long sum2 = 0L;
for (int i = 0; i < 1_000_000; i++) {
    sum2 += i; // 推荐：全程基本类型
}
```

集合中存储包装类也有对象开销；缓存只能复用少量小值对象。

---

## 10. 其他注意点

1. **不要用 `new Integer(...)`**：Java 9+ 已弃用，推荐 `Integer.valueOf(...)`。
2. **不要依赖缓存做业务相等判断**：`==` 对包装类比较的是引用。
3. **比较值用 `equals` / `Objects.equals` / `compare`**。
4. **防止自动拆箱 NPE**：包装类变量参与运算、比较、`switch` 前先判空。
5. **不要把缓存包装对象当锁**：如 `synchronized (Integer.valueOf(1))` 可能锁到全局共享对象，风险很大。
6. **浮点包装的 `equals` 按位比较**：`Double.NaN.equals(Double.NaN)` 为 `true`，而 `+0.0` 与 `-0.0` 的 `equals` 为 `false`
   ，与基本类型 `==` 行为不同。
7. **业务建议**：计算、性能敏感场景优先用基本类型；集合泛型、可空字段、API 返回值需要表达“无值”时用包装类。

---

一句话总结：**包装类对象是“不可变、可为 null、可缓存、可放入泛型集合的引用对象”；自动装箱拆箱是语法糖，比较值不要用 `==`
，并重点防范拆箱 NPE 和循环装箱性能问题。**
