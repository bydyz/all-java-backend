`BufferedReader` 是 Java I/O 体系中用于高效读取字符流的核心类。它的核心价值在于**通过缓冲机制极大地减少了对底层物理设备（如磁盘、网络）的 I/O 操作次数，从而显著提升读取性能**。它本身是**装饰器模式**的典型实现，可以为任何 `Reader` 对象动态添加缓冲功能。

---

### 🏗️ 核心功能与工作原理

`BufferedReader` 继承自 `Reader`，其内部维护一个字符数组作为缓冲区。当程序请求读取数据时，`BufferedReader` 会一次性从底层流中读取**一批字符**填充到缓冲区，后续的读取操作直接从内存缓冲区中获取，直到缓冲区为空才会再次访问底层流。

这种设计带来的直接好处是：
- **性能提升**：尤其适用于 `FileReader`、`InputStreamReader` 这类每次 `read()` 都可能触发系统调用的低效 Reader。
- **便利的按行读取**：提供了 `readLine()` 方法，可以方便地处理文本行，这是它相比普通 `Reader` 最常用的功能之一。

默认的缓冲区大小为 **8192 个字符**，通常足够应对大多数场景，也支持在构造时自定义。

---

### 🔧 构造器

`BufferedReader` 没有无参构造器，必须传入一个底层的 `Reader` 实例。

#### 构造器 1：使用默认缓冲区大小

```java
public BufferedReader(Reader in)
```

- **说明**：使用默认大小（8192 字符）的缓冲区包装指定的 `Reader`。
- **示例**：

```java
// 包装 FileReader 读取文件
BufferedReader reader = new BufferedReader(new FileReader("data.txt"));

// 包装 InputStreamReader 读取控制台输入
BufferedReader consoleReader = new BufferedReader(new InputStreamReader(System.in));

// 包装 StringReader 读取字符串
BufferedReader stringReader = new BufferedReader(new StringReader("Hello"));
```

#### 构造器 2：指定缓冲区大小

```java
public BufferedReader(Reader in, int sz)
```

- **说明**：使用指定大小 `sz`（单位：字符）的缓冲区进行包装。如果对性能有极致要求，可以调整缓冲区大小（通常设置为 2 的幂次，如 16384）。
- **示例**：

```java
// 创建一个缓冲区大小为 16KB 的 BufferedReader
BufferedReader reader = new BufferedReader(new FileReader("data.txt"), 16384);
```

### 📚 核心 API 详解与代码示例

#### 读取操作

##### `readLine()`

**最常用的方法**，读取一行文本。当遇到行终止符（`\n`、`\r` 或 `\r\n`）时返回该行内容（**不包含终止符**）；到达流末尾时返回 `null`。

```java
try (BufferedReader reader = new BufferedReader(new StringReader("第一行\n第二行\n第三行"))) {
    String line;
    while ((line = reader.readLine()) != null) {
        System.out.println("读取: " + line);
    }
}
// 输出:
// 读取: 第一行
// 读取: 第二行
// 读取: 第三行
```

##### `read()`

读取**单个字符**，返回其整数值（0-65535）。到达流末尾时返回 `-1`。

```java
try (BufferedReader reader = new BufferedReader(new StringReader("ABC"))) {
    int ch;
    while ((ch = reader.read()) != -1) {
        System.out.print((char) ch); // 输出: ABC
    }
}
```

##### `read(char[] cbuf, int off, int len)`

**批量读取**字符到数组的指定部分，返回实际读取的字符数；到达末尾返回 `-1`。批量读取通常比逐个字符读取更高效。

```java
try (BufferedReader reader = new BufferedReader(new StringReader("Java BufferedReader"))) {
    char[] buffer = new char[10];
    int charsRead = reader.read(buffer, 0, 10);
    System.out.println("读取了 " + charsRead + " 个字符: " + new String(buffer, 0, charsRead));
}
// 输出: 读取了 10 个字符: Java Buffe
```

##### `lines()` (Java 8+)

返回一个 `Stream<String>`，其中每个元素是读取到的一行文本。这为使用 Stream API 进行函数式处理提供了便利。

```java
try (BufferedReader reader = new BufferedReader(new StringReader("apple\nbanana\ncherry"))) {
    reader.lines()
          .map(String::toUpperCase)
          .forEach(System.out::println);
}
// 输出:
// APPLE
// BANANA
// CHERRY
```

#### 流控制操作

##### `skip(long n)`

**跳过并丢弃** `n` 个字符，返回实际跳过的字符数（可能小于 `n`，例如在流末尾附近）。这比先读取再丢弃效率更高。

```java
try (BufferedReader reader = new BufferedReader(new StringReader("ABCDEFGHIJ"))) {
    long skipped = reader.skip(3); // 跳过 A, B, C
    System.out.println("跳过了 " + skipped + " 个字符");
    System.out.println("下一个字符: " + (char) reader.read()); // 输出: D
}
```

##### `ready()`

判断流是否**已准备好被读取**（即缓冲区中有可读数据，或底层流有数据可读，读取操作不会阻塞）。返回 `true` 表示可以立即读取。

```java
// 注意：ready() 返回 false 并不代表流已结束，仅表示当前读取可能阻塞
```

##### `mark(int readAheadLimit)` 与 `reset()`

用于**标记位置**和**回退到标记位置**。`mark` 在当前位置做标记，`reset` 将流重置到最近一次标记的位置。`readAheadLimit` 指定在标记失效前最多可读取的字符数。

```java
try (BufferedReader reader = new BufferedReader(new StringReader("Hello, World!"))) {
    // 读取前 5 个字符
    char[] part1 = new char[5];
    reader.read(part1);
    System.out.println("第一次读取: " + new String(part1)); // Hello

    reader.mark(100); // 标记当前位置，允许后续读取 100 个字符内有效

    // 继续读取 7 个字符
    char[] part2 = new char[7];
    reader.read(part2);
    System.out.println("第二次读取: " + new String(part2)); // , World

    reader.reset(); // 回退到 mark 时的位置

    // 再次读取，得到的还是 ", World"
    char[] part3 = new char[7];
    reader.read(part3);
    System.out.println("reset 后读取: " + new String(part3)); // , World
}
```

> **注意**：`BufferedReader` 的 `markSupported()` **始终返回 `true`**，因此可以直接使用 `mark`/`reset`，无需额外判断。

#### 资源管理与状态查询

##### `close()`

关闭流并释放资源。**关键点**：关闭 `BufferedReader` 时，其**底层包装的 `Reader` 也会被自动关闭**。

**务必使用 try-with-resources**，以确保资源在任何情况下都能正确释放。

```java
try (BufferedReader reader = new BufferedReader(new FileReader("data.txt"))) {
    // 使用 reader 进行读取
} // 此处 reader 会自动关闭，底层的 FileReader 也随之关闭
```

##### `markSupported()`

判断当前流是否支持 `mark`/`reset` 操作。对于 `BufferedReader`，**始终返回 `true`**。

---

### 💡 关键注意事项

1. **优先使用 `try-with-resources`**：这是管理 `BufferedReader` 资源的标准方式，可以避免资源泄漏。
2. **`readLine()` 与换行符**：`readLine()` 返回的内容**不包含**行终止符。如果需要保留原始格式，需要自行追加 `System.lineSeparator()`。
3. **`ready()` 的局限性**：`ready()` 返回 `false` 仅表示读取可能阻塞，**不代表流已结束**。判断流是否结束应通过 `read()` 返回 `-1` 或 `readLine()` 返回 `null` 来进行。
4. **线程安全性**：`BufferedReader` 的读取操作是**同步的**，在多线程环境下是线程安全的，但这也意味着并发读取时会有锁开销。
5. **`BufferedReader` vs `Scanner`**：如果仅需逐行读取文本，`BufferedReader` 性能更好；如果需要解析结构化数据（如整数、token），`Scanner` 更为便捷。
