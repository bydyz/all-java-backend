缓冲流是 Java I/O 体系中用于**提升读写性能**的核心工具。它通过引入内存缓冲区，将多次小的、零散的 I/O 操作合并为少数几次大的批量操作，从而大幅减少与磁盘或网络等慢速设备的交互次数，实现效率的质的飞跃。

## 🚀 什么是缓冲流？作用是什么？

缓冲流（也叫高效流）是对基础字节流（`InputStream`/`OutputStream`）和字符流（`Reader`/`Writer`）的一种**装饰器（Decorator）增强**。它的核心原理是在内存中开辟一块**缓冲区**（内部通常是一个字节数组或字符数组），默认大小一般为 **8192 字节**（8KB）。

其作用机制非常直观：

- **读取时**：一次性从底层数据源（如文件）读取一大块数据填满缓冲区，之后程序从缓冲区中逐个读取数据。当缓冲区读完，再发起下一次大的读取。
- **写入时**：程序先将数据写入缓冲区，当缓冲区被填满（或流被关闭/刷新）时，才将整块数据一次性写入底层目的地。

这种做法将“**多次小批量 IO**”转变为“**少数大批量 IO**”，显著降低了频繁系统调用带来的开销。

## 📂 缓冲流有哪些分类？

根据处理的数据类型，缓冲流分为两大类，分别对应字节流和字符流，共四个核心类。

| 分类 | 输入流（用于读取） | 输出流（用于写入） | 处理数据 |
| :--- | :--- | :--- | :--- |
| **字节缓冲流** | `BufferedInputStream` | `BufferedOutputStream` | 字节（二进制数据，如图片、音频、可执行文件） |
| **字符缓冲流** | `BufferedReader` | `BufferedWriter` | 字符（文本数据，自带编码处理） |

字符缓冲流还提供了两个实用的特有方法：`BufferedReader.readLine()`（按行读取文本）和 `BufferedWriter.newLine()`（写入平台相关的换行符）。

## ⚡ 效率比较：缓冲流到底有多快？

效率提升是缓冲流存在的根本意义，差距通常是指数级的。以下数据均来自实际的文件复制测试：

**场景一：逐字节复制大文件（约 375MB）**

- **普通字节流**：耗时漫长，测试中甚至“十几分钟过去了”仍未完成。
- **字节缓冲流（逐字节读写）**：耗时约 **8016 毫秒（约 8 秒）**。即便依然是一次读写一个字节，但因为实际 IO 由缓冲区代理，性能已天差地别。

**场景二：复制一个 150MB 的文件（使用数组读写）**

- **普通流 + 数组缓冲**：耗时 **2300 毫秒**。
- **缓冲流 + 数组缓冲**：耗时 **623 毫秒**。在两者都使用了额外数组缓冲的情况下，缓冲流依然快了近 4 倍。

**效率跃升的关键：缓冲流 + 数组**

缓冲流虽强，但如果在调用 `read()`/`write()` 时依然**逐字节**操作，其内部仍存在一定的单字节方法调用开销。配合**数组**进行块读写，能进一步减少方法调用次数。在上述 375MB 文件测试中，使用 `byte[]` 数组配合缓冲流，时间从 8016 毫秒直接降至 **666 毫秒**。

## 💻 代码示例

### 1. 字节缓冲流：文件复制（最常用范式）

以下代码展示了**缓冲流 + 数组**的最佳实践，这是复制二进制文件（图片、视频、exe 等）的标准高效写法。

```java
import java.io.*;

public class BufferedByteStreamDemo {
    public static void main(String[] args) {
        String source = "source.exe";
        String dest = "dest.exe";

        // 推荐使用 try-with-resources 自动关闭流
        try (BufferedInputStream bis = new BufferedInputStream(new FileInputStream(source));
             BufferedOutputStream bos = new BufferedOutputStream(new FileOutputStream(dest))) {

            byte[] buffer = new byte[8192]; // 常与缓冲区默认大小对齐
            int len;
            // 一次性读取一块数据到数组，再一次性写出
            while ((len = bis.read(buffer)) != -1) {
                bos.write(buffer, 0, len);
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

### 2. 字符缓冲流：文本文件按行读写

`BufferedReader` 的 `readLine()` 方法让文本处理变得极其简洁。

```java
import java.io.*;

public class BufferedCharStreamDemo {
    public static void main(String[] args) {
        String source = "input.txt";
        String dest = "output.txt";

        try (BufferedReader reader = new BufferedReader(new FileReader(source));
             BufferedWriter writer = new BufferedWriter(new FileWriter(dest))) {

            String line;
            while ((line = reader.readLine()) != null) { // 一次读一行，无换行符
                writer.write(line);
                writer.newLine(); // 写入平台相关的换行符
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

## 💎 总结与最佳实践

1. **性能定位**：**缓冲流（配合数组） > 缓冲流（单字节） >> 普通流**。在处理中大文件时，性能差异会非常明显。
2. **包装而非替代**：缓冲流本身不直接连接数据源，它**必须包装一个底层的节点流**（如 `FileInputStream`），为其提供缓冲能力。
3. **资源管理**：始终使用 **try-with-resources** 语句。关闭缓冲流时，它会自动调用底层流的 `close()` 方法，无需手动关闭两次。
4. **缓冲区大小**：默认 8KB 在绝大多数场景下已足够。如果涉及超大批量数据的特定场景，可以通过带 `size` 参数的构造方法（如 `new BufferedInputStream(in, 32768)`）进行调优，但需权衡内存占用。
5. **场景选择**：处理**二进制文件**（图片、音视频）用**字节缓冲流**；处理**文本文件**，尤其是需要按行操作时，优先使用**字符缓冲流**。
