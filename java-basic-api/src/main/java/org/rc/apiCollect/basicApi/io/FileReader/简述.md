`java.io.FileReader` 是 Java I/O 体系中用于**以字符为单位读取文本文件**的便捷类。它的设计目标很明确：当你只需要用**系统默认编码**读取一个文本文件时，它让代码尽可能简洁。但它的“便捷”也带来了一个关键限制——**无法直接指定字符编码**，这在处理跨平台文本文件时需要特别注意。

---

## 功能定位

`FileReader` 继承自 `InputStreamReader`，本质上是一个“字节流 → 字符流”的适配器，只是把 `FileInputStream` 作为默认的字节来源封装了起来。

```java
public class FileReader extends InputStreamReader { ... }
```

它适合：读取字符文件（如 `.txt`、`.csv`），且文件编码与系统默认编码一致。
它不适合：读取原始字节数据（此时应使用 `FileInputStream`），或需要**显式指定编码**的场景（此时应使用 `InputStreamReader` 配合 `FileInputStream`）。

> **关于编码的关键提醒**：`FileReader` 使用平台默认字符集，无法在构造时指定编码。如果文件编码与系统默认编码不一致（例如在 UTF-8 环境中读取 GBK 文件），就会出现乱码。需要控制编码时，应改用 `new InputStreamReader(new FileInputStream(file), charset)`。

---

## 构造器

`FileReader` 提供了多个重载构造器，主要区别在于**数据源的指定方式**和**是否可指定编码**。

### 构造器一览

| 构造器 | 说明 |
|---|---|
| `FileReader(String fileName)` | 从文件路径字符串创建，使用**平台默认编码** |
| `FileReader(File file)` | 从 `File` 对象创建，使用**平台默认编码** |
| `FileReader(FileDescriptor fd)` | 从 `FileDescriptor` 创建，使用**平台默认编码** |
| `FileReader(String fileName, Charset charset)` | **Java 11+**，指定编码 |
| `FileReader(File file, Charset charset)` | **Java 11+**，指定编码 |

前三个构造器在文件不存在时会抛出 `FileNotFoundException`，它是 `IOException` 的子类，属于**受检异常**，必须显式捕获或声明抛出。Java 11 新增的带 `Charset` 参数的构造器解决了“无法指定编码”的核心痛点。

### 代码示例

```java
import java.io.*;
import java.nio.charset.StandardCharsets;

public class FileReaderConstructors {
    public static void main(String[] args) {
        // 1. 从文件路径字符串创建（默认编码）
        try (FileReader r1 = new FileReader("data.txt")) {
            // 使用 r1 读取
        } catch (IOException e) {
            e.printStackTrace();
        }

        // 2. 从 File 对象创建（默认编码）
        File file = new File("data.txt");
        try (FileReader r2 = new FileReader(file)) {
            // 使用 r2 读取
        } catch (IOException e) {
            e.printStackTrace();
        }

        // 3. Java 11+：显式指定 UTF-8 编码
        try (FileReader r3 = new FileReader("data.txt", StandardCharsets.UTF_8)) {
            // 使用 r3 读取
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

**实践建议**：始终使用 **try-with-resources** 创建 `FileReader`，确保底层文件句柄在读取完成后自动关闭，避免资源泄漏。

## 核心读取 API

`FileReader` 自身没有定义新的读取方法，所有读取能力都继承自 `InputStreamReader` 和 `Reader`。以下是最常用的读取方法。

### `int read()` —— 逐字符读取

每次读取**一个字符**，返回 0–65535 的字符码；到达文件末尾返回 `-1`。

```java
try (FileReader reader = new FileReader("data.txt")) {
    int ch;
    while ((ch = reader.read()) != -1) {
        System.out.print((char) ch);
    }
}
```

这种方式逻辑最直观，但**性能最差**，因为每个字符都触发一次方法调用和底层 I/O 交互，仅适合极小的文件。

### `int read(char[] cbuf)` —— 批量读取到字符数组

将字符读入 `char[]` 缓冲区，返回**实际读取的字符数**；末尾返回 `-1`。

```java
try (FileReader reader = new FileReader("data.txt")) {
    char[] buffer = new char[1024];
    int charsRead;
    while ((charsRead = reader.read(buffer)) != -1) {
        // 只处理实际读取到的部分
        System.out.print(new String(buffer, 0, charsRead));
    }
}
```

这是**推荐的默认读取方式**：一次读取一批字符，显著减少了方法调用次数，在简洁性和性能之间取得了平衡。缓冲区大小（如 1024、8192）可根据文件规模调整。

### `int read(char[] cbuf, int off, int len)` —— 读取到数组的指定区间

将最多 `len` 个字符读入 `cbuf`，从索引 `off` 开始存放，返回实际读取数。适合需要将多次读取结果**累积到同一个数组的不同位置**的场景。

```java
char[] bigBuffer = new char[4096];
int offset = 0;
try (FileReader reader = new FileReader("data.txt")) {
    int n;
    while (offset < bigBuffer.length &&
           (n = reader.read(bigBuffer, offset, bigBuffer.length - offset)) != -1) {
        offset += n;
    }
}
```

## 继承自 `Reader` 的其他实用方法

除 `read` 外，`Reader` 还定义了一些辅助方法，`FileReader` 可以直接使用。

### `void close()`

关闭流并释放底层文件资源。关闭后再调用 `read` 会抛出 `IOException`。**必须调用**，推荐用 try-with-resources 自动完成。

### `long skip(long n)`

跳过并丢弃 `n` 个字符，返回**实际跳过的字符数**（可能少于 `n`，例如接近文件末尾时）。

```java
try (FileReader reader = new FileReader("data.txt")) {
    long skipped = reader.skip(10);   // 跳过前 10 个字符
    System.out.println("实际跳过: " + skipped);
    int ch = reader.read();           // 读取第 11 个字符
}
```

### `boolean ready()`

判断流是否**可以立即读取**而不发生阻塞。对于本地文件，通常在有数据可读时返回 `true`，到达末尾后返回 `false`。它**不能替代 `read() == -1` 的末尾判断**。

```java
try (FileReader reader = new FileReader("data.txt")) {
    while (reader.ready()) {
        System.out.print((char) reader.read());
    }
}
```

### `boolean markSupported()` / `void mark(int)` / `void reset()`

`FileReader` 的 `markSupported()` **返回 `false`**，因此 `mark()` 和 `reset()` 不可用。如果需要标记/重置能力，应包装为 `BufferedReader`（`BufferedReader` 支持 `mark`）。

## 推荐用法：包装为 `BufferedReader`

`FileReader` **没有内部缓冲**，每次 `read()` 都可能直接触碰底层文件。**生产代码中读取文本文件的标准做法**是将 `FileReader` 包装进 `BufferedReader`，以获得 `readLine()` 和更好的批量读取性能。

```java
import java.io.*;

public class FileReaderWithBufferedReader {
    public static void main(String[] args) {
        try (BufferedReader br = new BufferedReader(new FileReader("data.txt"))) {
            String line;
            while ((line = br.readLine()) != null) {
                System.out.println(line);
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

`BufferedReader.readLine()` 返回不含行终止符的字符串，末尾返回 `null`，是按行处理文本时的首选方式。

## 编码控制：何时放弃 `FileReader`

如果文件编码与系统默认编码不一致，`FileReader` 的“便捷”反而会成为问题。以下是安全的替代方案：

```java
import java.io.*;
import java.nio.charset.StandardCharsets;

// 需要指定编码时：InputStreamReader + FileInputStream
try (BufferedReader br = new BufferedReader(
        new InputStreamReader(new FileInputStream("data.txt"), StandardCharsets.UTF_8))) {
    String line;
    while ((line = br.readLine()) != null) {
        System.out.println(line);
    }
}
```

这一模式保留了 `BufferedReader` 的缓冲和按行读取能力，同时**显式控制了字节 → 字符的解码过程**，是处理外部文本文件时更稳妥的写法。Java 11+ 的 `new FileReader(file, charset)` 也可以指定编码，但它同样没有缓冲，仍建议在外层再包装 `BufferedReader`。

---

## 小结

`FileReader` 是一个**定位清晰的便利类**：用默认编码、以字符为单位读文件时，它让代码最简洁；一旦涉及编码控制或性能要求，就应当转向 `InputStreamReader` + `BufferedReader` 的组合。日常使用中记住两条原则即可：**始终用 try-with-resources 管理资源**；**需要显式编码或按行读取时，不要单独使用 `FileReader`**。
