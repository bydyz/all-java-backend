# Java 反射创建运行时类的对象

## 一、术语与核心思路

“运行时类”指的是程序运行期间由 JVM 实际加载的那个类，它由内存中的 `java.lang.Class` 对象描述。所谓“利用反射创建运行时类的对象”，就是：

> 先拿到某个类的 `Class` 对象 → 通过它获取构造器（`Constructor`）→ 调用 `newInstance(...)` 创建该类的实例。

这个过程完全在运行期完成，编译期不需要知道具体类名，也不需要 `new` 关键字。

## 二、获取 Class 对象的四种方式

| 方式 | 示例 | 适用场景 |
|---|---|---|
| 类字面量 | `User.class` | 编译期已知类 |
| 对象反查 | `obj.getClass()` | 已有实例 |
| `Class.forName` | `Class.forName("com.demo.User")` | 由字符串（如配置）动态加载，会触发类初始化 |
| 类加载器 | `cl.loadClass("com.demo.User")` | 不触发类初始化 |

## 三、创建对象的三种方式对比

| 方式 | 能否调有参构造 | 能否调私有构造 | 状态 |
|---|---|---|---|
| `Class.newInstance()` | ❌ 只能无参 | ❌ 只能 public | Java 9 起 `@Deprecated` |
| `Constructor.newInstance(...)` | ✅ | ✅（需 `setAccessible(true)`） | 推荐 |
| `Array.newInstance(type, len)` | — | — | 专门创建数组 |

`Class.newInstance()` 被废弃的核心原因：它只能调用**无参且可访问**的构造器，并且会把构造器内部抛出的受检异常“原样”抛出，绕过编译期异常检查；而 `Constructor.newInstance()` 会统一包装为 `InvocationTargetException`，语义更清晰。

## 四、完整代码示例

```java
import java.lang.reflect.Constructor;
import java.lang.reflect.InvocationTargetException;

class User {
    private String name;
    private int age;

    public User() {
        System.out.println("[User] 无参构造器执行");
    }

    public User(String name, int age) {
        this.name = name;
        this.age = age;
        System.out.println("[User] 有参构造器执行: " + name + ", " + age);
    }

    private User(String name) {
        this.name = name;
        System.out.println("[User] 私有构造器执行: " + name);
    }

    @Override
    public String toString() {
        return "User{name='" + name + "', age=" + age + "}";
    }
}

public class ReflectionCreateObjectDemo {

    /** 非静态内部类，演示其构造器带有隐藏的外围类参数 */
    public class Inner {
        public Inner() { System.out.println("[Inner] 构造器执行"); }
    }

    public static void main(String[] args) throws Exception {

        /* ---------- 1. 获取运行时类的 Class 对象 ---------- */
        Class<?> clazz = Class.forName("User");  // 默认包；有包时写全限定名
        System.out.println("运行时类: " + clazz.getName());

        /* ---------- 2. Class.newInstance()（已废弃，不推荐） ---------- */
        // User u0 = (User) clazz.newInstance();  // Java 9+ 会给出弃用警告

        /* ---------- 3. 无参构造器 ---------- */
        Constructor<?> noArg = clazz.getConstructor();      // 只能拿到 public
        User u1 = (User) noArg.newInstance();               // 等价于 new User()
        System.out.println(u1);

        /* ---------- 4. 有参构造器 ---------- */
        Constructor<?> twoArg = clazz.getConstructor(String.class, int.class);
        User u2 = (User) twoArg.newInstance("张三", 20);
        System.out.println(u2);

        /* ---------- 5. 私有构造器（getDeclared + setAccessible） ---------- */
        Constructor<?> privateCtor = clazz.getDeclaredConstructor(String.class);
        privateCtor.setAccessible(true);                    // 突破访问控制
        User u3 = (User) privateCtor.newInstance("李四");
        System.out.println(u3);

        /* ---------- 6. 遍历所有构造器（含私有） ---------- */
        for (Constructor<?> c : clazz.getDeclaredConstructors()) {
            System.out.println("构造器: " + c + "，参数个数 = " + c.getParameterCount());
        }

        /* ---------- 7. 非静态内部类：构造器第一个参数是外围类 ---------- */
        Constructor<?> innerCtor = Inner.class.getConstructor(ReflectionCreateObjectDemo.class);
        Inner inner = (Inner) innerCtor.newInstance(new ReflectionCreateObjectDemo());
        System.out.println("内部类实例: " + inner);

        /* ---------- 8. 异常处理范式 ---------- */
        try {
            Constructor<?> bad = clazz.getConstructor(int.class);   // 不存在
            bad.newInstance(1);
        } catch (NoSuchMethodException e) {
            System.out.println("找不到匹配的构造器: " + e.getMessage());
        } catch (InvocationTargetException e) {
            System.out.println("构造器内部抛异常，真实原因: " + e.getCause());
        } catch (InstantiationException | IllegalAccessException e) {
            System.out.println("实例化失败: " + e);
        }
    }
}
```

输出大致为：

```
运行时类: User
[User] 无参构造器执行
User{name='null', age=0}
[User] 有参构造器执行: 张三, 20
User{name='张三', age=20}
[User] 私有构造器执行: 李四
User{name='李四', age=0}
构造器: public User()，参数个数 = 0
...
```

## 五、补充场景

**数组**（不能直接 `newInstance`）：

```java
Object arr = Array.newInstance(String.class, 3);   // 等价 new String[3]
Array.set(arr, 0, "hello");
```

**Record 类**（Java 16+）：通过规范构造器即可创建：

```java
record Point(int x, int y) {}
Constructor<?> c = Point.class.getConstructor(int.class, int.class);
Point p = (Point) c.newInstance(1, 2);
```

**枚举**：不能通过反射创建。`Constructor.newInstance` 会抛 `IllegalArgumentException("Cannot reflectively create enum objects")`，因为 JVM 内部做了保护。

**抽象类、接口、基本类型、void**：`newInstance` 会抛 `InstantiationException`。

## 六、注意事项

1. **异常分类要分清**
  - `NoSuchMethodException`：`getConstructor` 找不到匹配签名
  - `IllegalAccessException`：访问了不可访问的构造器且未 `setAccessible(true)`
  - `InvocationTargetException`：构造器**内部**抛了异常，用 `getCause()` 取真实原因
  - `InstantiationException`：抽象类/接口/数组类等无法实例化
  - `IllegalArgumentException`：枚举类等特殊类型

2. **`getConstructor` 与 `getDeclaredConstructor` 的区别**：前者只查 public 且包含继承来的；后者查本类所有（含 private），但**不包含继承来的**构造器（构造器本来也不继承）。

3. **`setAccessible(true)` 是“关闭访问检查”**，并非修改修饰符；在模块化（JPMS）环境下，跨模块访问非 public 成员可能仍需 `--add-opens`。

4. **性能**：反射创建比直接 `new` 慢一个数量级以上。高频场景应缓存 `Constructor` 对象（放入 `ConcurrentHashMap`），或改用 `MethodHandle`、`LambdaMetafactory` 等更快的方案。

5. **与其他“运行期创建对象”方式的区别**：`clone()`、反序列化、`Unsafe.allocateInstance` 也能在运行期产生对象，但它们不走构造器，不属于“反射通过构造器创建对象”的范畴；`Unsafe` 的方式连字段初始化和构造器都跳过，属于非常规手段，生产代码应避免。
