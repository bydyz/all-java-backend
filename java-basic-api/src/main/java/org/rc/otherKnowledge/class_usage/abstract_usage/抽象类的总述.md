# Java 抽象类（abstract class）详解

---

## 一、语法格式

抽象类：被 abstract 修饰的类。
抽象方法：被 abstract 修饰没有方法体的方法。

### 1. 抽象类的声明

```java
[访问修饰符] abstract class 类名 [extends 父类] [implements 接口列表] {
    // 成员变量（普通变量、常量都可以）
    // 构造方法（可以有，供子类调用）
    // 普通方法（有方法体）
    // 抽象方法（无方法体，以 ; 结尾）
    // 静态方法、静态代码块、内部类……
}
```

### 2. 抽象方法的声明

```java
[访问修饰符] abstract 返回值类型 方法名(参数列表);
// 注意：没有 {}，直接以分号结尾
```

### 3. 关键字组合速查

| 写法                                       | 是否合法 | 说明                     |
|------------------------------------------|------|------------------------|
| `abstract class`                         | ✅    | 抽象类                    |
| `abstract void f();`                     | ✅    | 抽象方法                   |
| `abstract final class`                   | ❌    | 语义冲突（抽象要继承，final 禁止继承） |
| `abstract private void f();`             | ❌    | 私有方法子类无法重写，抽象无意义       |
| `abstract static void f();`              | ❌    | 静态方法属于类，与"由子类实现"冲突     |
| `abstract final void f();`               | ❌    | 被覆盖与禁止覆盖冲突             |
| `abstract native/synchronized void f();` | ❌    | 均不合法                   |
| `abstract` 修饰构造方法 / 变量                   | ❌    | 只有类和方法能被 abstract 修饰   |

## 二、使用说明（核心要点）

1. **抽象类 = 不能实例化的类**：它存在的价值是**被继承**，为子类定义"共同契约 + 公共实现"。如果创建，编译无法通过而报错。
2. **抽象方法 = 只有签名、没有实现的方法**，强制子类必须重写。否则，编译无法通过而报错。除非该子类也是抽象类。
3. **抽象类可以有构造方法**：虽然自己不能 `new`，但子类构造方法会通过 `super(...)` 调用它，用来初始化抽象类中的成员变量。
4. **抽象类既可以有抽象方法，也可以有普通方法、成员变量、静态方法、内部类**——这是它与接口的最大差异（接口不能有实例字段、构造方法）。
5. **多态的核心用法**：用抽象类作为**引用类型**去指向子类对象，调用时动态绑定到子类实现。
6. **常见设计模式**：模板方法模式（Template Method）最典型的载体就是抽象类。
7. **有抽象方法的类必定是抽象类**

## 三、完整示例代码

### 示例 1：基础用法 —— 形状体系

```java
// ---------- 抽象父类 ----------
public abstract class Shape {

    // ① 抽象类可以有成员变量
    protected final String name;

    // ② 抽象类可以有构造方法（供子类 super() 调用）
    public Shape(String name) {
        this.name = name;
    }

    // ③ 抽象方法：只声明，不实现，强制子类实现
    public abstract double area();

    public abstract double perimeter();

    // ④ 普通方法：定义公共逻辑，内部可以调用抽象方法（多态）
    public void printInfo() {
        System.out.printf("%s -> 面积 = %.2f, 周长 = %.2f%n",
                name, area(), perimeter());
    }

    // ⑤ 抽象类可以有静态方法
    public static Shape maxArea(Shape a, Shape b) {
        return a.area() >= b.area() ? a : b;
    }
}
```

```java
// ---------- 子类 1：圆 ----------
public class Circle extends Shape {
    private final double r;

    public Circle(double r) {
        super("圆形");        // 必须显式/隐式调用父类构造方法
        this.r = r;
    }

    // 此时的方法重写，是子类对父类抽象方法的完成实现，我们将这种方法重写的操作，也叫做实现方法。
    @Override
    public double area() {
        return Math.PI * r * r;
    }

    @Override
    public double perimeter() {
        return 2 * Math.PI * r;
    }
}
```

```java
// ---------- 子类 2：矩形 ----------
public class Rectangle extends Shape {
    private final double w, h;

    public Rectangle(double w, double h) {
        super("矩形");
        this.w = w;
        this.h = h;
    }

    @Override
    public double area() { return w * h; }

    @Override
    public double perimeter() { return 2 * (w + h); }
}
```

```java
// ---------- 测试 ----------
public class ShapeDemo {
    public static void main(String[] args) {
        // Shape s = new Shape("x");   // ❌ 编译错误：抽象类不能实例化

        Shape[] shapes = { new Circle(2), new Rectangle(3, 4) };

        for (Shape s : shapes) {
            s.printInfo();              // ✅ 多态：运行时调用子类实现
        }

        Shape big = Shape.maxArea(shapes[0], shapes[1]);
        System.out.println("面积较大者：" + big.name);
    }
}
```

**输出：**

```
圆形 -> 面积 = 12.57, 周长 = 12.57
矩形 -> 面积 = 12.00, 周长 = 14.00
面积较大者：圆形
```

**关键点解释：**

- `Shape` 不能 `new`，但可以声明为引用类型，指向 `Circle`/`Rectangle` 实例，体现**面向抽象编程**。
- `printInfo()` 在父类中定义了一次，被两个子类复用；方法里调用 `area()` 时，实际执行的是子类版本（**动态绑定**）。
- 如果没有子类实现 `area()`、`perimeter()`，代码根本无法通过编译——这是抽象方法的**编译期约束**。

### 示例 2：模板方法模式（抽象类最经典的使用场景）

抽象类定义"算法骨架"，把可变步骤留给子类实现：

```java
public abstract class CaffeineBeverage {

    // 模板方法：算法骨架，用 final 防止子类改写流程
    public final void prepareRecipe() {
        boilWater();              // 公共步骤，父类已实现
        brew();                   // 可变步骤，交给子类
        pourInCup();              // 公共步骤
        if (customerWantsCondiments()) {   // 钩子方法（hook）
            addCondiments();
        }
    }

    // 公共步骤：private，子类无需关心
    private void boilWater()  { System.out.println("烧开水"); }
    private void pourInCup()  { System.out.println("倒入杯中"); }

    // 可变步骤：抽象方法，子类必须实现
    protected abstract void brew();
    protected abstract void addCondiments();

    // 钩子方法：给子类一个"可选改写"的开关，默认返回 true
    protected boolean customerWantsCondiments() {
        return true;
    }
}
```

```java
public class Coffee extends CaffeineBeverage {
    @Override protected void brew()           { System.out.println("用沸水冲泡咖啡粉"); }
    @Override protected void addCondiments()  { System.out.println("加糖和牛奶"); }
}

public class Tea extends CaffeineBeverage {
    @Override protected void brew()           { System.out.println("用沸水浸泡茶叶"); }
    @Override protected void addCondiments()  { System.out.println("加柠檬"); }

    // 覆盖钩子方法，改变流程分支
    @Override protected boolean customerWantsCondiments() { return false; }
}
```

```java
public class TemplateDemo {
    public static void main(String[] args) {
        CaffeineBeverage coffee = new Coffee();
        coffee.prepareRecipe();
        System.out.println("-----");
        CaffeineBeverage tea = new Tea();
        tea.prepareRecipe();
    }
}
```

### 示例 3：抽象类实现接口，把实现推迟给子类

```java
interface Flyable {
    void fly();
}

// 抽象类实现接口，但可以不实现接口中的方法，
// 这些方法就"变成"抽象方法，留给具体子类实现
public abstract class Bird implements Flyable {

    protected String name;

    public Bird(String name) { this.name = name; }

    // 父类仍可以定义自己的抽象方法
    public abstract void eat();

    // 也可以先实现一部分接口方法
    public void rest() { System.out.println(name + " 在休息"); }
}

class Sparrow extends Bird {
    public Sparrow(String name) { super(name); }

    @Override public void fly()  { System.out.println(name + " 展翅飞翔"); }
    @Override public void eat()  { System.out.println(name + " 吃虫子"); }
}
```

### 示例 4：匿名内部类 "实例化" 抽象类

抽象类不能直接 `new`，但可以用匿名内部类的方式，**在 new 的同时创建一个匿名的具体子类**：

```java
Shape anonymousShape = new Shape("匿名图形") {   // 生成的是一个匿名子类对象
    @Override public double area()      { return 0; }
    @Override public double perimeter() { return 0; }
};

anonymousShape.printInfo();   // 匿名图形 -> 面积 = 0.00, 周长 = 0.00
```

> 注意：匿名内部类本质上是"具体子类"，所以**必须实现所有抽象方法**，否则编译报错。

## 四、注意事项（易错点清单）

| #  | 注意事项                                                            | 说明                                                              |
|----|-----------------------------------------------------------------|-----------------------------------------------------------------|
| 1  | **抽象类不能实例化**                                                    | `new Shape()` 直接编译错误；只能通过子类对象使用                                 |
| 2  | **抽象类可以有构造方法**                                                  | 但不用于 `new`，而是供子类 `super(...)` 调用；若父类只有带参构造方法，子类必须显式 `super(参数)` |
| 3  | **抽象方法不能有方法体**                                                  | 以 `;` 结尾，不能写 `{}`，包括空方法体 `{}` 也是错误的                             |
| 4  | **非抽象子类必须实现全部抽象方法**                                             | 少实现一个就编译报错；若子类不想实现，子类本身也必须声明为 `abstract`                        |
| 5  | **抽象方法不能用 private / static / final / native / synchronized 修饰** | 都与"子类重写"这一语义冲突                                                  |
| 6  | **抽象类本身不能是 final**                                              | `abstract final class` 不合法（既要求被继承，又禁止继承）                        |
| 7  | **抽象类可以没有抽象方法**                                                 | 合法但无意义（常见于"禁止实例化的工具基类"场景），此时它只阻止被实例化                            |
| 8  | **构造方法不能是 abstract**                                            | 构造方法不能被重写，必须具体实现                                                |
| 9  | **子类重写抽象方法时不能降低访问权限**                                           | 例如父类是 `protected abstract`，子类不能写成包级私有                           |
| 10 | **抽象类可以包含 static 方法、static 块、内部类、main 方法**                      | `java Shape` 只要有 `main` 也能运行，只是不能 new 自身                        |
| 11 | **抽象类可以实现接口但不实现其方法**                                            | 未实现的方法会"下沉"为抽象方法，由具体子类负责                                        |
| 12 | **`abstract` 与 `final` 永远互斥**                                   | 无论修饰类还是方法，两者不可同时出现                                              |
| 13 | **抽象类不能直接 `new`，但引用类型可用**                                       | `Shape s = new Circle(1);` 是标准多态写法                              |
| 14 | **抽象类与接口的选择**                                                   | 需要"共享状态/成员变量/构造初始化 + 部分实现"→ 抽象类；只需要"能力契约"→ 接口；实际常组合使用（抽象类实现接口）  |

• 不能用 abstract 修饰变量、代码块、构造器；
• 不能用 abstract 修饰私有方法、静态方法、final 的方法、final 的类。

### 抽象类 vs 接口（快速对照）

| 维度      | 抽象类                         | 接口                                |
|---------|-----------------------------|-----------------------------------|
| 实例字段    | ✅ 可以有                       | ❌ 只能是 `public static final` 常量    |
| 构造方法    | ✅ 有                         | ❌ 无                               |
| 普通方法    | ✅ 有方法体                      | Java 8+ 有 `default` / `static` 方法 |
| 多继承     | ❌ 单继承（`extends` 一个类）        | ✅ 可实现多个接口                         |
| 抽象方法修饰符 | `public` / `protected` / 包级 | 隐式 `public abstract`              |
| 设计语义    | "是不是"（is-a），共享实现            | "能不能"（can-do），定义能力                |
| 典型用途    | 模板方法、骨架类（如 `AbstractList`）  | 能力契约、回调（如 `Comparable`）           |

### 一个容易忽略的细节

```java
abstract class A {
    abstract void f();
}

abstract class B extends A {
    // 不实现 f()，但自身仍是抽象类 —— 合法
}

class C extends B {
    @Override void f() { System.out.println("C.f"); }  // 必须在这里实现
}
```

抽象方法可以沿着继承链一直"传递"下去，直到某个**非抽象类**把它全部实现为止。

## 五、小结

- **语法**：`abstract class` + `abstract 方法;`，`abstract` 不能与 `final/private/static/native/synchronized`
  组合（修饰方法时），不能修饰构造方法和变量。
- **价值**：把"公共实现"上移到父类，把"可变部分"下放给子类，配合多态与模板方法模式，实现 **"骨架复用 + 细节延迟"**。
- **口诀**：**抽象类不可 new，可有构造供子调；抽象方法无方法体，子类非抽象必须全实现；private/static/final 不能配 abstract。**
