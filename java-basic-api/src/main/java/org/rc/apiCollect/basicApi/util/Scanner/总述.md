`java.util.Scanner` 是 Java 中用于解析文本的便捷工具类。它的核心机制是**将输入源按“分隔符”切分为若干“令牌”，再将这些令牌转换为所需的数据类型**。默认分隔符是空白字符（空格、制表符、换行符等）。

---

### 核心功能与设计定位

Scanner 的功能围绕两个独立的模式展开，理解这一点是掌握其行为的关键：

- **令牌模式**：`next()`、`nextInt()` 等方法属于此模式。它们会先跳过令牌之间的分隔符，然后读取下一个连续的非分隔符序列作为一个令牌。
- **行模式**：`nextLine()` 属于此模式。它不关心分隔符，直接读取当前位置到行尾（换行符）之间的所有内容。

这两种模式**彼此独立**，令牌模式将换行符仅仅视为一种空白，而行模式则将换行符视为行的终结。这一设计是许多常见“陷阱”的根源。

---

### 构造器（创建 Scanner 的来源）

Scanner 提供了多个构造器，核心区别在于**输入源的类型**以及**Scanner 是否“拥有”并需要关闭底层资源**。

| 构造器 | 输入源 | 资源所有权提示 |
|:---|:---|:---|
| `Scanner(InputStream source)` | 输入流，如 `System.in` | **通常不应关闭**，关闭会连带关闭 `System.in` |
| `Scanner(File source)` | 文件 | 应使用 try-with-resources **自动关闭** |
| `Scanner(String source)` | 字符串 | 不涉及外部资源，无需关闭 |
| `Scanner(Readable source)` | 任何 `Readable` 实现 | 所有权由调用方决定 |

常用构造器示例：

```java
// 从控制台读取
Scanner console = new Scanner(System.in);

// 从字符串解析
Scanner fromString = new Scanner("10 20 30");

// 从文件读取（推荐配合 try-with-resources）
// try (Scanner fromFile = new Scanner(new File("data.txt"))) { ... }
```


`System.in` 是一种特殊的 `InputStream`，**关闭基于它的 Scanner 会连带关闭 `System.in`**，导致后续无法再读取控制台输入。因此，对于 `new Scanner(System.in)`，通常**不**使用 try-with-resources 自动关闭；而对于从 `File` 构造的 Scanner，则应当关闭以释放文件句柄。

---

### API 使用方法

#### 读取令牌与基本类型

这是 Scanner 最常用的部分，用于逐个读取数据项。

```java
Scanner sc = new Scanner("42 3.14 hello");
int i = sc.nextInt();        // 42
double d = sc.nextDouble();  // 3.14
String s = sc.next();        // "hello"
```


`next()` 返回一个字符串令牌，`nextInt()`、`nextDouble()` 等则尝试将令牌解析为对应类型。如果令牌格式与目标类型不匹配，会抛出 `InputMismatchException`，并且**出错的那个令牌不会被消耗**，可以用其他方法再次读取或跳过。

#### 读取行：`nextLine()`

`nextLine()` 读取从当前位置到行尾的全部内容，**可以包含空格**，并消耗掉行尾的换行符。

```java
Scanner sc = new Scanner("Hello World\nJava");
String line1 = sc.nextLine(); // "Hello World"
String line2 = sc.nextLine(); // "Java"
```


#### 判断方法：`hasNext` 系列

在读取前判断是否有可用数据，可以避免 `NoSuchElementException`。

```java
Scanner sc = new Scanner("10 abc");
sc.hasNextInt();   // true（下一个令牌可解析为 int）
sc.nextInt();      // 10
sc.hasNextInt();   // false（"abc" 不是 int）
sc.hasNext();      // true（仍有令牌 "abc"）
sc.next();         // "abc"
```


常用的判断方法包括：`hasNext()`（是否有令牌）、`hasNextInt()`、`hasNextDouble()`、`hasNextLine()`（是否还有下一行）等。

#### 自定义分隔符：`useDelimiter()`

通过正则表达式改变令牌的切分方式，这是 Scanner 灵活性的集中体现。

```java
String input = "1 fish 2 fish red fish blue fish";
Scanner sc = new Scanner(input).useDelimiter("\\s*fish\\s*");
System.out.println(sc.nextInt()); // 1
System.out.println(sc.nextInt()); // 2
System.out.println(sc.next());    // red
System.out.println(sc.next());    // blue
```


`reset()` 方法可以将分隔符恢复为默认的空白字符。

### 必须留意的核心陷阱：`nextInt()` 后的 `nextLine()`

这是 Scanner 最常见的问题。执行 `nextInt()` 后，用户按下的回车（换行符）**不会被 `nextInt()` 消耗**，而是留在输入缓冲区中。紧接着调用 `nextLine()` 时，它会立刻读到这个残留的换行符并返回一个**空字符串**，表现为“跳过了输入”。

```java
Scanner sc = new Scanner(System.in);
System.out.print("Enter an integer: ");
int number = sc.nextInt();       // 用户输入 10 并回车
// 此时换行符仍在缓冲区中
System.out.print("Enter a line: ");
String line = sc.nextLine();     // 立即返回空字符串 ""
```

**标准解决方式**：在 `nextInt()`（或 `next()`、`nextDouble()`）之后，**额外调用一次 `nextLine()`** 来消耗残留的换行符。

```java
int number = sc.nextInt();
sc.nextLine();                   // 消耗残留的换行符
System.out.print("Enter a line: ");
String line = sc.nextLine();     // 现在可以正常读取
```

### 综合示例：安全地读取控制台输入

以下示例结合了 `hasNext` 判断、异常处理以及换行符消耗，展示了在实际交互中较为稳健的用法：

```java
import java.util.Scanner;
import java.util.InputMismatchException;

public class ScannerDemo {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        System.out.print("请输入一个整数：");
        while (!sc.hasNextInt()) {          // 循环直到输入合法
            System.out.println("输入无效，请重新输入一个整数：");
            sc.next();                      // 丢弃导致不合法的令牌
        }
        int num = sc.nextInt();
        sc.nextLine();                      // 消耗残留的换行符

        System.out.print("请输入一行文字：");
        String text = sc.nextLine();

        System.out.println("整数：" + num + "，文字：" + text);
        // 对于 System.in，通常不调用 sc.close();
    }
}
```

在这个例子中，`hasNextInt()` 避免了直接抛出异常，`sc.next()` 在输入非法时清除了错误令牌，而 `sc.nextLine()` 则解决了令牌模式向行模式切换时的换行符遗留问题。
