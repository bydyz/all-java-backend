# Java 子接口多继承处理分析

结论：Java 接口支持多继承，但**子接口本身必须在编译期是合法的**
。父接口方法冲突不会“自动拖到实现类”才处理：尤其是多个 `default` 方法冲突时，子接口必须显式解决，否则子接口编译失败。下面按冲突类型分析。

小贴士：
子接口重写默认方法时，default 关键字可以保留。
子类重写默认方法时，default 关键字不可以保留。

---

## 1. 抽象方法 + 抽象方法

### 1.1 签名相同、返回类型相同

直接合并，子接口不用写任何东西。

```java
interface A { void m(); }
interface B { void m(); }
interface C extends A, B {} // 合法，只有一个抽象方法 m()
```

实现类实现一次即可。

### 1.2 签名相同、返回类型协变兼容

如果返回类型有子类型关系，子接口继承“更具体”的返回类型，或者显式声明更具体的返回类型。

```java
interface A { Object m(); }
interface B { String m(); }

interface C extends A, B {}
// 合法，C 继承 String m()

interface D extends A, B {
    @Override String m(); // 也可以显式再声明
}
```

不能放宽返回类型：

```java
interface E extends A, B {
    Object m(); // 编译错误，不能覆盖 B 的 String m()
}
```

### 1.3 签名相同、返回类型不兼容

如果两个返回类型没有共同子类型，子接口无法同时覆盖两者，通常编译错误。

```java
interface A { String m(); }
interface B { Integer m(); }

interface C extends A, B {} // 编译错误
```

如果存在一个共同子类型，可以显式声明该子类型来解决：

```java
interface I1 {}
interface I2 {}
interface X extends I1, I2 {}

interface A { I1 m(); }
interface B { I2 m(); }
interface C extends A, B {
    @Override X m(); // X 同时是 I1、I2 的子类型
}
```

### 1.4 签名不同

属于重载，全部继承，实现类需要实现所有抽象方法。

```java
interface A { void m(int x); }
interface B { void m(String s); }
interface C extends A, B {} // 继承两个重载方法
```

## 2. 默认方法 + 默认方法

这是最需要注意的情况。两个父接口都有同签名 `default` 方法时，**子接口必须显式覆盖解决冲突**。

```java
interface A {
    default void m() { System.out.println("A"); }
}
interface B {
    default void m() { System.out.println("B"); }
}

interface C extends A, B {
    @Override
    default void m() {
        A.super.m();
        B.super.m();
    }
}
```

处理方式有三种：

### 2.1 选择一个父接口实现

```java
interface C extends A, B {
    @Override
    default void m() {
        A.super.m();
    }
}
```

### 2.2 组合多个父接口实现

```java
interface C extends A, B {
    @Override
    default void m() {
        A.super.m();
        B.super.m();
    }
}
```

### 2.3 重新声明为抽象方法，强制实现类实现

```java
interface C extends A, B {
    @Override
    void m(); // 重新抽象
}
```

注意：

- `A.super.m()` 只能出现在子接口的 `default` 方法体中。
- `A` 必须是当前接口的**直接父接口**；间接父接口不能直接 `A.super.m()`，需要通过中间接口暴露。
- 不能用 `static` 方法或 `private` 方法来解决实例默认方法冲突。
- 覆盖方法必须满足访问权限和返回类型协变要求。接口方法隐式 `public`，不能降低访问权限。

如果两个默认方法返回类型不兼容，例如 `String` 和 `Integer`，子接口通常无法通过覆盖同时兼容两者，只能修改父接口设计。

---

## 3. 默认方法 + 抽象方法

一个父接口提供 `default`，另一个父接口声明同签名抽象方法时，默认方法优先，子接口可以不再处理。

```java
interface A {
    default void m() { System.out.println("A"); }
}
interface B {
    void m();
}

interface C extends A, B {} // 合法，C 继承 A 的默认实现
```

如果希望强制实现类必须自己实现，可以在子接口中重新声明为抽象方法：

```java
interface C extends A, B {
    @Override
    void m(); // 重新抽象，默认实现不再生效
}
```

---

## 4. 菱形继承中的默认方法

如果多个路径继承的是**同一个祖先的同一个默认方法**，通常不冲突。

```java
interface A {
    default void m() {}
}
interface B extends A {}
interface C extends A {}
interface D extends B, C {} // 合法，m() 来自同一个 A
```

如果 `B` 或 `C` 分别覆盖了 `m()`，则 `D` 会面对两个不同默认实现，需要显式解决：

```java
interface B extends A {
    default void m() { System.out.println("B"); }
}
interface C extends A {
    default void m() { System.out.println("C"); }
}
interface D extends B, C {
    @Override
    default void m() {
        B.super.m(); // 或 C.super.m()
    }
}
```

---

## 5. 静态方法

接口的 `static` 方法**不会被继承**，因此父接口之间即使有同签名静态方法，也不构成子接口冲突。

```java
interface A {
    static void s() { System.out.println("A"); }
}
interface B {
    static void s() { System.out.println("B"); }
}
interface C extends A, B {}

// C.s(); // 编译错误：静态方法不继承
A.s();    // 正确
B.s();    // 正确
```

子接口可以自己定义同名静态方法，这不会“覆盖”父接口静态方法，只是子接口自己的静态方法。

```java
interface C extends A, B {
    static void s() { System.out.println("C"); }
}
C.s(); // 调用 C 自己的静态方法
```

---

## 6. 私有方法

Java 9 起接口可以有私有方法，但私有方法**不被继承**，也不会参与多继承冲突。子接口不能直接调用父接口的私有方法。

```java
interface A {
    private void helper() {}
    default void m() { helper(); }
}
interface B {
    default void m() {}
}
interface C extends A, B {
    @Override
    default void m() {
        A.super.m(); // 可以
        // helper(); // 不可以，私有方法不继承
    }
}
```

---

## 7. `Object` 中的方法

接口可以声明某些与 `Object` 方法同签名的抽象方法，例如 `boolean equals(Object)`
，但多个接口都声明它通常不冲突，最终由 `Object` 或实现类满足。

接口不能为 `Object` 的 `public` 方法提供 `default` 实现，例如：

```java
interface A {
    default String toString() { return "A"; } // 编译错误
}
```

`toString()`、`hashCode()`、`equals(Object)` 等 `Object` 方法不能通过接口默认方法覆盖。

## 8. 泛型继承与类型擦除

多继承泛型接口时，类型替换后可能产生相同签名或擦除冲突。

### 8.1 类型替换后签名相同

可以合并：

```java
interface G<T> { void m(T t); }
interface H { void m(String s); }

interface C extends G<String>, H {} // 合法，m(String) 合并
```

### 8.2 返回类型擦除后不兼容

编译错误：

```java
interface G<T> { T m(); }
interface H { String m(); }

interface C extends G<Integer>, H {} // 编译错误：Integer 与 String 返回不兼容
```

### 8.3 参数擦除导致 name clash

例如两个泛型父接口擦除后参数类型相同但语义不同，子接口可能需要显式覆盖统一签名，或者调整父接口设计。若无法用协变返回类型或共同签名解决，只能改父接口。

## 9. 常量字段冲突

接口字段隐式是 `public static final`。子接口同时继承多个父接口的同名字段时：

- 字段不会被重写，只会产生隐藏/歧义。
- 子接口未声明同名字段时，使用简单名或 `Child.X` 可能产生歧义。
- 必须通过父接口名限定，或在子接口中声明同名字段隐藏父字段。

```java
interface A { int X = 1; }
interface B { int X = 2; }

interface C extends A, B {
    int Y = A.X + B.X; // 必须限定
    // int Z = X;      // 编译错误：X 有歧义
}

// int v = C.X; // 如果 C 没有声明 X，也歧义
```

子接口声明同名字段：

```java
interface C extends A, B {
    int X = 3; // 隐藏 A.X 和 B.X
    int Y = X; // 3
    int Z = A.X + B.X; // 1 + 2
}
```

注意：字段是静态绑定，不存在多态覆盖。

---

## 10. 子接口与实现类的关系

子接口解决冲突后，实现类按子接口继承结果实现。

如果是类直接实现多个接口，规则类似：

- 多个默认方法冲突：类必须覆盖。
- 默认方法 + 抽象方法：默认方法通常胜出。
- 类中方法优先于接口默认方法。
- 类可以用 `A.super.m()` 选择接口默认实现。
- 如果超类中已有具体方法，超类方法优先；如果超类是抽象方法，接口默认方法通常不能替代该抽象超类方法，类可能仍需实现。

```java
class Impl implements A, B {
    @Override
    public void m() {
        A.super.m();
    }
}
```

---

## 11. 密封接口 `sealed`

如果父接口是 `sealed`，子接口必须在父接口的 `permits` 列表中；如果子接口直接扩展 `sealed`
父接口，它自身还必须声明为 `sealed` 或 `non-sealed`（接口不能声明 `final`）。多继承不改变这些限制。

```java
sealed interface P permits C {}
interface Q {}

non-sealed interface C extends P, Q {}
```

---

## 总结处理策略

| 情况              | 子接口如何处理                              |
|-----------------|--------------------------------------|
| 抽象 + 抽象，同签名同返回  | 自动合并，无需处理                            |
| 抽象 + 抽象，返回类型协变  | 继承更具体返回类型，或显式声明更具体类型                 |
| 抽象 + 抽象，返回类型不兼容 | 若有共同子类型可显式声明；否则编译错误，改父接口             |
| 默认 + 默认         | 必须显式覆盖：选一个、组合、或重新抽象                  |
| 默认 + 抽象         | 默认胜出；要强制实现则重新声明抽象                    |
| 静态方法            | 不继承、不冲突；通过父接口名调用                     |
| 私有方法            | 不继承、不冲突；子接口不能调用                      |
| 同名字段            | 简单名可能歧义；用父接口名限定或子接口声明字段隐藏            |
| 泛型擦除冲突          | 显式覆盖统一签名，或调整父接口                      |
| 菱形继承同一默认方法      | 不冲突；不同覆盖则需解决                         |
| 与实现类配合          | 子接口未解决默认冲突则子接口编译失败；实现类直接多接口冲突时由类覆盖解决 |
