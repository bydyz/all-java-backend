# 一些表述

* 并不是所有的小数都能可以精确的用二进制浮点数表示。二进制浮点数不能精确的表示 0.1、0.01、0.001 这样 10 的负次幂。
* 浮点类型 float、double 的数据不适合在不容许舍入误差的金融计算领域。如果需要精确数字计算或保留指定位数的精度，需要使用
  BigDecimal 类。

# 为什么 0.1 + 0.2 不等于 0.3

根本原因：十进制小数转二进制，很多是无限循环

计算机用二进制存浮点数，遵循 IEEE 754 标准。一个十进制小数要能被精确存储，必须能表示成有限位的二进制小数，即形如： 整数 / 2^n

0.125 = 1/8 ✅ 能精确
0.1 = 1/10 ❌ 分母含因子 5，二进制除不尽

0.1 的二进制展开是无限循环的：

```text
0.1(十进制) = 0.00011001100110011001100110011001100110011... (二进制)
                └──────── 0011 无限循环 ────────┘
```

0.2、0.3 同理，也都是无限循环二进制小数。

# double 的 64 位布局：

```text
符号	  指数	       尾数（有效数字）
1 位	  11 位	       52 位
```

* 0.1 的无限二进制序列，只能保留 52 位有效数字，后面被舍入（IEEE 754 默认"就近舍入到偶数"）。
* 所以存进去的 0.1 不是真正的 0.1，而是它的一个近似值：0.1000000000000000055511...（见上面输出）。
* 0.2 同样存成了 0.2000000000000000111022...。

# 这不是 Java 的 bug，是所有语言共有的

# 正确做法

* 金额/精确小数：用 BigDecimal（字符串构造）

```text
import java.math.BigDecimal;

BigDecimal a = new BigDecimal("0.1");
BigDecimal b = new BigDecimal("0.2");
BigDecimal c = a.add(b);
System.out.println(c);                    // 0.3
System.out.println(c.compareTo(new BigDecimal("0.3")) == 0);  // true
```

⚠️ 一定要用 String 构造器，不要用 new BigDecimal(0.1)（那样会把 double 的误差带进来）。

* 普通数值比较：允许一定误差（epsilon）

```text
System.out.println(1 + 2 == 3);   // true
```

* 浮点误差只针对小数。整数（在范围内）是精确的
