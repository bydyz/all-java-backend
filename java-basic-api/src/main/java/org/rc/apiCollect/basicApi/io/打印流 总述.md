**打印流是 Java I/O 体系中一类专门用于“输出”的处理流，它包装在底层输出流之上，提供了便捷的 `print`、`println`、`printf` 方法，使你能够直接打印任意类型的数据，而无需手动将数据转换为字节或字符数组。**

---

## 打印流的作用

普通输出流（如 `FileOutputStream`、`Writer`）写入数据时，通常要求你先将数据转为字节数组或字符串，使用上不够直接。打印流主要解决了以下几个问题：

1. **直接输出任意类型**：`print(Object)`、`println(Object)` 等方法内部会将数据转换为字符串后写出，`int`、`double`、`boolean`、`char[]` 等都可以直接打印。
2. **格式化输出**：`printf` / `format` 方法支持基于格式字符串的输出，可以精确控制数字、日期等的显示格式。
3. **不抛出受检异常**：`print`、`println`、`write` 等方法**不声明抛出 `IOException`**，调用时无需强制 `try-catch`，写日志或控制台输出时代码更简洁。
4. **可作为处理流包装其他输出流**：打印流可以包装字节流或字符流，为其“增强”打印能力。`System.out` 本身就是 `PrintStream` 的实例。

> **注意**：不抛异常不等于错误不存在。发生写入失败时，错误被“静默”记录在内部标志中，需要通过 `checkError()` 检测。

---

## 打印流的分类

Java 提供了两个打印流类，分别对应字节流和字符流体系：

| 分类 | 类 | 继承体系 | 数据单位 |
|---|---|---|---|
| 字节打印流 | `PrintStream` | `OutputStream` → `FilterOutputStream` | 字节 |
| 字符打印流 | `PrintWriter` | `Writer` | 字符 |

二者 API 高度相似，都提供了 `print` / `println` / `printf` / `format`，但存在一个关键差异：**`PrintWriter` 可以在构造时显式指定字符编码**，而 `PrintStream` 的字符→字节转换通常依赖平台默认编码（部分构造器也支持指定 charset）。因此，在文本输出场景下，**`PrintWriter` 是更推荐的选择**。

## PrintStream（字节打印流）

### 基本使用

```java
import java.io.*;

public class PrintStreamDemo {
    public static void main(String[] args) throws FileNotFoundException {
        PrintStream ps = new PrintStream("output.txt");

        ps.println(97);        // 输出 97（字符串形式，不是字节 97）
        ps.println('@');       // 输出 @
        ps.println(true);      // 输出 true
        ps.println(1.1);       // 输出 1.1
        ps.println("Hello");   // 输出 Hello

        ps.close();
    }
}
```

`println` 会将参数转换为字符串后原样写出；而继承自 `OutputStream` 的 `write(97)` 写出的是字节 `a`，这是 `print` 与 `write` 的本质区别。

### 自动刷新

`PrintStream` 可以开启自动刷新，但触发条件有明确限制：**写入字节数组之后、调用 `println` 之后，或写入换行符之后**。

```java
PrintStream ps = new PrintStream(
    new FileOutputStream("log.txt"), true, "UTF-8"
);
ps.println("这条会被自动刷新写出"); // autoFlush 为 true，println 后触发 flush
```

### System.out 重定向

`System.out` 本身就是 `PrintStream`，通过 `System.setOut()` 可以将标准输出重定向到文件或自定义目标：

```java
PrintStream fileOut = new PrintStream(new FileOutputStream("console.log"));
System.setOut(fileOut);

System.out.println("这句话会写入 console.log，而不是控制台");
```

## PrintWriter（字符打印流）

### 基本使用与自动刷新

```java
import java.io.*;

public class PrintWriterDemo {
    public static void main(String[] args) throws IOException {
        PrintWriter pw = new PrintWriter(
            new FileWriter("pw_output.txt"), true   // true = autoFlush
        );

        pw.println("第一行");
        pw.printf("整数：%d，小数：%.2f%n", 100, 3.14159);
        pw.println("第三行");

        if (pw.checkError()) {
            System.out.println("写入过程中发生了错误");
        }
        pw.close();
    }
}
```

与 `PrintStream` 不同，`PrintWriter` 的自动刷新**只在调用 `println`、`printf` 或 `format` 时触发**，单纯写入换行符不会触发。

### 指定字符编码（核心优势）

```java
PrintWriter pw = new PrintWriter(
    new OutputStreamWriter(
        new FileOutputStream("utf8_output.txt"),
        StandardCharsets.UTF_8
    )
);
pw.println("中文内容，使用 UTF-8 编码");
pw.close();
```

这是 `PrintWriter` 相比 `PrintStream` 最实质的优势：在构造时即可确定编码，避免因平台默认编码不同而导致中文乱码。

## 选型建议

| 场景 | 推荐 |
|---|---|
| 控制台输出（`System.out`） | `PrintStream`（已是既有事实标准） |
| 写文本文件、网络响应、日志（需要控制编码） | **`PrintWriter`** |
| 二进制数据输出 | `PrintStream` 或其他字节流 |
| 关键业务数据的可靠写入 | **不建议依赖打印流**，应使用 `BufferedWriter` / `FileOutputStream` 并严格处理 `IOException`，因为打印流的“静默失败”可能导致数据丢失而不报错 |

概括来说：**打印流的价值在于“打印的便利性”**——直接输出任意类型、支持格式化、不强制处理异常；代价是需要通过 `checkError()` 主动检查错误。文本场景下优先选择 `PrintWriter`，以便掌控字符编码。
