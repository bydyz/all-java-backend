# Java 反射的动态性详解

## 一、动态性的本质

Java 是静态类型语言，**编译期**就要确定类型、方法、字段的符号引用；而反射把这部分解析**推迟到运行期**。

对比一下同一件事的两种写法：

```java
// 静态方式：编译期就绑定，改目标类必须改代码并重新编译
UserService service = new UserServiceImpl();
service.save("Tom");

// 反射方式：类名、方法名都是运行期的字符串，编译期完全不认识它们
Class<?> clazz = Class.forName("com.demo.UserServiceImpl");
Object service = clazz.getDeclaredConstructor().newInstance();
Method save = clazz.getMethod("save", String.class);
save.invoke(service, "Tom");
```

第二种写法里，`clazz` 到底指向哪个类、`save` 到底调哪个方法，**只有在运行时字符串确定之后才知道**——这就是反射的动态性。

## 二、动态性的几个层面（附代码）

### 1. 类的动态加载

`Class.forName(...)` 或 `ClassLoader.loadClass(...)` 在运行期按字符串加载类，触发类加载流程（加载→验证→准备→解析→初始化）。

```java
String className = args[0];                    // 来自命令行/配置/数据库
Class<?> clazz = Class.forName(className);     // 运行期才知道是哪个类
System.out.println(clazz.getName());
```

同一个 `main` 方法，传入不同的类名就加载不同的类，这是编译期写死的 `new` 永远做不到的。

### 2. 对象的动态创建

```java
Class<?> clazz = Class.forName("java.util.ArrayList");
Object list = clazz.getDeclaredConstructor().newInstance();  // 推荐，替代已废弃的 Class.newInstance()

// 带参构造器
Class<?> sb = StringBuilder.class;
Object obj = sb.getConstructor(String.class).newInstance("hello");
```

构造器的参数类型同样可以在运行期从 `Constructor#getParameterTypes()` 动态推断出来，常见于 ORM/DI 框架。

### 3. 方法的动态调用

```java
Class<?> clazz = Class.forName("java.lang.String");
Object target = "hello world";

Method m = clazz.getMethod("substring", int.class, int.class);
Object result = m.invoke(target, 0, 5);      // "hello"

// 还可以完全不写死方法名
String methodName = "toUpperCase";
Method m2 = clazz.getMethod(methodName);
System.out.println(m2.invoke(target));       // "HELLO WORLD"
```

`getMethod` 的第二个参数是**参数类型**，靠它做重载方法的精确匹配；`getDeclaredMethod` 则能拿到私有方法（需 `setAccessible(true)`）。

### 4. 字段的动态读写

```java
class User { private String name = "Tom"; private int age = 18; }

User u = new User();
Field f = User.class.getDeclaredField("name");
f.setAccessible(true);                        // 突破 private
System.out.println(f.get(u));                 // Tom
f.set(u, "Jerry");
System.out.println(f.get(u));                 // Jerry
```

字段名、是否可访问、类型全部是运行期信息。Jackson、Gson 序列化、MyBatis 结果映射都依赖这一点。

### 5. 数组的动态操作

```java
Class<?> componentType = Class.forName("java.lang.String");
Object arr = Array.newInstance(componentType, 3);   // 元素类型运行期决定
Array.set(arr, 0, "a");
System.out.println(Array.get(arr, 0));              // a
```

### 6. 动态代理——真正的"运行时生成类型"

`Proxy.newProxyInstance` 在运行期（或从缓存）生成一个实现指定接口的新类 `$Proxy0`，字节码是运行时拼出来的：

```java
interface UserService { void save(String name); }

UserService target = name -> System.out.println("save " + name);

UserService proxy = (UserService) Proxy.newProxyInstance(
        UserService.class.getClassLoader(),
        new Class<?>[]{ UserService.class },
        (p, method, args1) -> {                       // InvocationHandler
            System.out.println("[before] " + method.getName());
            Object r = method.invoke(target, args1);  // 通过反射转发到真实对象
            System.out.println("[after] " + method.getName());
            return r;
        });

proxy.save("Tom");
// [before] save
// save Tom
// [after] save
```

这里同时体现了两种动态性：**代理类本身是运行期生成的**（编译期不存在 `$Proxy0`），**方法转发靠反射**（`method.invoke`）。Spring AOP 的 JDK 代理就是它；CGLIB 更进一步，用 ASM 在运行期生成**子类**字节码来拦截方法。

## 三、综合示例：配置驱动的插件

下面这段代码能直接跑，它演示了"编译期完全不知道要执行什么类"的典型场景：

```java
import java.io.StringReader;
import java.util.Properties;

public class PluginDemo {
    public static void main(String[] args) throws Exception {
        // 模拟从配置文件读取（实际可以是 properties/yml/数据库/注解）
        String config = "handler=com.demo.EmailHandler\n" +
                        "method=send\n" +
                        "arg=hello@example.com";
        Properties p = new Properties();
        p.load(new StringReader(config));

        String className  = p.getProperty("handler");
        String methodName = p.getProperty("method");
        String arg        = p.getProperty("arg");

        // 动态加载 + 实例化
        Class<?> clazz = Class.forName(className);
        Object handler = clazz.getDeclaredConstructor().newInstance();

        // 动态调用
        Method m = clazz.getMethod(methodName, String.class);
        m.invoke(handler, arg);
    }
}
```

把 `handler` 改成 `SmsHandler`，**一行 Java 代码都不用改、也不用重新编译**，只需改配置。这就是反射动态性带来的可扩展性，也是 Spring（Bean 定义）、MyBatis（Mapper 接口代理）、JUnit（测试类发现）、Tomcat（Servlet 加载）等框架的底层机制。

## 四、动态性从何而来（原理简述）

| 环节 | 静态调用 | 反射调用 |
|---|---|---|
| 方法定位 | javac 把符号引用写入 class 常量池，类加载/首次执行时解析为直接引用，可内联优化 | 方法名、参数类型是运行期字符串，JVM 必须按名字查方法表 |
| 调用实现 | `invokevirtual`/`invokestatic` 等字节码指令 | `Method.invoke` 内部经 `MethodAccessor`（Native 版或动态生成字节码版）转发 |
| 类型检查 | 编译期完成 | 运行期完成，失败抛 `NoSuchMethodException` / `IllegalAccessException` |

也就是说，**静态调用的"找谁"在编译期就定了，反射调用的"找谁"必须等运行时**——这份"迟到"换来了灵活性，但也带来了开销。

---

## 五、代价与注意事项

1. **性能**：反射调用比直接调用慢一两个数量级（虽然有 `MethodAccessor` 和 `inflation` 阈值优化，JDK 18+ 又引入了 MethodHandle 方式）。高频路径建议缓存 `Method`/`Field` 对象，或用 `MethodHandle`、`LambdaMetafactory` 替代。
2. **安全性**：`setAccessible(true)` 可绕过 `private`；Java 9+ 模块系统下，访问未 `opens` 的包会被 `InaccessibleObjectException` 拦截。
3. **错误推迟到运行期**：类名拼错、方法签名不符，编译期发现不了，只能靠测试和异常处理（`ClassNotFoundException`、`NoSuchMethodException`）。
4. **可读性与重构**：IDE 的"查找引用""重命名"对字符串无效，字符串里写的方法名重构后容易断。

---

## 六、小结

反射的动态性可以概括为一句话：**把类型、成员、调用的解析从编译期推迟到运行期**，具体体现在动态加载类、动态创建对象、动态调用方法、动态读写字段、动态操作数组、动态生成代理类六个层面。它牺牲了性能与编译期检查，换来"改配置不改代码"的扩展能力，是几乎所有主流 Java 框架的基石。
