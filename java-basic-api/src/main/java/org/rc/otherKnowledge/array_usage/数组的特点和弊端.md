# Java 数组的特点与弊端详解

## 一、先明确：数组在 Java 中到底是什么

根据 JLS（Java 语言规范），**数组是对象**。`int[]`、`String[]` 都是引用类型，数组实例由 `new` 创建，继承 `Object`，实现 `Cloneable` 和 `Serializable`。在堆内存中，一个数组对象的布局大致为：

```
[ 对象头(mark word + klass pointer) ][ length 字段 ][ 元素0 ][ 元素1 ] ... [ 元素n-1 ]
```

这决定了数组的很多特性。下面分"特点"和"弊端"两部分说明，每部分都尽量给出可运行的代码。

---

## 二、数组的特点（优点 / 特性）

### 1. 类型统一 + 内存连续 ⇒ 随机访问 O(1)

同一个数组里的元素类型完全相同，且基本类型数组的元素在堆上是连续存放的。通过下标访问时，JVM 只需做一次地址计算：

```
元素地址 = 数组基址 + i * 元素大小
```

所以 `arr[i]` 是常数时间，这是数组最核心的优势。

```java
int[] arr = {10, 20, 30, 40, 50};
// 无论 i 是多少，访问耗时基本一致
int x = arr[3]; // O(1)
```

对于**基本类型数组**，数据连续还能获得很好的 CPU 缓存局部性，遍历性能通常优于 `ArrayList<Integer>`（后者元素是分散的引用，且涉及装箱）。

### 2. `length` 是 public final 字段，获取长度为 O(1)

`length` 是数组对象头后面的一个字段，而不是方法调用，也不可修改：

```java
int[] arr = new int[5];
System.out.println(arr.length); // 5

// arr.length = 10; // 编译错误：final 字段不能赋值
```

注意：数组用 `length`（字段），`String` 用 `length()`（方法），这是常见的笔误来源。

### 3. 元素有默认初始化值

数组一经 `new` 出来，所有元素立即被初始化为该类型的默认值，不存在"未初始化"的元素：

| 元素类型 | 默认值 |
|---|---|
| byte/short/int/long | 0 |
| float/double | 0.0 |
| char | `'\u0000'` |
| boolean | false |
| 引用类型 | null |

```java
int[] a = new int[3];
System.out.println(Arrays.toString(a)); // [0, 0, 0]

boolean[] b = new boolean[2];
System.out.println(Arrays.toString(b)); // [false, false]

String[] s = new String[2];
System.out.println(Arrays.toString(s)); // [null, null]
```

### 4. 支持多维数组（本质是"数组的数组"）

Java 没有真正的多维数组，`int[][]` 是"元素为 `int[]` 的数组"。所以它可以是不规则的（锯齿数组）：

```java
int[][] matrix = new int[3][];
matrix[0] = new int[]{1};
matrix[1] = new int[]{1, 2, 3};
matrix[2] = new int[]{1, 2, 3, 4, 5};

for (int[] row : matrix) {
    System.out.println(Arrays.toString(row));
}
// [1]
// [1, 2, 3]
// [1, 2, 3, 4, 5]
```

这也意味着 `matrix.length` 只是"行数"，每行是独立对象、独立分配的，**并不保证整块内存连续**（这点和 C 的二维数组不同）。

### 5. 数组是对象：可作为 Object、可 clone、可序列化

```java
Object o = new int[3];          // 合法，数组是对象
System.out.println(o.getClass()); // class [I

int[] a = {1, 2, 3};
int[] b = a.clone();            // 数组的 clone 是"浅拷贝"
System.out.println(Arrays.toString(b)); // [1, 2, 3]
```

但要注意 `clone()` 对**引用类型数组是浅拷贝**，对基本类型数组才等价于深拷贝：

```java
int[][] m = {{1, 2}, {3, 4}};
int[][] c = m.clone();   // 只复制了外层数组，行数组仍共享
c[0][0] = 99;
System.out.println(m[0][0]); // 99 —— 原数组也被修改了
```

### 6. 数组类型协变（covariance）

如果 `String` 是 `Object` 的子类型，那么 `String[]` 也是 `Object[]` 的子类型：

```java
String[] strs = {"a", "b"};
Object[] objs = strs;   // 编译通过
```

这一特性让数组可以配合多态使用（如 `Arrays.sort(Object[])` 可以接收任何引用类型数组），但同时也是后面"弊端"中要讲的类型安全隐患。

注意：**基本类型数组不参与协变**——`int[]` 不是 `Object[]`，但它仍然是 `Object`：

```java
// Object[] o = new int[3];  // 编译错误
Object o = new int[3];        // 合法
```

### 7. 性能友好：`System.arraycopy` 是 native 方法

数组的批量复制由 JVM 底层实现，非常快，这也是 `ArrayList` 扩容的基础：

```java
int[] src = {1, 2, 3, 4, 5};
int[] dst = new int[5];
System.arraycopy(src, 0, dst, 0, src.length);
System.out.println(Arrays.toString(dst)); // [1, 2, 3, 4, 5]
```

### 8. 是集合类的底层基石

`ArrayList`、`HashMap`（桶数组）、`ArrayDeque`、`String`（内部 `byte[]`）等都以数组为底层存储结构，正是看中了"随机访问 + 内存紧凑"这两个优点。

## 三、数组的弊端（局限）

### 1. 长度固定，无法动态扩容

数组一旦创建，长度不可变。想"加一个元素"，只能新建一个更大的数组再复制：

```java
int[] arr = {1, 2, 3};

// 模拟追加元素 4
int[] newArr = Arrays.copyOf(arr, arr.length + 1); // 底层 System.arraycopy
newArr[newArr.length - 1] = 4;
System.out.println(Arrays.toString(newArr)); // [1, 2, 3, 4]
```

这是 `ArrayList` 帮我们封装掉的工作（`grow()` 按 1.5 倍扩容）。如果直接使用数组做动态数据存储，需要自己管理扩容逻辑，容易出错。

### 2. 插入 / 删除元素需要移动元素，O(n)

在中间插入或删除一个元素，必须整体挪动后面所有元素：

```java
int[] arr = {1, 2, 3, 4, 5};

// 在 index=2 处插入 99
int insertIndex = 2;
int[] newArr = Arrays.copyOf(arr, arr.length + 1);
System.arraycopy(arr, insertIndex, newArr, insertIndex + 1, arr.length - insertIndex);
newArr[insertIndex] = 99;
System.out.println(Arrays.toString(newArr)); // [1, 2, 99, 3, 4, 5]

// 删除 index=2 的元素
int removeIndex = 2;
System.arraycopy(arr, removeIndex + 1, arr, removeIndex, arr.length - removeIndex - 1);
arr[arr.length - 1] = 0; // 末尾置零（逻辑删除）
System.out.println(Arrays.toString(arr)); // [1, 2, 4, 5, 0]
```

当数组很大、增删频繁时，性能会明显劣化——这正是需要 `LinkedList`、`ArrayList` 等封装类的原因。

### 3. 没有便利的 API：只有 `length` 和下标

数组没有 `add`、`remove`、`contains`、`indexOf`、`isEmpty` 等方法，所有操作都要手写或用 `java.util.Arrays` 工具类：

```java
int[] arr = {3, 1, 4, 1, 5};

// 查找元素下标：没有 indexOf，只能自己写
int target = 4, idx = -1;
for (int i = 0; i < arr.length; i++) {
    if (arr[i] == target) { idx = i; break; }
}
System.out.println(idx); // 2

// 排序、查找要用工具类
Arrays.sort(arr);
System.out.println(Arrays.toString(arr)); // [1, 1, 3, 4, 5]
System.out.println(Arrays.binarySearch(arr, 4)); // 3
```

### 4. 类型协变导致运行时类型不安全（`ArrayStoreException`）

协变让编译期"看起来很安全"，但把类型检查推迟到了运行时：

```java
String[] strs = {"a", "b"};
Object[] objs = strs;      // 编译通过（协变）
objs[0] = "ok";            // 合法
objs[1] = 123;             // 编译通过，运行时抛 ArrayStoreException
```

原因是 JVM 在 `aastore` 指令执行时会检查实际数组的运行时类型（这里是 `String[]`）。**这是数组协变带来的典型弊端**：错误在运行期才暴露。相比之下，泛型集合（`List<String>`）在编译期就能拦住这种错误：

```java
List<String> list = new ArrayList<>();
// list.add(123);  // 编译错误，编译期就阻止了
```

### 5. 不支持泛型，不能 `new T[]` / `new List<String>[]`

由于类型擦除，Java 禁止直接创建泛型数组：

```java
// T[] arr = new T[10];                    // 编译错误
// List<String>[] ls = new List<String>[10]; // 编译错误：generic array creation
```

常见变通方式（都有代价）：

```java
// 方式一：用 Object[] 转型，配合注解抑制警告（运行期有 ClassCastException 风险）
@SuppressWarnings("unchecked")
List<String>[] ls = (List<String>[]) new List<?>[10];

// 方式二：反射创建（需要 Class 对象）
@SuppressWarnings("unchecked")
T[] arr = (T[]) Array.newInstance(String.class, 10);
```

正因如此，Java 集合框架内部大量使用 `Object[]` + 强转，再配合 `@SuppressWarnings`。

### 6. `equals` / `hashCode` / `toString` 都不是"内容语义"

数组继承自 `Object`，这三个方法都是引用语义，直接打印或比较往往不是你想要的结果：

```java
int[] a = {1, 2, 3};
System.out.println(a);            // [I@1b6d3586（类型@哈希）
System.out.println(Arrays.toString(a)); // [1, 2, 3]  ← 需要工具类

int[] b = {1, 2, 3};
System.out.println(a.equals(b));        // false ← 比较的是引用
System.out.println(Arrays.equals(a, b)); // true  ← 内容比较
```

如果把数组放进 `HashMap` / `HashSet` 当 key，得到的也是"身份哈希"，几乎无法按内容去重：

```java
Set<int[]> set = new HashSet<>();
set.add(new int[]{1, 2});
set.add(new int[]{1, 2});
System.out.println(set.size()); // 2，而不是 1
```

### 7. 下标越界只能在运行时发现

编译器不会检查下标范围，越界时抛 `ArrayIndexOutOfBoundsException`：

```java
int[] arr = new int[3];
arr[2] = 1; // OK
arr[3] = 1; // 运行时抛 ArrayIndexOutOfBoundsException
```

同理，数组引用为 `null` 时访问 `length` 或元素会抛 `NullPointerException`：

```java
int[] arr = null;
// System.out.println(arr.length); // NPE
```

而且"空数组"和"null 数组"语义不同，调用方必须自己判断，接口契约容易混乱。

### 8. 基本类型数组与包装类型数组不通用

数组不参与自动装箱/拆箱，`int[]` 和 `Integer[]` 是完全不同的类型，不能互转：

```java
int[] a = {1, 2, 3};
// Integer[] b = a; // 编译错误
Integer[] b = Arrays.stream(a).boxed().toArray(Integer[]::new); // 需要手动转换
```

还有一个著名的坑：`Arrays.asList` 对基本类型数组的处理：

```java
List<int[]> list = Arrays.asList(new int[]{1, 2, 3});
System.out.println(list.size());   // 1，而不是 3！
// 因为 int[] 被当成一个 Object 元素（T = int[]）
```

想得到 `List<Integer>` 必须先装箱：

```java
List<Integer> list2 = Arrays.stream(new int[]{1, 2, 3}).boxed().collect(Collectors.toList());
System.out.println(list2.size()); // 3
```

### 9. 多维数组不是真正的矩阵

如前面所说，`int[][]` 是"数组的数组"，每行单独分配，所以：

- 各行的长度可以不同（可能不是矩形）；
- 整块内存不保证连续，缓存局部性不如 C 的二维数组；
- 访问时要经过两次解引用，比一维数组慢；
- 容易出现"只初始化了外层，内层为 null"的问题：

```java
int[][] m = new int[3][];
// System.out.println(m[0][0]); // NPE！m[0] 还是 null
m[0] = new int[3];
System.out.println(m[0][0]); // 0
```

### 10. 数组是可变共享的，没有"不可变"语义

把数组作为参数或字段传递时，传的是引用，调用方可以随意修改内容，无法防御性保护（除非每次复制）：

```java
public class Box {
    private final int[] data;
    public Box(int[] data) { this.data = data; } // 外部仍持有引用，可修改内容
    public int[] getData() { return data; }      // 直接返回内部数组，可被外部改
}

int[] src = {1, 2, 3};
Box box = new Box(src);
src[0] = 999;                // 通过外部引用修改
System.out.println(box.getData()[0]); // 999
```

如果想安全，只能在构造和返回时都做 `clone()`（成本不低），或者改用不可变集合/包装类。

## 四、总结对比

| 维度 | 数组 | 集合（如 ArrayList） |
|---|---|---|
| 长度 | 固定，不可变 | 动态扩容 |
| 随机访问 | O(1)，最快 | O(1)，但有方法调用/装箱开销 |
| 中间插入/删除 | O(n)，需手动移动 | O(n)，封装好 |
| API 丰富度 | 极简（length + 下标） | 丰富（add/remove/contains…） |
| 泛型支持 | 不支持 | 支持 |
| 类型安全 | 协变 → 运行期 `ArrayStoreException` | 编译期检查 |
| 基本类型 | 直接存储，无装箱 | 需装箱（除非用 fastutil 等库） |
| 内容比较/打印 | 需 `Arrays.toString/equals` | 已重写 `equals/toString` |
| 内存开销 | 最小 | 有对象头、扩容冗余空间 |

**选型建议：**

- 数据量固定、以随机访问/遍历为主、追求极致性能（尤其是基本类型）→ 用**数组**；
- 需要动态增删、需要丰富 API、需要泛型和类型安全 → 用**集合**；
- 数组作为底层存储时，对外应提供封装好的 API，并注意防御性拷贝；
- 多维数据且追求矩阵性能时，可考虑一维数组模拟 `arr[i * cols + j]`，或使用专门的数值库。

数组是 Java 最基础的数据结构，它"快、省、简单"，但"死板、裸奔、不安全"——理解这些特点与弊端，才能在数组和集合之间做出正确取舍。
