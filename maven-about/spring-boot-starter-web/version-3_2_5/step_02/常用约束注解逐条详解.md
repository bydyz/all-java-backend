# 常用约束注解逐条详解

以下是基于 Jakarta Bean Validation（Spring Boot 3.x+）的常用约束注解逐条详解，涵盖依赖配置、字段级用法与 Controller 触发校验。

---

## 依赖与命名空间

Spring Boot 3.x 使用 `jakarta.validation.*` 命名空间，不再使用旧的 `javax.validation.*`。自 Spring Boot 2.3 起，`spring-boot-starter-web` **不再传递引入** validation 依赖，必须显式添加：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

该 starter 会引入 Hibernate Validator 与 Jakarta EL。

---

## 1. `@NotNull`：不能为 `null`

**语义**：字段值不能为 `null`。注意，**空字符串 `""` 可以通过**，因为它不是 `null`。

```java
public class UserDTO {

    @NotNull(message = "ID 不能为空")
    private Long id;

    @NotNull(message = "金额不能为空")
    private BigDecimal amount;
}
```

`@NotNull` 适用于任意类型（对象、包装类型、数组等），是“必填”校验的基础注解。如果字段是 `Long`、`Integer` 等包装类型，`@NotNull` 是必要的；基本类型（如 `long`）本身不可能为 `null`，不需要使用。

---

## 2. `@Size`：长度或元素个数在指定范围内

**语义**：校验 `CharSequence`（字符串）、集合、`Map` 或数组的长度 / 元素个数是否落在 `min` 和 `max` 之间。`min` 和 `max` 均为**可选**，可以只指定一边。

```java
public class UserDTO {

    @Size(min = 2, max = 20, message = "用户名长度必须在 2 到 20 之间")
    private String username;

    @Size(min = 6, max = 64, message = "密码长度必须在 6 到 64 位之间")
    private String password;

    @Size(max = 10, message = "角色数量不能超过 10 个")
    private List<String> roles;
}
```

对字符串，`@Size` 统计的是**字符数**；对集合/数组，统计的是**元素个数**。如果只需校验“非空”而不关心长度，优先用 `@NotBlank` 或 `@NotEmpty`，`@Size` 更适合精确的边界控制。

---

## 3. `@Min` / `@Max`：数值的闭区间边界

**语义**：`@Min(value)` 要求数值 **≥ value**；`@Max(value)` 要求数值 **≤ value**。两者都是**闭区间**，`value` 为 `long` 类型，适用于整数类型（`Integer`、`Long`、`Short` 等）。对于小数，应使用 `@DecimalMin` / `@DecimalMax`。

```java
public class ProductDTO {

    @NotNull(message = "年龄不能为空")
    @Min(value = 1, message = "年龄最小为 1")
    @Max(value = 150, message = "年龄最大为 150")
    private Integer age;

    @Min(value = 1, message = "ID 必须大于等于 1")
    private Long id;
}
```

`@Min` / `@Max` 通常与 `@NotNull` 组合使用：`@Min` 本身不负责校验 `null`，如果字段为 `null`，`@Min` 不会报错，因此必填数值字段需要同时加 `@NotNull`。

---

## 4. `@Email`：邮箱格式

**语义**：校验字符串是否符合邮箱格式。默认匹配相对宽松的邮箱规则，也可以配合 `regexp` 自定义，但日常场景直接使用默认即可。

```java
public class UserDTO {

    @NotBlank(message = "邮箱不能为空")
    @Email(message = "邮箱格式不正确")
    private String email;
}
```

`@Email` 接受 `null` 值，**不校验空值**。如果邮箱是必填项，需要额外加 `@NotBlank` 或 `@NotEmpty`。

---

## 5. `@Pattern`：正则匹配

**语义**：要求字符串匹配指定的正则表达式 `regexp`。可用于手机号、身份证号、车牌号等自定义格式校验。

```java
public class ContactDTO {

    @Pattern(
        regexp = "^1[3-9]\\d{9}$",
        message = "手机号格式不正确"
    )
    private String phone;

    @Pattern(
        regexp = "^[A-Z]{2}$",
        message = "国家代码必须是两个大写字母"
    )
    private String countryCode;
}
```

`@Pattern` 同样**接受 `null`**。如果手机号是必填项，应同时加 `@NotBlank`。`regexp` 中使用的是 Java 字符串转义，所以 `\d` 要写成 `\\d`。

---

## 补充：`@NotBlank` 与 `@NotEmpty`（高频搭配）

这两个注解在实际开发中出现频率很高，常与上述注解配合使用。

`@NotBlank`：仅适用于 `CharSequence`（字符串），要求**不为 `null`、去除首尾空白后长度 > 0**。它能拦截 `"   "` 这类纯空白字符串，而 `@NotNull` 和 `@NotEmpty` 做不到这一点。

`@NotEmpty`：适用于字符串、集合、`Map`、数组，要求**不为 `null` 且长度 / 元素个数 > 0**。对字符串来说，`""` 会被拦截，但 `"   "` 可以通过。

```java
public class CreateUserRequest {

    @NotBlank(message = "用户名不能为空")
    @Size(min = 2, max = 20, message = "用户名长度需在 2~20 之间")
    private String username;

    @NotEmpty(message = "角色列表不能为空")
    private List<@NotBlank(message = "角色名不能为空白") String> roles;
}
```

字符串必填场景优先用 `@NotBlank`，集合/数组必填用 `@NotEmpty`，单纯的“不能为 `null`”（如 `Long id`）用 `@NotNull`。

## 在 Controller 中触发校验

### 请求体校验：`@Valid` / `@Validated`

```java
@RestController
@RequestMapping("/api/users")
public class UserController {

    @PostMapping
    public Long create(@Valid @RequestBody UserDTO dto) {
        return userService.create(dto);
    }
}
```

`@Valid` 作用于 `@RequestBody` 参数，Spring 会自动触发 JSR-380 校验。校验失败时抛出 `MethodArgumentNotValidException`，默认返回 400。

`@Validated` 是 Spring 的变体，额外支持**分组校验**；当约束标注在 `@PathVariable`、`@RequestParam` 上时，必须将 `@Validated` 标在 **Controller 类上**，方法参数级的约束才会生效（由 `MethodValidationPostProcessor` 生成的 AOP 代理完成）。

```java
@RestController
@RequestMapping("/api/users")
@Validated
public class UserController {

    @GetMapping("/{id}")
    public UserVO get(@PathVariable @Min(1) Long id) {
        return userService.findById(id);
    }
}
```

### 嵌套对象校验

如果 DTO 中包含另一个对象，需要在嵌套字段上加 `@Valid`，否则嵌套对象内部的约束**不会被触发**：

```java
public class OrderDTO {

    @NotNull(message = "订单号不能为空")
    private String orderNo;

    @Valid
    @NotNull(message = "用户信息不能为空")
    private UserDTO user;
}
```

### 全局异常处理（可选，推荐）

未处理的校验异常默认返回 Spring 的通用错误格式。如需统一响应体，可添加 `@RestControllerAdvice`：

```java
@RestControllerAdvice
public class ValidationExceptionHandler {

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<Map<String, String>> handle(MethodArgumentNotValidException ex) {
        Map<String, String> errors = new HashMap<>();
        ex.getBindingResult().getFieldErrors().forEach(err ->
            errors.put(err.getField(), err.getDefaultMessage())
        );
        return ResponseEntity.badRequest().body(errors);
    }
}
```

该处理器将 `字段名 → 错误消息` 映射为响应体，便于前端直接使用。

---

## 关键注意事项

- `@NotNull` 允许空字符串，`@NotBlank` 才拦截空白字符串；两者不可混用替代。
- `@Email`、`@Pattern`、`@Min`、`@Max` 对 `null` 值默认视为通过，必填字段需搭配 `@NotNull` / `@NotBlank` / `@NotEmpty`。
- Spring Boot 3.x 务必使用 `jakarta.validation.constraints.*`，旧包 `javax.validation.*` 下的注解不会生效。
- `@Valid` 用于触发嵌套校验和请求体校验；`@Validated` 额外支持分组，且是 `@PathVariable` / `@RequestParam` 约束生效的必要条件（标在类上）。
