# Java 继承中的泛型使用详解

泛型与继承的结合是 Java 中容易混淆又极常用的知识点。下面按「继承泛型类 → 实现泛型接口 → 泛型方法重写 → 通配符与继承关系 → 自限定泛型 → 实战模式 → 类型擦除陷阱」的顺序系统讲解，每个知识点都配可运行代码。

---

## 一、继承泛型类的四种形态

### 1.1 子类保留父类的类型参数

最常见，子类仍是泛型类，类型参数「透传」：

```java
class Box<T> {
    protected T content;
    public void set(T content) { this.content = content; }
    public T get() { return content; }
}

// 子类保留 T
class SubBox<T> extends Box<T> {
    public void setAll(T... items) {
        if (items.length > 0) this.content = items[0];
    }
}

// 使用
SubBox<String> sb = new SubBox<>();
sb.set("hello");
String s = sb.get();   // 返回 String，无需强转
```

### 1.2 子类固定父类的类型参数

子类不再泛型化，把 `T` 确定为具体类型：

```java
class StringBox extends Box<String> {
    // 继承来的 set 只接受 String
    public String upper() { return content == null ? null : content.toUpperCase(); }
}

StringBox b = new StringBox();
b.set("java");       // OK
// b.set(123);       // 编译错误，因为 set 的参数是 String
```

> ⚠️ 注意：此时 `StringBox` **不是** `Box<Integer>` 的父类，`Box<String>` 与 `Box<Integer>` 之间没有任何关系。

### 1.3 子类新增类型参数

子类可以在父类泛型基础上扩展新的类型参数：

```java
class PairBox<K, V> extends Box<K> {
    private V extra;
    public void setExtra(V extra) { this.extra = extra; }
    public V getExtra() { return extra; }
}

PairBox<String, Integer> pb = new PairBox<>();
pb.set("key");
pb.setExtra(100);
```

### 1.4 子类部分保留、部分固定

```java
import java.util.Map;

// 父类的 T 被固定为 Map<K, String>，而 K 由子类决定
class MapHolder<K> extends Box<Map<K, String>> {
    public String getValue(K key) {
        Map<K, String> m = get();
        return m == null ? null : m.get(key);
    }
}
```

### 1.5 ⚠️ 不写类型参数 = 原始类型（raw type）

```java
class RawBox extends Box { }   // 编译器警告：raw use of parameterized class

RawBox rb = new RawBox();
Object o = rb.get();           // 返回 Object，泛型信息丢失
```

除非维护老代码，**不要**这样写。

## 二、实现泛型接口

### 2.1 实现时指定类型

```java
interface Converter<S, T> {
    T convert(S source);
}

class StringToIntConverter implements Converter<String, Integer> {
    @Override
    public Integer convert(String source) {
        return Integer.valueOf(source);
    }
}
```

### 2.2 实现时保留类型参数（实现类仍是泛型类）

```java
class IdentityConverter<T> implements Converter<T, T> {
    @Override
    public T convert(T source) { return source; }
}
```

### 2.3 实现时扩展类型参数

```java
class PairConverter<A, B, C> implements Converter<A, C> {
    private final Converter<A, B> first;
    private final Converter<B, C> second;

    public PairConverter(Converter<A, B> first, Converter<B, C> second) {
        this.first = first;
        this.second = second;
    }

    @Override
    public C convert(A source) {
        return second.convert(first.convert(source));
    }
}
```

### 2.4 经典例子：`Comparable<T>`

```java
class Person implements Comparable<Person> {
    private final String name;
    public Person(String name) { this.name = name; }

    @Override
    public int compareTo(Person o) {
        return this.name.compareTo(o.name);  // 参数就是 Person，不用强转
    }
}
```

## 三、泛型方法在继承中的重写与「桥接方法」

### 3.1 重写泛型方法

父类的泛型方法，子类重写时**签名要一致**（类型变量可以重命名，但结构要对上）：

```java
class Parent<T> {
    public void process(T t) {
        System.out.println("parent: " + t);
    }
}

class Child extends Parent<String> {
    @Override
    public void process(String s) {          // 参数已具体化为 String
        System.out.println("child: " + s);
    }
}
```

### 3.2 编译后会发生什么？—— 桥接方法（bridge method）

因为泛型会被**类型擦除**，`Parent.process` 擦除后签名是 `process(Object)`，而 `Child.process` 是 `process(String)`。为了让多态生效，编译器会**自动生成一个桥接方法**：

```java
import java.lang.reflect.Method;

public class BridgeDemo {
    public static void main(String[] args) {
        for (Method m : Child.class.getDeclaredMethods()) {
            System.out.println(m.getName() + "(" + m.getParameterTypes()[0].getSimpleName()
                    + ") bridge=" + m.isBridge());
        }
    }
}
```

输出：

```
process(String) bridge=false
process(Object) bridge=true
```

运行时，`Parent<?> p = new Child(); p.process("x")` 会命中桥接方法 `process(Object)`，桥接方法内部 `checkcast String` 后转调 `process(String)`。

> 这就是为什么有时反射里会「多出」一个方法 —— 它不是 bug，是编译器生成的。

### 3.3 泛型方法本身的继承

子类可以定义自己的泛型方法，与父类互不影响：

```java
class Base {
    public <E> E identity(E e) { return e; }
}
class Sub extends Base {
    // 继承即可，也可重写
    @Override
    public <E> E identity(E e) { return e; }
}
```

## 四、通配符与继承关系：泛型不是协变的

这是最容易踩坑的地方：

```java
List<Integer> ints = new ArrayList<>();
// List<Number> nums = ints;   // ❌ 编译错误：类型不兼容

// 即使 Integer 是 Number 的子类，
// List<Integer> 也绝不是 List<Number> 的子类
```

`Box<String>` 与 `Box<Object>` **没有继承关系**（无协变、无逆变）。

### 4.1 用 `? extends` 实现「读取式协变」

```java
List<? extends Number> nums = new ArrayList<Integer>();  // ✅

Number n = nums.get(0);        // ✅ 读出来是 Number（或子类型）
// nums.add(1);                // ❌ 不能写（除了 null）
```

### 4.2 用 `? super` 实现「写入式逆变」

```java
List<? super Integer> sink = new ArrayList<Number>();   // ✅
sink.add(1);                   // ✅ 可以放 Integer
Object o = sink.get(0);        // 读出来只能当 Object
```

### 4.3 PECS 原则

**P**roducer **E**xtends, **C**onsumer **S**uper：生产者用 `extends`，消费者用 `super`。

```java
public static <T> void copy(List<? super T> dest,   // 消费者：写
                            List<? extends T> src) { // 生产者：读
    for (T t : src) {
        dest.add(t);
    }
}

// 使用
List<Integer> src = List.of(1, 2, 3);
List<Number> dest = new ArrayList<>();
copy(dest, src);   // 编译通过
```

### 4.4 泛型类继承时的通配符

```java
class Box<T> { /* ... */ }

class Util {
    // 只关心读取，参数用通配符，提高兼容性
    static Number sum(Box<? extends Number> box) {
        return box.get();
    }

    // 只关心写入，参数用 super
    static void fill(Box<? super Integer> box) {
        box.set(42);
    }
}
```

## 五、自限定泛型（CRTP 风格）

经典例子：Java 标准库的 `Enum<E extends Enum<E>>`、`Comparable<T>`，以及各种 Builder 链式调用的类型保持。

```java
abstract class Builder<T extends Builder<T>> {
    protected String name;

    // 返回类型是 T 而不是 Builder<T>，保证链式调用返回正确的子类类型
    public T name(String name) {
        this.name = name;
        return self();
    }

    protected abstract T self();
}

class PersonBuilder extends Builder<PersonBuilder> {
    private int age;

    @Override
    protected PersonBuilder self() { return this; }

    public PersonBuilder age(int age) {
        this.age = age;
        return this;
    }

    public String build() {
        return name + ":" + age;
    }
}

// 使用
String result = new PersonBuilder().name("Tom").age(18).build();
// 因为 name() 返回 PersonBuilder，所以后面还能调用 age()
```

如果不用自限定，`name()` 返回 `Builder<T>`，`.age()` 就调不到 —— 这就是自限定类型的意义。

## 六、实战：泛型抽象基类（模板 + DAO）

### 6.1 模板方法模式

```java
abstract class AbstractProcessor<T> {

    // 模板方法：流程固定，具体步骤由子类实现
    public final void processAll(List<T> items) {
        for (T item : items) {
            if (validate(item)) {
                handle(item);
            }
        }
    }

    protected boolean validate(T item) { return true; }  // 默认实现
    protected abstract void handle(T item);
}

class StringProcessor extends AbstractProcessor<String> {
    @Override
    protected void handle(String s) {
        System.out.println(s.toUpperCase());
    }
}
```

### 6.2 泛型 DAO + 反射推断实体类型

常见于 Spring 的 `JpaRepository<T, ID>` 风格：

```java
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.Type;

abstract class BaseRepository<T, ID> {
    protected Class<T> entityClass;

    @SuppressWarnings("unchecked")
    public BaseRepository() {
        Type superType = getClass().getGenericSuperclass();
        if (superType instanceof ParameterizedType pt) {
            this.entityClass = (Class<T>) pt.getActualTypeArguments()[0];
        }
    }

    public T newEntity() throws Exception {
        return entityClass.getDeclaredConstructor().newInstance();
    }
}

class User { }   // 实体

class UserRepository extends BaseRepository<User, Long> {
    // 不需要写任何反射代码，基类自动拿到 User.class
}

// 验证
public class Demo {
    public static void main(String[] args) throws Exception {
        UserRepository repo = new UserRepository();
        System.out.println(repo.newEntity().getClass());   // class User
    }
}
```

> 技巧点：`getGenericSuperclass()` 在**子类有具体类型实参时**能拿到 `ParameterizedType`，从而解析出 `T` 的真实 Class。这也是 Spring 能自动注入正确泛型 Bean 的原理之一。

## 七、类型擦除带来的继承陷阱

泛型在编译后被擦除，因此继承泛型类时有若干「不能做」：

### 7.1 不能 `new T()`、不能 `T.class`

```java
class Factory<T> {
    // T t = new T();       // ❌
    // Class<T> c = T.class; // ❌

    // 正确做法：构造器传入 Class<T>
    private final Class<T> type;
    public Factory(Class<T> type) { this.type = type; }
    public T create() throws Exception {
        return type.getDeclaredConstructor().newInstance();
    }
}
```

### 7.2 不能用 `instanceof T`

```java
class Checker<T> {
    // if (obj instanceof T) { }   // ❌
    // 只能在外部用 Class 判断：
    boolean check(Object o, Class<T> type) { return type.isInstance(o); }
}
```

### 7.3 不能创建泛型数组

```java
class Stack<T> {
    // private T[] arr = new T[10];                 // ❌
    @SuppressWarnings("unchecked")
    private T[] arr = (T[]) new Object[10];         // ⚠️ 需要 unchecked 强转
}
```

### 7.4 静态成员不能使用类的类型参数

```java
class Box<T> {
    // static T value;              // ❌
    // static void f(T t) { }       // ❌

    // 但可以定义独立的泛型静态方法
    static <E> E identity(E e) { return e; }        // ✅
}
```

### 7.5 泛型类不能被 `catch`，泛型异常有限制

```java
// class MyEx<T> extends Exception { }   // ❌ 类型参数不能用在异常类
class MyEx extends Exception { }
```

### 7.6 泛型子类的重载冲突

```java
class Base<T> {
    public void f(T t) { }
}

// 擦除后两个方法签名都是 f(Object)，无法重载
// class Sub extends Base<String> {
//     public void f(String s) { }
//     public void f(Object o) { }   // ❌ 编译错误：name clash
// }
```

## 八、快速对照表

| 场景 | 写法 | 说明 |
|---|---|---|
| 子类保留 T | `class Sub<T> extends Box<T>` | 类型透传，子类仍是泛型类 |
| 子类固定 T | `class Sub extends Box<String>` | 子类非泛型，方法参数固定 |
| 子类扩展 | `class Sub<K,V> extends Box<K>` | 新增类型参数 |
| 继承原始类型 | `class Sub extends Box` | ⚠️ 泛型信息丢失，有警告 |
| 实现泛型接口 | `class X implements Converter<A,B>` | 三种：固定 / 保留 / 扩展 |
| 泛型非协变 | `List<Integer> ≠ List<Number>` | 必须用通配符桥接 |
| 读 | `? extends T` | 生产者，可读不可写（除 null） |
| 写 | `? super T` | 消费者，可写不可读（除 Object） |
| 桥接方法 | `m.isBridge()` | 重写泛型方法时编译器自动生成 |
| 自限定 | `T extends Builder<T>` | 链式调用保持子类类型 |
| 反射拿实际类型 | `getGenericSuperclass()` | DAO 基类推断实体 Class |

## 小结

1. **继承泛型类**：子类可以「保留」「固定」「扩展」「部分固定」四种方式处理父类类型参数，避免使用原始类型。
2. **接口实现**同理；`Comparable<T>`、`Converter<S,T>` 是典型范式。
3. **泛型方法重写**时注意 `@Override` 的签名约束，编译器会生成**桥接方法**保证多态。
4. **继承关系上**：`Box<Integer>` 与 `Box<Number>` 无关系，跨类型操作需 `? extends` / `? super`，遵循 **PECS**。
5. **自限定泛型**（`T extends Builder<T>`）用于保持链式调用返回类型。
6. **类型擦除**导致 `new T()`、`instanceof T`、泛型数组、静态类型参数等都不能直接用，通常通过**传入 `Class<T>`** 或**反射解析泛型父类**绕开。

掌握以上模式后，就能正确设计泛型基类、泛型 DAO、Builder 继承体系等常见结构了。
