`java.io.FileWriter` 是 Java 中用于向**文本文件**写入字符数据的便捷类。它继承自 `OutputStreamWriter`，本质上是对 `FileOutputStream` 的封装，内部会自动处理字符到字节的编码转换。与直接操作字节的 `FileOutputStream` 不同，`FileWriter` 专为处理文本设计，使得写入字符串或字符数组更加直接。

---

### 核心功能与定位

- **专用于字符流**：`FileWriter` 用于写入字符流，适合处理 `.txt`、`.csv` 等文本文件。如果需要写入图像、音频等原始字节数据，则应使用 `FileOutputStream`。
- **自动创建文件**：如果目标文件不存在，`FileWriter` 在构造时会自动创建它。
- **依赖默认编码（Java 11 之前）** ：在 Java 11 之前，`FileWriter` 只能使用平台默认的字符编码（如 Windows 的 GBK、Linux 的 UTF-8），这在跨平台处理中文时容易导致乱码。
- **缓冲机制**：`FileWriter` 内部使用固定大小的字节缓冲区（8192 字节），写入的数据可能先进入缓冲区，需要 `flush()` 或 `close()` 才能确保真正落盘。

---

### 构造器详解

`FileWriter` 提供了多种重载构造器，核心区别在于**数据源形式**（`String` 路径、`File` 对象或 `FileDescriptor`）、**是否追加**以及**是否指定字符集**。

#### Java 11 之前的 5 个构造器

| 构造器 | 说明 |
|---|---|
| `FileWriter(String fileName)` | 根据文件名创建，**覆盖**已有文件。 |
| `FileWriter(String fileName, boolean append)` | 根据文件名创建；`append = true` 时以**追加**模式打开。 |
| `FileWriter(File file)` | 根据 `File` 对象创建，**覆盖**模式。 |
| `FileWriter(File file, boolean append)` | 根据 `File` 对象创建，可控制追加。 |
| `FileWriter(FileDescriptor fd)` | 基于已有的文件描述符创建。 |

> 以上构造器均使用平台默认字符集和默认缓冲区大小。

#### Java 11 新增的 4 个支持字符集的构造器

Java 11 起，`FileWriter` 新增了可以显式指定 `Charset` 的构造器，解决了长期以来无法控制编码的问题：

```java
FileWriter(String fileName, Charset charset)
FileWriter(String fileName, Charset charset, boolean append)
FileWriter(File file, Charset charset)
FileWriter(File file, Charset charset, boolean append)
```

**使用建议**：涉及中文或跨平台场景时，**优先使用带 `Charset` 的构造器**，并显式指定 `StandardCharsets.UTF_8`，以避免平台默认编码带来的乱码风险。

---

### 核心 API 使用方法与代码

`FileWriter` 本身不定义新的写入方法，所有写入能力均继承自 `Writer` 和 `OutputStreamWriter`。以下是最常用的几组方法。

#### `write` 系列：写入数据

`write` 方法有多个重载，分别对应不同粒度的写入：

```java
import java.io.FileWriter;
import java.io.IOException;
import java.nio.charset.StandardCharsets;

public class FileWriterWriteExample {
    public static void main(String[] args) {
        String path = "demo.txt";
        char[] chars = {'a', 'b', 'c', 'd'};

        try (FileWriter writer = new FileWriter(path, StandardCharsets.UTF_8)) {
            writer.write('H');                    // 写入单个字符
            writer.write(chars);                  // 写入整个字符数组
            writer.write(chars, 1, 2);            // 写入数组的一部分：bc
            writer.write("Hello FileWriter");     // 写入整个字符串
            writer.write("Java IO", 0, 4);        // 写入字符串的一部分：Java
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

> `try-with-resources` 会自动调用 `close()`，即使发生异常也能保证资源释放。

#### `append` 系列：追加数据

`append` 与 `write` 功能相似，但返回 `Writer` 自身，支持**链式调用**。它常用于在已有内容后继续添加数据。

```java
try (FileWriter writer = new FileWriter("demo.txt", true)) { // append = true
    writer.append("第一行\n")
          .append("第二行\n")
          .append('X'); // 追加单个字符
} catch (IOException e) {
    e.printStackTrace();
}
```

> 注意：**追加模式需要在构造时指定**（`append = true`）；在已覆盖模式的 `FileWriter` 上调用 `append()` 并不会改变“从头写入”的行为，它只是在当前写入位置继续追加。

#### `flush()`：强制刷新缓冲区

`flush()` 会强制将缓冲区中尚未写入磁盘的字符数据推送到目标文件。在需要确保数据“立刻可见”（如日志实时落盘）的场景中尤为重要。

```java
FileWriter writer = new FileWriter("log.txt", true);
try {
    writer.write("important log entry\n");
    writer.flush(); // 立即将缓冲区数据写入磁盘
    // ... 继续写入更多内容
} finally {
    writer.close();
}
```

> `close()` 在关闭前会自动执行 `flush()`，因此 **`flush()` 不是 `close()` 的替代品**，而是在流关闭之前“手动推一把”的手段。

#### `close()`：释放资源

`close()` 是**必须执行**的操作。它会先刷新缓冲区，再关闭底层文件流，释放系统资源。推荐始终使用 `try-with-resources` 来确保 `close()` 被调用，避免资源泄漏。

### 补充说明与注意事项

#### 与 `FileOutputStream` 的选择

| | `FileWriter` | `FileOutputStream` |
|---|---|---|
| 数据单位 | 字符 | 字节 |
| 适用场景 | 文本文件（`.txt`、`.csv`） | 任意二进制文件（图片、音视频） |
| 编码处理 | 自动进行字符编码 | 不处理编码，直接写入字节 |

写入原始字节流时应使用 `FileOutputStream`；写入字符数据时 `FileWriter` 更便捷。

#### 性能优化：配合 `BufferedWriter`

`FileWriter` 自身的缓冲区较小且固定。在高频写入或大数据量场景下，建议用 `BufferedWriter` 包装 `FileWriter`，通过更大的缓冲区减少底层 I/O 次数，显著提升性能。

```java
try (BufferedWriter bw = new BufferedWriter(new FileWriter("big.txt", StandardCharsets.UTF_8))) {
    for (int i = 0; i < 10000; i++) {
        bw.write("line " + i);
        bw.newLine(); // 跨平台换行
    }
}
```

#### 平台文件锁限制

某些平台（如 Windows）对文件独占锁较为严格，同一文件在同一时刻只能被一个 `FileWriter` 打开写入，否则构造时会抛出 `IOException`。在并发场景下需要做好异常处理或改用其他同步策略。
