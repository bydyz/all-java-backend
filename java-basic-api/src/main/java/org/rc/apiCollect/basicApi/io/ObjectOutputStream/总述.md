`ObjectOutputStream` 是 Java 序列化机制的核心输出类。它的职责是将 Java 对象的状态转换为字节流，以便持久化到文件或通过网络传输，之后可由 `ObjectInputStream` 还原为对象。

---

### 功能概述

`ObjectOutputStream` 将**基本数据类型**和**Java 对象图**写入一个底层的 `OutputStream`。它的核心能力包括：

- **对象图遍历**：写入一个对象时，会自动递归写入该对象引用的其他对象，从而保存完整的对象图结构。
- **引用共享**：对同一对象的多次引用，在流中只写入一次，后续通过反向引用指向前一次写入的记录，从而在反序列化时恢复原本的对象图形态（而非产生多个副本）。
- **仅支持可序列化对象**：只有实现了 `java.io.Serializable` 接口的对象才能被写入。`String`、数组、基本类型包装类等都是可序列化的。
- **绕过构造器**：反序列化时，可序列化类的对象**不会调用其任何构造器**，对象状态直接从流中恢复。对于未实现 `Serializable` 的非可序列化超类，则会调用其无参构造器来初始化。

---

### 构造器

`ObjectOutputStream` 提供了两个构造器：

| 构造器 | 说明 |
|---|---|
| `public ObjectOutputStream(OutputStream out) throws IOException` | 最常用的构造器。创建时**会立即向底层流写入序列化流头部**（包含魔数和版本号），该头部会被 `ObjectInputStream` 在构造时读取并校验。 |
| `protected ObjectOutputStream()` | 供子类使用，用于完全重新实现 `ObjectOutputStream` 行为的场景，不分配当前实现的私有数据。 |

**使用单参数构造器时需要注意**：由于构造器本身就会写出流头部，如果在同一个底层流上**重复创建** `ObjectOutputStream` 实例，会导致流头部被重复写入，进而使反序列化失败。正确做法是在一个 `ObjectOutputStream` 实例上连续写入多个对象，而不是反复创建新实例。

---

### 核心 API

#### `writeObject(Object obj)` — 序列化对象

```java
public final void writeObject(Object obj) throws IOException
```

这是最核心的方法，将指定对象写入流中。对象所属的类、类的签名、字段值、数组内容以及所有被引用的对象，都会被一并编码写入。同一个对象在流中只会被完整写入一次，后续写入的是反向引用。

#### `writeUnshared(Object obj)` — 以“非共享”方式写入

```java
public void writeUnshared(Object obj) throws IOException
```

行为与 `writeObject` 基本相同，但**每次都把对象作为流中全新的独立对象写入**，即使该对象之前已经被写入过，也不会使用反向引用。这意味着反序列化后，该对象与其他位置出现的同源对象不再是同一个实例（`==` 为 `false`），而是两个内容相同的独立副本。

#### `defaultWriteObject()` — 在自定义 `writeObject` 中写出默认字段

```java
public void defaultWriteObject() throws IOException, NotActiveException
```

当类自行定义了 `private void writeObject(ObjectOutputStream out)` 方法来进行定制序列化时，可以在该方法内调用 `defaultWriteObject()`，以写出当前类的**非静态、非瞬态**字段的默认序列化状态。只能在 `writeObject` 的执行过程中调用，否则抛出 `NotActiveException`。

#### `reset()` — 重置流状态

```java
public void reset() throws IOException
```

将流中“已写入对象”的记录清空。调用后，之前写入过的对象再被写入时，会被当作全新的对象完整写入，而不再使用反向引用。这在需要**避免内存泄漏**（流持有大量已写对象的引用）或需要将同一个对象多次独立写入时非常有用。

#### 基本类型写入方法

`ObjectOutputStream` 实现了 `DataOutput` 接口，可以直接写入基本类型，无需装箱：

```java
writeInt(int val)   writeLong(long val)   writeDouble(double val)
writeBoolean(boolean val)   writeUTF(String str)   // 等等
```

文档示例：

```java
try (FileOutputStream fos = new FileOutputStream("t.tmp");
     ObjectOutputStream oos = new ObjectOutputStream(fos)) {
    oos.writeInt(12345);
    oos.writeObject("Today");
    oos.writeObject(new Date());
}
```

读取时必须按照**写入的相同类型和相同顺序**进行，因为序列化流中的对象和基本类型没有名称标签，完全依赖顺序来还原。

#### `flush()` 与 `close()`

- `flush()`：刷新缓冲区，确保数据写入底层流。
- `close()`：关闭流。`ObjectOutputStream` 关闭时会同时关闭底层的 `OutputStream`，通常不需要单独再关闭底层流。

---

### 使用中的关键约束与机制

#### 1. `Serializable` 接口

只有实现了 `java.io.Serializable` 的类才能被 `writeObject` 写入。`Serializable` 是一个**标记接口**，没有需要实现的方法，仅用于告诉 JVM 该类的对象允许序列化。未实现该接口的对象在写入时会抛出 `NotSerializableException`。

#### 2. `serialVersionUID` — 版本一致性

`serialVersionUID` 是用于验证序列化与反序列化两端类版本是否一致的标识符。如果两端的 `serialVersionUID` 不匹配，反序列化会抛出 `InvalidClassException`。

强烈建议在可序列化类中**显式声明**：

```java
private static final long serialVersionUID = 1L;
```

如果不声明，JVM 会根据类的结构（字段、方法等）自动计算一个值。这样一来，对类的任何微小修改（哪怕只是增加一个无关方法）都可能导致自动计算出的值变化，从而使之前序列化的数据无法反序列化。显式声明可以避免这种脆弱性。

#### 3. `transient` — 排除字段

被 `transient` 修饰的字段**不会**被默认序列化。反序列化后，该字段将保持其类型的默认值（如 `null`、`0`、`false`）。适用于密码、缓存、派生字段等不需要或不应该被持久化的数据。

#### 4. `writeReplace()` — 替换被写入的对象

可序列化类可以实现以下签名的方法，在对象被写入流之前“提名”一个替代对象：

```java
ANY-ACCESS-MODIFIER Object writeReplace() throws ObjectStreamException;
```

当 `ObjectOutputStream` 准备写入该类的对象时，会先调用 `writeReplace()`，并将其返回的对象写入流中。这提供了一种在序列化层面控制实例表示方式的机制，例如将复杂对象替换为轻量代理。

#### 5. 自定义 `writeObject` 的精确签名

如果需要在序列化时进行特殊处理（如加密、校验），必须实现的方法签名**精确**如下：

```java
private void writeObject(java.io.ObjectOutputStream stream)
    throws IOException;
```

方法名、修饰符、返回类型、参数类型都必须完全匹配，否则序列化机制不会调用该方法。在该方法内部，通常先调用 `defaultWriteObject()` 写出默认字段，再追加自定义数据。

### 完整代码示例

#### 可序列化类

```java
import java.io.Serializable;

class Person implements Serializable {
    private static final long serialVersionUID = 1L;

    private String name;
    private int age;
    private transient String password; // 不会被序列化

    public Person(String name, int age, String password) {
        this.name = name;
        this.age = age;
        this.password = password;
    }

    @Override
    public String toString() {
        return "Person{name='" + name + "', age=" + age
                + ", password='" + password + "'}";
    }
}
```

#### 序列化与反序列化

```java
import java.io.*;

public class ObjectStreamDemo {
    public static void main(String[] args) throws Exception {
        Person person = new Person("Alice", 30, "secret");

        // 序列化
        try (ObjectOutputStream oos =
                     new ObjectOutputStream(new FileOutputStream("person.ser"))) {
            oos.writeObject(person);
            oos.writeInt(100);
            oos.writeUTF("附加字符串");
        }

        // 反序列化（必须与写入顺序一致）
        try (ObjectInputStream ois =
                     new ObjectInputStream(new FileInputStream("person.ser"))) {
            Person restored = (Person) ois.readObject();
            int num = ois.readInt();
            String text = ois.readUTF();
            System.out.println(restored); // password 为 null
            System.out.println(num + ", " + text);
        }
    }
}
```

**输出**：

```
Person{name='Alice', age=30, password='null'}
100, 附加字符串
```

`password` 因被 `transient` 修饰，反序列化后恢复为 `null`。

---

`ObjectOutputStream` 是 Java 原生序列化的入口，其设计围绕**对象图遍历、引用共享和流式顺序读写**展开。使用时最需要留意的三点是：**显式声明 `serialVersionUID`**、**理解 `writeObject` 的共享引用行为与 `writeUnshared` 的差异**，以及**保证写入与读取的类型和顺序严格一致**。
