`PrintStream` 是 Java I/O 体系中一个非常“实用主义”的类。它的设计目标不是提供最底层的字节控制，而是**让你能以最方便的方式，把各种类型的数据转换成文本形式输出**。我们最熟悉的 `System.out.println()`，`System.out` 本身就是一个 `PrintStream` 实例。

### 🎯 核心功能与设计特性

`PrintStream` 在 `FilterOutputStream` 的基础上，叠加了三个关键特性：

1. **便捷的“打印”能力**：提供大量重载的 `print` / `println` 方法，可以直接接受 `boolean`、`char`、`int`、`long`、`float`、`double`、`char[]`、`String`、`Object` 等类型，并将它们转换为其字符串表示形式后输出。
2. **“静默”的错误处理**：与大多数 I/O 流不同，`PrintStream` 的 `print`/`println`/`write` 等方法**从不抛出 `IOException`**。如果底层发生 I/O 错误，它只是设置一个内部的错误标志，你需要主动调用 `checkError()` 来检查是否发生了错误。
3. **可选的自动刷新与字符编码**：你可以选择开启 `autoFlush`，让流在特定时机自动将缓冲区数据推送到目的地。同时，它负责将字符按指定的字符集（或平台默认字符集）编码为字节。

### 🏗️ 构造器详解：控制“流向”与“行为”

`PrintStream` 的构造器主要围绕三个维度展开：**输出目的地**、**是否自动刷新 (`autoFlush`)** 和 **字符编码 (`Charset`)**。

| 构造器签名 | 目的地 | 自动刷新 | 字符编码 |
| :--- | :--- | :--- | :--- |
| `PrintStream(OutputStream out)` | 一个已有的字节流 | **关闭** | 平台默认 |
| `PrintStream(OutputStream out, boolean autoFlush)` | 一个已有的字节流 | 由 `autoFlush` 指定 | 平台默认 |
| `PrintStream(OutputStream out, boolean autoFlush, String encoding)` | 一个已有的字节流 | 由 `autoFlush` 指定 | 指定 `encoding` |
| `PrintStream(String fileName)` | 文件路径（**会覆盖**） | **关闭** | 平台默认 |
| `PrintStream(File file)` | `File` 对象（**会覆盖**） | **关闭** | 平台默认 |
| `PrintStream(String fileName, String csn)` | 文件路径（**会覆盖**） | **关闭** | 指定 `csn` |

> **注意**：直接使用 `String` 或 `File` 构造器打开文件时，如果文件已存在，其内容**会被截断（覆盖）**。若需追加，应使用 `new FileOutputStream(file, true)` 包装后再交给 `PrintStream`。

#### 代码示例：创建不同配置的 `PrintStream`

```java
import java.io.*;
import java.nio.charset.StandardCharsets;

public class PrintStreamConstructors {
    public static void main(String[] args) throws IOException {
        // 1. 包装已有的 OutputStream，开启自动刷新，使用 UTF-8
        try (PrintStream ps1 = new PrintStream(
                new FileOutputStream("output1.txt"), true, "UTF-8")) {
            ps1.println("UTF-8 与 autoFlush 已启用");
        }

        // 2. 直接通过文件路径创建，不自动刷新，使用平台默认编码
        try (PrintStream ps2 = new PrintStream("output2.txt")) {
            ps2.println("平台默认编码");
            // 因为没有开启 autoFlush，数据可能仍在缓冲区中
            ps2.flush(); // 需要手动刷新以确保写入
        }

        // 3. 追加模式写入文件（PrintStream 本身不支持追加，需借助 FileOutputStream）
        try (PrintStream ps3 = new PrintStream(
                new FileOutputStream("append.log", true), true, StandardCharsets.UTF_8)) {
            ps3.println("这是一条追加的日志记录");
        }
    }
}
```

### 📚 核心 API 使用方法与代码

`PrintStream` 的 API 可以清晰地分为几组。

#### 1. `print` / `println`：基础输出

这是最核心的方法族。`print` 输出后不换行，`println` 输出后追加一个**平台相关的行分隔符**（`System.lineSeparator()`）。

```java
public class BasicPrintDemo {
    public static void main(String[] args) {
        PrintStream out = System.out; // 直接使用标准输出流

        out.print("不换行");
        out.print(" - 继续在同一行");
        out.println(); // 仅输出一个换行符

        out.println(true);
        out.println(3.14159);
        out.println(new Object()); // 调用对象的 toString()
    }
}
```

> **关键区别**：`print(97)` 会将整数 `97` 转换为其字符串表示 `"97"` 输出；而继承自 `OutputStream` 的 `write(97)` 则会将 `97` 作为一个字节写出，在控制台可能显示为字符 `'a'`（取决于编码）。`print` 系列方法实现了“数据原样写出”的效果。

#### 2. `printf` / `format`：格式化输出

这两个方法功能完全相同（`printf` 是 `format` 的别名），提供 C 语言风格的格式化能力，支持宽度、精度、对齐、日期时间等丰富格式。

```java
public class FormattingDemo {
    public static void main(String[] args) {
        // 基本格式化：%d 整数，%.2f 保留两位小数，%n 平台无关换行符
        System.out.printf("整数: %d, 浮点数: %.2f%n", 42, 3.14159);

        // 宽度与对齐
        System.out.printf("|%-10s|%10s|%n", "左对齐", "右对齐");

        // 日期时间格式化
        System.out.printf("当前日期: %tF %n", new java.util.Date());
    }
}
```

> **建议**：在 `printf`/`format` 中，使用 `%n` 代替 `\n` 作为换行符，以保证跨平台的可移植性。

#### 3. `write`：底层字节写入

`PrintStream` 也保留了从 `OutputStream` 继承的 `write` 方法，用于直接写入字节。这些方法**不进行字符到字符串的转换**，直接操作字节。

```java
public class WriteDemo {
    public static void main(String[] args) {
        PrintStream ps = System.out;
        // 写入字节 'A' (ASCII 65)
        ps.write(65);
        ps.println(); // 换行以分隔输出

        byte[] bytes = "字节数组".getBytes();
        // 写入字节数组的一部分
        ps.write(bytes, 0, bytes.length);
        ps.println();
    }
}
```

#### 4. 错误处理：`checkError()`

由于 `PrintStream` 不抛出 `IOException`，你需要使用 `checkError()` 来检查在之前的操作中是否发生了错误。调用 `checkError()` 时，它会**先刷新流**，然后返回内部错误标志的状态。一旦错误标志被设置，它会一直保持，直到流关闭。

```java
public class ErrorCheckDemo {
    public static void main(String[] args) {
        // 模拟一个总是失败的 OutputStream
        PrintStream ps = new PrintStream(new OutputStream() {
            @Override
            public void write(int b) {
                throw new RuntimeException("模拟写入失败");
            }
        });

        ps.println("这条消息将无法写入");
        // PrintStream 内部捕获了异常，没有向外抛出

        if (ps.checkError()) {
            System.err.println("检测到写入错误！");
        }
        ps.close();
    }
}
```

#### 5. `flush` 与 `close`

- **`flush()`**：强制将缓冲区中的数据写出到底层流。
- **`close()`**：关闭流并释放资源。关闭前会自动执行 `flush`。

即使开启了 `autoFlush`，在关闭流或程序结束前，仍建议显式调用 `flush()` 或依赖 `close()` 来确保所有数据都被写出。

### 🔄 进阶：重定向 `System.out` 与追加文件

`PrintStream` 的一个常见高级用法是**重定向标准输出**。`System.setOut(PrintStream)` 可以改变 `System.out` 的流向，将控制台输出捕获到文件或其他目的地。

```java
public class RedirectDemo {
    public static void main(String[] args) throws FileNotFoundException {
        PrintStream originalOut = System.out; // 保存原始的控制台输出流

        // 将 System.out 重定向到文件
        PrintStream fileOut = new PrintStream("console_redirect.log");
        System.setOut(fileOut);

        System.out.println("这行文字会写入文件，而不是控制台。");

        // 恢复原始的控制台输出
        System.setOut(originalOut);
        System.out.println("已恢复，这条消息回到控制台。");

        fileOut.close();
    }
}
```

### 💡 补充：`PrintStream` vs. `PrintWriter`

了解这一点有助于在合适的场景选择正确的工具。二者的核心区别在于**处理数据的层面**：

- **`PrintStream` 是字节流**：它本质上是一个 `OutputStream`，字符编码是在内部完成的。这使它在处理二进制数据或需要与底层字节流紧密交互时（例如 `System.out`）更为合适。
- **`PrintWriter` 是字符流**：它直接处理 `char`，能更好地处理国际化文本，并支持更一致的编码控制。在编写文本文件、网络响应或日志时，**通常推荐优先使用 `PrintWriter`**。

`PrintStream` 的核心价值在于**便利性**。它以牺牲严格的错误传播为代价，换取了极其简洁的输出代码。对于大多数控制台输出、调试打印或简单的文件写入场景，它完全够用；但在需要精细控制编码或严格错误处理的场合，则应根据上述差异做出选择。
