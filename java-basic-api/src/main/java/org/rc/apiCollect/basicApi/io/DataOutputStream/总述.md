`DataOutputStream` 的核心价值在于提供一种**与机器无关**的方式，将 Java 原始数据类型写入输出流，使得写入的二进制数据可以在任何平台上被 `DataInputStream` 正确还原。它本身不直接连接数据源（如文件、网络），而是作为**装饰器**包装在另一个 `OutputStream` 之上，为底层字节流添加“类型感知”的写入能力。

---

### 核心特性与定位

在展开 API 之前，先明确 `DataOutputStream` 的几个关键设计约定，这些约定直接影响所有方法的行为：

1. **固定的大端序（Big-Endian）**：所有多字节类型（`short`、`int`、`long`、`float`、`double`、`char`）均以**高字节在前**的顺序写入，与具体硬件平台无关。
2. **不是线程安全的**：JDK 文档明确指出，`DataOutputStream` 不适合被多个线程并发使用；若需多线程写入，必须在外部进行同步控制。
3. **与 `DataInputStream` 成对使用**：写入的二进制格式是为 `DataInputStream` 的对应读取方法设计的，二者共同构成可移植的二进制 I/O 基础。

---

### 构造器

`DataOutputStream` 有且仅有一个 public 构造器：

```java
public DataOutputStream(OutputStream out)
```

它接收一个底层 `OutputStream`，并将内部的字节计数器 `written` 初始化为 `0`。典型用法是包装 `FileOutputStream`（写入文件）或 `ByteArrayOutputStream`（写入内存）：

```java
// 写入文件
DataOutputStream dos = new DataOutputStream(new FileOutputStream("data.bin"));

// 写入内存字节数组
ByteArrayOutputStream baos = new ByteArrayOutputStream();
DataOutputStream dos = new DataOutputStream(baos);
```

实际使用时，通常建议在 `FileOutputStream` 之上再套一层 `BufferedOutputStream`，以避免每次小量写入都触发系统调用：

```java
DataOutputStream out = new DataOutputStream(
    new BufferedOutputStream(new FileOutputStream("data.bin"))
);
```

### 核心 API 详解与代码示例

`DataOutputStream` 的方法可分为三类：**原始类型写入**、**字符串写入**、**底层字节操作与状态方法**。

#### 原始类型写入方法

每个方法都以**固定字节宽度**写出对应类型，写入成功后内部计数器 `written` 会相应增加。

| 方法签名 | 写入字节数 | 说明 |
|---|---|---|
| `writeBoolean(boolean v)` | 1 | `true` 写为 `(byte)1`，`false` 写为 `(byte)0` |
| `writeByte(int v)` | 1 | 写出 `v` 的低 8 位 |
| `writeShort(int v)` | 2 | 写出 16 位，高字节在前 |
| `writeChar(int v)` | 2 | 写出一个 UTF-16 码元，高字节在前 |
| `writeInt(int v)` | 4 | 写出 32 位，高字节在前 |
| `writeLong(long v)` | 8 | 写出 64 位，高字节在前 |
| `writeFloat(float v)` | 4 | 先经 `Float.floatToIntBits` 转为 `int`，再按 4 字节写出 |
| `writeDouble(double v)` | 8 | 先经 `Double.doubleToLongBits` 转为 `long`，再按 8 字节写出 |

```java
try (DataOutputStream dos = new DataOutputStream(
        new BufferedOutputStream(new FileOutputStream("primitives.bin")))) {
    dos.writeBoolean(true);        // 1 字节
    dos.writeByte(65);            // 1 字节，低8位 = 'A'
    dos.writeShort(1000);         // 2 字节
    dos.writeChar('X');           // 2 字节
    dos.writeInt(123456);         // 4 字节
    dos.writeLong(999999999L);    // 8 字节
    dos.writeFloat(3.14f);        // 4 字节
    dos.writeDouble(2.71828);     // 8 字节
}
```

上述 8 次调用总共写入 `1+1+2+2+4+8+4+8 = 30` 字节。这些字节以二进制形式存储，直接以文本方式打开文件会看到乱码，这是预期行为。

---

#### 字符串写入方法：`writeBytes`、`writeChars`、`writeUTF`

`DataOutputStream` 提供了三种写入字符串的途径，但它们的**语义和适用场景截然不同**，其中只有 `writeUTF` 是为与 `DataInputStream.readUTF` 配对使用而设计的。

**`writeBytes(String s)`**：仅写出每个字符的低 8 位，高 8 位被**丢弃**。它不保证字符串能被正确还原，仅适用于确定字符串中每个字符都在 ASCII 范围内（或仅关心低字节）的特殊场景。

**`writeChars(String s)`**：将字符串中的每个 `char` 以 **2 字节**（高字节在前）依次写出。写入的是原始的 UTF-16 码元序列，不包含长度信息；读取端需要自行知道字符数量。

**`writeUTF(String str)`**：这是最常用且最安全的方法。它使用 **Modified UTF-8** 编码写出字符串，并**首先写入一个 2 字节的无符号长度前缀**（表示后续编码字节的数量，而非字符数量）。这一长度前缀使得 `DataInputStream.readUTF` 可以自动确定字符串的边界。

```java
try (DataOutputStream dos = new DataOutputStream(
        new FileOutputStream("strings.bin"))) {

    dos.writeUTF("Hello");         // 长度前缀(2字节) + Modified UTF-8 数据
    dos.writeUTF("Java T-Shirt");  // 同上

    // writeBytes 仅写低8位，不推荐用于一般字符串
    dos.writeBytes("ABC");         // 3 字节，丢失高8位（此处恰好均为ASCII，未丢失）

    // writeChars 写每个char的2字节，无长度前缀
    dos.writeChars("XYZ");         // 6 字节，读取端需自行知道有3个char
}
```

`writeUTF` 的长度前缀是以**实际写出的字节数**计的，因此它有一个硬性限制：**字符串经 Modified UTF-8 编码后的字节数不能超过 65535**（2 字节无符号长度上限）。对于纯 ASCII 字符串，理论上限约为 65535 个字符；对于含非 ASCII 字符的字符串，上限会更低。如果需要传输更长的字符串，`writeUTF` 不适用，应改用其他分帧方式。

**三种方式的对比小结**：

| 方法 | 是否带长度前缀 | 写入粒度 | 能否可靠还原字符串 |
|---|---|---|---|
| `writeBytes` | 否 | 每字符 1 字节（截断高8位） | 通常不能，仅限低字节即可表示的场景 |
| `writeChars` | 否 | 每字符 2 字节 | 可以，但读取端需自行确定字符数 |
| `writeUTF` | 是（2 字节） | Modified UTF-8 变长 | **能**，与 `readUTF` 配对使用 |

#### 底层字节操作与状态方法

**`write(int b)` / `write(byte[] b, int off, int len)`**：从父类 `OutputStream` 继承的直接字节写入方法，`DataOutputStream` 对其进行了覆盖，在写入的同时更新内部计数器 `written`。

**`size()`**：返回自流创建以来**已写入的字节总数**（`written` 字段的值）。这是一个 final 方法，常用于在写入过程中确认已产出的数据量。

**`flush()`**：强制将底层缓冲区中的数据刷出。如果包装了 `BufferedOutputStream`，需要在适当位置调用 `flush()`，否则数据可能暂留在缓冲区中。

**`close()`**：关闭 `DataOutputStream`，进而关闭底层流。使用 try-with-resources 时无需手动调用。

```java
ByteArrayOutputStream baos = new ByteArrayOutputStream();
try (DataOutputStream dos = new DataOutputStream(baos)) {
    dos.writeInt(42);
    dos.writeUTF("test");
    System.out.println("已写入字节数: " + dos.size()); // 4 + (2+4) = 10
    dos.flush();
}
```

### 完整使用示例：写入一组“记录”

以下示例模拟将若干条结构化记录写入文件，每条记录由 `double`、`int`、`String` 三个字段组成，这是 `DataOutputStream` 最典型的使用模式：

```java
import java.io.*;

public class DataOutputStreamDemo {
    public static void main(String[] args) throws IOException {
        String file = "invoicedata.bin";

        double[] prices = {19.99, 9.99, 15.99};
        int[] units = {12, 8, 13};
        String[] descs = {"Java T-Shirt", "Java Mug", "Java Pin"};

        try (DataOutputStream out = new DataOutputStream(
                new BufferedOutputStream(new FileOutputStream(file)))) {

            for (int i = 0; i < prices.length; i++) {
                out.writeDouble(prices[i]);  // 8 字节
                out.writeInt(units[i]);      // 4 字节
                out.writeUTF(descs[i]);      // 2 字节长度前缀 + 变长数据
            }
        }

        // 读取时需使用 DataInputStream，且读取顺序必须与写入完全一致
        try (DataInputStream in = new DataInputStream(
                new BufferedInputStream(new FileInputStream(file)))) {

            for (int i = 0; i < prices.length; i++) {
                double price = in.readDouble();
                int unit = in.readInt();
                String desc = in.readUTF();
                System.out.printf("%s: %.2f x %d%n", desc, price, unit);
            }
        }
    }
}
```

这里的关键约束是：**写入顺序与读取顺序必须严格一致**，因为二进制流本身不携带字段名或类型元数据，`DataInputStream` 完全依赖调用方按照约定顺序读取对应类型的数据。这也是 `DataOutputStream` 适合“由同一方定义读写协议”的场景（如自定义二进制文件格式、网络协议的基础数据帧）的原因。

---

### 使用要点总结

- **始终与 `BufferedOutputStream` 组合**用于文件或网络场景，避免频繁的小量底层写入。
- **优先使用 `writeUTF` 写入字符串**，除非有特殊理由使用 `writeBytes`/`writeChars`；注意 `writeUTF` 的 65535 字节上限。
- **写入顺序即协议**：读写两端必须约定完全相同的字段顺序和类型。
- **不是线程安全的**：多线程环境下需外部同步，或为每个线程使用独立的 `DataOutputStream` 实例。
- **使用 try-with-resources 管理资源**，确保底层流被正确关闭和刷新。
