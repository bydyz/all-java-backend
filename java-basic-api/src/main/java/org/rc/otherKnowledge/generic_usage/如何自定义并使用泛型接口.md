# Java 泛型接口的自定义与使用详解

## 一、泛型接口的定义语法

泛型接口就是在接口名后声明一个或多个**类型参数**（Type Parameter），这个类型参数可以在接口内部当作类型使用：

```java
// 语法：interface 接口名<类型参数列表> { ... }
public interface 接口名<T> {
    T method(T param);
}
```

类型参数惯例命名：

| 符号 | 含义 |
|------|------|
| `T` | Type（通用类型） |
| `E` | Element（集合元素） |
| `K` / `V` | Key / Value |
| `R` | Result（返回值） |
| `S` / `U` / `V` | 第二、三、四个类型参数 |

## 二、自定义泛型接口的几种形式

### 2.1 单类型参数

```java
public interface Container<T> {
    void add(T item);
    T get(int index);
    int size();
}
```

### 2.2 多类型参数

```java
public interface Converter<S, T> {
    T convert(S source);
}
```

### 2.3 有界类型参数（Bounded Type Parameter）

```java
// T 必须是 Number 或其子类
public interface NumberProcessor<T extends Number> {
    double process(T value);
}

// 多重边界：类必须写在接口前面，用 & 连接
public interface ComparableContainer<T extends Comparable<T> & Serializable> {
    T max();
}
```

### 2.4 带默认方法的泛型接口（Java 8+）

```java
public interface Repository<T, ID> {

    T findById(ID id);

    List<T> findAll();

    void save(T entity);

    void deleteById(ID id);

    // 默认方法可以使用接口的类型参数
    default boolean existsById(ID id) {
        return findById(id) != null;
    }

    default void saveAll(Collection<? extends T> entities) {
        entities.forEach(this::save);
    }
}
```

## 三、如何使用泛型接口（实现侧）

实现泛型接口有 **4 种典型方式**，区别非常关键。

### 方式 1：实现时指定具体类型（最常见）

```java
public class StringToIntegerConverter implements Converter<String, Integer> {
    @Override
    public Integer convert(String source) {
        return Integer.valueOf(source);
    }
}

// 使用
Converter<String, Integer> converter = new StringToIntegerConverter();
Integer num = converter.convert("123");  // 返回类型明确，无需强转
```

此时实现类是**非泛型类**，接口的类型参数已经被"填死"。

### 方式 2：实现时保留类型参数（通用实现）

```java
// 实现类本身也是泛型的，把类型参数继续往下传
public class ListConverter<T> implements Converter<List<T>, T[]> {

    private final Class<T> type;

    public ListConverter(Class<T> type) {
        this.type = type;
    }

    @Override
    @SuppressWarnings("unchecked")
    public T[] convert(List<T> source) {
        T[] array = (T[]) java.lang.reflect.Array.newInstance(type, source.size());
        return source.toArray(array);
    }
}

// 使用
Converter<List<String>, String[]> c = new ListConverter<>(String.class);
String[] arr = c.convert(List.of("a", "b"));
```

> **注意**：由于类型擦除，`new T[]` 无法直接编译，通常需要借助 `Class<T>` 或 `Array.newInstance` 反射创建数组。

### 方式 3：匿名内部类

适合一次性实现、逻辑简单的场景：

```java
Converter<String, Integer> lengthConverter = new Converter<String, Integer>() {
    @Override
    public Integer convert(String source) {
        return source.length();
    }
};
```

### 方式 4：Lambda / 方法引用（接口必须是函数式接口）

泛型接口只要满足 **只有一个抽象方法**，就是函数式接口（可加 `@FunctionalInterface` 标注）：

```java
@FunctionalInterface
public interface Converter<S, T> {
    T convert(S source);
}

// Lambda
Converter<String, Integer> c1 = s -> s.length();

// 方法引用
Converter<String, Integer> c2 = Integer::valueOf;

// 使用
System.out.println(c2.convert("42"));  // 42
```

### 方式 5：先继承泛型接口，再由子类指定类型

```java
// 抽象基类保留类型参数
public abstract class AbstractRepository<T, ID> implements Repository<T, ID> {
    protected final Map<ID, T> store = new HashMap<>();

    @Override
    public T findById(ID id) {
        return store.get(id);
    }

    @Override
    public List<T> findAll() {
        return new ArrayList<>(store.values());
    }

    @Override
    public void save(T entity) {
        // 子类需提供 getId
        store.put(getId(entity), entity);
    }

    @Override
    public void deleteById(ID id) {
        store.remove(id);
    }

    protected abstract ID getId(T entity);
}

// 具体子类确定类型
public class UserRepository extends AbstractRepository<User, Long> {
    @Override
    protected Long getId(User user) {
        return user.getId();
    }
}
```

## 四、使用侧的技巧：通配符与 PECS 原则

当方法**接收**泛型接口的实例时，往往不需要精确类型，这时用通配符更灵活。

### 4.1 三种通配符

```java
public class ConverterUtils {

    // 只读取：接受任何 Number 子类型的转换器 —— 上界通配符
    public static void printConverted(Converter<String, ? extends Number> c, String s) {
        Number n = c.convert(s);   // 可以读，返回值当作 Number
        System.out.println(n);
    }

    // 只写入：接受任何能接收 Integer 的容器 —— 下界通配符
    public static void fill(List<? super Integer> list) {
        list.add(1);               // 可以写
        // Integer x = list.get(0); // 不能读成具体类型（只能读成 Object）
    }

    // 完全不关心类型：无界通配符
    public static int size(Container<?> c) {
        return c.size();
    }
}
```

### 4.2 PECS 原则（Producer Extends, Consumer Super）

> - **生产者（只读）用 `extends`**
> - **消费者（只写）用 `super`**

经典应用 —— `Collections.copy` 的签名：

```java
public static <T> void copy(List<? super T> dest, List<? extends T> src)
```

`dest` 是消费者（写），用 `super`；`src` 是生产者（读），用 `extends`。

### 4.3 泛型方法与泛型接口配合

```java
public class Converters {

    // 泛型方法 + 泛型接口，实现"任意输入输出"的通用转换
    public static <S, T> List<T> convertAll(
            Collection<S> sources, Converter<S, T> converter) {

        List<T> result = new ArrayList<>(sources.size());
        for (S s : sources) {
            result.add(converter.convert(s));
        }
        return result;
    }
}

// 使用：类型全部自动推断，无需显式指定
List<String> strs = List.of("1", "2", "3");
List<Integer> nums = Converters.convertAll(strs, Integer::valueOf);
```

## 五、完整实战示例：自定义 `Result<T>` 结果封装接口

```java
// 1. 定义泛型接口
public interface Result<T> {
    boolean isSuccess();
    T getData();
    String getMessage();

    // 静态工厂：注意静态方法不能使用接口自己的类型参数！
    // 必须自己声明 <E>，否则编译报错
    static <E> Result<E> success(E data) {
        return new SuccessResult<>(data);
    }

    static <E> Result<E> failure(String message) {
        return new FailureResult<>(message);
    }

    // 泛型默认方法：结果映射
    default <R> Result<R> map(Function<? super T, ? extends R> mapper) {
        if (isSuccess()) {
            return Result.success(mapper.apply(getData()));
        }
        return Result.failure(getMessage());
    }

    // 内部实现类
    class SuccessResult<T> implements Result<T> {
        private final T data;
        SuccessResult(T data) { this.data = data; }
        @Override public boolean isSuccess() { return true; }
        @Override public T getData() { return data; }
        @Override public String getMessage() { return "OK"; }
    }

    class FailureResult<T> implements Result<T> {
        private final String message;
        FailureResult(String message) { this.message = message; }
        @Override public boolean isSuccess() { return false; }
        @Override public T getData() { return null; }
        @Override public String getMessage() { return message; }
    }
}
```

使用：

```java
public class Demo {
    public static void main(String[] args) {
        Result<String> r1 = Result.success("hello");

        // 链式转换：String -> Integer -> 结果
        Result<Integer> r2 = r1.map(String::length).map(i -> i * 10);
        System.out.println(r2.getData());   // 50

        // 失败分支
        Result<Integer> r3 = Result.<Integer>failure("出错了").map(i -> i + 1);
        System.out.println(r3.isSuccess()); // false
        System.out.println(r3.getMessage()); // 出错了
    }
}
```

这个例子体现了泛型接口的几个核心用法：**类型参数贯穿接口方法 + 静态工厂的自声明类型参数 + 泛型默认方法做类型转换**。

## 六、常见坑与注意事项

### 1. 静态方法 / 静态字段不能使用接口自身的类型参数

```java
public interface Box<T> {
    // static T instance;           // ✗ 编译错误
    // static T create() { ... }    // ✗ 编译错误

    // ✓ 静态方法必须自己声明类型参数
    static <E> Box<E> of(E value) { return () -> value; }
}
```

原因：`T` 是**实例级别**的类型参数，而静态成员属于类级别，独立于任何实例。

### 2. 不能对泛型类型使用 `instanceof`（除了无界通配符）

```java
List<String> list = new ArrayList<>();
// if (list instanceof List<String>) {}  // ✗ 编译错误
if (list instanceof List<?>) { }         // ✓ 可以
```

### 3. 不能 `new T()`、不能创建泛型数组

```java
public interface Factory<T> {
    // T create() { return new T(); }     // ✗
    // T[] array = new T[10];             // ✗
}
```

通常通过传入 `Class<T>` 或 `Supplier<T>` 解决：

```java
public interface Factory<T> {
    T create();
}

Factory<StringBuilder> f = StringBuilder::new;  // 用方法引用规避
```

### 4. 泛型实现类不能用菱形语法

```java
// Converter<String, Integer> c = new StringToIntegerConverter<>();  // ✗ 非泛型类不能用 <>
Converter<String, Integer> c = new StringToIntegerConverter();      // ✓
```

### 5. 类型擦除导致的重载冲突

```java
public interface Handler<T> {
    void handle(T t);
}

// 下面两个实现会导致"方法签名冲突"（擦除后都是 handle(Object)）
// class A implements Handler<String> { public void handle(String s) {} }
// class B implements Handler<Integer> { public void handle(Integer i) {} }
```

实际上这是两个不同的类，不冲突；但**同一个类**里不能同时存在 `handle(String)` 和 `handle(Integer)` 作为同一接口方法的实现（擦除后签名相同），要注意的是桥接方法（Bridge Method）的存在。

### 6. 泛型接口不能被 `@FunctionalInterface` 之外的东西滥用

一个接口如果有多个抽象方法，就不能用 Lambda，必须用匿名类或具体实现类。

## 七、小结

| 场景 | 推荐做法 |
|------|----------|
| 想固定实现类型 | 实现时直接指定：`implements Converter<String, Integer>` |
| 想做通用实现 | 实现类保留类型参数：`class X<T> implements I<T>` |
| 一次性使用 | 匿名内部类 或 Lambda（函数式接口） |
| 接收方只读 | `I<? extends T>` |
| 接收方只写 | `I<? super T>` |
| 不关心类型 | `I<?>` 或无界 `I<Object>` 慎用 |
| 静态工厂 | 在接口内自己声明 `<E>`，如 `static <E> Box<E> of(E)` |

掌握以上内容，就覆盖了 Java 泛型接口从**定义 → 实现 → 调用 → 通配符 → 踩坑**的完整链路。
