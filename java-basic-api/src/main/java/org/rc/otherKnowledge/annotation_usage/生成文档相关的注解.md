# Java 中生成文档相关的注解详解

Java 中与生成文档相关的注解，主要分为两个层面：**JDK 内置的 Javadoc 文档注释标签**，以及**用于生成 REST API 接口文档的框架注解**（如 Swagger/OpenAPI）。两者的用途和生效方式不同：前者由 `javadoc` 工具直接解析，生成 HTML 格式的 API 参考文档；后者通常由框架在运行时扫描，生成可交互的在线接口文档。

---

## 一、JDK 内置：Javadoc 文档注释标签

Javadoc 注释以 `/**` 开始、`*/` 结束，可以放在类、方法、字段等声明之前。除了描述性文字，其中以 `@` 开头的**块标签**和以 `{@` 开头的**内联标签**会被 `javadoc` 工具识别并提取为结构化文档内容。

### 常用标签一览

| 标签 | 适用位置 | 作用 |
| :--- | :--- | :--- |
| `@author` | 类/接口 | 标明作者信息 |
| `@version` | 类/接口 | 标明版本号 |
| `@param` | 方法/构造器 | 描述参数的含义与要求 |
| `@return` | 方法 | 描述返回值的含义 |
| `@throws` / `@exception` | 方法/构造器 | 说明可能抛出的异常及触发条件 |
| `@see` | 任意 | 引用相关类、方法或外部链接 |
| `@since` | 任意 | 标明该 API 开始支持的版本 |
| `@deprecated` | 任意 | 标记已过时，建议给出替代方案 |
| `{@link}` | 行内任意位置 | 创建指向其他类/成员文档的内联链接 |
| `{@code}` | 行内任意位置 | 以代码字体显示文本，不解析其中的 HTML 或 Javadoc 标签 |

上表基于 Javadoc 的常见核心标签整理。`@author`、`@version` 通常只出现在类级注释中；`@param`、`@return`、`@throws` 用于方法或构造器的文档化。

### 代码示例：类级与方法级注释

```java
/**
 * 这是一个简单的计算器类，用于演示 Javadoc 的常用标签。
 *
 * @author example
 * @version 1.0
 * @since 1.0
 */
public class Calculator {

    /**
     * 计算两个整数的和。
     *
     * <p>此方法不做溢出检查，调用方需自行保证参数范围。</p>
     *
     * @param a 第一个加数
     * @param b 第二个加数
     * @return 两个参数之和
     * @throws IllegalArgumentException 如果任一参数为 null（此处仅为示例）
     */
    public int add(int a, int b) {
        return a + b;
    }

    /**
     * 除法运算。
     *
     * @param dividend 被除数
     * @param divisor  除数，不能为 0
     * @return 商
     * @throws ArithmeticException 当 {@code divisor} 为 0 时抛出
     * @see #add(int, int) 相关加法方法
     */
    public int divide(int dividend, int divisor) {
        return dividend / divisor;
    }
}
```

使用命令行生成 HTML 文档：

```bash
javadoc -d doc -encoding UTF-8 -charset UTF-8 Calculator.java
```

生成的 `doc/index.html` 即文档入口。`-d` 用于指定输出目录，`-encoding` 与 `-charset` 用于避免中文乱码。

## 二、REST API 文档生成注解：Swagger 2 与 OpenAPI 3

在 Spring Boot 等 Web 项目中，这类注解用于让框架自动生成可读、可交互的在线接口文档。目前存在两套主流注解体系：

- **Swagger 2**（`io.swagger.annotations.*`）：旧版注解。
- **OpenAPI 3 / Swagger 3**（`io.swagger.v3.oas.annotations.*`）：当前推荐使用的版本，`@Api`、`@ApiOperation` 等旧注解已被 `@Tag`、`@Operation` 等替代。

下面以**推荐使用的 OpenAPI 3** 为主展示代码示例，并在对照表中列出 Swagger 2 的对应注解。

### 注解对照与常用场景

| 用途 | Swagger 2（旧版） | OpenAPI 3（推荐） |
| :--- | :--- | :--- |
| 给 Controller 分组/打标签 | `@Api` | `@Tag` |
| 描述单个接口操作 | `@ApiOperation` | `@Operation` |
| 描述方法参数 | `@ApiParam` | `@Parameter` |
| 描述响应状态码 | `@ApiResponse` / `@ApiResponses` | `@ApiResponse` / `@ApiResponses` |
| 描述实体/模型 | `@ApiModel` | `@Schema` |
| 描述模型字段 | `@ApiModelProperty` | `@Schema` |

OpenAPI 3 中，`@Schema` 同时承担了描述类和字段的职责，不再需要区分 `@ApiModel` 与 `@ApiModelProperty`。

### 代码示例：实体类的文档注解（OpenAPI 3）

```java
import io.swagger.v3.oas.annotations.media.Schema;

@Schema(title = "用户实体", description = "描述用户的基本信息")
public class User {

    @Schema(title = "用户ID", description = "用户的唯一标识", example = "1001", required = true)
    private Long id;

    @Schema(title = "用户名", description = "用户的名称", example = "张三", defaultValue = "匿名用户")
    private String name;

    @Schema(title = "年龄", description = "用户的年龄", example = "25")
    private Integer age;

    // getters / setters 省略
}
```

`@Schema` 的 `description` 会显示为字段说明，`example` 会在文档中展示示例值，`required` 标记必填项，`defaultValue` 展示默认值。

### 代码示例：Controller 的文档注解（OpenAPI 3）

```java
import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.Parameter;
import io.swagger.v3.oas.annotations.responses.ApiResponse;
import io.swagger.v3.oas.annotations.responses.ApiResponses;
import io.swagger.v3.oas.annotations.tags.Tag;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/users")
@Tag(name = "用户管理", description = "用户相关的增删改查接口")
public class UserController {

    @Operation(summary = "根据 ID 查询用户", description = "返回指定 ID 的用户详细信息")
    @ApiResponses({
            @ApiResponse(responseCode = "200", description = "查询成功"),
            @ApiResponse(responseCode = "404", description = "用户不存在")
    })
    @GetMapping("/{id}")
    public User getUser(
            @Parameter(name = "id", description = "用户 ID", example = "1", required = true)
            @PathVariable Long id) {
        // 模拟查询逻辑
        return new User();
    }

    @Operation(summary = "创建用户", description = "根据请求体中的用户信息创建新用户")
    @PostMapping
    public String createUser(@RequestBody User user) {
        return "创建成功";
    }
}
```

- `@Tag` 将同一 Controller 下的接口归入一个分组，便于文档中分类浏览。
- `@Operation` 描述单个接口的摘要（`summary`）和详细说明（`description`）。
- `@Parameter` 用于描述方法参数，`example` 会在文档中展示示例值。
- `@ApiResponses` / `@ApiResponse` 用于覆盖或补充默认的响应状态码说明。

在 Swagger 2 中，上述代码的注解大致对应为 `@Api`、`@ApiOperation`、`@ApiParam` 以及实体类上的 `@ApiModel` / `@ApiModelProperty`，语义基本一致，只是注解包名和属性名有所不同。

## 三、补充：Spring REST Docs（另一种思路）

除了基于注解自动扫描的 Swagger/OpenAPI 方案，Spring 生态中还有 **Spring REST Docs**。它的核心思路不是通过注解让工具“读取”接口描述，而是**通过编写测试来生成文档片段**，再用手写的 AsciiDoc 整合为最终文档。这种方式生成的文档质量较高，但需要编写和维护测试代码。它通常不依赖上述 Swagger/OpenAPI 注解来描述接口，而是依靠测试中的文档化 DSL（如 `document(...)`、`parameterWithName(...)`）来生成片段。

---

## 小结

| 层面 | 代表注解/标签 | 生成物 | 生效方式 |
| :--- | :--- | :--- | :--- |
| JDK Javadoc | `@param`、`@return`、`@throws`、`@author` 等 | HTML 格式的 API 参考文档 | 运行 `javadoc` 命令 |
| Swagger 2（旧） | `@Api`、`@ApiOperation`、`@ApiModel` 等 | 在线接口文档 + 调试页面 | 框架运行时扫描 |
| OpenAPI 3（推荐） | `@Tag`、`@Operation`、`@Parameter`、`@Schema` 等 | 在线接口文档 + 调试页面 | 框架运行时扫描 |
| Spring REST Docs | 测试中的文档化 DSL + AsciiDoc | 片段 + 整合文档 | 运行测试生成片段 |

实际项目中，**Javadoc 标签用于源码级别的 API 说明**，而 **OpenAPI 3 注解用于面向调用方的 REST 接口文档**；两者用途不同，通常并行使用。
