`BufferedOutputStream` 是 Java IO 体系中一个重要的**装饰器类**，它的核心使命是为另一个输出流（如 `FileOutputStream`）添加**缓冲功能**，从而显著提升 I/O 性能。

### 🎯 核心功能：为什么要用缓冲？

直接向磁盘或网络写入每一个字节，意味着每一次 `write()` 调用都可能触发一次昂贵的本机 I/O（Native I/O）操作。`BufferedOutputStream` 通过在内存中开辟一块缓冲区（一个字节数组），将多次小的写入操作累积起来，当缓冲区满或流被关闭时，再一次性将数据批量写入底层流。这大大减少了与底层设备（如磁盘）的通信次数，从而大幅提高效率。

### 🏗️ 构造器：如何创建带缓冲的输出流

`BufferedOutputStream` 提供了两个构造器，用于包装一个已存在的 `OutputStream`。

| 构造器 | 说明 |
| :--- | :--- |
| `BufferedOutputStream(OutputStream out)` | 使用**默认缓冲区大小**（通常为 **8192 字节，即 8KB**）创建一个缓冲输出流。 |
| `BufferedOutputStream(OutputStream out, int size)` | 使用**指定的缓冲区大小** `size` 创建一个缓冲输出流。如果 `size <= 0`，会抛出 `IllegalArgumentException`。 |

**代码示例：两种创建方式**
```java
import java.io.*;

public class ConstructorDemo {
    public static void main(String[] args) {
        try {
            // 方式一：使用默认缓冲区大小 (8192 字节)
            OutputStream fileOut1 = new FileOutputStream("output_default.txt");
            BufferedOutputStream bufferedOut1 = new BufferedOutputStream(fileOut1);

            // 方式二：指定自定义缓冲区大小，例如 16KB
            OutputStream fileOut2 = new FileOutputStream("output_custom.txt");
            BufferedOutputStream bufferedOut2 = new BufferedOutputStream(fileOut2, 16384);

            System.out.println("缓冲输出流创建成功。");
            bufferedOut1.close();
            bufferedOut2.close();
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

### ⚙️ 核心 API 方法与使用

`BufferedOutputStream` 重写了父类 `OutputStream` 的关键方法，所有 `write` 和 `flush` 方法都是 `synchronized` 的，以保证线程安全。

#### **1. `write(int b)`：写入单个字节**

将指定的字节写入内部缓冲区。如果缓冲区已满，会先自动将其内容写入底层流，然后再将新字节放入缓冲区。

```java
try (BufferedOutputStream bos = new BufferedOutputStream(new FileOutputStream("byte.txt"))) {
    bos.write('H'); // 写入单个字节
    bos.write('i');
    // ... 数据此时可能还在缓冲区中
    bos.flush(); // 强制将缓冲区数据写入文件
} catch (IOException e) {
    e.printStackTrace();
}
```
上述代码演示了逐字节写入，并调用 `flush()` 确保数据被立即写出。

#### **2. `write(byte[] b)` 与 `write(byte[] b, int off, int len)`：写入字节数组**

这是**更高效**的写入方式。`write(byte[] b)` 将整个字节数组的内容写入；`write(byte[] b, int off, int len)` 则写入数组中从 `off` 开始、长度为 `len` 的部分。

```java
try (BufferedOutputStream bos = new BufferedOutputStream(new FileOutputStream("array.bin"))) {
    byte[] data = "Hello, BufferedOutputStream!".getBytes();
    bos.write(data); // 写入整个数组

    byte[] partialData = {0x01, 0x02, 0x03, 0x04, 0x05};
    bos.write(partialData, 1, 3); // 只写入 0x02, 0x03, 0x04
} catch (IOException e) {
    e.printStackTrace();
}
```
在源码层面，如果一次写入的长度 `len` 超过了缓冲区大小，`BufferedOutputStream` 会先将缓冲区现有数据刷出，然后**直接将这个大数组写入底层流**，避免不必要的内存拷贝。

#### **3. `flush()`：强制刷新缓冲区**

`flush()` 方法会**立即**将缓冲区中所有尚未写入的数据推送到下层输出流，并调用下层流的 `flush()` 方法。**这是确保数据及时落盘的关键**，尤其是在网络通信或需要实时反馈的场景中。

```java
BufferedOutputStream bos = new BufferedOutputStream(new FileOutputStream("flush_demo.txt"));
bos.write("Critical data".getBytes());
// 在关闭前或需要确保数据可见时，调用 flush()
bos.flush();
// ... 后续操作
bos.close();
```
> **注意**：如果不调用 `flush()` 且缓冲区未满，程序结束或流未正常关闭时，缓冲区内的数据**可能会丢失**。

#### **4. `close()`：关闭流并释放资源**

`close()` 方法在关闭流之前，会**自动调用一次 `flush()`**，确保缓冲区中的所有数据都被写入底层流。随后，它还会关闭被包装的底层流（例如 `FileOutputStream`）。因此，在 `close()` 之前再显式调用 `flush()` 通常是冗余的。

```java
// 推荐使用 try-with-resources 语法，它会自动调用 close()
try (BufferedOutputStream bos = new BufferedOutputStream(new FileOutputStream("auto_close.txt"))) {
    bos.write("Data written with try-with-resources".getBytes());
} // 在此处，bos.close() 会被自动调用，数据会被安全写入文件
catch (IOException e) {
    e.printStackTrace();
}
```

### 💎 总结与要点

*   **装饰器模式**：它不直接提供数据源，而是**包装**另一个 `OutputStream` 来增强其功能。
*   **性能优化**：通过**批量写入**减少本机 I/O 次数，是提升 I/O 性能的标准做法。
*   **使用模式**：典型的使用模式是 `new BufferedOutputStream(new FileOutputStream(...))`。
*   **关键操作**：**`flush()` 确保数据及时写出**，而 **`close()` 会自动刷新并释放所有资源**。推荐使用 try-with-resources 语句来管理流的关闭。
*   **默认缓冲区**：默认大小为 **8192 字节**，可根据实际情况在构造时调整，以达到性能与内存占用的最佳平衡。
