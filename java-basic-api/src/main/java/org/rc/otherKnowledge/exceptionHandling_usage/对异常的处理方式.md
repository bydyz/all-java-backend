# Java 中异常处理方式详解

在 Java 中，异常处理是构建健壮应用程序的核心机制。Java 将异常视为对象，所有的异常都继承自 `java.lang.Throwable` 类。异常处理的主要目的是将**错误处理代码**与**正常业务逻辑代码**分离，提高程序的可读性和容错性。

Java 的异常主要分为两类：

1. **受检异常（Checked Exception）**：编译器强制要求处理的异常（如 `IOException`），必须使用 `try-catch` 捕获或使用 `throws` 声明抛出。
2. **非受检异常（Unchecked Exception / RuntimeException）**：编译器不强制要求处理（如 `NullPointerException`、`ArithmeticException`），通常代表代码逻辑错误。

以下是 Java 中处理异常的几种核心方式及代码示例。

---

## 1. 使用 `try-catch` 捕获异常

这是最基础的处理方式。将可能发生异常的代码放在 `try` 块中，一旦发生异常，控制流会立即跳转到匹配的 `catch` 块。

```java
public class TryCatchExample {
    public static void main(String[] args) {
        try {
            int result = 10 / 0; // 可能发生 ArithmeticException
            System.out.println("结果: " + result); // 这行不会被执行
        } catch (ArithmeticException e) {
            System.out.println("捕获到算术异常: " + e.getMessage());
            // 可以在这里进行补救措施，如记录日志、设置默认值等
        }
        System.out.println("程序继续向下执行...");
    }
}
```

---

## 2. 使用 `try-catch-finally`

`finally` 块中的代码**无论是否发生异常都会执行**（除非 JVM 退出）。它通常用于释放资源（如关闭文件流、数据库连接）。

```java
public class FinallyExample {
    public static void main(String[] args) {
        try {
            System.out.println("打开资源...");
            int[] arr = new int[3];
            arr[5] = 10; // 抛出 ArrayIndexOutOfBoundsException
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("捕获到数组越界异常");
        } finally {
            System.out.println("执行 finally 块：关闭资源/清理工作");
        }
    }
}
```

---

## 3. 使用 `throws` 声明异常（向上抛出）

如果当前方法不知道如何处理某个受检异常，可以使用 `throws` 关键字将异常抛给调用者处理。

```java
import java.io.FileInputStream;
import java.io.FileNotFoundException;

public class ThrowsExample {

    // 声明该方法可能抛出 FileNotFoundException，调用者必须处理
    public static void readFile() throws FileNotFoundException {
        FileInputStream fis = new FileInputStream("不存在的文件.txt");
    }

    public static void main(String[] args) {
        try {
            readFile(); // 调用者捕获异常
        } catch (FileNotFoundException e) {
            System.out.println("文件未找到，请检查路径！");
        }
    }
}
```

---

## 4. 使用 `throw` 手动抛出异常

除了系统自动抛出异常，开发者也可以根据业务逻辑主动使用 `throw` 抛出异常对象。

```java
public class ThrowExample {
    public static void checkAge(int age) {
        if (age < 18) {
            // 手动抛出非受检异常（运行时异常）
            throw new IllegalArgumentException("年龄必须大于等于18岁");
        }
        System.out.println("年龄合法，允许注册");
    }

    public static void main(String[] args) {
        try {
            checkAge(15);
        } catch (IllegalArgumentException e) {
            System.out.println("业务异常: " + e.getMessage());
        }
    }
}
```

---

## 5. 多重捕获（Multi-catch）与异常链

- **多重捕获（Java 7+）**：在一个 `catch` 块中捕获多种异常，用 `|` 分隔。
- **异常链**：捕获一个异常后，抛出一个新的异常，并将原异常作为新异常的 `cause` 传入，保留原始错误信息。

```java
public class MultiCatchExample {
    public static void main(String[] args) {
        try {
            String str = null;
            if (System.currentTimeMillis() % 2 == 0) {
                System.out.println(str.length()); // NullPointerException
            } else {
                int num = Integer.parseInt("abc"); // NumberFormatException
            }
        } catch (NullPointerException | NumberFormatException e) {
            System.out.println("捕获到空指针或数字格式异常: " + e.getClass().getSimpleName());

            // 异常链：将原始异常包装后抛出（常见于框架底层）
            throw new RuntimeException("数据处理失败", e);
        }
    }
}
```

---

## 6. 使用 `try-with-resources`（Java 7+）

对于实现了 `AutoCloseable` 接口的资源（如 `InputStream`、`Connection`），可以使用 `try-with-resources` 语法。无需编写 `finally` 块，JVM 会自动调用资源的 `close()` 方法，且能自动处理**抑制异常**（Suppressed Exceptions）。

```java
import java.io.BufferedReader;
import java.io.FileReader;
import java.io.IOException;

public class TryWithResourcesExample {
    public static void main(String[] args) {
        // 资源在 try 的括号中声明，程序执行完毕后自动关闭
        try (BufferedReader br = new BufferedReader(new FileReader("test.txt"))) {
            String line = br.readLine();
            System.out.println("文件内容: " + line);
        } catch (IOException e) {
            System.out.println("IO异常: " + e.getMessage());
        }
    }
}
```

## 7. 自定义异常

当 Java 内置异常无法满足业务需求时，可以自定义异常类。通常继承 `Exception`（受检异常）或 `RuntimeException`（非受检异常）。

```java
// 自定义业务异常（继承 RuntimeException，调用者无需强制捕获）
class InsufficientBalanceException extends RuntimeException {
    private double balance;

    public InsufficientBalanceException(String message, double balance) {
        super(message);
        this.balance = balance;
    }

    public double getBalance() { return balance; }
}

public class CustomExceptionExample {
    public static void withdraw(double amount, double balance) {
        if (amount > balance) {
            throw new InsufficientBalanceException("余额不足", balance);
        }
        System.out.println("取款成功");
    }

    public static void main(String[] args) {
        try {
            withdraw(500, 100);
        } catch (InsufficientBalanceException e) {
            System.out.println("错误: " + e.getMessage() + "，当前余额: " + e.getBalance());
        }
    }
}
```

## 💡 最佳实践建议

1. **不要吞掉异常**：不要写空的 `catch` 块，至少应打印日志 `e.printStackTrace()`。
2. **捕获具体的异常**：优先捕获具体的异常类型（如 `FileNotFoundException`），而不是直接捕获 `Exception`，以免掩盖未知错误。
3. **尽早抛出，尽早捕获**：在底层发现错误时立即抛出（Fail-fast），在能够处理该错误的最上层进行捕获。
4. **释放资源**：优先使用 `try-with-resources` 替代 `finally` 关闭资源，代码更简洁且安全。
5. **异常不要用于流程控制**：异常处理性能开销较大，不要用异常来替代正常的条件判断（如 `if-else`）。
