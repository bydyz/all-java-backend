下面按“异常体系 → 自定义异常 → 使用方式 → 异常链 → try-with-resources → 最佳实践”说明，并给出可运行风格的示例代码。

---

## 1. Java 异常体系简要回顾

Java 中异常相关顶层类型是 `Throwable`，主要分为：

- `Error`：系统级严重错误，如 `OutOfMemoryError`，通常不应捕获和自定义继承。
- `Exception`：程序可处理的异常。
  - **受检异常 Checked Exception**：继承 `Exception` 但不继承 `RuntimeException`。方法必须 `throws` 声明，调用方必须 `try-catch` 或继续 `throws`。
  - **非受检异常 Unchecked Exception**：继承 `RuntimeException`。编译器不强制处理，常用于编程错误或业务规则失败。

自定义异常一般：
- 业务异常、参数错误、状态错误：常继承 `RuntimeException`；
- 调用方必须显式处理的异常：继承 `Exception`。

不要继承 `Throwable` 或 `Error`。

## 2. 自定义非受检异常：带错误码的业务异常

适合业务规则失败，例如支付失败、库存不足。调用方不强制捕获，但可通过全局异常处理器统一处理。

```java
public class BusinessException extends RuntimeException {
    private static final long serialVersionUID = 1L;

    private final String code; // 业务错误码

    public BusinessException(String code, String message) {
        super(message);
        this.code = code;
    }

    public BusinessException(String code, String message, Throwable cause) {
        super(message, cause);
        this.code = code;
    }

    public String getCode() {
        return code;
    }
}
```

使用：

```java
public class PayService {
    public void pay(String orderId, boolean success) {
        if (!success) {
            throw new BusinessException("PAY_001", "订单支付失败，orderId=" + orderId);
        }
    }
}
```

调用方可以捕获，也可以不捕获：

```java
PayService payService = new PayService();
try {
    payService.pay("A100", false);
} catch (BusinessException e) {
    System.err.println("错误码：" + e.getCode());
    System.err.println("错误信息：" + e.getMessage());
}
```

## 3. 自定义受检异常：调用方必须处理

适合“调用方必须显式处理或继续声明”的场景，例如订单校验失败、文件格式不合法等。

```java
public class InvalidOrderException extends Exception {
    private static final long serialVersionUID = 1L;

    private final String orderId;

    public InvalidOrderException(String orderId, String message) {
        super(message);
        this.orderId = orderId;
    }

    public InvalidOrderException(String orderId, String message, Throwable cause) {
        super(message, cause);
        this.orderId = orderId;
    }

    public String getOrderId() {
        return orderId;
    }
}
```

使用：方法必须 `throws` 声明。

```java
public class OrderService {

    public void createOrder(String orderId, int amount) throws InvalidOrderException {
        if (orderId == null || orderId.isBlank()) {
            throw new InvalidOrderException(orderId, "订单号不能为空");
        }
        if (amount <= 0) {
            throw new InvalidOrderException(orderId, "订单金额必须大于 0");
        }

        try {
            // 模拟底层调用可能抛出非受检异常
            if (amount > 100000) {
                throw new IllegalArgumentException("金额超过系统限制");
            }
            System.out.println("创建订单成功：" + orderId);
        } catch (IllegalArgumentException e) {
            // 包装为受检异常，并保留原始异常链
            throw new InvalidOrderException(orderId, "创建订单失败", e);
        }
    }
}
```

调用方有两种处理方式。

方式一：`try-catch` 处理：

```java
public class Demo {
    public static void main(String[] args) {
        OrderService service = new OrderService();

        try {
            service.createOrder("A100", 200000);
        } catch (InvalidOrderException e) {
            System.err.println("订单号：" + e.getOrderId());
            System.err.println("失败原因：" + e.getMessage());

            // 打印完整异常链
            e.printStackTrace();
        }

        try {
            new PayService().pay("A100", false);
        } catch (BusinessException e) {
            System.err.println(e.getCode() + " : " + e.getMessage());
        }
    }
}
```

方式二：继续向上声明：

```java
public void handle() throws InvalidOrderException {
    new OrderService().createOrder("A100", 100);
}
```

## 4. 异常链：包装底层异常时保留 cause

上面代码中的：

```java
throw new InvalidOrderException(orderId, "创建订单失败", e);
```

就是异常链。`e` 是 cause，通过 `getCause()` 可获取原始异常。

也可以手动设置：

```java
InvalidOrderException ex = new InvalidOrderException(orderId, "创建订单失败");
ex.initCause(new IllegalArgumentException("金额超过系统限制"));
throw ex;
```

推荐使用带 `Throwable cause` 的构造器，不要丢失原始异常：

```java
// 不推荐：原始异常信息丢失
catch (IOException e) {
    throw new BusinessException("FILE_001", "文件读取失败");
}

// 推荐：保留 cause
catch (IOException e) {
    throw new BusinessException("FILE_001", "文件读取失败", e);
}
```

## 5. try-with-resources 与 suppressed 异常

如果自定义资源实现 `AutoCloseable`，`try-with-resources` 会自动关闭资源。若 `try` 块和 `close()` 都抛异常，主异常抛出，`close()` 异常会作为 suppressed 异常保留。

```java
import java.io.IOException;

public class MyResource implements AutoCloseable {

    public void work() throws IOException {
        throw new IOException("work 执行失败");
    }

    @Override
    public void close() throws IOException {
        throw new IOException("close 关闭失败");
    }

    public static void main(String[] args) {
        try (MyResource resource = new MyResource()) {
            resource.work();
        } catch (IOException e) {
            System.err.println("主异常：" + e.getMessage());

            for (Throwable suppressed : e.getSuppressed()) {
                System.err.println("被抑制异常：" + suppressed.getMessage());
            }
        }
    }
}
```

输出大致为：

```text
主异常：work 执行失败
被抑制异常：close 关闭失败
```

这比手动 `finally` 中关闭资源更安全，也避免 `close()` 异常覆盖主异常。

## 6. 多异常捕获与 catch 顺序

```java
try {
    service.createOrder("A100", 200000);
    new PayService().pay("A100", false);
} catch (InvalidOrderException | BusinessException e) {
    // 多个异常类型处理
    System.err.println("业务处理失败：" + e.getMessage());
} catch (RuntimeException e) {
    System.err.println("运行时异常：" + e.getMessage());
}
```

注意：
- 子类异常要放在父类异常前面；
- 多异常捕获 `A | B` 时，二者不能有继承关系；
- 不要随意 `catch (Exception e)` 后什么都不做。

## 7. 自定义异常和使用的最佳实践

1. **命名以 `Exception` 结尾**，如 `OrderNotFoundException`、`PaymentException`。
2. **选择父类要明确**：
  - 业务异常、参数错误、状态错误：常用 `RuntimeException`；
  - 调用方必须处理的场景：用 `Exception`。
3. **不要继承 `Throwable` 或 `Error`**。
4. **提供必要构造器**：至少提供 `message` 和 `message + cause`；需要序列化时加 `serialVersionUID`。
5. **不要吞异常**：
   ```java
   // 不推荐
   catch (IOException e) {
       e.printStackTrace();
   }
   ```
   应记录日志后抛出，或转换为业务异常并保留 cause。
6. **异常信息包含上下文但不要包含敏感信息**，如密码、身份证号、密钥。
7. **不要用异常做普通流程控制**，例如用异常判断循环结束。
8. **`finally` 中不要 `return`**，否则可能覆盖 `try` 中的异常或返回值。
9. **日志记录和抛出通常只做一次**，避免上层重复打印同一异常。
10. **框架项目中可用全局异常处理器**统一把 `BusinessException` 转为错误响应，但异常类本身应保持简单。

## 8. 一个完整的小示例结构

```java
public class BusinessException extends RuntimeException {
    private static final long serialVersionUID = 1L;
    private final String code;

    public BusinessException(String code, String message) {
        super(message);
        this.code = code;
    }

    public BusinessException(String code, String message, Throwable cause) {
        super(message, cause);
        this.code = code;
    }

    public String getCode() {
        return code;
    }
}
```

```java
public class InvalidOrderException extends Exception {
    private static final long serialVersionUID = 1L;
    private final String orderId;

    public InvalidOrderException(String orderId, String message) {
        super(message);
        this.orderId = orderId;
    }

    public InvalidOrderException(String orderId, String message, Throwable cause) {
        super(message, cause);
        this.orderId = orderId;
    }

    public String getOrderId() {
        return orderId;
    }
}
```

```java
public class OrderService {
    public void createOrder(String orderId, int amount) throws InvalidOrderException {
        if (orderId == null || orderId.isBlank()) {
            throw new InvalidOrderException(orderId, "订单号不能为空");
        }
        if (amount <= 0) {
            throw new InvalidOrderException(orderId, "订单金额必须大于 0");
        }

        try {
            if (amount > 100000) {
                throw new IllegalArgumentException("金额超过系统限制");
            }
            System.out.println("订单创建成功：" + orderId);
        } catch (IllegalArgumentException e) {
            throw new InvalidOrderException(orderId, "订单创建失败", e);
        }
    }

    public void pay(String orderId, boolean success) {
        if (!success) {
            throw new BusinessException("PAY_001", "支付失败，orderId=" + orderId);
        }
    }
}
```

```java
public class Demo {
    public static void main(String[] args) {
        OrderService service = new OrderService();

        try {
            service.createOrder("A100", 200000);
        } catch (InvalidOrderException e) {
            System.err.println("订单号：" + e.getOrderId() + "，原因：" + e.getMessage());
            e.printStackTrace();
        }

        try {
            service.pay("A100", false);
        } catch (BusinessException e) {
            System.err.println("错误码：" + e.getCode() + "，信息：" + e.getMessage());
        }
    }
}
```

核心就是：**自定义异常类负责表达“哪类错误、带什么上下文”；`throw` 负责抛出；`throws` 声明受检异常；`catch` 负责恢复、转换或记录；包装异常时保留 cause；资源关闭优先用 try-with-resources。**
