# Java 异常的定义与抛出机制详解

## 一、异常的定义

异常 ：指的是程序在执行过程中，出现的非正常情况，如果不处理最终会导致 JVM 的非正常停止。
异常指的并不是语法错误和逻辑错误。
语法错了，编译不通过，不会 产生字节码文件，根本不能运行。
代码逻辑错误，只是没有得到想要的结果

### 1.1 异常是对象

Java 中的“异常”不是语法错误，而是**程序运行期间出现的非正常情况的抽象**。在语言层面，它被建模成一个对象——所有异常都是 `java.lang.Throwable` 的实例。这个对象封装了三样关键信息：

- **类型**：异常的类别（决定了谁可以捕获它）；
- **消息**：`getMessage()` 返回的描述；
- **栈轨迹**：`getStackTrace()` 返回异常产生时的方法调用链。

抛出异常本质上是一次**非局部控制跳转**：从出错点直接跳到最近的、类型匹配的处理器，中间的代码被跳过。

### 1.2 Throwable 体系

```
Throwable
├── Error                     JVM 级严重问题，程序通常无法恢复
│   ├── OutOfMemoryError
│   ├── StackOverflowError
│   └── NoClassDefFoundError
└── Exception
    ├── RuntimeException      “非受检”异常：编程错误，编译器不强制处理
    │   ├── NullPointerException
    │   ├── IllegalArgumentException
    │   ├── ClassCastException
    │   └── IndexOutOfBoundsException
    └── 其他 Exception        “受检”异常：可预期的外部条件，编译器强制处理
        ├── IOException
        ├── SQLException
        └── InterruptedException
```

**两类异常的本质区别在于编译器的强制程度：**

| | 受检异常 (checked) | 非受检异常 (unchecked) |
|---|---|---|
| 代表 | `IOException` | `RuntimeException` 及其子类 |
| 编译器要求 | 必须 `try-catch` 或 `throws` 声明 | 无要求 |
| 语义 | 调用者可以恢复的外部条件 | 调用者的编程错误 |
| 设计意图 | 强制 API 使用者在类型系统层面面对可能的失败 | 表示 bug，应通过修正代码消除 |

`Error` 是给 JVM 用的，业务代码一般**不应该**捕获它。

### 1.3 自定义异常

业务异常一般继承 `Exception`（受检）或 `RuntimeException`（非受检），并携带结构化上下文：

```java
// 受检异常：强制调用方处理
public class InsufficientBalanceException extends Exception {
    private final double balance;
    private final double amount;

    public InsufficientBalanceException(double balance, double amount) {
        super("余额不足：当前 " + balance + "，需要 " + amount);
        this.balance = balance;
        this.amount = amount;
    }
    public double getBalance() { return balance; }
    public double getAmount()  { return amount; }
}
```

```java
public class Account {
    private double balance;

    // throws 声明：告诉编译器与调用者“本方法可能抛出该受检异常”
    public void withdraw(double amount) throws InsufficientBalanceException {
        if (amount > balance) {
            // throw：真正创建并抛出异常对象
            throw new InsufficientBalanceException(balance, amount);
        }
        balance -= amount;
    }
}
```

调用方不处理就无法通过编译：

```java
Account acc = new Account();
try {
    acc.withdraw(100);
} catch (InsufficientBalanceException e) {
    System.out.println(e.getMessage());
    System.out.println("缺口: " + (e.getAmount() - e.getBalance()));
}
```

## 二、抛出机制

Java 中把不同的异常用不同的类表示，一旦发生某种异常，就创建该异常类型的对象，并且抛出（throw）。
然后程序员可以捕获(catch)到这个异常对象，并处理；
如果没有捕获(catch)这个异常对象，那么这个异常对象将会导致程序终止。

### 2.1 两种抛出方式

**（1）显式抛出：`throw` 语句**

```java
throw new IllegalArgumentException("参数不能为负: " + x);
```

- `throw` 的操作数必须是 `Throwable` 子类的引用；
- 若操作数为 `null`，运行时会抛 `NullPointerException`；
- 执行 `throw` 后，当前语句之后的代码不再执行。

**（2）隐式抛出：由 JVM 在检测到错误条件时自动抛出**

```java
int[] a = new int[3];
a[10] = 1;                  // JVM 抛 ArrayIndexOutOfBoundsException
Object o = null;
o.toString();               // JVM 抛 NullPointerException
int r = 10 / 0;             // JVM 抛 ArithmeticException
```

JVM 内部相当于执行了 `athrow` 字节码指令，效果与 `throw` 完全一致。

### 2.2 `throw` 与 `throws` 的区别

```java
// throws：方法签名上的“声明”，是契约，编译期检查
public void read(String path) throws IOException { ... }

// throw：方法体内的“动作”，是运行期行为
throw new IOException("文件不存在");
```

一个方法可以声明多个：`throws IOException, SQLException`。

### 2.3 传播机制：栈展开（stack unwinding）

抛出异常后，JVM 的处理流程是：

1. 在当前方法的**异常表**中查找与异常类型匹配的处理器（catch 块）；
2. 找到 → 控制流跳转到该 catch 块，栈帧保留；
3. 找不到 → **弹出当前栈帧**，回到调用者，重复步骤 1；
4. 一直到 `main` 都没有匹配 → 线程终止，交由 `uncaughtExceptionHandler` 处理（默认打印栈轨迹）。

```java
public class Propagation {
    static void c() { throw new IllegalStateException("来自 c"); }
    static void b() { c(); }
    static void a() { b(); }

    public static void main(String[] args) {
        try {
            a();
        } catch (IllegalStateException e) {
            e.printStackTrace();
        }
        System.out.println("程序继续运行");
    }
}
```

输出（注意栈是**自顶向下**从抛出点到捕获点）：

```
java.lang.IllegalStateException: 来自 c
    at Propagation.c(Propagation.java:2)
    at Propagation.b(Propagation.java:3)
    at Propagation.a(Propagation.java:4)
    at Propagation.main(Propagation.java:8)
程序继续运行
```

关键点：`b()` 和 `a()` 并没有 catch，异常“穿过”它们向上传播，它们的栈帧在传播过程中被丢弃——这就是“栈展开”。

### 2.4 catch 的匹配规则

```java
try {
    risky();
} catch (FileNotFoundException e) {      // 子类必须在前
    System.out.println("文件没找到");
} catch (IOException e) {                // 父类在后
    System.out.println("其他 IO 错误");
}
```

- 匹配依据是 `instanceof`（即实际异常类型是否是 catch 参数类型的子类）；
- **顺序必须从子类到父类**，否则子类分支不可达，编译报错；
- Java 7+ 支持多重捕获，此时变量隐含 `final`：

```java
catch (IOException | SQLException e) {
    logger.error("操作失败", e);
}
```

### 2.5 底层实现：异常表

编译器并不把 try-catch 编译成跳转指令，而是在方法的 `Code` 属性中生成一张**异常表**（exception table）。用 `javap -c` 可以看到：

```java
static void demo() {
    try {
        mayThrow();
    } catch (IOException e) {
        System.out.println("io");
    } finally {
        System.out.println("done");
    }
}
```

```
Exception table:
   from    to  target type
      0     8    11   Class java/io/IOException   // [0,8) 内抛 IOException → 跳到 11
      0     8    22   any                          // [0,8) 内抛任何异常 → 跳到 22（finally）
     11    22    22   any                          // catch 块内再抛 → 也走 finally
```

`from/to` 是字节码偏移区间，`target` 是处理器入口，`type` 为 `any` 表示 `finally` 的“兜底”入口（JVM 用 `athrow` 重新抛出原异常）。这也是为什么 `finally` 一定会执行：**它被编译成了每个出口路径上的一份拷贝**。

### 2.6 finally 的执行时机与陷阱

`finally` 在以下情况都会执行：正常结束、抛异常、`return`、`break`、`continue`。例外只有 `System.exit()`、JVM 崩溃等。

**陷阱一：finally 里的 return 会吞掉异常**

```java
static int bad() {
    try {
        throw new RuntimeException("会被吞掉");
    } finally {
        return 1;   // 直接返回，异常被丢弃
    }
}
// bad() 返回 1，不会抛出任何异常
```

**陷阱二：finally 里抛异常会覆盖原异常**

```java
try {
    throw new IllegalStateException("原始异常");
} finally {
    throw new IllegalArgumentException("finally 中的异常");  // 原始异常丢失
}
```

**正确做法**：`finally` 只做资源释放，不要 `return`、不要抛异常。

### 2.7 异常链（cause）与抑制异常（suppressed）

**异常链**：把底层异常包进业务异常，保留根因。

```java
try {
    config = loadConfig();
} catch (IOException e) {
    throw new ConfigException("加载配置失败", e);   // e 作为 cause
}
```

上层可以逐层追溯：

```java
catch (ConfigException e) {
    Throwable root = e;
    while (root.getCause() != null) root = root.getCause();
    System.out.println("根因: " + root);
}
```

**抑制异常**：`try-with-resources` 中，若 `try` 体抛异常、`close()` 也抛异常，`close` 的异常不会覆盖前者，而是被挂到前者的 `suppressed` 列表上。

```java
try (Resource r = new Resource()) {   // Resource 实现 AutoCloseable
    throw new RuntimeException("业务异常");
} catch (Exception e) {
    System.out.println("主异常: " + e.getMessage());
    for (Throwable s : e.getSuppressed()) {
        System.out.println("被抑制: " + s.getMessage());   // close 中的异常
    }
}
```

这也是 `try-with-resources` 优于手写 `finally` 关闭的原因之一。

### 2.8 未捕获异常的最终归宿

如果异常一路传播到 `main` 仍无人处理：

```java
Thread.setDefaultUncaughtExceptionHandler((t, e) -> {
    System.err.println("线程 " + t.getName() + " 崩溃: " + e);
});
```

默认处理器会把栈轨迹打印到 `System.err` 并终止该线程（不影响其他线程）。

## 三、实践要点小结

1. **能不用异常就不用**：异常用于“异常”情况，不要用异常做正常流程控制（性能与可读性都差）；异常对象的构造（`fillInStackTrace`）开销较大。
2. **受检异常用于可恢复的外部失败**（IO、网络、数据库），**`RuntimeException` 用于编程错误**（参数非法、状态错误）。
3. **不要吞异常**：空的 `catch {}` 是最危险的代码；至少记录日志，或包装后重抛。
4. **包装时保留 cause**：`new XxxException(msg, e)`，不要丢弃根因。
5. **`finally` 只做清理**，避免在其中 `return` 或抛异常。
6. **优先 `try-with-resources`**，它天然处理抑制异常。
7. **catch 要精确**：不要为了省事写 `catch (Exception e)` 然后什么都不做；捕获后要么处理，要么声明继续上抛。
8. **自定义异常要携带上下文**（如 `InsufficientBalanceException` 里的 `balance`/`amount`），让调用方可以做出决策，而不是解析字符串。
